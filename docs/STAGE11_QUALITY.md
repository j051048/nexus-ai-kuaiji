# 第十一阶段：真实业务评测

评测用于验证辅助记账流程，不增加自动审批或正式总账能力。当前没有收集真实试点样本；仓库测试仅使用合成企业、票据和明确标记的模拟模型结果。

## 标准及证据

进入标准的分录必须来自 `learning_samples` 已审核样例，当前凭证仍为已审核或已导出，来源、事实与冻结证据仍有效。标准提议冻结业务输入、原始来源、已审核最终分录、原件名称及 SHA256、实际成功 OCR 结果及模型/提示词/事实版本。不能提交自行编造的最终分录。

会计先查看原凭证与原件，并手工录入希望评测的 OCR 字段标准答案；不选择的字段不被测量。页码引用必须属于实际票据。字段标注包含价税合计、不含税金额、税额、交易方、税号、日期、号码和币种，金额保持整数分比较。标准由另一位拥有此账套复核权限的人员明确确认“已经独立核对原件”后才允许回放。提议人不能自审，确认记录不可覆盖。

标准不改业务事实和凭证。如果原审批有误，仍走业务事实修订及独立审批流程；不能通过更新评测标准改账。原件上传、补件或 OCR 证据改变后旧标准显示失效，需要重新建立标准。已关闭期间仍可进行证据评测，不允许借此恢复账务写入。

## 可重复的回放

每次运行最多 100 个已独立确认的标准，保存所选标准、范围、配置上下文、逐项候选、差异、版本归属和幂等键。运行是一次有界的确定性事务，报告持久保存；不发起新模型调用，不创建或审核草稿。

| 范围 | 取值方式 | 实际测量 |
|---|---|---|
| 当前企业规则 | 只取本账套当前已发布且正例均可用于普通分类的规则；匹配稳定往来方 ID 或旧精确原文；冲突不猜测 | 借贷金额、科目、辅助项 |
| 当前固定模板 | 本账套当前启用模板；按具体类别/付款状态优先级选唯一候选 | 借贷金额、科目、辅助项 |
| 存量分录模型 | 指定模型和提示词版本，选择同一事项、草稿和审核前版本的实际成功归档候选；生成审计中的事实版本须一致 | 金额、科目、辅助项，以及所引用原件字段与页码是否存在 |
| 存量票据 OCR | 指定模型和提示词版本，选择同一附件和事实版本的实际成功 OCR | 仅已由会计手工标注并独立确认的字段值与页码 |

存量模型比较的是历史归档结果，报告保留输入版本及指纹，不宣称该结果按当前补件、规则或科目上下文重新生成。金额精确到分，不根据置信分认定正确。核销清偿样例保留追踪，普通规则/模板回放将其标记为未覆盖。

`passed` 表示本次已测项一致；`different` 表示存在逐字段或分录差异；`uncovered` 表示缺少配置、标签或指定模型结果；`stale` 表示事实或证据已失效。未覆盖与失效不会计入通过。规则/模板不会声称已经评测来源日期、交易方名称或税务处理，只有相应 OCR 人工字段标注被测量时才有该字段结果。任何抽样通过比例都不能推算成整家企业、月结或税务正确率。

科目、模板、规则、已审核别名或所选模型结果改变后，历史运行保留原报告并显示配置已变化。每次查看、回放和确认都重新检查企业及账套授权；撤权立即拒绝读取。PostgreSQL 三张新增表开启 FORCE RLS，标准原生校验对照实际审核来源，运行原生重算候选与报告，伪造 passed 报告不能写入。SQLite 用于本地演示，生产授权边界由 PostgreSQL 承担。

## 月度测量口径

界面按当前企业、月份及业务类型统计已独立确认标准。账套人工分钟复用明确开启并持续确认活跃的计时；补件等待复用首次请求到首次响应的日历时间；交付差异观察最新最多 100 次人工导入回执并与冻结导出核对，同一事项重复回执可能重复计项，界面明确标记截断。未采集返回 `null`，不会把空样本展示为零错误或零工时。人工工时尚未精确分摊到每个业务类型。

`GET /api/books/{book_id}/quality/report` 及 overview 的 `report_groups` 为月度业务类型回放汇总。SQL 在当前已授权账套内按回放范围分组，各取最新一次运行，最多 4 次运行、每次最多 100 个标准，按 `items.business_type` 统计一致、差异、未覆盖和失效。每行保留运行 ID、创建时间、所选样本数及当前配置是否变化。已经变化的运行只展示历史计数，`measured_match_rate` 和 `measured_sample_count` 返回 `null`，不会继续作为当前通过比例。各类型无法归因的工时、等待与交付差异同样保持 `null`。

下一步试点应由会计在 2–3 家企业中挑选覆盖主要业务类型的实际样例，并保留真实原件及独立确认记录，再按月份测量处理分钟、字段和分录修正、未覆盖原因及最终交付差异。当前结果不能证明 200–500 家容量。
