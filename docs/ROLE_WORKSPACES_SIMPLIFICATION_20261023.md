# 第二批岗位工作台收敛：本地实现与验收

日期：2026-10-23。基线：`cf07ef0874c76b37f55c364e42b08cce9852c46e` 加开始时的既有未提交修改。

## 目标与范围

围绕员工提交、企业财务核验移交、事务所协调交付三个主任务收敛界面。复用已有录入、资料清单、业务事项、服务单、人员管理、同屏复核和导出，不另造流程或授权体系。

本轮仅本地开发与离线回归，使用虚构资料和本机验证身份。没有提交、推送、部署、线上数据库或真实模型操作。测试 API 在本机一次性 SQLite 中使用仓库既有迁移初始化数据；本轮没有新增或改写数据库迁移。

## 已实现

| 工作台 | 首要内容 | 辅助内容 |
|---|---|---|
| 员工 | 三张提交卡：报销、采购/费用、日常收支；本人补件和办理进度 | 岗位/权限说明默认折叠；兼任会计权限不抢占主操作 |
| 企业财务 | 核验资料并移交会计；真实当前清单中的下一项；业务事项和资料清单入口 | 本人提交、报告、额外会计能力放在后部折叠区；权限失效时不推荐核验 |
| 事务所管理 | 本月服务进度、需要协调的客户、人员安排；进入客户进度/人员管理/客户开通 | 全部客户明细与统计口径按需展开；月结完成不等同于交付完成 |

- 管理层主导航收为全所概览、客户企业、月度交付、异常与补件；会计作业及其他日常业务按需展开。
- 数据接入、运行可观测性、费用监控、后台运行、票据任务、识别异常、试点评测等集中到“设置”，继续使用原有能力位。
- 企业门户的附加会计/企业管理入口同样在默认折叠的设置中，入口须同时具备真实能力和受控回调。
- 成员与账套授权入口保留并移入设置；未减少既有授权操作。
- 不再在首页额外查询 `/api/agent-workspace/summary`；运行记录由设置中的既有页面读取。
- 手机主任务区纵向排列；设置与品牌不逐字竖排，导航采用图标加单行文字；保留键盘焦点、移动导航关闭和未保存变更保护。

## 本轮额外复现并修复的问题

1. **管理服务单串月**：原查询按企业归并全部月份的服务计划，可能借用其他月份的负责人和期限。改为当前账套 ID，并在查询、最新版本和关联中绑定事务所/企业/账套；无当月服务单显示待安排，不借用次月。
2. **管理按钮丢失月份**：工作台局部月份未传到“客户进度/新增客户”。回调传递所选期间，父级导航时保留；浏览器覆盖历史月份跳转。
3. **默认路由竞争**：管理员的角色默认入口曾被路由规范化覆盖回待办。默认落地放在路由同步之后，同时更新路由状态与 URL；仅裸根入口使用默认，显式页面和深链接不改写。
4. **撤权后的主动作**：财务展示身份保留但核验能力失效时，禁用入口、不使用缓存任务推荐，并保留重新读取权限说明。
5. **手机文字竖排**：财务账号的品牌和设置原先会在窄屏挤成两行。先以浏览器 Range 测量文字行数复现，再调整弹性布局和单行导航。

## 协作边界与实际限制

- 开始时保存 `tmp_test/role2-baseline.json`：HEAD、工作区状态及 1517 个路径的哈希/缺失标记；最终再对比。既有第一批 UI、C01、PG 持续门禁及其他任务的 OCR 改动都保留。
- C01 子账/辅助维度/银行证据、所有迁移、数据库实现、Worker/费用/attempt 和模型处理代码未由本轮修改；本轮后端生产源码仅修改只读的 `app/cockpit/service.py`。
- **管理待办仍是企业当前未结事项，可能跨月；人员面板按所选月份的主办会计归组，数值是客户合计待办，不是该人员实际获指派量。** 页面已有常显说明和展开口径说明。本轮未重建任务投影，也不宣称精确的逐月工作负载统计。
- 未做本轮 PostgreSQL/Supabase、生产身份和真机验证；手机证据来自 Chromium 视口模拟。本轮验收不替代 C01、真实模型或上线门槛。

本轮只验收上述岗位工作台收敛，不把已有未完成的其他工作包宣布完成。
