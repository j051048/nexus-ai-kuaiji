# 账本优先：6 家客户、6 个月双轨执行计划

日期：2026-10-18　适用范围：初期 6 家客户　周期：26 周（2026-10-19 至 2027-04-18）
性质：执行规划，不含代码改动。上游判断见 [产品、代码与体验审核及优化规划](PRODUCT_CODE_UX_REVIEW_20261018.md) 第 14 节。

---

## 0. 结论

**6 家客户 + 6 个月双轨，足够把“最小完整账本（L2）”跑通，但不适合做“全量 ERP”。**

- 不做：多币种、合并报表、存货/成本、工资、预算、资金、税务申报直连、SSO、多区域。
- 要做：总账、明细账、辅助账、期初、凭证号、期末结转、试算平衡、资产负债表、利润表、现金流量表（间接法）、应收应付、银行对账、固定资产折旧、税务底稿、审计追踪、多客户隔离。
- 节奏：**先影子账本（双轨）→ 再客户可见（仍双轨）→ 最后停外部软件（单轨）**。
- 验收：连续 2 个账期、6 家客户、零未解释差异，才允许停外部软件。

## 1. 前提与假设

### 1.1 已确认

- 初期目标客户：**6 家**。
- 接受 **6 个月双轨**：同一批业务在外部财务软件与新账本各做一遍，逐月对照。
- 产品目标：事务所成为“代理记账中心 Agent”，账本必须自有。

### 1.2 待确认（第 1 周补齐，不阻塞启动）

- 6 家客户的纳税人身份（一般纳税人/小规模）、行业、会计准则、税种。
- 是否有固定资产、存货、进出口、多币种、关联交易。
- 现用财务软件与数据可导出程度。
- 报表口径签字人（见第 11 节）。

### 1.3 工作假设（若不成立，调整范围）

- 6 家均为中国大陆、人民币、单法人、小企业会计准则。
- 无合并报表、无多币种、无复杂存货成本；固定资产按直线法。
- 历史数据可导出最近 12 个月凭证、科目余额、往来明细、固定资产清单。
- 事务所可投入约 4.5–5 个全职当量，其中至少 0.5 个首席会计师。

## 2. 6 个月目标与成功标准

### 2.1 业务目标

1. 6 家客户全部在新账本完成“凭证→过账→结账→出表→税务底稿”闭环。
2. 会计不再需要把凭证手工搬进外部软件；外部软件只作为对照/回退。
3. 单客户月度结账时间下降 ≥ 50%，报表出具时间从“天”降到“小时”。
4. 客户领导能拿到一页结论 + 可下载报表，不再看科目编码。

### 2.2 技术目标

1. 账本核心支持：分录、过账、红冲、期初、结转、锁期、报表快照、审计追踪。
2. 连续 2 个账期，6 家客户“新账本 vs 外部软件”科目余额差异为 0（或全部可解释并签字）。
3. 任一张报表可下钻到凭证、再到原件证据。
4. 单户迁移（期初+历史+主数据）≤ 2 小时；回退演练 ≤ 1 小时。
5. 账本核心有自动化测试：借贷平衡、期间校验、凭证号唯一、幂等、红冲、结转、报表勾稽。

### 2.3 不追求的目标

- 不追求功能对标的“大而全”。
- 不追求 1000 家客户的性能；6 家客户的正确性优先。
- 不追求全自动 Agent 过账；Agent 先做草稿与解释，过账仍需人工确认。

## 3. 范围：L2 最小完整账本

### 3.1 必须做（P0）

| 模块 | 能力 | 说明 |
|---|---|---|
| 科目与主数据 | 标准科目模板 + 客户级映射；客户/供应商/项目/部门辅助核算 | 模板化，不为单客户改代码 |
| 期初余额 | 按科目+辅助核算导入、勾稽、确认、锁定 | 切换前必须完成 |
| 凭证 | 分录、凭证号、日期、期间、摘要、附件证据、来源 | 凭证号按账套/期间连续 |
| 过账 | 从已审草稿过账；手工凭证走“草稿→审核→过账” | 过账原子、幂等、可追溯 |
| 红冲/调整 | 红字冲销、调整分录、原凭证关联 | 已过账不可原位修改 |
| 期末结转 | 损益结转、年末结转、折旧、待摊（如需要） | 规则版本化 |
| 锁期/反结账 | 结账后禁止写入；反结账单独授权并留痕 | 分离职责 |
| 账簿 | 总账、明细账、辅助账、科目余额表 | 支持按期间/科目/辅助查询 |
| 试算平衡 | 期初/本期/期末借贷平衡 | 借贷不平禁止结账 |
| 报表 | 资产负债表、利润表、现金流量表（间接法） | 口径版本化、快照、可下钻 |
| 应收应付 | 往来明细、账龄、核销 | 与总账勾稽 |
| 银行对账 | 流水导入、匹配、未达项、余额调节表 | 与总账勾稽 |
| 固定资产 | 卡片、折旧、处置 | 直线法为主 |
| 税务底稿 | 增值税、附加税、企业所得税预缴、印花税（按客户实际税种） | 测算，不直连申报 |
| 审计追踪 | 过账/红冲/结账/反结账/报表生成全留痕 | 含操作人、时间、前后值 |
| 多客户隔离 | firm/company/book 三级隔离 + RLS | 沿用现有安全底座 |
| 导出 | 报表 PDF/Excel、凭证清单、账簿导出 | 客户可带走 |

### 3.2 可延后（P1/P2）

- 批量结账、批量报表（6 家客户可手工，先不做）。
- 行业报表模板（先做通用小企业模板，按客户微调）。
- 固定资产批量导入、折旧批量重算。
- 银行流水自动匹配（先人工匹配，规则后置）。
- 税务底稿自动取数（先半自动，人工复核）。

### 3.3 明确不做（本阶段）

- 存货/成本核算、工资、合并报表、多币种、预算、资金管理。
- 税务申报直连、电子发票全流程、银行直连。
- SSO/SCIM、多区域部署、移动端 App。
- 全自动 Agent 过账、自动审计、自动出表给客户（需人工确认）。
- 为 6 家客户中的任何一家写定制代码；只做配置与模板。

## 5. 四条工作流

### 5.1 账本核心（后端为主）

1. 数据模型：`journal_entries`、`journal_lines`、`opening_balances`、`account_balances`、`voucher_sequences`、`closing_runs`、`report_snapshots`、`tax_workpapers`、`fixed_assets`、`depreciation_schedules`、`report_mappings`。
2. 过账引擎：借贷平衡、期间开放、科目有效、辅助核算、凭证号、幂等键、来源证据。
3. 红冲/调整：红字分录、原凭证关联、不可原位修改。
4. 结账引擎：损益结转、年末结转、折旧、锁期、反结账授权。
5. 报表引擎：科目→报表行映射、版本化、快照、勾稽、下钻。
6. 迁移工具：期初导入、历史凭证导入、科目/辅助映射、差异报告。
7. 审计与权限：`can_post`、`can_close`、`can_reopen`；审核人与过账人分离。

### 5.2 迁移与双轨（会计运营为主）

1. 客户画像：6 家逐户建档（税号、税种、科目、银行、固定资产、往来、特殊处理）。
2. 数据提取：最近 12 个月凭证、科目余额、往来明细、固定资产、未结事项。
3. 映射：科目映射、辅助核算映射、客户/供应商映射。
4. 期初：导入、勾稽、首席会计师确认、锁定。
5. 双轨：同一业务两边各做一遍；周对比、月结对比；差异日志。
6. 切换：逐户切换、回退包、外部软件保留只读。

### 5.3 报表与税务（首席会计师为主）

1. 报表映射 v0：科目→资产负债表/利润表/现金流量表行；经首席会计师签字。
2. 报表口径：合并/净额/备抵/上年比较；版本化。
3. 税务底稿：按 6 家实际税种配置；先增值税、附加税、企业所得税预缴、印花税。
4. 差异分析：账载金额 vs 申报金额；差异说明模板。
5. 签收：每户每月报表由首席会计师复核签字。

### 5.4 交付与运营（产品/实施为主）

1. 客户门户：报表下载、月度结论、待办。
2. 内部看板：6 户进度、差异、结账状态、风险。
3. SOP：迁移、双轨、结账、报表、税务、回退。
4. 培训：会计 2 次、客户 1 次。
5. 支持：问题清单、每周复盘。

## 6. 数据模型与过账规则（设计要点）

### 6.1 核心表

| 表 | 关键字段 | 作用 |
|---|---|---|
| `journal_entries` | id, firm_id, company_id, book_id, period, voucher_no, entry_date, description, source_type, source_id, status, version, posted_by, posted_at, idempotency_key, reversal_of, evidence_ref | 正式凭证头 |
| `journal_lines` | id, entry_id, line_no, account_id, account_code, debit_cents, credit_cents, aux_json, description | 分录行 |
| `opening_balances` | id, book_id, account_id, aux_json, amount_cents, direction, source, confirmed_by, confirmed_at | 期初 |
| `account_balances` | book_id, period, account_id, opening_debit, opening_credit, period_debit, period_credit, closing_debit, closing_credit | 余额快照 |
| `voucher_sequences` | book_id, period, prefix, next_no, version | 凭证号 |
| `closing_runs` | id, book_id, period, status, rules_version, snapshot_hash, started_at, finished_at, approved_by | 结账 |
| `report_mappings` | version, account_code, report_type, report_line, sign, formula, effective_from | 报表映射 |
| `report_snapshots` | id, book_id, period, report_type, mapping_version, source_hash, payload_json, generated_by, generated_at | 报表快照 |
| `tax_workpapers` | id, book_id, period, tax_type, payload_json, variance_json, reviewed_by | 税务底稿 |
| `fixed_assets` | id, book_id, name, category, original_cost_cents, salvage_cents, useful_life_months, method, start_date, status | 固定资产 |
| `depreciation_schedules` | asset_id, period, amount_cents, accumulated_cents, status | 折旧 |

### 6.2 过账不变量（必须自动化校验）

1. `sum(debit_cents) = sum(credit_cents)`，且 > 0。
2. 金额为整数分，不接受浮点。
3. 科目属于当前账套、启用状态、方向正确。
4. 期间为 `open`；已锁期拒绝写入。
5. 辅助核算必填项齐全；往来方/项目/部门有效。
6. 凭证号按 `book_id + period` 连续、唯一；并发生成用序列 + 唯一约束。
7. 幂等键唯一；重复请求返回同一结果。
8. 红冲必须引用原凭证；原凭证不可删除。
9. 过账与草稿状态更新在同一事务；外部副作用走 outbox。
10. 已过账凭证不可原位改金额/科目；只能红冲后重做。
11. 结账前试算平衡；结账后禁止反写。
12. 反结账需单独权限 + 原因 + 审计。

### 6.3 与现有 `drafts` 的共存

- `drafts` 继续作为“复核对象”，保留版本、证据、审核记录。
- 新增 `drafts.journal_entry_id`、`drafts.posted_at`。
- 过账成功后写 `journal_entries`，并回填 `drafts.journal_entry_id`。
- 过渡期：已审核未过账的草稿仍可导出；过账后的凭证以账本为准。
- 历史数据：对已审核/已导出的草稿做一次性回填，生成带 `migration` 标记的凭证，供报表使用。

### 6.4 报表口径

- 先做小企业会计准则通用模板；6 家客户按需微调，不写死代码。
- 资产负债表：资产/负债/所有者权益；注意备抵科目（累计折旧、坏账准备）。
- 利润表：营业收入/营业成本/税金及附加/期间费用/营业外/所得税。
- 现金流量表：间接法；先做可解释的简化版，标注“管理参考”。
- 每张报表保存 `mapping_version` 与 `source_hash`；口径变化生成新版本，不覆盖历史。

## 7. 双轨协议（6 个月的核心纪律）

### 7.1 双轨定义

同一笔业务，在外部财务软件与新账本各生成一套凭证；两边都完成审核、过账、结账；每月对比。

### 7.2 节奏

| 频率 | 动作 | 责任人 |
|---|---|---|
| 每日 | 新账本录入/过账；异常记入差异日志 | 会计 |
| 每周 | 科目余额对比；差异初查 | 主办会计 |
| 每月 | 两边结账；报表对比；差异说明；签字 | 首席会计师 |
| 每季 | 流程复盘；模板/映射修订 | 项目负责人 |

### 7.3 差异处理

- 差异日志字段：客户、期间、科目、辅助、外部金额、新账本金额、差异、原因分类、责任人、修复动作、状态。
- 原因分类：映射错、漏单、重复、金额错、期间错、税额错、外部软件特殊处理、未达项。
- 阈值：**未解释差异必须为 0**；任何差异必须有原因与签字。
- 每月出具《双轨差异报告》，作为 Gate 依据。

### 7.4 切换纪律

- 未连续 2 个账期零未解释差异，不得停外部软件。
- 切换前备份、回退包、回退演练。
- 切换后外部软件保留只读至少 3 个月。

## 8. 逐户迁移与切换

### 8.1 单户迁移清单

1. 基础信息：企业、税号、纳税人身份、会计准则、税率、银行账户。
2. 科目表：标准模板 + 客户差异；科目映射表。
3. 期初余额：按科目 + 辅助核算；与外部软件核对。
4. 历史凭证：最近 12 个月（至少覆盖当年）；导入或仅保留外部查询。
5. 往来：客户/供应商余额、账龄。
6. 固定资产：卡片、原值、累计折旧、剩余年限。
7. 未结事项：未开票、未收款、未付款、待摊、预提。
8. 税务：最近申报表、留抵、预缴。
9. 权限：会计/复核/客户可见范围。

### 8.2 单户切换步骤

```
画像 → 提取 → 映射 → 期初导入 → 勾稽 → 首席会计师确认
→ 双轨 1 个月 → 差异清零 → 客户可见 → 双轨 2 个月
→ 停外部软件（Gate 5）
```

### 8.3 回退

- 保留外部软件只读 + 最近 12 个月数据。
- 新账本导出全量凭证/余额/报表。
- 回退演练：任选 1 户，模拟“停用新账本、回到外部软件”，记录耗时与差异。
- 回退目标：≤ 1 小时，数据不丢。

## 11. 仍需确认的一件事：报表口径谁签字

你尚未指定。建议：

- ** accountable（最终负责）**：你（事务所负责人）。
- ** executor（执行签字）**：首席会计师/财务负责人，必须具备中级以上或同等经验。
- ** reviewer（外部复核）**：外部注册会计师/税务顾问，按季度抽查。
- **签字范围**：科目表、报表映射、税务规则、每户月度报表、口径变更。
- **签字形式**：版本化签字记录（谁、何时、哪一版、依据），进审计追踪。

**如果 W2 结束前没有明确这个人，M1 不应开工。** 账本错了可以改，口径错了会连着报表、税务、客户信任一起错。

## 13. 风险清单（6 户专属）

| 风险 | 触发 | 缓解 |
|---|---|---|
| 6 户样本太小，模板过拟合 | 每户都“特殊” | 标准模板 + 配置；特殊处理进映射表，不写代码 |
| 首席会计师成为瓶颈 | 只有一个人懂口径 | 外部 CPA 备份；文档化；每周口径会 |
| 双轨疲劳，会计抵触 | 两套账重复劳动 | 明确 6 个月期限；优先自动化重复动作；每月复盘 |
| 客户数据质量差 | 历史账乱、期初不平 | 先清理再迁移；期初勾稽；不齐不切换 |
| 春节前后容量下降 | W16 低效 | 关键 Gate 避开；W16 只做文档/培训 |
| 税务规则差异 | 行业/地区特殊 | 先做标准税种；特殊项人工复核；外部顾问 |
| 报表口径反复 | 客户/会计意见不一 | 版本化；一次签字；变更走流程 |
| 范围蔓延 | 6 户提定制需求 | 不做单户定制；进 backlog；只有合规/正确性可插队 |
| 单点故障 | 关键人离职 | 文档、双人复核、代码评审、交接清单 |
