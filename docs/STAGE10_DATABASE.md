# 第十阶段数据库与权限边界

本阶段以向前迁移保留第九阶段所有源记录、任务输入和冻结凭证。不修改已应用的 PostgreSQL 001–038 / SQLite 001–024 迁移。应用、任务 worker 与迁移管理员继续使用不同角色；客户生产库与真实模型未在这一轮接入。

## 当前映射与不可变版本

`business_mappings` 保留一个事项的当前来源/草稿。`business_mapping_versions` 保留每个旧/新来源对应的原始映射，按 `(event_id,firm_id,company_id,book_id,draft_id)` 提供历史完整外键。

`proposal_jobs` 和 `ai_proposal_applications` 的外键改为引用版本表，避免更新当前映射时级联改写历史任务和模型应用的原输入。已有银行关联仍保留来源、事件、企业和账套外键及当前映射插入检查；未审事实替代前必须先人工解除旧关联。

SQLite 迁移重建必要的依赖表，保留其全部列、数据、索引和触发器，并执行 `foreign_key_check`。PostgreSQL 仅变更必要外键与受限函数。新增当前映射自动记入版本表，版本记录禁止更新/删除。

## 事实替代的事务

`fact_revisions` 固定提议时的版本、原事实/原映射/原件快照、新完整业务事实和原因。`fact_revision_decisions` 固定独立复核结果及幂等回执。`fact_revision_lineage` 固定旧/新源、草稿、账套和事实版本。

提议和接受均核对当前企业归属、授权、期间和版本。接受未审替代时在同一事务内追加新来源、新空草稿、映射版本与替代链，再更新当前映射和事实版本，并衔接后台草稿任务。原审批提交快照不变；旧来源/草稿及分录冻结，不再可写。

有旧银行关联、有效核销分配或未关闭异常/补件时不执行未审替代。已审核/导出的记录只追加调整建议，保持原事件和凭证冻结。过时提议可以由当前独立复核人拒绝，不允许借拒绝改写提议输入。

`revision_source_blocked` 按原账套当前读权限返回布尔值，即使目标账套失去授权而修订表 RLS 隐藏，也不会漏掉原来源的待复核阻断。`source_inactive` 合并替代与重复隔离，`source_workflow_blocked` 合并来源和关联银行的全部阻断。worker 成功回执沿用原租约/版本围栏和当前流程检查。

## 历史证据的权限

不能把“曾有旧账套权限”推广成同一业务事项新期间的读取权。047 撤销通用业务事件的历史映射扩权；通用事件、附件、后续动作和模型结果继续以当前映射和当前成员关系授权。

`revision_source_history` 只在原账套当前 `book_allowed` 下投影替代前固定快照与原审批提交快照；`revision_historical_attachment` 只允许该清单中的附件 ID。两者不返回新期间当前事实或后续材料，worker 无执行权限。HTTP 只返回公开元数据或核验后的原件字节；私有路径和存储键不回显。

## 重复隔离与期间

`bank_source_dispositions` 保存副本、主来源、双方事实指纹、版本、依据和核验人的不可变记录。当前来源须未审、未导出、未关联；有效核销分配或未关闭的原异常/补件阻止隔离，主来源不能是被隔离的来源。固定来源及原件保留，隔离后新增触发器阻止修改旧草稿/分录、关联或建立“独立交易”决定。

`ledgers` 提供长期 ID，`ledger_periods` 对应原物理月份账套。迁移为既有账套分别建立长期 ID，保留原 ID 和外键；同企业不同账套不自动合并。`ledger_managers` 是明确授权，父级可见性不自动授予某个期间的读/编辑/复核权。

`ledger_rule_candidates` 只继承公式并保留原规则版本。新期正例/反例评估形成待发布规则；企业样例、票据和原件不会隐式跨期复制。`company_master_entities`、`company_master_aliases` 和历史表保留稳定企业主数据、独立批准的别名及版本。

054 / 039 将银行清偿样例与普通银行分类规则的样例输入隔离。原清偿审核证据继续留存，但不能用其推断新普通流水也应计入应收/应付清偿；未来如扩展核销规则，须采用明确的核销条件与独立评测。

## 月结和接入冻结

`closing_snapshots` 固定检查输入指纹和完整结果；`closing_reviews` 保存本人明确的资料完整性确认；`closing_receipts` 保存锁期回执。数据库重新计算当前输入、检查结果和本人确认后才允许关期，不能通过伪造“passed”报告直接锁期。

048 将无法确定归期的未移交员工资料作为本企业账套级完整性阻断；报告不返回私有事项 ID 或内容。PostgreSQL 内部事实基准只返回 SHA-256 摘要，快照也不保存可由 API 读取的原始输入基准。SQLite 保留服务端私有输入基准供原生触发器比对，HTTP 始终只返回摘要及授权范围内的泛化报告。

同期 `settlement_items`、`settlement_allocations`、`settlement_reversals` 纳入当前账套指纹；分配或逆分配即使没有推进草稿版本，也使旧月结快照失效。仅当前有效分配计入余额，未完整分配的银行来源继续阻断；正常未付款的应付余额可继续留存。运行账号不能直接关闭、复开或删除期间，可信迁移管理员仅用于历史恢复。

052 / 037 对回执的缺失、NULL、标量及非法明细形状使用显式 JSON 类型分支后再遍历，不能依赖 SQL 条件短路顺序。完整字段、分录和辅助项仍须逐行一致，坏形状保持 `delivery_pending`，不会抛解析错误、自动忽略明细或变成已核验。

`bridge_configurations` 固定跨期软件映射版本。`bridge_import_previews` 固定导入参考，`bridge_reference_records` 仅保留预览中的原记录，不创建凭证来源。`bridge_outbox` 固定审核后导出的清单和映射包，状态仅为 `awaiting_adapter`。

接入表启用 FORCE RLS，native guard 核对企业、长期账套、当前期间权限、配置版本、原记录绑定和逐行冻结映射。已有参考或交付意图时，通过受限布尔查询确认整个长期账套已使用，避免只有新期授权的管理人因看不到旧期记录而重新绑定外部身份。真实 T+ 发送保持关闭，部分/未知结果不会自动重发。

## 试点迁移与恢复

迁移前保留数据库及私有原件的同一恢复点；升级完成后检查迁移校验和、外键及受限角色，再验证旧来源/草稿读取、历史原件 hash、当前权限和后台重启恢复。恢复不是只还原数据库：原件丢失或 hash 不符必须报错并人工恢复，不能用新文件静默替换旧证据。

共享写锁和原队列并发限制没有在这一轮未经测量拆除。增量监控、事务/锁等待和人工效率指标为后续容量实验提供依据，不能据此宣称已经证明 200–500 家生产容量。
