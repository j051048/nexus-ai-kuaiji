# 下一阶段决策基线

日期：2026-10-20  
状态：已确认，作为后续排期依据。

## 1. 目标客户

同时覆盖：

- 小规模纳税人；
- 一般纳税人。

产品不按纳税人类型拆成两套系统。采用同一账套与主线，通过账套级税务配置区分：

- 小规模：季度增值税、简易计税提示、附加税预估；
- 一般纳税人：月度进销项、税额匹配、留抵/转出提示。

税务只做提示和报表口径，不做申报、不做自动缴税。

## 2. SQLite 定位

- SQLite 仅用于本地 demo、单元测试和快速回归；
- 新业务规则、RLS、权限、并发、迁移校验以 PostgreSQL 为唯一事实来源；
- 不再为 SQLite 单独扩展业务能力；
- 现有 SQLite 测试可保留，但 PG 对等套件必须进入 CI 必过项。

## 3. 旧账迁移

- 冻结新功能，只修正确性、数据安全和阻塞缺陷；
- 从客户默认导航移出，作为实施人员的“开户初始化”工具；
- 不再扩建 132KB 级迁移向导；
- 已有真实迁移数据与回滚证据继续保留。

## 4. 财务软件适配

- 暂不选 T+ / 用友 / 金蝶；
- 当前保留中性文件导入导出；
- 等真实客户样本和字段映射明确后再立项，不先做接口猜测。

## 5. 接下来的硬约束

1. 暂停 AG01-R1 新功能、UX 新导航和 AG02–AG05 生产接线；
2. 先做 P0.1：迁移可重复、PG 套件进 CI、依赖锁定、仓库/文档基线；
3. 再做一条主线切片：合成客户完整跑一个月；
4. 主线只用现有页面，不先做老板看板；
5. 小规模与一般纳税人各用一家合成客户验证税务分支；
6. 未完成 PG 对等和真实客户验证前，不宣称生产可用。
