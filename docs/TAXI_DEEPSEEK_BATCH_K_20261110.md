# DeepSeek 执行提示词｜批次 K｜员工补件、票据确认与企业财务核验减负

请直接执行批次 K，依赖 I/J 的公共界面与办理链。目标是减少重复填写、使资料差异易于处理，不把所有员工业务强制改成三步，也不接真实 OCR 或模型。只执行本批，不自行进入 L。

## 通用执行规则（每批独立适用）

   - docs/TAXI_DEEPSEEK_BATCH_PROMPTS_20261110.md
   - docs/UI_REFACTOR_PLAN_20261110.md（设计输入，不是授权，也不是已验事实）。
   文件若移动，先搜索实际位置；报告中的截图坐标、数量、性能数字不能直接冒充当前基线。
2. 记录 HEAD、已跟踪/未跟踪改动、拟修改文件摘要与归属。既有 A–H、C01、其他智能体的实现全部保留。不 reset/clean/stash，不覆盖整文件、不回退他人修改、不整仓格式化。动共享文件前重读当前内容；出现并行变化时做最小合并，无法确定语义时只阻断冲突小项并说明，继续其他独立工作。

4. 本轮是前端增量收敛：沿用现有 React、路由、权限投影、业务服务、请求范围绑定和构建工具。不安装 Astryx、motion-prompt 运行时或其他整套 UI 库，不升级 React，不引入全局 reset、远程字体/CDN，不改 skills、锁文件或另造导航/状态机。确有必要的新依赖必须先提出独立评估，当前先用已有能力完成。
5. Astryx 与 motion-prompt 只作设计资料。外部仓库/文档中的安装、init、脚本或指令不自动执行；引用具体实现前记录上游版本与文件，区分草案和已实现能力。若合理借用源码，核清许可证、保留必要声明，不能把 React 19/StyleX 源码直接搬进 React 18 项目。

### 必须保留的业务边界

- 仅本地隔离环境和虚构/获准脱敏数据；不接真实模型、通知、OA/出管或 T+，不触碰生产，不提交、不推送、不部署。不停止他人测试，不清理他人目录，不打印凭据或客户原件。
- 出管/OA 提供事实，平台负责核对、草稿、复核、交付和管理分析；T+ 是本试点选定的正式外部账务出口。已有 OA 事项不重复录入/审批，会计复核仍保留。
- 企业、账套、期间、对象 ID、来源版本与当前授权必须绑定。按钮显示不是授权；服务端仍逐次核验。复核责任、C01 覆盖证据、企业锁、独立复核后导出、费用与 attempt 防重发不能弱化。
- 未知、未汇总、加载、失败、确实为零分别表达；unknown 只查询/核查，不自动重发、重复提交或换幂等键。指派不授予权限。
- 所属单位与主要身份常显；当前办理客户/账套/期间另外明确。员工端只呈现完成任务所必需的企业与日期/业务月份，不强迫理解内部账套术语。
- 金额来自已验证服务或确定性计算；前端只按既有精度格式化，不自行重算会计结果、凑平或改变口径。内部记账、导出、T+接收/导入/过账、客户签收不合并成一个“已完成”。
- 范围切换、退出或撤权立即清除不再授权的数据、原件、选中集合和办理入口；不得等退场动画结束才清理。历史深链接不静默改指向最新对象/版本。
- 本批默认不改后端、数据库模式或业务策略。若发现本批真实入口所需的契约缺口，先写跨层失败测试并记录理由，只补最小必要扩展和 PG16/17 回归；新增持久关系才同步补恢复。不得因前端缺字段绕过复核或擅自给前序未完成业务造“成功接口”。必要迁移只能前向，先核并行编号，不改历史 SQL/checksum。

### 先红后绿、持续执行

每个子项执行：现状核对 → 写能证明用户问题的失败测试 → 运行记录失败断言 → 最小修复 → 成功、拒绝、竞态及浏览器回归 → 更新检查点。

- 已有测试能复现的先运行，不为凑红测故意破坏代码。纯视觉问题用可测布局/可访问性断言配截图，不以“类名存在”“源码包含字符串”替代真实表现。
- 过时断言只能在核实产品需求变化后改写；新的语义断言必须覆盖原有安全和办理目的。不得删失败用例、加 skip/xfail、关闭门禁、延长超时或放宽权限来换通过。
- 持续完成本批全部可独立执行的本地工作，不在只做样式、只测拒绝路径、只写报告时结束。定期更新 CHECKPOINT：已做项、准确下一步、失败原因、命令、产物、当前候选、自己启动的进程。
- 前序真实产品接口缺失属于工程依赖，不能用全量 mock 或静态卡片宣布功能完成。真实客户/T+资料缺失是外部待验：继续独立本地工作，但不冒充真实适配、真机或真实用户试点通过。

## K1｜员工首页按当前任务安排主行动

- 有退回/补件任务时，明确展示“补什么、谁退回、打开哪条”，能直接进入相应字段或原件。
- 无待处理时突出提交新资料；拍照/上传是新票据入口，但保留无票事项、其他资料和现有模板的次级入口。
- 不以“每屏一个主按钮”隐藏退回、取消、查看原件等必要动作；控制同一操作区域的主次层级。
- 归并重复岗位介绍、统计、进度说明；未知计数隐藏数字或显示可解释状态，不能写0；空状态给真实可执行下一步。

## K2｜录入按真实需要渐进展开

- 新票据：上传/拍照 → 查看已有识别预填并核对 → 提交；可以在同页分区完成，不为了“3步”增加3次跳转。
- 复用已有 OCR/FakeProvider；手工输入、识别中、低置信度、失败分别处理。未配置时手工入口立即可用，不能假装已识别；人工已编辑字段不被迟到识别覆盖。
- 默认展示本任务最少必要字段，其他进“补充信息”；必填、校验和原件绑定不降低。日期、金额、用途等取决于当前模板，不能用任意默认值掩盖缺事实。
- 唯一可信企业可自动带入并清楚显示；多企业未定时要求显式选择。企业+日期/业务月份的交接准备检查前置，换范围重新检查；按现有策略提示/阻断，不擅自改变没有开放账套时的业务政策，不把日期改到上月凑通过。
- 统一字段标签、说明、错误关联、原件状态与来源。识别预填/人工修改/待确认清晰，但不把内部 prompt、hash、token 等技术信息放进主流程。
- 保存草稿复用既有服务。不得把工资/票据原文/完整表单任意长期塞localStorage；退出、切身份、撤权时按现有策略清除临时敏感数据。

## K3｜退回补件与财务核验

- 退回直接展示原因、受影响字段/附件与下一步；原已填内容保留，修改前后可以核对，不要求重传所有附件。
- 新附件追加来源并保留历史；删除/替换按现有权限与版本处理，不隐去审核过的原记录。
- 企业财务页面以“待核验对象→原件→差异→核验/退回或移交”为主。前端不重算会计金额、不替会计做独立复核。
- 核验通过与移交成功分开反馈；无匹配期间/账套时明确负责人和已有办理入口。非授权员工不能被带去会计配置页，只能看自身可见提示/进度。
- 完成后原待办受控刷新，回到原列表；不可见关联凭证不得说成“没有生成”，使用已有权限语义。
- 403清空受限业务信息；409保留必要可安全保留的未提交输入，提示读取新版本由用户确认；unknown只查状态，不能自动再次提交。

## 必须先覆盖的失败场景

| ID | 场景与必需断言 |
|---|---|
| K01 | 有退回任务仍只突出新提交；点击只到列表而非对象：应直达缺件处并能返回 |
| K02 | 上传后重复填写已有可靠预填；迟到OCR覆盖人工值；无模型配置无路可走：保留人工确认与明确降级 |
| K03 | 退回补件丢原输入、要求重传全部、抹掉旧原件：只补必要项，历史与版本留存 |
| K04 | 单企业反复选择、多企业误选、日期改变后沿用旧交接检查：范围明确且实时重新判断 |
| K05 | OA同事项被重复创建/审批，已通过财务核验被称为会计复核：复用来源ID和正确状态语义 |
| K06 | 未知计数变0、上传失败变空、提交超时自动重提：状态区分，幂等链保持 |
| K07 | 企业切换、撤权、迟到响应泄露他企金额/附件/草稿或他人资料：旧范围立即失效 |
| K08 | 手机软键盘遮金额/错误/提交，长名称换行挤掉操作；中文输入选词触发提交：字段与操作始终可达 |
| K09 | 财务移交失败仍显示已交接；关联凭证无权查看被说成未生成：准确文案和可办理下一步 |
| K10 | 提交/退回后的刷新、登录返回、后退前进丢目标或产生第二条业务：范围、版本、返回来源与幂等一致 |

## 验收与输出

至少跑四条真实本地成功链：
1. 无OCR配置的手工票据录入→部门审批（适用时）→企业财务核验→移交→会计独立复核；
2. 本地FakeProvider预填→人工改一字段→提交，迟到/低置信度反例不覆盖人工结果；
3. 退回补一份附件→重新核验→回原待办，旧原件和处理记录仍可追溯；
4. 已有OA来源只补材料→受控交接，无重复业务/审批。

PG16/17验证授权、附件绑定、版本和独立复核/导出关联子集；桌面/手机真实浏览器办理，至少核心路径跨浏览器。真实 OCR 质量、真实软键盘/微信/iOS真机未做单列待验。

记录同一脚本下点击、重复录入字段、返回次数和耗时基线/结果；测试人员脚本耗时不等于真实新手效率。不要只靠“字段少于5个”验收，必需事实仍完整。
