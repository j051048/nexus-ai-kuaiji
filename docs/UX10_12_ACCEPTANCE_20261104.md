## PG16/17 批量及持续读取实测

每版使用两个独立的 200 家虚构企业组：导出组每家一张真正独立复核的 0.30 元草稿；交付组每家完成零发生额期初、独立复核、锁期及报表发布。校验每家成功、结果 ID 唯一且企业集合完整；原件为约 7 MB 随机 PNG，逐次比对 hash，外企业读取拒绝。

| 版本 | 200 家导出 | 200 家包草稿 | 持续读取 | 原件字节 | 客户响应最大字节 |
|---|---:|---:|---:|---:|---:|
| PG16 | 13.219 秒 / 200 成功 | 36.692 秒 / 200 成功 | 60.656 秒，8 线程 | 7,088,206 | 22,931 |
| PG17 | 13.245 秒 / 200 成功 | 35.283 秒 / 200 成功 | 60.343 秒，8 线程 | 7,089,048 | 22,931 |

| 版本 | 客户分页 p50 / p95 | 包下载 p50 / p95 | 原件 p50 / p95 |
|---|---:|---:|---:|
| PG16 | 655.62 / 1257.6 ms | 31.87 / 635.05 ms | 35.04 / 635.02 ms |
| PG17 | 613.73 / 1171.41 ms | 31.5 / 588.62 ms | 35.61 / 591.72 ms |

批量时间从已审核/已锁期就绪开始，不包含造数和逐户开账准备；两个 OS 进程处理，详细 PID、等待、延迟分布、池状态及进程 CPU/RSS 在 JSON。PG16/17 共用本机并与其他本地回归存在重叠，时间是观察值，不作为两版本性能优劣结论。
本轮容量通过表示结果守恒、访问控制及持续操作没有失败；未以这些数据宣称达到通用生产延迟 SLO。客户页 p95 仍在秒级，响应虽已限制为一页，全所统计查询成本和共享连接等待仍值得后续按实测继续优化。连接池上限保持每进程 4，没有靠扩池掩盖等待。统计中的一次 rollback 来自明确的他企原件拒绝测试。

**边界：**这里只验证受限服务层和私有本地存储；没有测互联网/HTTP、多机器、云对象存储、真实通知、复杂多凭证客户，也没有把一分钟持续读取称作长稳压测。没有重做 50/100 并发全套，也不沿用旧报告来宣称本候选在这些负载下通过。
