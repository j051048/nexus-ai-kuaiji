# 第七阶段数据库与后台权限

所有新增业务表启用 PostgreSQL FORCE RLS。模板配置要求当前账套复核权限；原件仍按业务本人、部门、企业与移交后账套边界访问。科目、模板历史及已审核辅助值不能改写。关闭期间同时由服务和 SQL 守卫保护。

`document_extractions` 不直接授予 app/worker 读写。当前附件授权函数只按当前获授权附件的企业、字节 SHA 和配置键读取纯识别结果；保存函数只消费当前请求人成功的识别记录。原 `ai_runs` 保持不可变，派生缓存可以被明确重识别后的成功结果更新，不能写入人工确认结论。

`catalog_auxiliary_people` 只在账套范围读取。受限记录函数检查编辑权限、开放期间、当前企业人员或本账套已移交申请人的历史归属，保存不可变姓名快照。字典存在不授予该人员登录或原件权限，运行账号不能直接插入任意人员。

`proposal_jobs` 与 `ocr_jobs` 分开，避免把无附件的分录任务塞入 OCR 表。受限 worker 通过统一领取函数访问任务，不能直接遍历任务或缓存表。API 登录不能调用领取或完成函数；worker 以原请求人的当前业务权限读取原件、生成和采用草稿。

领取、发送、续期、结果保存和采用均验证租约、当前事实、草稿及策略版本。规则采用、模型结果、自动采用和任务回执原子提交；自动采用失败的 savepoint 回滚不能留下被部分替换的草稿。模型费用仍独立记录已发送事实，取消或撤权不把已经发生的成本置零。

本阶段保留短事务的现有全库写协调锁，未同时进行锁拆分。多 worker 仍受全库 2 件、企业 1 件限制。扩大吞吐需要另行测量 PostgreSQL/RLS、模型吞吐、附件内存和锁等待。

升级前停止旧 API 和 worker，显式迁移后用一致版本重新启动。027/016 保守保护审计中已有人工更新或人工采用的未审核草稿；能由成功后台回执证明的同版本自动采用不会被误判为人工。人工保存、人工采用及当前版本人工确认会阻止未来自动覆盖，旧版本幂等重放与已审核记录不会写入新的确认。
