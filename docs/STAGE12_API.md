# 第十二阶段：角色工作台与录入、复核体验

本阶段面向 2–3 家企业的辅助记账试点，保持业务审批、会计复核和导出三道独立操作。模型未配置时仍能录入、保存原件和人工核验；识别按钮明确显示配置状态。没有启用真实财务软件连接或自动过账。

## 按角色进入工作

登录后统一进入“我的待办”，工作内容按当前企业成员、部门审批人及账套权限计算。员工可直接选择报销、采购 / 费用、日常收支；部门审批人优先看到待审批事项；企业财务优先核验和移交；会计看到授权企业的复核、异常和交付工作。兼任角色仍保留其获授权能力。

导航保留业务事项、异常与补件及会计复核入口。票据历史、后台处理、监控和成员授权归入“处理记录与管理”；核销、规则、科目、主数据、接入、效率、评测和月结归入“更多账套操作”。手机可横向切换主要入口，录入与复核详情采用独立全屏及固定底部操作。

## 统一待办

- `GET /api/workspace/profile` 返回当前工作角色、可提交 / 审批 / 财务 / 复核 / 管理能力及可见企业摘要。
- `GET /api/workspace/tasks?bucket=action|waiting|all&kind=...&company_id=...&limit=20&offset=0` 返回当前授权范围的任务及分页，最大 100 条。
- `GET /api/workspace/tasks/{kind}/{ref}` 在打开前重新确认当前权限与状态；已处理、失权或不存在时返回 404，前端保留提示并刷新列表。
- `GET /api/intelligence/jobs/{job_id}` 沿用业务事项权限返回指定 OCR 任务及当前重试 / 取消权限，支持从月结和待办精确定位。

任务包括本人资料草稿、业务修改、部门审批、财务核验、移交、异常补件、待复核凭证、识别及草稿任务、审核后待导出、已导出待核验回执和管理员运行告警。“需要我处理”与“等待他人 / 后台”分开显示，并保留企业、处理角色、截止日及下一步。

每个来源查询在数据库中先按当前授权过滤，再计数和分页；PostgreSQL 保留 FORCE RLS。待办自身不会授予来源、原件或账套权限。补件收件人只得到公开任务入口，不返回内部标题、账套及凭证标识。首页不加载全量原文，不在浏览器本地存储业务数据。

## 一体化录入

`/api/intake/drafts` 使用独立、本人私有的资料草稿，允许先选择企业 / 部门 / 模板、上传多个原件、拍照及识别，再填写完整事实。缺金额时不会创建虚构业务事项。识别候选保留原文位置；员工逐字段采用、核对并确认后，完整事实及附件原子进入原有业务流程。提交后仍须另一名部门审批人及财务核验，移交生成待会计复核草稿。

OCR 使用原有企业开关、供应商配置和统一费用预留 / 统计。请求结果未知时保留费用核验约束；成功识别转入既有结构化证据，不再重复付费识别。本人撤权或部门变更后，资料草稿和原件也重新校验。

详细接口与限制见 [员工录入](STAGE12_EMPLOYEE_INTAKE.md)。

## 中文导入与证据

新的导入向导支持 UTF-8 / GBK CSV、受限 `.xlsx` 及粘贴中英文数据。确认固定来源和脱敏账号、列映射、日期和金额模式后，逐行预览错误、重复及相似交易，并核对总额。合法金额均以整数分处理；冲突阻断整批，确认重试保持幂等。

原始文件、真实行位置、规范化结果和映射依据留存，复核时可读取原表并下载受保护原件。映射按当前账套、企业及账号范围保存。上传限制 10 MB、最多 5,000 行 / 64 列；超过 2 MB 的文件使用两阶段直传，拒绝公式、宏、外部链接及危险 XML / ZIP 内容。历史 CSV 导出与指纹算法保持原样。

详细接口与格式边界见 [中文导入](STAGE12_CHINESE_IMPORT.md)。

## 同屏复核与恢复

单笔及批量复核可在当前页面查看原件、来源、分录和异常，保存与审核继续使用最新版本及原有校验。修改包内凭证后旧预览明确暂停，保留其余选择并重新准备；审核不会触发导出。

离开并返回复核页面可恢复内存中的筛选、选择和服务器复核包 ID；恢复时重新获取当前授权和版本。未保存编辑会拦截切换或要求明确放弃。换身份、事务所、退出或权限错误会清空状态。浏览器刷新后未保存选择不恢复，服务端已保存草稿与记录仍在。

详细行为见 [同屏复核](STAGE12_INLINE_REVIEW.md)。

## 部署与恢复

新迁移为 PostgreSQL 059–061、SQLite 044–046，历史 SQL 不修改。059 是私有录入草稿及合法费用来源，060 是原表与转换凭据，061 为授权查询所需索引。先使用独立迁移账号升级，再启动 API / worker；API 与 worker 账号仍分离。

数据库与私有原件须一起备份。`scripts/backup_accounting.py` 新增采集录入附件及银行原表，旧备份仍按其存在的表读取。模型密钥仍由部署配置提供，本阶段不在前端新增密钥存储。
