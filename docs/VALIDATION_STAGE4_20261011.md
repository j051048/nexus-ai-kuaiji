# 第四阶段验证记录（2026-10-11）

## 交付范围

基于前三阶段的企业、部门、私有附件和会计审核流程，新增可配置 OpenAI 兼容接口、票据字段提取、证据页码与转录原文、确定性核对、人工异常处理、银行流水人工关联、模型分录建议及幂等采用。公司默认关闭外部处理，供应商与密钥尚未配置；未配置时页面提示等待，不生成假识别结果。

员工按本人范围、部门审批人按明确部门范围处理附件；企业财务处理企业事项；会计处理已移交到获授权账套的事项。管理身份不自动开放员工原件，员工不能查看会计分录或自行消除核对异常。模型只能读取当前事项及当前账套可用科目，不调用审批、导出或正式过账工具。

## 已验证的不变量

- 模型调用在数据库事务外执行；同键并发不重复调用，终态不可覆盖，晚响应不能覆盖已失效任务。没有隐式重试或切换供应商。
- 调用期间撤权、停用账号、暂停企业或关闭期间，结果不发布；员工即使不能读取账套映射，也能正确得到冻结状态。跨企业原始 SQL 不能读取票据、异常和人工处理记录。
- 金额使用字符串及整数分。缺税额保留 `null`；票据税额关系、业务总额、交易对方、购买/销售方税号、日期、币种、页码及证据引用不符时进入人工核对。
- 重复发票在当前授权事项范围内标记；发票与付款回执不直接重复相加。流水候选需人员确认，同账套、同方向、合计与事项一致，银行和业务凭证均须未审核。已关联银行来源阻止再次单独审核或导出。
- 分录只使用当前有效科目，借贷分别等于来源金额，付款方向与支付状态匹配，引用当前识别记录及金额证据。无效输出留失败记录，不改原草稿。
- 采用建议必须校验资料指纹、当前版本、开放期间和权限；采用回执与草稿修改在同一事务中完成。重复采用返回已有结果，不重复增版本；采用仍为草稿，须会计独立复核后导出。
- 人工处理依据随当前事实保存；新原件或关联改变后旧确认失效。已采用模型警示不会因普通保存、审核版本递增而消失。
- 只读详情、异常列表及审核校验不写异常、不调用模型；即时发现先登记，再由独立财务/复核者填写依据。前端未保存修改时暂停处理写入，冲突后重读状态，超时只提供人工重试入口。

## 真实试点尚需完成

配置实际供应商与模型后，由会计专家确定科目及业务样例，分别授权 2–3 家企业，以已知答案的少量票据逐字段验收，再验证真实完整月份。记录金额/税额/交易对方错误、异常处理时间、人工修改量及费用；验证真实 Supabase 登录、数据库与原件联合备份恢复、客户财务软件导入回执。

当前没有真实供应商准确率或会计生产力提升数据。图像转录及引用相互一致不证明票据真实；代码没有判断税务抵扣，也没有生成正式总账。异常聚合和持久后台任务队列的规模建设见 [建设路线](ACCOUNTING_ROADMAP.md)，本阶段不宣称已达到一名会计管理 200–500 家企业的容量。
