# RWK03：补做 OPT09 被替换的三个模块

先读 `RWK00_MASTER.md` 和 `docs/fsc_opt/OPT09_FRONTEND_WORKBENCH.md` 原文。前置：RWK01。

上一轮把 OPT09-C、D、E 改写成别的内容后报了"A–E 完成"。本批按**原文**补做。已做的年度矩阵、切换筛选清空选择、不可撤销提示文字都保留，但它们不替代原要求。

## RWK03-A  常驻的单位、身份、期间切换条（原 OPT09-D）

**现状。** 验收时在 `src/` 下搜不到任何此类组件。

**要求（与原文一致）。**

1. 先读 `src/workspace-route.ts`、`src/useWorkspaceRoute.ts`、`src/api.ts` 中切换范围时中止在途请求的逻辑。上下文已在地址参数里，本模块给它一个固定可见的控件。
2. 在工作区壳层顶部加一个固定条，**在每个工作页面都可见**：当前办理单位、当前身份、当前期间及其状态（开放或已锁）。"我所属的单位"与"我正在办理的单位"分开显示，不混成一个标签。
3. 可在条上切换单位和期间。切换时：复用现有未保存离开拦截；复用现有中止在途请求逻辑；更新地址参数，可后退恢复。
4. 只列出当前用户有权访问的单位，数据来自现有接口。
5. 各页面自带的月份输入框：与顶部期间含义相同的，改为读取顶部期间并移除；含义不同的（如查询范围）保留并改清标签。逐个判断并列表。
6. 窄屏下可折叠为一行摘要，但单位与期间始终可见。
7. 用现有变量与公共组件；注意 RWK01-D 的体积预算，切换条属于壳层会进首屏，保持精简。

**先失败测试。** 路由解析与切换的纯函数有改动则补单测。

**验收。**

- `npm run typecheck`、`npm test`、`npm run lint`、`npm run format:check`、`npm run build`、`npm run test:frontend-budget` 全部通过。
- 新增 Playwright 用例（1366 与 390）：
  - 在至少六个不同工作页面上，切换条可见且显示的单位、期间与地址参数一致。
  - 切换单位后，页面数据、地址参数、切换条三者一致。
  - 有未保存修改时切换出现拦截。
  - 人为延迟旧单位的响应，切换后旧数据不出现在新单位页面上。
  - 后退恢复到切换前的单位与期间。
- `e2e/role2-firm-period.spec.ts`、`e2e/v09-navigation-history.spec.ts` 通过。
- 状态文件列出：被移除和被保留的月份输入框清单。

## RWK03-B  不可逆操作的确认对话框（原 OPT09-E）

**现状。** `window.confirm` 仍在：`src/FormalClosePanel.tsx`（锁期，文案自己写着"本次不支持重开"）、`src/FormalBooksWorkbench.tsx`、`src/DeliveryFollowupPanel.tsx`。

**要求（与原文一致）。**

1. 搜索 `window.confirm` 的全部用法，按后果分两类：不可逆（锁期、正式过账、发布、对外发送）和可恢复（放弃未保存的编辑）。
2. 用 `src/AppPrimitives.tsx` 的 `Modal` 做一个确认对话框组件：
   - 不可逆类：显示对象、单位、期间、后果说明；**要求输入期间或对象名称才能点确认**；默认焦点在取消。
   - 可恢复类：普通确认；默认焦点在取消。
3. 全部替换。替换后 `src/` 业务代码中不再有 `window.confirm`。
4. 复核抽屉中单键 `A` 审核：保留；现有审核门槛不变；抽屉打开后 400 毫秒内忽略 `A`，防连按误触。

**验收。**

- `grep -rn "window\.confirm" src --include=*.tsx --include=*.ts` 仅允许测试文件命中。
- 六条前端门槛通过。
- 新增 Playwright 用例：锁期对话框中未输入正确期间时确认按钮不可用，输入后可用且锁期成功；Esc 关闭后焦点回到触发按钮；抽屉刚打开时立即按 `A` 不触发审核。
- 搜索 `page.on('dialog'` 与 `page.once('dialog'`，依赖原生确认框的用例逐个更新并列表。

**要求。**

5. 状态用文字或图标加颜色表达。
