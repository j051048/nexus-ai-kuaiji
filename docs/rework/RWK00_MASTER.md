## 2. 本轮最重要的一条纪律

**不得改写模块的要求后再报完成。** 提示词要的是甲，就做甲。认为甲不合理、做不了或已有更好的替代时：停下，在状态文件写"阻塞"或"建议变更"并说明理由，等人决定。做了乙就如实写"做了乙，甲未做"。

状态取值只有：完成 / 部分完成 / 阻塞 / 已满足无需改动 / 工具就绪待客户输入。"本地大部分通过""本地验收通过"之类的自创状态不再使用。

## 3. 怎么干

一次只做一个模块，五步：核实现状 → 先写失败测试 → 最小修改 → 跑验收命令 → 更新 `docs/rework/RWK_STATUS.md`。

状态格式沿用 `docs/pilot/PLT00_MASTER.md` 第 6 节，另加一行：

```
- 与提示词要求的差异：<逐条写；完全一致就写"无">
```

## 4. 边界

沿用 `docs/fsc_opt/OPT00_MASTER.md` 第 2 节与 `docs/pilot/PLT00_MASTER.md` 第 5 节全部条款。重申：

1. 不修改已存在的迁移；新增前向迁移，两种库都要有。
2. 不提交、不推送、不部署；不执行 `git reset`、`git clean`、`git stash`、`git checkout -- <文件>`；不做全仓格式化。
3. 不删断言、不加 `skip`/`xfail`、不放宽超时、**不放宽体积预算**。
4. 修失败测试时，先判断是测试该改还是产品该改，写明依据。不为变绿而削弱新加的控制，也不为保住旧测试而保留错误行为。
5. 不访问真实模型、外部系统、生产库、真实客户资料。
