# 登录账号的所属单位与身份显示验收

日期：2026-11-05。结论：本地验收通过，未提交、未推送、未部署。

## 行为

- 复用工作台、企业门户、管理后台已有身份栏，未展开时直接显示所属单位、岗位与姓名。
- 事务所人员显示所属事务所；企业员工、部门审批人、企业财务及企业管理人员显示真实企业成员关系。
- 同时加入多家企业时简要显示前两家及总数，展开可查看全部企业名称及各企业身份。不把可服务的客户列表当作员工所属单位。
- 读取失败、身份范围不匹配或权限拒绝时，显示待确认并清除旧企业名单，不以旧数据冒充有效身份。
- 手机单位名称过长时简略显示，展开保留全名；员工首条待办的原有首屏可达性断言保持通过。

## 实现与边界

`DirectoryService.me_in_connection` 在既有身份响应中增加当前用户在所选事务所的有效企业成员关系。PostgreSQL 读取单位名称时临时绑定已核实的事务所范围，完成后恢复调用方范围；没有新增授权或放宽 RLS。

前端展示不授予权限，不发起额外业务请求。企业隔离、独立复核及复核后导出规则不变。本轮没有修改迁移、C01、模型或通知渠道。

开始基线：`47488e0a9c1c723622597d654337f626316b6b14`，开始时工作区干净。仅修改身份展示、身份读取及对应测试。候选文件 SHA-256 记录在本地 `tmp_test/account-units-20261105/candidate.json`。

## 先失败再修复

- 前端新增身份归属断言：9 failed、35 passed；原实现未返回或显示企业归属。
- 后端新增成员关系用例：2 failed；原响应缺少该字段。
- PostgreSQL 16：新增 2 项均失败，暴露 `/me` 的初始空事务所范围导致 RLS 下企业名称不可见；绑定并恢复已验证范围后通过。
- 浏览器回归发现手机多单位信息挤压首条待办。调整名称收敛与间距后通过，未放宽首屏阈值。
