## 实际修复

1. ContextPack 原预算只覆盖 pack，自身放得下不代表加上系统提示、schema 与 JSON 转义后仍放得下。现已在 Worker 费用预留和发送标记前检查完整请求。
2. 历史由旧到新读取，而共享编译器从末尾裁剪，导致最近问题优先丢失。助手现在明确将最近问题优先交给原编译器。
3. 原 Provider 在 ContextPack 裁剪生效前检查整份原始历史的字节数。携带合法 pack 时，现改为校验实际发送的 pack 与完整请求；无 pack 的旧兼容调用保留原限制。
4. 历史被裁剪后，服务端明确说明本轮保留/省略的历史问题数与重新提问的下一步。不会依靠模型自报资料是否完整。
5. 大量反斜杠/引号会造成额外 JSON 转义，最初的溢出量相减算法可能过度收紧预算。改为有界预算搜索，保留能够放下的最近问题。

**始终不裁剪当前事实、证据、金额、阻断项或必需规则。** 必需内容超过预算时明确阻断，不提高限额、不调用摘要模型、不放宽审核与导出条件。只进行原有一次模型调用。
