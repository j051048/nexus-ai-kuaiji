# PLT01：OPT 遗留清零与同候选验收包

先读 `PLT00_MASTER.md`。无前置。后续模块建立在 OPT 产物上，本批先把自报"部分完成"的项目收尾，并产出一份可供独立验收方直接复跑的清单。

## PLT01-A  盘点 OPT 状态 【可独立完成】

**做法。** 只读。逐节阅读 `docs/fsc_opt/OPT_STATUS.md`，输出一张表写入 `docs/pilot/OPT_CARRYOVER.md`：

- 每个 OPT 模块的最新状态（同一模块有多节时取最后一节，并注明存在重复节，如 OPT04-B）。
- 标"部分完成""阻塞"或带"未验""待做"字样的，逐条列出：缺什么、缺的部分是代码、测试、PG 验证还是人工项。
- OPT08 是合并成一节记录的，按原提示词的 A–E 五个模块逐个核对代码是否真实存在（`src/money.ts`、`MoneyCell`、`AccountPicker`、键盘导航、行摘要的结论）。
- OPT09、OPT10、OPT11 各模块是否有记录；没有记录的标"未开始"。

2026-11-18 的线索：OPT01-C、OPT02-C、OPT02-E、OPT05-E、OPT07-E、OPT07-F 为部分完成；OPT08 跨浏览器与输入法未验。以你实际读到的为准。

本模块不改代码。

## PLT01-B  收尾可本地完成的遗留 【可独立完成】

按 `OPT_CARRYOVER.md`，对每条"缺代码或缺测试"的遗留，回到对应的 OPT 提示词完成它。每条单独记一节状态（如 `PLT01-B / OPT05-E`）。重点：

1. **OPT01-C 税额取整**：确认三处是否已统一到同一函数；仍保留截断的地方必须有出处注释。
2. **OPT05-E 关账发布可恢复**：注入"第二段成功、第三段前崩溃"后重试，最终状态 `published`、报表只有一份。
3. **OPT07-E 税费政策条目**：缺政策时阻断并提示缺哪一项；无默认值。
4. **OPT07-F 通用别名前端**：补齐管理界面，沿用现有公共组件。
5. **OPT08 的守卫测试**：确认"`src/` 下除白名单外无 `parseFloat(` 与 `Number(x) * 100` 金额写法"的测试存在且通过。

属于人工或远端的遗留（推送后 CI、分支保护、真机输入法）不要尝试，汇总进 PLT01-D。

**验收。** 每条遗留对应的原 OPT 验收命令通过。

## PLT01-C  OPT09 与 OPT10 【可独立完成】

`OPT_CARRYOVER.md` 中 OPT09、OPT10 未开始或未完成的模块，按 `docs/fsc_opt/OPT09_FRONTEND_WORKBENCH.md`、`OPT10_SECURITY_ADMISSION.md` 原文执行，状态仍写入 `docs/fsc_opt/OPT_STATUS.md`。

依赖提醒：PLT03 需要 OPT09-D（常驻单位、身份、期间切换条）；PLT06 需要 OPT10-A（备份加密）和 OPT10-B（脱敏）；PLT08 需要 OPT09-A（风险分档）。按此顺序优先。

## PLT01-D  同候选验收包 【可独立完成】

**目的。** 让独立验收方用最少的时间复核 OPT01–OPT10。

**做法。**

1. 新增 `scripts/opt_acceptance.py`（只读运行，不改库、不改文件，输出到 `tmp_test/pilot/PLT01-D/<运行标识>/`）：
   - 记录 HEAD、已跟踪与未跟踪源文件指纹、迁移文件数与指纹。
   - 依次执行每个 OPT 模块的验收命令（从各 OPT 提示词的"验收"小节整理成清单，写在脚本内的一张表里，每行注明来自哪个模块）。
   - 每条命令记录：命令、退出码、耗时、输出尾部。PG 命令在未配置数据库时记为"跳过：无 PG"，不记为通过。
   - 最后输出一张汇总表：模块、命令数、通过、失败、跳过。
2. 另做一组越界检查，结果同样进汇总：
   - `git diff --stat HEAD -- nexus_backend/migrations` 中是否有**已存在迁移被修改**（只允许新增）。
   - 测试目录中 `skip`、`xfail`、`skipif` 的数量与 `767f7cdf` 相比的变化，并列出新增的每一处。
   - 所有 `*_cents` 列均为 64 位的扫描测试是否存在并通过。
   - `python scripts/verify_audit_chain.py` 在本地测试库上的退出码。
3. 写 `docs/pilot/OPT_ACCEPTANCE_HANDOFF.md`：如何运行脚本、汇总表、所有需要人处理的事项（推送后确认 CI、分支保护、真机验证等）。

**验收。** 脚本可重复运行且两次结果一致；汇总表贴入状态文件。任何失败项如实列出，不为了让汇总好看而去改测试。
