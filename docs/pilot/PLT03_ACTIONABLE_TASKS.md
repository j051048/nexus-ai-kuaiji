# PLT03：待办成为真正的办理入口

先读 `PLT00_MASTER.md`。无硬前置；常驻切换条（OPT09-D）已存在时配合使用。

这是最直接影响"员工愿不愿意用"的部分。判断标准只有一个：点了待办，是否落在**准确的单位、期间、对象、版本**上，并且能当场办。

线索：`nexus_backend/app/firm_tasks/`、`nexus_backend/app/workspace/`、`nexus_backend/app/cockpit/`、`src/FirmInbox.tsx`、`src/firm-inbox-contract.ts`、`src/WorkspaceHome.tsx`、`src/workspace-route.ts`。

## PLT03-A  待办来源盘点 【可独立完成】

**做法。** 只读。列出系统里所有会出现在"待办、我的事项、消息、收件箱、卡点"中的条目类型，写入 `docs/pilot/TASK_INVENTORY.md`。每类一行：

- 来源模块与生成位置。
- 当前点击后去哪里：具体对象，还是模块首页，还是无链接。
- 链接是否带单位、期间、对象标识、版本。
- 谁能办、谁只能看；该判断在服务端还是前端。
- 办完后待办如何消失或更新。

**验收。** 清单存在，并标出"只到模块首页"和"无链接"的类型数量。

## PLT03-B  待办契约：谁办、办什么、去哪办 【可独立完成】

**做法。** 待办条目由服务端统一返回以下字段（在现有待办接口上扩展，不另起一套）：

1. **目标定位**：单位、账套、期间、对象类型、对象标识、对象版本。
2. **对当前用户的可用动作**：服务端按当前权限计算，取值如"可办理""仅可查看""无权查看"。
3. **动作名称**用业务语言：补上传原件、核对到账差额、复核这张凭证、确认补件、处理月结阻断。
4. **当前由谁处理**：处理人或处理岗位；等待外部时写明等谁。
5. **当前用户能做什么**：无权办理时给出可做的事（催办、查看进度），没有就明确为"无需操作"。
6. 截止时间、金额影响（整数分，可空）。

规则：

- 可用动作每次请求重新计算，不缓存在待办行里。
- 无权查看的对象不返回任何内容细节，只返回"有一项不属于你的事项"或直接不返回，按现有同类接口的做法统一。

**先失败测试。**

- 同一条待办，制单人、复核人、只读成员、其他单位成员分别请求，得到不同的可用动作；其他单位成员看不到。
- 权限被撤销后再次请求，可用动作立即变化。
- 制单人对自己制的单，动作不是"复核"。

**验收。** 新增用例 SQLite 与 PG 通过。

## PLT03-C  直达与返回 【可独立完成】

**做法。**

1. 每种待办的链接落到**具体对象的办理界面**，地址参数带齐单位、期间、对象、版本。按 `TASK_INVENTORY.md` 逐类修正"只到模块首页"的类型。
2. 打开时如果当前所在单位或期间不同，自动切到目标范围，并在顶部明确提示"已切换到某单位某期间"；有未保存修改时走现有离开拦截。
3. 落地校验，以下情况各有明确页面，不落到空白或首页：
   - 对象已被他人办完：显示"已由某人于某时办理"，给出查看入口。
   - 版本已变化：显示"内容已更新"，提供进入最新版本的入口，不在旧版本上办理。
   - 权限已被撤销：显示无权限及当前处理人。
   - 对象不存在或不属于该单位：统一的不可见页面，不泄露存在性。
4. 办完后回到进入前的队列，筛选条件和滚动位置不变；该条目状态已更新。
5. 多层返回（待办 → 对象 → 原件 → 返回 → 返回）每一步都回到上一层的原位置。

**先失败测试（Playwright，桌面 1366 与手机 390 各跑）。**

- 员工、出纳、会计、复核人四种身份各走一条：从待办进入、办理、返回原队列。
- 当前在甲单位时点乙单位的待办：范围切换且提示可见，数据属于乙单位。
- 旧链接（版本已变）、处理中被撤权、他人已办完：各落到对应页面。
- 多层返回后位置正确。

**不算通过的情况。** 进入模块首页；只能查看而不能办理却被计为成功。

**验收。** 上述用例通过；`npm run typecheck`、`npm test` 通过。

## PLT03-D  "仅查看"不计为"已办理" 【可独立完成】

**做法。**

1. 待办的完成只由服务端的业务事实驱动（原件已上传并通过校验、差额已处理、复核已完成）。打开、阅读、关闭都不改变待办状态。
2. 搜索现有代码中"打开即标记完成""已读即消失"的逻辑，逐个判断：通知类可以按已读处理；需要办理的事项不可以。
3. 统计口径同步：任何"已处理数量""处理率"只统计真实办结。

**先失败测试。** 打开一条需办理的待办再关闭，待办仍在、计数不变；真实办结后才消失。

**验收。** 新增用例通过；相关统计接口的现有测试无新增失败。
