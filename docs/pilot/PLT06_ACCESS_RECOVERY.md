# PLT06：分级授权与恢复演练

先读 `PLT00_MASTER.md`。前置：PLT01（OPT06 的职责分离、OPT10 的备份加密与脱敏已就位）。

两条原则：**能看汇总不等于能看明细，能看明细不等于能下载原件；被指派任务不等于获得复核权。** 恢复成功以**恢复后能办完一单**判定。

线索：`nexus_backend/app/accounting/access.py`、`access_policy`、`nexus_backend/app/fsc/organization.py`、OPT06 的替补授权、`scripts/backup_accounting.py`、`docs/BACKUP_RECOVERY.md`、`docs/B07_DEPLOYMENT_RECOVERY_CONTRACT.md`。

## PLT06-A  三级可见性：汇总、明细、原件 【可独立完成】

**做法。**

1. 先盘点现有权限模型能否表达三级：
   - 汇总：跨单位的合计数字与状态。
   - 明细：某单位的凭证、分录、台账行。
   - 原件：附件内容的查看与下载。
   
   把现状写入状态文件：现在哪些角色自动同时拥有三级。
2. 使三级可以分别授予。集团层身份默认只有被批准范围内的汇总；明细和原件须按单位显式授权。
3. 对标记为敏感的单位（配置项，默认关闭；医院在客户确认前按敏感处理）再细一层：汇总、科室级明细、原件下载分开授权。
4. 汇总接口不得成为反查明细的通道：
   - 汇总只按批准的粒度聚合。
   - 聚合范围内只有一条记录时，对无明细权限的人不显示该数字（显示为"受限"），避免由合计反推单笔。
   - 下钻链接对无权限者不可用，且服务端拒绝。
5. Postgres RLS 与服务层同步。搜索、导出、助手取数、缓存、后台任务生成的内容同样受限。
6. 全部授权变更写审计。

**先失败测试。**

- 只有汇总权限的身份：能读汇总；读任一单位凭证列表 403；读原件 403；通过汇总下钻被拒。
- 有明细无原件权限：能看凭证，原件接口 403，界面显示"有原件，无权限查看"。
- 单记录聚合对无明细权限者显示受限。
- 助手以该身份提问，回答不含无权明细（与 PLT08 联动，PLT08 未做时先测助手取数接口）。
- PG：以业务角色直接查询明细表与原件表，RLS 拒绝。

**验收。** 新增用例 SQLite 与 PG16、PG17 通过；全量后端测试无新增失败。

## PLT06-B  指派、代办、换岗、到期 【可独立完成】

**做法。** 在 OPT06-B、OPT06-C 的基础上补齐并集中验证：

1. 被指派任务：只获得办理该任务所需的最小可见范围，不获得复核权。
2. 代班：有起止时间与范围；到期按当前时间即时失效；代班人不能复核自己制的单。
3. 换岗撤权：撤销后，已打开的页面下一次请求即被拒；已生成的下载链接失效；后台为其排队的任务不再以其身份执行。
4. 自制自审：在所有复核入口（凭证、差异处理、税务底稿、月结、政策批准）一律拒绝。列出全部入口并逐个测。

**先失败测试。** 每条规则各一个用例；另加一个"处理中被撤权"的用例：用户打开办理页后被撤权，提交时返回 403 且无任何写入。

**验收。** 新增用例 SQLite 与 PG 通过。

## PLT06-C  同候选权限矩阵 【可独立完成】

**做法。** 新增一个参数化测试文件，在**同一个**本地库上建立五家合成单位与以下身份：集团负责人、共享中心主管、经办、出纳、独立复核人、各单位财务、各单位员工、已撤权人员、代班人员（生效中与已到期）。

对"身份 × 单位 × 动作"的矩阵逐格断言允许或拒绝。动作至少包含：看汇总、看明细、看原件、下载原件、制单、复核、处理差异、批准政策、导出、发布、月结锁定、管理成员。

期望矩阵写成数据文件，文件头注明"合成矩阵，未经客户确认"。真实岗位矩阵待客户提供后替换。

**验收。** 矩阵测试在 SQLite 与 PG16、PG17 全部通过；状态文件贴出格数与通过数。

## PLT06-D  恢复演练：恢复后办完一单 【可独立完成】

**做法。** 新增一个可重复运行的演练脚本或测试（仅本地隔离库与独立文件存储目录）：

1. 准备：五家合成单位，含已过账凭证、在途草稿、未处理差异、原件、审计链、一条"结果未知"的通知记录、一条生效中的代班授权、一名已撤权人员。
2. 加密备份（OPT10-A）。
3. 销毁库与存储，恢复到新位置。
4. 恢复后断言：
   - 恢复保持标志生效：不自动发送、不自动导出、不自动记账。
   - **权限不扩大**：已撤权人员仍无权；到期的代班仍无效；PLT06-C 的矩阵在恢复库上全部通过。
   - 每份原件的内容摘要与备份前一致。
   - `scripts/verify_audit_chain.py` 返回 0。
   - "结果未知"的通知**没有被补发**，状态仍为未知。
   - 所有 `*_cents` 合计、凭证数、试算平衡与备份前一致。
5. 解除保持（按现有受控流程）后，**办完一单**：经办把一张在途草稿提交，独立复核人复核，过账成功，凭证号接续不断号，报表可生成（模式按 PLT02-B）。
6. 记录恢复耗时。

**先失败测试。** 演练脚本本身就是测试；首次运行失败的断言逐条记录并修复对应问题（修产品，不改断言）。

**验收。** 演练在 PG16 与 PG17 各通过一次，SQLite 通过一次；输出目录 `tmp_test/pilot/PLT06-D/<运行标识>/` 保留全部记录。PG 本机无库时写"PG 未验证"，本模块状态为"部分完成"。
