## PLT07-A  三段式队列 【可独立完成】

**做法。**

1. 个人与主管的工作首页按三段组织，数据来自 PLT03-B 的待办契约：
   - **今天必须办**：当前用户可办理，且截止日在今天或已逾期，或阻断他人。
   - **等待别人**：与我有关但当前不由我办理；写明等谁。
   - **即将逾期**：当前用户可办理，截止日在配置的天数内。
2. 每条显示：单位、期间、事项、金额影响、截止日、责任人、替补（有生效代班时）。
3. 分段规则在服务端一个纯函数里，带版本，可测试。截止日来自现有服务计划、报税期限配置、月结日历；没有截止日的条目不进"今天必须办"，单列"无截止日"。
4. 排序依据写明并可测试，不使用模型打分。

**先失败测试。** 分段函数的单元测试覆盖每条规则与边界（当日、跨时区按 `Asia/Shanghai`、无截止日、已办结）。接口返回的三段互不重复。

**验收。** 后端用例通过；前端 `npm run typecheck`、`npm test` 通过；Playwright 用例：三段可见，条目可直达。

## PLT07-B  积压归因与转派 【可独立完成】

**做法。**

1. 主管视图按"卡在哪里"汇总积压，四类：业务部门（等资料、等补件）、共享中心（等经办、等复核）、外部系统（等回执、结果未知）、未分配。归类依据是待办当前的处理方，不是推测。
2. 每类显示数量、最久等待时长、涉及单位；可展开到条目。
3. 转派：主管可把条目转给有资格的人。
   - 候选人列表只含对该对象有相应权限的人；不通过转派授予权限。
   - **转派不能绕过独立复核**：不能把复核转给制单人；不能由主管代为"标记已复核"。
   - 转派写审计，原处理人与新处理人都能看到。
4. 预计完成时间：只在有依据时给出（如"该类事项近若干条的实际中位处理时长 × 积压数"），并显示依据与样本数；样本不足时显示"样本不足"，不给数字。

**先失败测试。**

- 四类归因各一条合成用例。
- 转派给无权限的人被拒；把复核转给制单人被拒。
- 样本不足时不返回预计时间。

**验收。** 新增用例 SQLite 与 PG 通过。

## PLT07-C  月末高峰模拟 【可独立完成】

**做法。** 新增一个场景测试（合成数据，真实本地服务层）：

- 两家单位同一天月结。
- 独立复核人处于"请假"（无权办理，且有一条生效的代班授权给另一人）。
- 其中一家的银行流水"迟到"（尚未导入）。

断言：

1. 代班人能看到并办理请假者的复核事项，但不能复核自己制的单。
2. 流水迟到的那家：月结预检明确阻断并指出缺什么；它的阻断不影响另一家完成月结。
3. 其余三家单位的日常待办不被这两家拖住：它们的写入不被长时间阻塞（PG 下设短的 `lock_timeout` 验证；发现阻塞时记录是哪一处仍在用全局写锁，写入"顺带发现"，不在本模块修）。
4. 主管视图能说明积压在哪一类、涉及谁。

**验收。** 场景测试在 SQLite 与 PG 通过；PG 未验证时如实标注。

## PLT07-D  集团经营汇总的完整性标注 【可独立完成】

**原则。** 这是经营观察用的汇总，不是合并报表：没有内部往来抵销、没有统一口径调整。本模块只把现有汇总做可信，不新增合并功能。

**做法。**

1. 每个汇总数字附带并可展开查看：纳入了哪些单位、各自的期间、各自数据状态（已复核、未复核、试算、未报送）、数据截至时间、口径。
2. **不完整不显示为完整**：有单位缺报或未复核时，标题处显示"纳入 4/5，缺某单位"之类的明确说明；合计旁标"不完整"。不把缺报当 0 相加而不提示。
3. **不同口径不静默相加**：各单位的准则（PLT02 的政策）或金额单位不同时，不给出合计，改为分列并说明原因。政策未核定的单位单列为"口径未核定"。
4. 页面固定标注"管理汇总，非合并财务报表"（OPT11-D 已做则复用）。
5. 可见性遵守 PLT06-A：无明细权限者不能由汇总反查。
6. 先按 FSC 总令第 7 节审查 `observability/value.py` 的跨月混算问题；本模块修掉汇总页用到的指标中存在的同类问题，逐条列出。

**先失败测试。**

- 四家已报一家缺：标题与合计都显示不完整；缺的那家被点名。
- 两家口径不同：不返回合计，返回分列与原因。
- 一家为试算数据：该数字带试算标记，合计标为含试算。
- 只有汇总权限者无法通过下钻取得明细。

**验收。** 新增用例 SQLite 与 PG 通过；`e2e/firm-insights.spec.ts`、`e2e/firm-operations.spec.ts` 本机能跑则跑。
