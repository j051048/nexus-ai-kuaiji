## 任务和判断依据

目标是让五个独立法人在同一共享中心完成可追溯的核算、分工、异常处理与月结，使团队可以用真实数据判断五人能否承担原十五项岗位职能。首个试点是出租车公司，其余为内部医院、物业与食材采购、广告传媒、贸易。业务范围来自客户签批资料；仓库五个档案目前用作合成练习。核算首先支持从原件到已复核凭证与报表，申报和资金办理必须能区分内部准备、外部受理、最终结果。

交接复核时主仓为 `c8da0237`，PLT03、PLT04 有并行未提交修改。PLT04-B 台账已登记六类计费差异的本地验收和两版 PG 并发结果，本轮台账中的本地 PG 最高迁移已到 297。不要沿用 Gemini 快照的 293 预分配新编号。开始时核对实际代码、工作区、数据库和最后一段验收记录。Gemini 对银行和税务之间的数据搬运、行业映射、实施人员配置负担、跨实例控制的判断值得落地。报告中的 75% 节工、单笔复核 5–8 秒、7–8 人或 4.5–5 人均无现场计时；性能、认证、信创兼容性也须各自举证。把这些写成待验证假设，用实测替代。

## 连续执行规则

1. 用主仓最新内容建立起点。读取分支、HEAD、已暂存/未暂存/未跟踪文件、现行迁移和已有候选工具。列本包可改的路径与共用文件。遇并行编辑先重新读差异，能分离的最小补丁继续；同一段归属不清则登记冲突、转做独立子项。保留所有已有改动。禁止全仓格式化、覆盖、清理、暂存、提交、推送、触发 CI 或部署。
2. 每个缺口按“用户从哪个入口办理 → 用哪条失败断言证明 → 最小实现 → 原断言转绿 → 同域回归”执行。状态机、权限和副作用先从正常 API 或真实组件测试，数据库有直接写约束的再加数据库测试。已有能力且当前测试能证明时，记录复用和结果即可；禁止虚构红测或仅改截图、删断言、增加跳过、上调预算换绿。
3. 使用虚构法人、虚构金额、本地身份、私有测试原件和本地替身。不得使用生产库、真实账号及密钥，不调用真实模型、OA、T+、银行、税局、邮件、短信或外部监控。未知的银行格式、税表版本、税率、免税资格、监管要求一律列资料缺口。未经现场授权不接入真企业数据。迁移如确有需要，只加前向迁移，临写前查最新号码，保留历史 SQL、checksum 及已批准旧版本。
4. 权限由服务端和数据库决定，列表、下载、确认时均按需要重查。审批、付款、记账、申报、正式报表与签收各有业务事实。保留独立会计复核后导出、版本和来源指纹、企业与账期隔离；指派或备岗不授予权限。历史更正追加记录。外部结果未知进入核查，禁止以超时为由自动重发、切换供应商或重复计费。AI 只查证、解释、导航和提出草稿。
5. 每包给出两个判断。工程状态用“已复用并验证 / 已修复并验证 / 部分完成 / 技术阻塞”；现场状态用“无需外部 / 待资料 / 待授权联测 / 待业务签认”。局部未验不得计为整包通过。缺客户资料时先完成格式接口、合成用例、拒绝路径和交接清单；把外部部分挂起，立即执行下一项无依赖工作。缺银行资料不阻塞税务、行业、恢复或计量。
6. 状态写入现有 `docs/pilot/PLT_STATUS.md` 对应包；若该文件正由他人编辑，写入本轮独占的运行目录并留下索引，避免覆盖。每次记录输入候选、变更文件、红/绿用例、实际命令、用例数及跳过数、证据路径、外部依赖和下一个未完成子项。中断重入时从最近检查点继续。不要每做一包就请求确认；只在无法安全继续、需新外部权限或所有可执行项已耗尽时交还。
7. 一次只修改一个业务域。先完成关键路径，独立任务可交错推进；每次移交必须记录仍未通过的依赖。最终报告要能分别回答“这个版本本地可办哪些事”“五家中哪家能进下一阶段”“谁还欠哪份现场证据”。

### 10　集团准入、恢复和可观测性（PLT06，工程优化按证据触发）
