# PLT02：核算政策与正式出表门槛

先读 `PLT00_MASTER.md`。前置：PLT01-A。

问题核心：口径错了，后面算得再对也没用。当前账套没有生效的核算政策时，报表会静默按小企业准则出。

## PLT02-A  去掉静默回落 【可独立完成】

**问题。** `nexus_backend/app/reports/service.py` 的 `_standard_kind`：

```
return row["standard_kind"] if row else "small_enterprise"
```

没有 `status='active'` 的 `accounting_policies` 行时返回小企业准则。

**做法。**

1. 搜索全仓同类回落：`"small_enterprise"` 作为默认值、`or "small_enterprise"`、`TEMPLATE_ID` 被直接使用的位置（报表、期初、开账、月度简报、交付包、助手取数）。列表写入状态文件。
2. 无生效政策时，`_standard_kind` 返回"未核定"这一明确结果，不返回任何准则。
3. 下游行为按 PLT02-B 的两种模式处理；本模块先保证没有任何路径把"未核定"当成小企业准则用。
4. 现有账套的兼容：写一个只读盘点脚本，列出本地库中没有生效政策的账套数量。**不自动为它们补政策。**

**先失败测试。** 无生效政策的账套请求报表：修改前返回小企业模板结果，修改后返回"未核定"。政策状态为草稿、已过期、已被取代时同样是"未核定"。

**验收。** `python -m pytest nexus_backend/tests -q -k "report or policy"`；大量现有测试会因夹具没建政策而失败，逐个给夹具补上明确的合成政策（带合成标记），不恢复回落。在状态文件列出改了哪些夹具。

## PLT02-B  试算与正式两种出表模式 【可独立完成】

**设计约束。**

1. 报表生成结果带 `mode`：`trial`（试算）或 `formal`（正式）。
2. **正式**须同时满足，由服务端在一个函数里判断并返回逐项结果：
   - 账套有生效的核算政策，且政策有批准人和生效期，当前期间在生效期内。
   - 政策不是合成标记的。
   - 准则对应的报表模板存在，模板版本已记录。
   - 科目到报表行次的映射在政策批准之后没有未经批准的变化（对映射做指纹，政策批准时冻结；指纹变化即失效）。
   - 现有的勾稽检查、月结权威预检通过（沿用，不改）。
3. 任一项不满足只能出**试算**。试算结果：
   - 接口响应、导出文件名、文件内每页页眉、界面标题区都带"试算，不可对外"字样。
   - 不能进入发布、月度交付包、对外导出流程。这些流程的服务端入口检查 `mode`，试算一律拒绝。
4. 正式报表记录：法人、期间、准则、模板版本、映射指纹、政策版本、批准人、生成人、生成时间。写审计。
5. 数据库层加约束：发布记录必须引用一条正式模式的生成记录。

**先失败测试。**

- 上述每个条件单独缺失时：只能试算，发布接口返回 409 并列出缺哪一项。
- 合成政策下可以试算，不能正式。
- 政策批准后修改科目映射：再次生成只能试算，直到新政策版本被批准。
- 试算结果直接调用发布、交付包组装、导出接口均被拒；绕过服务直接写发布表被数据库拒绝（PG）。
- 全部满足时正式生成成功，记录字段齐全。

**验收。** 新增用例 SQLite 与 PG16、PG17 通过；`b04_close`、`delivery`、`reports` 现有测试无新增失败。

## PLT02-C  前端呈现 【可独立完成】

**做法。**

1. 报表与关账页面在标题区固定显示模式。试算时显示不满足的条件清单，每条说明"缺什么、谁能处理"，不折叠。
2. 发布、交付、导出按钮在试算时禁用，禁用原因取自服务端返回。
3. 账套政策页显示：当前生效政策、版本、批准人、生效期、是否合成、映射是否与批准时一致。
4. 样式用现有变量与公共组件，不做版式重设计。

**验收。** `npm run typecheck`、`npm test`、`npm run lint`、`npm run format:check` 通过；新增 Playwright 用例：无政策账套打开报表页，可见"试算"与缺失项，发布按钮不可用。

## PLT02-D  五家单位的政策建档 【需客户输入】

**你要做的。**

1. 确认政策的创建、提交、批准、生效流程可用，且制单人不等于批准人。缺环节则补齐。
2. 为五家单位各建一条**合成**政策（带合成标记），仅用于离线演练。合成政策的准则选择不代表对客户的任何判断，在数据说明里写明。
3. 输出 `docs/pilot/POLICY_INTAKE.md`：每家单位需要客户填写和确认的项目清单（法人性质、适用准则、纳税人类型、科目表来源、报表格式、批准人），对应到系统中的字段。

**不得做。** 不把任何一家的档案或政策标为已确认；不为医院选准则。

**验收。** 五家合成政策下均只能试算（PLT02-B 的合成限制生效）。状态最高为"工具就绪待客户输入"。

## PLT02-E  报表逐行对平工具 【需客户输入】

**目的。** 客户财务负责人拿出一份已确认的报表后，能逐行对出差异并解释。

**你要做的。**

1. 新增只读对比功能：输入一份"参考报表"（行次、行名、金额的 CSV，格式写入文档）和系统同法人同期间的报表，输出逐行对比：一致、金额不同、系统有而参考无、参考有而系统无。
2. 对每条金额差异给出可下钻的构成：该行由哪些科目、哪些凭证组成（复用 PLT04-D 的下钻；PLT04-D 未完成时先输出科目级构成）。
3. 差异可登记解释类型：舍入、重分类、口径不同、待查。解释有登记人和时间，写审计。**不提供"忽略差异"按钮。**
4. 用合成参考报表演练：故意制造舍入差 1 分、一笔重分类、一行缺失。

**验收。** 合成演练三种差异都被识别并可登记解释。真实对平标"待客户提供已确认报表"。
