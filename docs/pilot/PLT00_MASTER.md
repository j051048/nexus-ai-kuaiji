# PLT 总令：五企试点作业流程打通（DeepSeek 分模块执行）

2026-11-18。性质：代码实施工作令，不是上线许可、客户事实确认或完成证明。完成后由独立验收方逐模块复查，以代码、测试和命令输出为准，不以你的报告为准。

## 1. 这一轮要解决什么

软件已具备试点基础，但现有验收全部是合成数据走正常路径。本轮目标是把已有的核算、复核、证据、待办、助手**接成五家单位每天能用的作业流程**，并为真实试点做好可核对的准备。

本轮**不做**：新的通用 Agent 框架、多 Agent 编排、长期记忆扩容、全面重做界面（界面改版归 `docs/design/frontend-redesign/`）、正式合并报表、在线对接外部系统接口。

优先级：先保证口径和控制正确，再保证办得通，最后才是办得快。

## 3. 两类模块

每个模块标题后标注类别：

- **【可独立完成】**：只需本地合成数据。必须做完并通过验收。
- **【需客户输入】**：最终验收依赖客户授权样本或确认。你要做的是把**工具、模板、合成演练和阻断**做完，使资料一到即可执行；真实部分保持"待验"，不得用合成结果冒充，不得替客户填写或确认任何内容。

2026-11-18 时 `docs/fsc/five_company_profiles_20261116.json` 中五家单位状态均为 `unconfirmed`。除非该文件或数据库中的档案已被有权限的人确认，否则一律按未确认处理。

## 4. 怎么干

**一次只做一个模块**。每个模块固定五步：

1. **核实现状。** 文件中的路径是 2026-11-18（HEAD `7cce49a5`）的线索。先搜索确认；已满足的记录证据并跳过，不重做。
2. **先写失败测试**，保存修改前的失败输出。
3. **最小修改。** 只改本模块范围。范围外问题记入"顺带发现"。
4. **跑验收命令**，输出尾部原样贴入状态文件。
5. **更新 `docs/pilot/PLT_STATUS.md`**，格式见第 6 节。

## 5. 不可突破的边界

沿用 OPT 总令第 2 节与 FSC 总令第 3 节全部条款。本轮特别强调：

1. 不修改任何已存在的迁移文件；新增前向迁移，编号临用前核对，Postgres 与 SQLite 都要有。
2. 不提交、不推送、不部署；不执行 `git reset`、`git clean`、`git stash`、`git checkout -- <文件>`；不做全仓格式化。
3. 不访问真实模型、OA、T+、税局、通知通道、生产库、真实客户资料。
4. 测试不靠作弊变绿：不删断言、不加 `skip`/`xfail`、不放宽超时、不用管理员直写代替服务流程。
5. **不从行业名称推定任何政策**：准则、税率、确认方法、证据要求都来自企业批准的、带版本和生效期的数据。没有就阻断或标"试算"，不用默认值。
6. **"试算"与"正式"、"已导出""对方已接收""对方已过账"、"仅查看"与"已办理"，这几组状态在数据、接口、界面上始终分开。**
7. 权限从服务端和数据库重新验证。指派、代办、汇总可见，都不自动授予明细或原件权限。
8. AI 只产生建议和调查结论，不决定正式金额、复核、记账、发送。结果未知不自动重试、不重复计费。
9. 金额只用整数分；前端只走 `src/money.ts`。

## 6. 状态文件格式

`docs/pilot/PLT_STATUS.md`，每模块一节，追加不覆盖：

```
## PLT02-A  <状态：完成 / 部分完成 / 阻塞 / 已满足无需改动 / 工具就绪待客户输入>

- 现状核实：<命令或文件> → <关键结论>
- 失败测试：<文件::用例>，修改前输出：<摘要>
- 修改文件：<逐个列出，含迁移编号>
- 验收命令与输出：<原样粘贴尾部>
- 仅合成验证的部分：<写明真实边界；没有就写"无">
- 需客户或人提供：<具体到哪份资料、谁确认>
- 未做或未验证：<如实写>
- 顺带发现：<范围外问题>
```

"完成"只在验收命令全部真实通过时使用。【需客户输入】模块在真实资料到位前最高只能标"工具就绪待客户输入"。PostgreSQL 用例本机无库时写"PG 未验证"，不算通过。
