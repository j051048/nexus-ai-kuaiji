# 出租车真实月份走查工具包

状态：**工具就绪待客户输入**。本文件不记录合成数据，也不宣称链路已在真实客户数据上跑通。

## 1. 客户提供什么

走查前由客户书面指定一名业务负责人和一名财务负责人，并确认以下范围。

| 资料 | 最小样本 | 用途 | 脱敏要求 |
| --- | --- | --- | --- |
| 平台结算单 | 一个完整会计月 | 从结算行走到利润表/月度包 | 可保留虚构或脱敏后的车牌、驾驶员编号；不得出现真实姓名、手机号、身份证、银行卡 |
| 对应银行流水 | 同月、同一收款账户 | 核对到账与手续费 | 账号只保留后四位；户名可替换为“某出租车公司” |
| 一笔对不上的业务 | 至少 1 笔 | 走差异登记、证据、处理与阻断 | 金额可保留真实差值，客户名称/摘要替换为可核对的代号 |
| 手续费/退款/跨期依据 | 如客户确有该情形 | 验证原因不是猜的 | 原件可遮盖无关信息，但保留金额、日期、出具方与编号 |
| 上期签字报表 | 如客户走多期 | 验证上期比较和冻结 | 可提供脱敏 PDF/扫描件 |

客户需同时确认：

- 走查用的账套、期间、企业名称和参与人；
- 哪些资料可以带出客户现场、哪些只能现场查看；
- 走查记录能否保留截图/耗时，是否需匿名化；
- 发生差异时由谁判定原因、谁复核、谁批准更正。

未取得上述确认时，只能使用本目录的合成样本演练，不得写“真实走查通过”。

## 2. 脱敏与保管

1. 原始文件只放在客户批准的本地目录；文件名不含姓名、手机号、账号。
2. 进入衡账前先复制一份，使用替换后的企业名、驾驶员代号、车牌尾号和摘要；原件 hash 由客户或驻场人员单独登记，不写进公开报告。
3. 走查记录只写问题类型、样本标识、步骤、耗时、是否求助，不写真实金额明细、姓名、账号、凭证号。
4. 走查结束由客户确认证据保留期限；未确认的临时文件当日清理。
5. 不在聊天、工单、公开仓库粘贴客户原件或 DSN/令牌。

## 3. 走查步骤与记录

每一步一行，使用 `docs/pilot/templates/taxi_walkthrough_handoff.csv`。必须记录“是否需要开发人员解释”和“是否需要改库”两列；任一项为“是”，当场记录原因与后续动作，不得用口头解释代替产品或数据修复。

| 步骤 | 谁操作 | 记录什么 | 通过判据 |
| --- | --- | --- | --- |
| 0. 导入前校验 | 驻场/客户 IT | 文件名、行数、期间、校验脚本退出码 | 校验通过；失败项客户已确认修正 |
| 1. 导入结算单和银行流水 | 客户财务/会计 | 文件 hash、绑定账套、导入结果 | 两笔来源可打开；无临时 SQL |
| 2. 平台结算与到账核对 | 会计 | 差额、是否找到手续费/退款/跨期依据、耗时 | 能说清差额；无依据时保持“待核对” |
| 3. 差异登记与证据 | 会计 | 差异类型、原因来源、证据版本、处理人 | 待查不被当成已解决；处理人非制单人/复核人冲突 |
| 4. 利润表下钻 | 会计/财务负责人 | 报表版本、利润行、凭证行、来源原件、耗时 | 不输入编号即可到原始结算行；换版后旧依据失效 |
| 5. 月度包与签收 | 会计/客户 | 包版本、冻结状态、客户签收 | 未复核不能导出；签收绑定准确版本 |
| 6. 差异阻断与恢复 | 会计/复核人 | 阻断原因、下一步、恢复后重新核验 | 未解决差异阻断月结；恢复后不自动重发/不伪造签收 |

每次交接都记录起止时间、实际耗时、是否求助、是否离开系统查 Excel。不能把“看了一遍”写成“走通”。

## 4. 导入前校验脚本

```bash
python scripts/validate_taxi_walkthrough.py \
  --period 2026-10 \
  --date-format ymd \
  --json \
  /path/to/settlement.csv /path/to/bank.csv
```

- 只读：不建库、不写对象存储、不改业务状态。
- 复用 `app.import_wizard.parser` 的 CSV/XLSX 大小、编码、表头、日期和金额规则。
- 检查表头可识别性、交易编号、摘要、金额/收支列、日期是否在本期、金额格式与零金额提示。
- 退出码 0 通过，1 有错误；`--json` 输出每个文件的 `rows/columns/total_cents/errors/warnings`。
- 合成演练：`nexus_backend/tests/test_plt04_walkthrough.py` 三例（正常、跨期/坏金额、缺编号/摘要）**3 passed**。
- 脚本通过不等于业务正确：客户仍需确认列映射、方向、手续费归属和差异原因。

## 5. 走查结束的判定

以下全部满足才可写“真实月份走查通过”：

1. 正常款和客户确认存在的一种差异情形各走通一次；
2. 会计能从利润表数字找到原始结算行，能从未匹配流水找到处理人；
3. 全程没有改库、没有靠开发人员解释、没有用 Excel 临时补业务状态；
4. 客户对样本范围、脱敏、差异原因和包版本签字/书面确认；
5. 记录中“是否需要改库”全部为“否”；如有“是”，已转为缺陷并修复后重走。

任一未满足，状态只能是“工具就绪待客户输入”或“走查发现缺陷”，不能写“通过”。
