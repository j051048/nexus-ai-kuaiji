# PLT08：会计能核验的调查助手

先读 `PLT00_MASTER.md`。前置：PLT03（办理入口）、PLT04（差异与下钻）。

目标是**记得对、说得清、点得进去**。不新增 Agent 框架、不做多 Agent、不扩大上下文、不换更强的模型。已有的受限只读调查、事实校验、离线评测直接复用。

线索：`nexus_backend/app/assistant/`（`investigation.py`、`fact_validation.py`、`actions.py`、`scope.py`、`snapshot_reads.py`、`request_budget.py`、`meter.py`）、`tools/assistant_replay/`、`src/GlobalAccountingAssistant.tsx`。

本批所有模型调用在测试中使用现有的回放或桩；不访问真实模型。

## PLT08-A  固定的回答结构 【可独立完成】

**做法。**

1. 调查类回答由服务端组装成固定结构，六个部分缺一不可，缺内容时显式写"无"或"未检查"：
   - **结论**：一两句话。
   - **依据**：每条指向具体的原件或记录，带对象标识与**版本**。
   - **差额或数字**：由服务端从依据计算，不取模型输出的数字。
   - **未检查的范围**：哪些来源没查、为什么（无权限、未加载、超出预算）。
   - **由谁处理**：取自 PLT03-B 的待办契约。
   - **办理入口**：直达具体对象的链接，遵守 PLT03-C。
2. 模型只负责在服务端给定的事实之间组织语言和选择要点；结构中的标识、版本、金额、处理人、链接全部由服务端填入并校验存在。
3. 依据之间金额冲突时，**不选一个当答案**：并列列出各来源的值与差额，结论写"存在差异，原因未确认"，除非已有人登记的原因（PLT04-B）。禁止因"差额恰好符合某费率"而断定原因。
4. 依据不足以回答时，明确弃答并说明缺什么，不给猜测。

**先失败测试。**

- 合成场景：结算单 100,000.00 元、银行入账 99,650.00 元、无扣费凭据。回答须包含两份来源、差额 350.00、"原因未确认"、处理人、入口；不得出现"手续费"的断定。用回放桩让模型输出"这是手续费"，服务端校验应拒绝或改写为未确认。
- 模型输出了一个不存在的对象标识或与依据不符的金额：被事实校验拦下。
- 无任何依据：弃答。

**验收。** `python -m pytest nexus_backend/tests -q -k "assistant"`，新增用例通过。

## PLT08-B  三类高频问题 【可独立完成】

围绕三类问题各做一条确定的调查路径（读取哪些来源由服务端固定，不由模型自由决定）：

1. **"本月为什么不能交付"**：读月结权威预检结果、未处理差异、缺失证据、未完成复核、PLT02-B 的出表资格、PLT05 的对外状态。按阻断项列出，每项带处理人与入口。
2. **"这笔收入为什么与回款不一致"**：读该应收项、相关流水、分配与差异处理记录（PLT04-B）。
3. **"这个数字来自哪里"**：走 PLT04-D 的下钻，返回逐层构成。

每类路径的读取都受当前用户权限与 PLT06-A 的三级可见性约束；无权部分进入"未检查的范围"。

**先失败测试。** 每类问题各两条合成用例（有问题、无问题）；阻断项与月结预检结果完全一致（不多不少）；只读成员提问时无权部分列为未检查。

**验收。** 新增用例 SQLite 与 PG 通过。

## PLT08-C  失效即清除 【可独立完成】

**做法。**

1. 每条回答记录它依赖的对象及版本。以下任一发生时，该回答在界面上立即标为失效并不再显示结论，提供"重新调查"：
   - 用户权限被撤销或切换了单位。
   - 任一依据对象的版本变化。
   - 出现了新的冲突证据。
2. 失效判断在服务端；前端在显示前和切换范围时重新确认。
3. "重新调查"是一次新的调查。**同一问题不因重试、刷新、增加调查步骤而重复计费或重复发送**：沿用现有 attempt、预算、租约与结果未知语义；结果未知时不自动重试。
4. 调查不产生任何写入业务数据的副作用。

**先失败测试。**

- 回答生成后修改依据对象：再次读取该回答，结论不可见，标为失效。
- 回答生成后撤权：读取返回无权限，不泄露原结论。
- 同一问题连续触发三次：计费记录与模型调用次数符合现有预算规则，无重复发送。
- 模型调用结果未知：不自动重试，计费为未知而非零。

**验收。** 新增用例通过；`src` 中助手相关单测与 `e2e/assistant-delivery-pages.spec.ts` 无新增失败。

## PLT08-D  三类记忆 【可独立完成】

**做法。** 先盘点现有"记忆""规则记忆""学习"相关代码（`nexus_backend/app/learning/`、`RuleMemory`、`src/business-task-memory.ts`）。把它们归入以下三类，并补齐缺失的约束：

| 类别 | 例子 | 规则 |
| --- | --- | --- |
| 个人偏好 | "我习惯先看差额" | 归属个人；只影响排序和展示；可随时删除；不影响任何金额与判断 |
| 企业规则 | "甲公司这类回款按某规则归集" | 助手只能**提议**；须有权限的人提交、另一人批准，有生效期与版本；按单位隔离 |
| 当前事实 | "本月这笔款已到账" | **不记忆**。每次从来源重读 |

硬约束：

1. 甲单位的规则与处理习惯不自动用于乙单位。
2. 一次人工更正不自动升级为企业规则；只可生成"是否提议为规则"的建议，由人发起。
3. 更不自动升级为集团政策。
4. 规则被撤销或过期后立即不再生效。
5. 回答中使用了哪条企业规则，在"依据"里写明规则标识与版本。

**先失败测试。**

- 甲单位批准的规则，在乙单位的同类场景不生效。
- 人工更正一次后，同类下一笔的建议不因此改变（除非规则被批准）。
- 当前事实类信息在来源变化后，回答随来源变化，不沿用旧值。
- 未批准的规则提议不影响任何建议。
- 提议人自己批准被拒。

**验收。** 新增用例 SQLite 与 PG 通过；`learning` 现有测试无新增失败（行为确有改变的逐条说明）。

## PLT08-E  离线评测集与指标 【可独立完成】

**做法。**

1. 在 `tools/assistant_replay/` 现有框架上，新增一组**独立保留**的合成样本（与开发调试用样本分目录，开发时不查看其期望答案），覆盖 PLT08-B 三类问题，含：正常、有差异、证据冲突、证据缺失、无权限、来源已变化。不少于 60 条，每类不少于 15 条。
2. 评测输出五个指标，分别统计，不合成一个总分：
   - 事实正确率（结论与期望一致）。
   - 引用准确率（依据指向的对象与版本正确）。
   - 漏报阻断率（应列出的阻断项被漏掉的比例）。
   - 应弃答而未弃答率。
   - 每次有效诊断的成本（按现有计量；回放模式下注明为回放成本）。
3. 评测只读、可重复，输出到 `tmp_test/pilot/PLT08-E/<运行标识>/`。
4. 样本由你编写，属于合成数据，在文件头注明；真实样本待试点采集。

**验收。** 评测可运行，五个指标贴入状态文件。不设"达标线"，数字如实报告。
