# 外部财务软件返回结果文件契约（PLT05-B，待真实 T+ 确认）

## 状态

**假设契约，未与真实 T+ 联调。** 当前客户使用的 T+ 是否可导出该格式、字段名和编码方式均未确认；真实导入前必须由客户在测试账套取一份样本，按本文件核对，不得把本契约写成 T+ 原生格式。

## 文件

- UTF-8，可带 BOM；CSV，逗号分隔，首行表头。
- 单文件 ≤ 2 MB、1–10,000 行；不允许公式前缀（`= + - @`）进入标识/原因字段。
- 推荐文件名：`<批次标识>-result.csv`。

## 表头

| 列 | 必填 | 说明 |
|---|---|---|
| `批次标识` | 是 | 本系统导出的批次标识，必须与当前 artifact/outbox 匹配。 |
| `凭证标识` | 是 | 本系统导出的本地凭证标识（`voucher_external_code`），不是对方凭证号。 |
| `对方凭证号` | 否 | 对方系统中的凭证号；空值表示对方未返回。 |
| `结果` | 是 | `accepted`、`rejected`、`duplicate`、`unknown`。另允许 `missing`、`extra`、`amount_mismatch`、`account_mismatch` 用于逐笔差异，但不得由系统自行臆测。 |
| `失败原因` | 条件 | `rejected`、`duplicate`、`unknown` 或任一 mismatch 必填。 |
| `对方过账日期` | 否 | ISO `YYYY-MM-DD`；只有对方明确返回过账日期时才填写，不能由“已接收”推定。 |
| `金额` | 否 | 对方该凭证金额，人民币元，两位小数；缺失时不得判“金额一致”。 |
| `科目` | 否 | 对方主科目编码或“编码:名称”；缺失时不得判“科目一致”。 |

## 匹配和状态

1. 每一行按 `凭证标识` 匹配本次导出的凭证；同一标识重复出现 -> 整份文件拒绝（422），不能静默取最后一条。
2. 导出凭证在文件中缺失 -> 生成 `missing` 差异；文件出现未导出的 `凭证标识` -> 生成 `extra` 差异。两者都进入差异清单，不把批次判为全部一致。
3. `金额`/`科目` 有值且与冻结包不一致 -> `amount_mismatch`/`account_mismatch`；没有值 -> 结果保持文件声明，不能补判一致。
4. 全部匹配且均为 `accepted`：登记“对方已接收”；只有每一行都有有效 `对方过账日期` 才能登记“对方已过账”，否则保持“未过账”。
5. 出现任一差异：批次为“部分失败/需核对”，不自动重发、不自动改账。
6. 同一文件（内容 SHA-256）或同一回执编号重复导入：幂等返回原记录；同编号不同内容或不同批次 -> 409。
7. 批次标识不属于当前企业/账套 -> 404，不泄露对象是否存在。

## 手工登记

- 无返回文件时，允许经理手工登记“对方已接收”或“已过账”，但必须绑定一个已上传的原件（回执/截图/邮件导出）及摘要，并标记 `manual_unverified`。
- 手工登记不生成 `accepted` 行；它只是状态证据，不能冒充逐笔文件核对。
- 手工“已过账”仍不能生成正式报表、不能改变本系统凭证、不能触发自动外发。

## 差异清单

每条差异至少保存：批次、凭证标识、类型、期望/实际金额或科目、原因、来源文件摘要、发现时间、处理人、处理结果。处理人不能是自己复核自己生成的差异凭证；处理结果需独立复核。

## 验收边界

合成 CSV 只验证协议和代码；真实 T+ 的列名、编码、空值、重复导入、部分失败仍需客户测试账套样本。未取得样本前，PLT05-B 只能标“代码/合成验收”，不能标“真实往返通过”。
