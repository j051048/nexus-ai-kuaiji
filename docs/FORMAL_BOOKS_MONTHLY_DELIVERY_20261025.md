# 正式账簿与月度交付包：本地候选说明

基线：`main@189b4970`。本轮只在隔离候选和本地虚构数据上开发、验收；未提交、推送、部署、发送邮件或调用真实模型。

**发布前置仍然是完整 C01 验收和数据库、原件、身份及权限的联合恢复验证。本轮专项通过不能替代这两项。**

## 使用入口

- 会计选择账套后，在“更多账套操作 → 正式账簿”查看科目余额、科目明细、现金与银行日记账、辅助账，按正式凭证 ID 查看原分录。查询只读取正式期初与正式凭证，未审核或尚未记账草稿不计入余额。
- 账簿 CSV 下载要求当前账套导出权限，服务端再次校验；截止日期与屏幕查询一致，只接受该账期内有效日期。金额使用整数分及精确格式化，文本防电子表格公式注入。导出增加审计事件，但不改变审核、记账或外部交付状态。
- 月度服务单沿用“资料 → 会计复核 → 交付”入口。在交付页先检查本月条件，再选择当前有效的已发布报表，填写说明并确认企业、月份、版本，生成冻结包。
- 企业客户在原“报告”页面查看、下载及签收交付包。客户界面按主岗位呈现，兼任其他账套权限不会把报告页变成事务所工作台。正式包独立读取授权，不依赖旧参考简报的关闭月份状态。

## 生成与签收契约

生成要求当前会计复核权限、冻结期初、正式试算及银行核验通过、B04 内部锁期、当前有效且独立复核的已发布报表；已配置的必需资料须验收且证据仍有效，不能存在未复核或未正式入账草稿。报表版本、当前联系人及权限在公司范围事务中重新检查。

服务单客户联系人必须有当前企业身份及账套查看权限。签收同时绑定冻结联系人、当前服务单联系人和本版 manifest SHA-256；创建人不能代客户签收。签收只是收到该版本，不表示外部财务软件已接受或税务申报完成。

没有配置资料请求时，包明确标记 `no_requests_configured`，不能据此证明企业全部资料已经收齐。旧参考简报、客户签收与财务软件导入回执是不同证据。

## 文件和版本

ZIP 包含 `manifest.json` 及 11 个冻结文件：

- `README.html`、`report.html`、`account_balances.csv`；
- `formal_vouchers.json`、`formal_books.json`、`published_report.json`；
- `bank_verification.json`、`frozen_exports.json`、`materials.json`；
- `unresolved_matters.json`、`originals_index.json`。

人可读页面无外部资源和脚本，动态内容转义。CSV 金额为人民币元；JSON `*_cents` 为分。原件只包含授权范围内的索引、大小与 SHA-256，不复制原件正文、私有存储地址或凭据。每个文件与 manifest 有 SHA-256，下载从持久快照确定性重建，旧包不会随当前报表变化。

创建请求有持久幂等标识和内容指纹；相同请求重放返回原包，改内容不得复用。签收同内容重放不重复追加，改写已有签收被拒绝。单个快照限制 8 MB，每类来源行有上限，超限明确阻断。

## 数据库变更

- 新增 SQLite `095_monthly_delivery_packages.sql`、PostgreSQL `155_monthly_delivery_packages.sql`：包与签收独立表、公司归属、当前身份、精确版本和哈希守卫、不可变记录；PG 使用 RLS 和最小 SELECT/INSERT 授权。
- 新增 PostgreSQL `156_control_reference_alias.sql`：本地 PG16/17 复现既有 135 的 SQL `old` 别名与 PL/pgSQL `OLD` 记录冲突。只把该 SQL 别名改为 `prior_ref`，逐字保留其余归属、版本和异常谓词。没有修改既有迁移或其校验和，也没有绕过触发器。
- SQLite SHA-256 守卫仅由月度创建事务注册确定性连接函数，不修改数据库底座或旧 C01 文件。

## 当前能力边界

本轮是已有正式核算的查询与交付前端，没有重建核算算法、期初审批或制单流程。未就绪账套明确提示前置条件，不生成虚假零余额。日记账仍采用现有标准现金/银行科目识别口径；特殊行业、非标准科目及跨账期覆盖须另行验证。

本包支持 HTML/CSV/JSON，不等同于完整离任交接、全税种申报、所有行业报表或第三方财务软件真实自动回执。完整恢复、连续账期、真实企业会计签收与生产容量仍须完成发布前验收。
