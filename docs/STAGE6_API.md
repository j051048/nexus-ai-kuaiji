# 第六阶段 · 企业运行、站内告警与模型费用

本阶段为 2–3 家企业的 MVP 试点增加运行概览、站内告警、模型用量与费用记录，以及可选月额度。原有员工录入、附件权限、后台识别、人工异常处理、独立会计复核和审核后导出继续使用同一规则。

费用用于控制本产品的模型调用，不是企业会计账本，也不是供应商账单或支付系统。预留额不代表资金冻结或充值扣费。当前没有自动扣款、采购模型额度、实时获取供应商报价、自动汇率换算、邮件或消息平台通知。

## 权限与接口

所有端点位于 `/api`，使用真实登录或本地演示会话及当前数据库授权。运行监控权与员工原件访问权分开，获取企业概览不会打开未移交业务事项的附件。

| 身份 | 运行概览 | 告警知晓 | 修改预算或核定费用 |
| --- | --- | --- | --- |
| 当前事务所 owner/admin | 所属有效客户企业 | 可以 | 可以 |
| 当前企业 owner/admin | 所属企业 | 可以 | 可以 |
| 当前企业 finance | 所属企业 | 可以 | 不可以 |
| 普通员工、部门审批人、仅有账套复核权的会计 | 无企业运行入口，仍使用原授权事项或账套 | 不可以 | 不可以 |

| 方法与路径 | 输入 | 返回 |
| --- | --- | --- |
| `GET /operations/companies` | 无 | `{companies:[{id,name,can_manage_budget}]}`，无运行监控授权时为 `[]` |
| `GET /operations/companies/{company_id}/overview` | 可选 `period=YYYY-MM`，2000–2099 年 | 企业政策、用量、费用、队列、异常、心跳和告警 |
| `PUT /operations/companies/{company_id}/policy` | 完整政策及 `expected_version` | 更新后的政策与新版本 |
| `POST /operations/companies/{company_id}/refresh` | 无或 `{}` | 刷新监控条件后的企业概览 |
| `POST /operations/alerts/{alert_id}/acknowledge` | `expected_version`、`reason` | 知晓后的告警 |
| `POST /operations/costs/{cost_id}/reconcile` | `expected_version`、`confirmed_cost`、`reason` | 核定后的费用记录 |

预算初始版本为 `0`，第一次保存使用 `expected_version: 0`，后续使用刚读取的政策版本。告警与费用版本从 `1` 开始，知晓或核定要求当前版本，旧版本返回 `409`。金额输入只能为精确两位小数的非负字符串，不接受浮点数、指数、负数或布尔值；核定金额可以为 `"0.00"`，但必须明确填写依据，系统不会自行假定免费。原因须为 1–1000 字非空白文本。

政策示例：

```json
{
  "expected_version": 0,
  "quota_enabled": true,
  "monthly_limit": "100.00",
  "ocr_reserve": "1.00",
  "proposal_reserve": "2.00",
  "failure_threshold": 3,
  "failure_window_minutes": 60,
  "backlog_threshold": 10,
  "backlog_age_minutes": 60,
  "queue_wait_minutes": 10,
  "worker_stale_seconds": 90
}
```

示例只说明输入格式，不是供应商报价或适合所有企业的预算建议。默认额度限制关闭、三类预算金额为 `"0.00"`；开启限制时月额度及两个请求预留额都须大于零。

| 政策字段 | 默认 | 接口允许范围 |
| --- | --- | --- |
| `failure_threshold` | 3 | 1–1000 次 |
| `failure_window_minutes` | 60 | 1–10080 分钟 |
| `backlog_threshold` | 10 | 1–1000 项 |
| `backlog_age_minutes` | 60 | 1–10080 分钟 |
| `queue_wait_minutes` | 10 | 1–10080 分钟 |
| `worker_stale_seconds` | 90 | 30–3600 秒 |

服务按企业当前授权读取完整运行统计，响应不返回原件内容、文件存储键、供应商密钥或租约令牌，也不提供未移交事项的原件链接。撤销企业或事务所授权后，下次请求即按新授权拒绝；前端切换企业和退出登录清理旧概览。

## 价格、用量与费用状态

部署管理员在 API 和 worker 的新会计配置中设置：

```text
ACCOUNTING_AI_OCR_INPUT_CNY_PER_MILLION=
ACCOUNTING_AI_OCR_OUTPUT_CNY_PER_MILLION=
ACCOUNTING_AI_PROPOSAL_INPUT_CNY_PER_MILLION=
ACCOUNTING_AI_PROPOSAL_OUTPUT_CNY_PER_MILLION=
```

单位为每百万输入/输出 token 的人民币价格，最多六位小数。留空或不合法的价格为未知，不回退到零价或另一模型。管理员应按所配置供应商、模型及计费约定填写；API 与独立 worker 保持同一组供应商、模型和价格。没有内置美元报价或汇率假设。

每次请求保存供应商标识、模型、原价格快照和报告 token 数。估算使用整数微元（人民币一百万分之一元）计算，小于一微元的正费用向上取整，避免因精度被当成免费；费用响应统一为六位小数字符串，未知为 `null`。预算输入为两位小数，内部仍以微元表示。

视觉输入用量和其他计费项目以供应商实际报告为限；简单 token 估算未必覆盖缓存优惠、附加计费或账单舍入。即使供应商报告用量，也只能形成估算，不能自动变成已核对的实际费用。

| 费用状态 | 含义 |
| --- | --- |
| `reserved` | 已登记请求预留，尚未登记发送 |
| `sent` | 已登记发送，预留额继续占用 |
| `estimated` | 用量及价格齐全，保存确定性费用估算 |
| `uncertain` | 请求可能已发生，但用量或价格不完整，预留额保留 |
| `released` | 能明确判断请求未执行或被安全拒绝，释放预留 |
| `reconciled` | 管理者填写依据并核定金额，保留原用量、价格和估算 |

企业概览的 `usage` 包括请求数、输入/输出 token、已报告及不确定请求数、预留费用、估算费用、核定费用、当前占用与可用额度、超预留请求数。过去月份尚未核定的 `reserved/sent/uncertain` 记录保守计入当前额度的占用，并显示 `carried_reserved_cost`；已确定或核定的历史费用仍归原月份，不在新月份重复计入。预算月份使用 `Asia/Shanghai`，记录时间保存 UTC。

历史月份概览使用费用记录的当前核定状态汇总，不是历史时点的账务快照；政策、队列和告警仍反映当前运行状态。费用列表最多展示 100 条，优先显示超预留、不确定和仍在执行的记录；核定一批后刷新可继续处理其他记录。没有已报告用量时，token 合计为 `null`，不展示成零。

## 请求额度与人工核定

同步 OCR、后台 OCR 的每次尝试及分录建议都在模型调用前执行额度检查和预留。数据库短事务串行处理同企业额度竞争，避免并发请求都使用最后一份额度；重复返回原识别结果不增加新费用记录。预留绑定当前请求及不可公开的结算令牌，不凭浏览器传来的金额或状态结算。

开启额度时，费率未配置、单次预留超出月额度、当前占用加预留超限或有尚未确认的超预留请求，都会在发送原件前拒绝模型调用。关闭额度限制保持旧工作流可用，并继续记录已报告用量及费用不确定性；企业是否允许外发原件仍由原企业模型处理开关控制。

未知用量不能直接释放预留。超时、断网、数据库回执不确定、取消或撤权都不证明供应商免费。已发送请求的费用事实可以在原件权限被撤销后，用该次请求的结算令牌继续登记；这不会重新授予原件访问权。费用结算失败时保留占用，并在运行概览中交管理者处理。

核定仅允许 `estimated/uncertain/reconciled` 记录，由有预算管理权限的人填写两位小数金额及原因。`reserved/sent` 仍在执行，不能手工按免费释放。核定使用版本校验并记录操作者和依据，保留原供应商、模型、价格、用量、预留和估算。会计业务的字段异常与费用核定分开；核定模型费用不会消除票据异常或审核凭证。

## 站内告警与试点检查

监控条件包括额度耗尽、超预留费用、费用不确定、近期任务失败、异常长期积压、队列等待及 worker 心跳不新鲜。告警状态为 `open / acknowledged / resolved`。知晓表示有人接手，原因写入历史；它不重试任务、不修改单据、不核定费用、不恢复额度，也不表示故障已经解决。条件改善后监控刷新才会更新告警状态。

本阶段只使用站内告警，不发送邮件或其他外部消息。监控使用企业范围的统计与异常快照，不把模型原文或员工附件写入告警正文。首轮应由企业管理者与财务共同验证阈值、人工核定依据和失败处理安排。

先用 2–3 家真实企业逐步验证：同企业并发额度竞争、供应商遗漏用量、超时、取消与撤权、worker 重启、月底不确定费用保留、知晓与故障恢复、独立会计复核导出，以及实际供应商账单差异。仓库测试使用合成票据、注入模型响应和模拟用量，不能据此断言真实模型费用、识别准确率或 200–500 家企业容量已经验证。
