## 首页与助手性能

迁移前基线采用第二十阶段代码优化上线后的结果；迁移后使用同一正式域名、既有虚构账号及相同浏览器脚本。员工和会计首页同时登录，计时从点击登录到角色资料、待办及后台摘要全部返回。助手计时为已有会话详情读取，包含取证与当前范围核验，**不是新回答的模型生成时间**。

| 场景 | 加拿大数据库 | 首尔数据库 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 员工首页就绪 | 15.614 s | 5.722 s | 63.4% |
| 会计首页就绪 | 14.142 s | 6.405 s | 54.7% |
| 已有助手会话详情 | 19.414 s | 1.391 s | 92.8% |

三种场景各为一次功能验收样本，包含登录、浏览器网络及并发竞争影响，不是 p95、稳定响应承诺或容量基准。两种角色的首页和助手均未发现 JavaScript 或 HTTP 请求失败。助手保留 4 条来源引用、历史依据变化提示以及人工会计复核提示；390 px 手机布局无横向溢出，没有创建新的助手轮次或执行操作。

## 后续边界

同地域部署已显著缩短数据库读取，但首页仍包含登录及多个已授权接口，后续应分别观察稳定样本的端到端 p50/p95、数据库往返、锁等待、任务排队及连接池等待，再决定优化顺序。

本轮没有进行 200–500 家企业容量验收，也没有改为自动复核或自动正式过账。继续保持企业权限隔离、异常人工处理、后台草稿与会计复核后导出的流程。实际历史并存费用由平台按小时结算；旧库已退役，避免继续同时运行两套数据库。
