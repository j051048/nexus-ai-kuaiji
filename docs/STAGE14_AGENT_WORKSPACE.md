# 第十四阶段：会计 Agent 工作空间

## 操作入口

工作空间的主入口为“我的待办（我的工作）”“客户企业”和“后台运行”。业务事项、异常补件、跨企业复核保留为工作快捷入口，账套配置、历史记录和管理功能收进次级菜单。手机顶部保留品牌和导航按钮，通过抽屉进入工作区，避免导航占满首屏。

顶部查找按钮或 `Ctrl / Cmd + K` 打开企业与工作入口快搜。企业结果来自当前授权账套，选中精确账套后重新读取；撤权后的目标不会回退到其他企业。

## 集中分诊

“我的待办”可切换清单和紧凑表格，按优先级、期限、金额或更新时间排序，搜索事项或企业。金额来自授权来源的整数分，不由浏览器浮点计算；补件等不应披露财务金额的事项保持为空。

企业选择器支持搜索和分页，查询先授权过滤再计数。最多保存三个常用工作视图，仅保存类型、企业 ID、排序和显示密度等过滤条件，不保存 token、企业名称、事项内容或搜索文字。视图按用户、事务所和登录模式隔离，刷新后可恢复；恢复视图后仍重新授权，旧企业失权时保留指定范围并显示空结果，不改选其他企业。

“处理下一项”重新读取事项权限与当前状态，再打开同屏复核或实际处理页。保存视图和金额排序不构成会计审核。

## 真实后台轨迹

后台运行汇总当前授权的票据识别、分录草稿及旧账迁移任务，展示持久状态、已处理量、最近更新时间、介入提示和下一负责人。按执行中、需要介入、执行记录筛选，也可查询指定企业。

每条轨迹描述该作业的记录，不能把“识别完成”当成“凭证已审核”，或把“解析完成”当成“旧账验收完成”。没有数据的阶段显示未核验；无计数的结束任务显示未记录数量，不编造百分比。重试、取消和审批仍通过原有任务详情的版本、权限及明确确认流程执行。

## 会计上下文助手

凭证复核页与同屏复核可打开“会计助手”。桌面显示独立侧栏，手机显示专门页面，返回后保留当前凭证和工作位置。

助手固定当前企业、期间、凭证 ID、已保存版本及事实版本，整理来源记录、建议分录、现有解释、校验问题、证据引用及已记录操作。可以询问科目依据、金额与借贷、缺失材料或下一处理人，引用会打开相应资料。未保存的编辑会明确提示以保存版本为依据；换凭证、切换用户或撤权时清空问答。

本阶段助手模式是 `evidence_summary`：读取既有资料作确定性解释，**未新增大模型聊天调用**，没有独立税法判断或跨企业检索能力。已有 OCR 和模型分录建议仍使用原后台管道。材料不足时明确说明，助手不会自行审批、修改分录或导出，也不把旧解释当作新的模型核验结论。

原件仅按真实留存的页码或文段提供定位。没有坐标或页码时不画假框、不标注推测位置。字段级 OCR 定位仍需进一步完善数据来源。

## 接口与部署

| 接口 | 用途 |
| --- | --- |
| GET `/api/workspace/tasks` | 原待办接口新增 `sort=priority/due/amount/updated`、`q` 及可空的金额字符串 |
| GET `/api/workspace/companies` | 当前授权待办企业查询与分页 |
| GET `/api/agent-workspace/summary` | 当前授权的真实任务统计 |
| GET `/api/agent-workspace/runs` | 按状态、企业与关键词查询持久任务分页 |
| GET `/api/agent-workspace/companies` | 包含执行记录的授权企业分页 |
| GET `/api/agent-workspace/context/books/{book_id}/drafts/{draft_id}` | 当前凭证资料、轨迹、引用和人工入口 |
| POST 同一路径的 `/explain` | 只读问题解释，`question` 为 1–1000 字 |

本阶段没有新增数据库迁移，没有更改已应用的 PG062–065 / SQLite047–050。仍按既有部署方式运行 API 与后台 worker，生产不得使用演示身份。所有新查询重新核验当前用户、事务所、有效企业和资源权限；统计与分页只覆盖可见资料，不返回任务租约、执行令牌或隐藏批次数量。

## 验证与试点

详见 [第十四阶段验证记录](VALIDATION_STAGE14_20261013.md)。测试使用合成资料和受限数据库账号，不代替真实会计可用性测试。下一步应在 2–3 家企业记录查找资料、处理例外、连续复核和补件的实际耗时，再根据瓶颈扩展性能；本阶段不证明 200–500 家企业的生产容量。
