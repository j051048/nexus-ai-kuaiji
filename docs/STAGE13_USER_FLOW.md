# 第十三阶段：旧账迁移与接管

## 适用范围

在当前企业空的、开放的新月份里建立迁移项目，把明确历史范围内的科目、辅助档案、完整凭证、余额和未结往来保留为可追溯的历史资料。接管后，客户原软件继续承担正式账本；历史凭证不会进入当前凭证草稿、审核和导出队列。

当前入口是文件接入。产品名和版本记录来源，不代表已经连接金蝶、用友或 T+，也不代表其原生备份格式已经验证。试点先核对一种实际文件格式；通用 JSON 包供标准化接入。下载文件名以 `SYNTHETIC` 开头的资料是合成示例，不能当作客户真实旧账。

## 会计操作

1. 在“会计工作台”选择目标账套，打开“更多账套操作 → 旧账迁移”。目标月份应为空且开放；历史结束月必须紧接目标月份。
2. 建立项目，填写具体产品版本、原软件账套 ID、固定来源系统标识、历史起止月份及依据。系统固定当前目标月份首日为接管日期。
3. 一次选择完整 JSON 包或附件；表格逐份选择科目、辅助档案、凭证、余额或未结往来类别。CSV/Excel 要确认列对应、日期格式、余额口径和凭证状态含义。原件保留后才进入后台解析。
4. 后台解析可以离开页面继续运行。任务显示进度和失败原因，重新排队保留原任务依据。资料修订时选择替代的原文件，旧件、修订版和关系均保留。
5. 按页确认科目与辅助映射。可记账明细科目使用类别、余额方向和辅助维度兼容的已有科目，或明确建立兼容明细；上级科目只保留在历史树中，不创建可记账父科目。原科目编码、层级、名称、凭证和分录均留存。部门和员工辅助档案不自动变成登录账号。
6. 有未结往来时明确应收、应付来源科目范围。系统按对应科目和往来方辅助余额核验，只有汇总余额时不推测逐笔欠款。
7. 运行完整校验。阻断问题、复核提醒和原表位置同屏显示；打开依据后返回原工作位置。修正文件或映射后，重新完整校验，旧报告不能继续验收。
8. 给另一名当前获授权会计授予明确的历史验收权限。由其核对当前报告和全部差异，勾选范围确认并记录独立验收。
9. 长期账套管理人核对独立验收后确认接管。接管快照冻结，历史资料进入只读归档。下载报告留存，新月份仍经过业务审批、后台生成草稿、会计复核后明确导出。

## 关键边界

- 原凭证 ID、原账套、期间和分录序号共同保留，不能仅用凭证号判断重复。
- 同一来源同内容跳过；不同内容进入冲突处理，不静默覆盖。
- 红字、冲销、作废、未记账分别保留。未支持的外币、数量等核算阻断相关接管，不能删列绕过。
- 日期、金额、平衡和余额由确定程序复算，界面不使用浮点求和。
- 历史资料授权与当前企业、账套权限同时生效。撤权、切换企业或退出登录会收起历史资料和原件。
- 已接管快照只读，不能把旧凭证再次作为新凭证导出。
- 历史样例与企业规则须另行候选审核与评测，不因旧软件状态直接成为学习答案。

## 手机体验

五步导航、文件上传、差异查询和历史原件详情均适配手机。映射未保存时阻止换页和离开；抽屉全屏显示字段与原件，底部保留返回操作。后台进度只在任务执行时刷新，不要求一直打开页面。

## 历史经验复用

已接管项目的“确认接管”页可以按需展开“审核历史样例与企业规则”。先核对历史凭证原件，选定能确认普通银行收支事实的正例，指定企业稳定往来方、收支方向及借贷科目，保存待审核候选。另一名获授权会计独立核对事实后审核；再选择不会命中规则的真实反例，确认正反例回放结果。只有当前版本的回放通过，才可明确发布企业规则。

红字、结转、复杂分摊及事实不清的凭证不直接形成普通流水规则。候选、独立审核与回放保留自己的版本记录，不把原软件的状态直接复制为当前系统审核样例。规则发布后仅帮助生成新草稿，最终继续由会计复核。

## 接管后清偿历史未结事项

“确认接管”页可以展开“处理历史未结清偿”。先选择当前同一长期账套、接管后月份里的未审核银行流水与银行存款科目，再将整笔流水分配到同一已确认往来方的同类历史应收或应付。可部分清偿某个未结事项，也可将一笔付款分配给多个事项；本次分配合计须精确等于流水金额，不能超过各事项剩余余额。

预览同时显示原银行草稿与确定性清偿分录。核对并明确确认后，只替代当前未审核草稿；打开准确凭证，继续会计复核后导出。错误分配仅能由另一名当前复核人员在凭证尚未审核且事实未变化时独立撤销整笔分配。已审核、已导出或版本变化须通过原有调整流程处理。
