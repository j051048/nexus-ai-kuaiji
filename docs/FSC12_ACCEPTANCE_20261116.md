# FSC12：同候选五人运营仿真、恢复容量与试点准入

前置：FSC01–11本地必验完成，行业外部输入不足的能力仍安全关闭。完整读总工作令。本批不能用最终报告掩盖前批红项。

## A. 冻结与持续门禁

1. 核清全部归属，保存候选源文件/迁移/配置/策略/夹具指纹，前后比对；他人变更时重跑受影响测试，不覆盖其成果。
2. 接入已有PR快检、夜间、发布前层级，业务和安全关键集合禁止静默跳过。只修改必要门禁，不顺手全仓重排。
3. 本地运行受影响全量及核心门槛；远端CI、推送和发布另需授权，不能把本地通过叫远端通过。

## B. 五企业真实本地全流程

本地GoTrue/实际API/PG/原件存储，五名共享人员和企业端人员分别登录，桌面与手机完成：开户/授权→交资料→补件→核验→行业草稿→独立复核→往来核销→正式记账→月结→报表→交付→客户签收。

覆盖两期和跨年、多银行、零业务企业、部分失败、更正、人员请假、撤权和代理到期；默认不直接SQL补状态。外部T+/OA/HIS/通知均用明确的本地模拟契约，不冒充外部已验。

## C. PostgreSQL16/17动态与联合恢复

- 业务受限角色，验证RLS、直接SQL越权、竞争领取、重复生成、来源版本变动、独立复核、核销超额、导出围栏、通知unknown；禁止以管理员角色绿灯证明权限。
- 备份源库包含各行业实际数据、原件、规则/映射版本、授权时限、接手历史、复核记录、费用attempt、冻结导出、通知unknown。
- 恢复到全新隔离库与存储，验证原件hash、身份重映射、撤权、角色、hold受控解除和恢复后业务继续；不得自动发通知/记账/导出或补造旧审。
- 无敏感数据进入产物，配置每次独立、失败现场保留，环境状态与运行归属可核对。

## D. 有界容量与五人仿真

1. 使用FSC01业务量定义合成负载：五家常态、月末峰值、集中补件、较大凭证、附件下载和交付生成；同时保留已有50并发/200家回归，禁止只换小样本掩盖退化。
2. 至少多API/worker进程，测等待/队列年龄、公平性、p95/p99、错误率、连接池等待、锁、内存和长时间运行；慢公司不拖死其他公司，不盲目扩池。阈值基于基线与确认目标制定，失败不得事后改线。
3. 五个真实测试身份分工，核对请假与峰值下复核不冲突、任务不丢、不重复办理、责任可接手。仿真只证明软件机制和容量，不证明真实五人工时。

## E. 实际试点准备（本轮不擅自执行）

输出真实试点任务书和所需授权：先出租车，第二家按资料成熟度选；其他公司逐家满足准入后进入。真实客户/模型/通知/外部接口/生产变更单独批准。

建议获准后至少观察连续三个完整月结周期，记录各周期业务量、季节性、正常/峰值工时、质量、逾期、异常、业务端转移工时及外部援助。只有在工作范围可比、五人可用工时覆盖实际需求、复核与及时性不下降、没有隐形外援时，才讨论15→5目标是否成立。

“2天完成全部月结”“节省80%”不预写为通过标准；先测出当前基线、资料到齐时间、外部等待和可控处理时间，再与业务方确认目标。未达目标时定位最大的人工耗时/返工瓶颈，形成下一轮小改造，不强行改权限或隐藏失败。
