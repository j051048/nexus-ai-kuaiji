全量后端收集 1,334 项。两个失败来自旧 `execution` 适配器未实现新增计时 hook，被误转为处理失败；计时改为可选回调后，原租约、输入、发送前及终态回执协议保持严格，原测试的回滚和成功断言全部通过。另一失败是旧原生测试只接受旧错误文字，新稳定身份护栏提前拒绝了伪交易对方；测试按具体字段期待对应错误，仍要求数据库拒绝写入。没有为通过测试放松账务或权限规则。

全量运行期间补齐按业务类型的最新模式汇总，因此最后 61 项复测还覆盖了最终的评测代码、10 项 PostgreSQL 评测测试、真实受限 worker 的规则与队列执行，以及全部 3 个原失败项。最新 13 项 SQLite/HTTP 评测和相关前端 helpers 也通过。此处不把初次全量运行描述为一次全绿，不把重复复测数与全量结果直接相加。

唯一跳过是 `test_intelligence_ledger.py` 中 SQLite 不适用的 PostgreSQL 私有冻结函数分支，对应实际 PostgreSQL 分支执行。未因缺少数据库而跳过整组 PG 测试。

浏览器初次发现评测测试切换财务身份后仍在默认业务页，已补实际会计工作台导航；之后发现旧附件上传 helper 在保存后列表刷新未结束时绕过隐藏 input 的禁用状态，上传操作被正常操作锁忽略。测试改为先等待真实上传按钮可用，保留附件 POST 200、提交状态及审批导出断言。最终完整 34 项通过；业务上传产品锁没有放松。

## 新能力的验证

- 同类复核包按同企业、期间、稳定身份和分录结构聚合，逐笔金额差异、税额未知和原件仍展示。未解析身份单独分组，当前检查通过的子集单独形成预览；变化、失权、原包外选择和复制指纹伪造展示不能审核。没有创建导出或外部凭证。
- 默认关闭的条件续跑需要管理员明确启用。真实独立补件接受并关闭后能换代事实；原执行人权限、当前映射、草稿版本、取消、人工修改、额度、期间、来源和发送阶段重查。恢复收据幂等且重启后保留，每轮有界企业轮转。缓存及模板/规则没有新外发时不会被新费用预检额外阻断。
- 后台阶段计时持久化并跨 worker 汇总；有效租约范围记录、当前企业管理授权过滤，指标不包含请求、原件或连接凭据。计时可选协议不改变旧执行器的事务回执行为。
- 稳定规则支持独立审核别名，歧义、停用或跨企业身份拒绝。同语义候选去重不暗中合并样例；已发布范围冲突需人工处置。实际受限 worker 在已审核别名下使用企业规则生成未审草稿，分录模型调用未增加。
- 评测标准冻结真实已审样例和原件，由另一名当前有权限的复核人确认。原生数据库拒绝自审、伪通过报告、空 mode、NULL 字段及跨账套；失权停止读取。规则、模板、存量 OCR/分录候选的正例与差异回放不增加供应商调用或改变凭证。
- 各模式的最新有界运行按月份及业务类型汇总。旧规则/别名或证据变更后保留原报告，但停止展示当前一致比例；未覆盖不计通过，类型工时无法分摊时返回未测量。

## 试点边界

本轮完成的是 2–3 家企业试点的复核、恢复、规则和质量测量工具。评测一致比例只代表已测样本与已测字段；已审无修改、缓存命中或低异常率都不能直接等同于整月账务正确率。

下一步仍需真实身份及供应商配置、会计确认客户科目和模板、完整月份与客户 T+ 逐笔对照，并记录会计/员工处理时间、补件、返工和交付差异。T+ 真实发送仍关闭；跨期收付、未收款员工模板和正式总账继续列为后续业务里程碑。现全库两件、每企业一件并发及共享写锁未提高，200–500 家端到端容量尚未验证。
