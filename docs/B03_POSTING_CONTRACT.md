# B03 正式凭证、原子记账与账簿契约

日期：2026-10-18
性质：受控记账原型契约；**不是完整财务报表、不是生产切换**

---

## 1. 三条状态轴

| 轴 | 载体 | 含义 |
|---|---|---|
| 草稿/审核 | `drafts.status`、审核记录 | 业务事实是否已由会计复核 |
| 内部记账 | `vouchers.status=posted` | 是否形成本系统正式会计分录 |
| 外部交付 | `exports`、回执 | 是否导出/送达客户或外部账套 |

- `exported` 不等于 `posted`，互不自动转换。
- 正式记账不修改 `drafts.status`、不删除回执、不触发导出。
- 外部账本模式仍可“复核 → 导出”，不强制先内部记账。
- 导出不会隐式触发记账。

---

## 2. 正式凭证

不可变事实：

- 事务所、企业、长期账套、旧 book、期间；
- 凭证类型（记/收/付/转）与正式编号；
- 会计日期、记账时间；
- 描述、来源类型/来源、审核政策版本；
- 期初绑定、内容指纹；
- 制备/记账主体；
- 分录：稳定科目 ID + 版本、科目/名称/类别/方向快照、借/贷分、辅助 JSON、来源行；
- 冲销/调整关系。

约束：

- 不直接扩展 `draft_lines` 作为正式事实；`vouchers`/`voucher_lines` 独立。
- 正式凭证及分录 append-only；数据库触发器拒绝 UPDATE/DELETE。
- 更正只能新增冲销/调整凭证。
- `exported`、回执和附件权限不因凭证可见而自动开放。

---

## 3. 期初绑定

- 只能绑定 B02 `opening_package_versions.status='frozen'` 的版本。
- 绑定记录：账套、期间、期初版本、内容指纹、绑定人/时间。
- 一个账套/期间只能有一个 active 绑定；重复绑定同一版本幂等，不同版本拒绝。
- 记账读取绑定版本，不读取“最新期初”。
- 绑定指纹与冻结版本指纹不一致时拒绝记账。
- 期初更正/换绑策略未实现：先拒绝，不静默替换。

---

## 4. 统一记账命令

入口：

- 已审核/已导出的草稿；
- 手工转账/计提/折旧/摊销凭证；
- 调整凭证；
- 全额冲销凭证。

事务内检查：

| 检查 | 当前实现 |
|---|---|
| 企业/账套/期间有效 | 是 |
| book 当前期间 open | 是 |
| 当前 review 权限 | 是 |
| 冻期初绑定/指纹 | 是 |
| 科目版本当前、启用、末级 | 是 |
| 辅助必填项 | 是（仅必填 key） |
| 借贷平衡、单侧金额 | 是 |
| 草稿状态/version/source active | 是 |
| 草稿→稳定科目映射 | 是 |
| 幂等键/命令回执 | 是 |
| 编号唯一/事务内分配 | 是 |
| 来源金额=凭证金额 | 是（整张草稿） |
| 证据分配/拆分合并/超额 | **未实现** |
| 红字负数金额 | **未实现** |

- AI 不得直接写 `vouchers`/`voucher_lines`；只能经服务/接口。
- 事务内不调用模型、不下载附件、不访问外部网络。
- 失败不产生凭证、分录、编号或成功回执。
- 通知/外发失败不回滚已提交记账。

---

## 5. 幂等、防重复、编号

### 幂等

- 作用域：`firm_id + book_id + command_key`。
- 同键同规范化内容：返回同一凭证，`replayed=true`。
- 同键不同内容：409。
- 命令回执持久化；响应丢失可查询恢复。
- 读取回执仍校验当前 `book` 权限。

### 业务防重复

- 已实现：同一草稿不能生成第二张正式凭证（`voucher_sources` 检查）。
- 未实现：换键重复手工凭证、拆单/合并分配、部分收付、证据金额分配约束。
- 不用“附件只能一张凭证”之类的粗糙限制。

### 编号

- 作用域：`book_id + voucher_type`。
- `voucher_sequences` 行内 `next_no` 与凭证插入同一事务。
- 回滚不消耗号码；重试复用原凭证号。
- 回滚/失败不会留下空号或改号。
- 当前使用全局写锁，SQLite 串行；PostgreSQL 并发未验收。

---

## 6. 冲销与调整

- 全额冲销：新增一张借贷方向相反的正式凭证，关联原凭证；原凭证不变。
- 一张原凭证最多一次全额冲销；重复冲销 409。
- 调整：手工凭证 + `voucher_relations.kind='adjustment'`；必须关联原凭证。
- 原凭证与冲销都参与余额计算，不删除原分录，避免双重抵销。
- 红字冲销（负数金额）与反向分录是不同表达；**当前只实现反向分录，红字未实现**。
- 部分更正/多次调整：关系表允许多次 adjustment，但金额上限/可更正范围校验未实现。
- 跨期更正：只允许当前 open 期间；关闭期间拒绝；跨期开放期间策略未实现。
- 旧科目停用/辅助要求变化：按当前版本校验；历史冲销使用原科目版本快照，未做“最新科目替换”。

---

## 7. 账簿

唯一事实来源：**绑定冻结期初 + 已提交正式分录**。

- 不使用未审核草稿、`exported`、回执、参考余额。
- 余额按需从期初和分录计算，无缓存/汇总表；清缓存重建一致。
- 总账/明细/日记账共用同一分录来源。
- 父级由子级汇总；父子不重复计入。
- 余额公式：`closing = opening + debit - credit`（借正贷负）。
- 查询期初来自绑定版本；本期发生额来自正式分录；本年累计字段当前未单独输出。
- 冲销/调整作为普通已提交分录参与发生额，不删除原分录。

已实现查询：

- 科目余额表（含父子汇总、叶子合计）；
- 科目明细账（期初、逐笔余额）；
- 现金/银行日记账（科目编码 1001/1002 前缀）；
- 辅助明细（按辅助 key/value 过滤）；
- 凭证详情/关联链；
- 命令回执查询。

未实现：

- 数据库侧分页/权限过滤（当前服务层读权限、Python 过滤）；
- 跨期承接余额的权限限制展示；
- 本年累计、查询期初与期初历史累计的完整分栏；
- 并发快照隔离、半提交可见性验证；
- 正式报表/月结。

---

## 8. 权限

- 复用现有 `book` 读/复核权限。
- 记账要求 review 权限；非授权返回 403/404。
- 期初绑定要求 review 权限。
- 凭证列表/详情/余额/日记账均重新校验当前 book 权限。
- 无历史 book 权限时不能通过长期账套管理权自动读取。
- 撤权、企业停用当前请求即生效；并发竞争未在 PostgreSQL 验证。
- 技术管理员不自动获得会计复核权。

---

## 9. 与 B02/现有模块关系

- 使用 B02 `accounting_policies`、`ledger_accounts/versions`、`ledger_account_mappings`、`opening_packages/versions/lines`。
- 使用现有 `drafts`、`sources`、`exports`、回执、附件和审计。
- 不新建平行账套/科目/期初模型。
- 不修改旧 `drafts.status` 语义；不把 `exported` 回填 `posted`。

---

## 10. 明确不实施

- 完整损益结转、财务报表、月结引擎。
- 固定资产/工资/存货/应收应付子系统。
- 自动审核、税务申报、资金支付。
- 真实企业账本切换。
- 生产环境迁移/部署。
- 完整前端改版（当前只有 API）。
- 真实 PostgreSQL 并发/RLS/故障注入验收。
