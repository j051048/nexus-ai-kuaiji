# 第九阶段数据库与部署

本阶段继续使用模块化单体、精确人民币金额、PostgreSQL 强制 RLS，以及独立 API / worker 账号。不会建立正式总账或向客户软件自动过账。先在独立环境为 2–3 家企业验证一个完整月份。

## 迁移顺序

使用现有管理员迁移命令应用所有待执行文件，禁止修改已应用文件或数据库校验记录。API 启动时验证每个迁移的 checksum，迁移缺失或不同即拒绝启动。

| PostgreSQL | SQLite | 内容 |
| --- | --- | --- |
| `028`–`031` | `017`–`020` | 第八阶段批量复核、异常补件、审核样例与规则、规则任务回执 |
| `032` | `021` | 稳定银行身份、相似来源人工辨别；追加修正规则回执人民币与辅助项渲染 |
| `033` | `022` | 固定流水匹配、版本与事实指纹、幂等关联回执 |
| `034` | `023` | 不可变导出清单、人工回执事实、逐项交付差异说明 |
| `035` | 服务校验 | PostgreSQL 原始 CSV 证明、导出原事务科目快照及原生回执结构守卫 |
| `036` | 服务校验 | 关联流水的异常与重复风险传递到业务凭证及企业规则任务 |
| `037` | `024` | 新旧来源混用时的重复辨别与数据库真实性守卫 |
| `038` | 服务校验 | 固定模板与模型任务成功回执同样检查当前权限、期间及来源异常；失败清理不受新增成功闸门阻碍 |

SQLite 用于本机演示与行为测试，不证明生产数据库隔离。生产仍须 Supabase 登录、受限 PostgreSQL 和持久私有附件存储，配置见 [数据库接入](POSTGRES_SETUP.md)、[后台部署](STAGE5_API.md)。本轮没有部署到用户 Supabase 或修改生产资料。

## 银行交易身份

`bank_import_keys` 保存来源命名空间、脱敏账户标识、稳定交易编号、原显示编号和经济事实指纹。唯一范围为事务所、客户企业、来源、账户、稳定编号；同一企业另一个账套不能重复导入同身份，存在性检查不返回无权账套的 ID 或原文。源表使用独立内部编号，展示保留原显示编号。

旧格式没有身份表记录，继续沿用原始字段的 hash，不因新增空字段而使历史重导冲突。新格式相同身份、相同经济事实计为重复；同身份内容冲突整批回滚。附件或显示文件名不充当银行身份。

同账套同日、同金额、同方向、同交易对方的来源，只要一方有银行身份，双方同账户或一方账户未知即提示待辨别；明确不同已知账户不误合并，双方均旧格式维持原去重行为。`bank_duplicate_decisions` 保存会计当前权限、来源指纹、草稿版本和独立交易依据，不可覆写。确认独立后只变更未审核草稿版本，旧审核与原始来源保持冻结。

真正重复的来源应继续阻断，不得为了清空待办谎报为独立交易。当前没有“确认重复后隔离来源”的专用处置动作，也不删除或合并原始记录；该处置及规范银行账户字典列入下一阶段。账户标识目前由会计固定配置，系统无法自动识别同一物理账户的不同别名。

## 匹配确认与异常传播

`reconciliation_receipts` 记录不可变匹配请求与幂等凭据。PostgreSQL 运行账号只能读当前请求者仍获授权的回执，通过受限 `confirm_reconciliation` 原子执行关联，不能直接插入伪成功回执。混合批次先授权全部真实账套与事项，再校验每笔当前状态及版本。

确认要求事项已移交且已付款、期间开放、凭证未冻结；流水同账套、同方向、精确交易对方、日期差不超过七天，多笔合计与事项全额相等。流水仍由唯一 `ai_bank_links.bank_source_id` 保护，不能用于两个事项；不支持一个流水拆分至多个事项。候选只能提出建议，歧义由会计判断。

数据库能力与业务服务都拒绝待处理的银行异常。`source_workflow_blocked` 只在当前授权源范围返回阻断布尔值，不披露内部任务标题、内容或原件。已关联银行的后续异常或相似来源也会阻止业务凭证审核、新导出和后台自动采用；关闭模型处理开关不会跳过这些确定性检查。

## 导出证明和人工回执

新的导出在同一事务中冻结凭证、写审计及 `delivery_manifests`。清单保留企业、账套、期间、人民币金额、原审核与导出版本、来源指纹、分录序号、科目和辅助项。原导出 CSV、清单、回执及说明均不可覆写。

PostgreSQL 的私有 `delivery_export_proofs` 由导出插入触发器保存原事务 ID 与科目快照；API、worker、浏览器角色无直接读写权限。新清单只能在原事务捕获，必须与该快照及实际原 CSV 一致。历史回填必须有唯一导出/审核审计，并逐行匹配原 CSV；历史科目未知时保持 `null`，不能拿当前配置冒充。

`delivery_receipts`、`delivery_receipt_items` 只保存人工提供的事实和原内容 hash。核验状态在读取时按冻结清单重新计算，调用方不能写入“核验成功”标志。范围、金额、完整分录、辅助项和外部凭证号逐项核对；缺失、未知、拒绝、重复凭证及冲突进入待人工核验或差异。

`delivery_notes` 追加处理依据，不抹除差异、不释放额度、不修改冻结凭证。关闭期间仍允许追加交付证据；不允许更改原账务。接收部分或未知结果不会自动重发。

回执是人工上传，内容一致不能独立证明客户软件已经正式过账。本阶段未选定供应商适配器、认证回调或外部凭证撤回机制。下一阶段应基于客户实际软件验收这些能力。

## 试点验收

验证身份重放不重复、冲突整批回滚、新旧相似来源阻断、混合企业权限拒绝、关联后异常继续阻断、草稿与事实版本变化拒绝、关闭期间只追加交付证据、实际 CSV 清单一致、回执重放及外部编号冲突。真实月份还需逐笔对照客户软件，记录复核耗时、等待补件时间、修改比例和交付差异。

全库写事务协调锁、总并发 2 件及企业轮转保持原实现。没有通过此阶段证明 200–500 家的生产容量；查询及端到端并发须单独压测。
