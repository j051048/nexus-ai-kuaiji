# 出租车试点 P0–P2 改良任务规划

日期：2026-11-10。依据：[出租车试点适配评估](<C:/Users/Fei/Desktop/AI应用/nexus-ai-kuaiji/docs/TAXI_PILOT_FIT_GAP_REPORT_20261110.md>)。

本文件是后续实施范围与验收规划，不表示任务已经完成，也不授权生产操作。将原报告 T01–T08 展开为 **24 个可验收子任务：P0 九项、P1 九项、P2 六项**。不是重新实现已有模块；执行前必须核对当时的代码和修改归属，已通过的能力只复用和回归。

## 一、目标和完成口径

**P0：能安全办理一条核心业务链。** 先完成“规费应收 → 收款核销 → 独立复核 → T+ 原生文件 → 导入结果核对”，修复已复现的结转缺陷，建立来源与期间控制。

**P1：能办理这家公司的完整月度业务。** 补齐成本、摊销、OA 费用与薪酬、租赁、税费、利润下钻和双档归档，完成一户两期试点。无法自动计算的业务必须能凭核定底稿受控人工办理，且明确标识；不能为了“自动化率”猜规则。

**P2：用起来省事，并在实际数据上持续改进。** 补经营指标、稳定接口接入、助手质量、容量和交互细节。P2 不是全部无条件开工：涉及真实系统的自动化必须由试点证据和用户授权决定。

四个边界始终保持：

1. 出管/OA 是业务事实来源；平台处理核对、规则、草稿、复核、交付和管理分析；T+ 保留本客户选定的法定账与法定报表出口。
2. 内部记账、文件导出、T+ 接收/导入、T+ 审核或过账、客户签收分别记录；未知结果不按成功或失败猜测，不自动重发。
3. 企业隔离、当次授权检查、来源版本绑定、独立复核后导出、历史不可覆盖保持有效；工资和驾驶员个人信息按任务最小披露。
4. 全部先写失败测试再修复或扩展。先本地合成/脱敏数据，不接真实模型、不真实发送、不推送、不修改线上。生产配置、真实业务发送和正式数据操作另行授权；不改历史 SQL 和 checksum，确需改库使用前向迁移。

## 二、所有工作包共用的执行要求

### 开工与协作

- 记录 HEAD、已有修改清单、涉及文件当前内容摘要和任务负责人；不重置、不整文件覆盖其他智能体的修改。
- 查找现有服务、组件和测试，列明“直接复用/局部扩展/确需新增”。不能仅凭旧报告判断仍缺功能。
- 每包交付必须包含后端行为、对应前端办理入口、错误后的下一步、测试和验收记录。纯底层包至少应证明已有调用入口受益。
- 客户尚未提供的模板、规则和原件列为外部依赖，不编造默认值。依赖未齐只阻断相关自动处理，其他已核实工作继续推进。

### 验收层级

| 层级 | 要证明什么 |
|---|---|
| 本地工程 | 红测复现真实缺口，修复后成功与拒绝路径均通过；确定性金额、幂等、版本和无外发副作用可验证。 |
| PG16/17 | 涉及数据库的任务验证两版本下的权限、RLS、并发、撤权、恢复；必验子集不允许静默跳过。 |
| 桌面/手机 | 使用真实组件和本地 API 办理；点击待办到正确对象，完成后返回原筛选；失败不能丢输入或错误显示成功。 |
| 客户适配 | 客户确认实际规则、原生模板与金标；T+ 测试账套导入及结果回核。需要环境与授权，不能用模拟导入替代。 |
| 受控试点 | 客户会计与复核人跑完真实月份，记录实际人工耗时和差异；此层不由本次规划自动授权。 |

各层分别标记完成状态。代码本地完成而客户适配未验证，应写“本地工程通过，客户适配待验”，不得写“试点已通过”。

### 同一候选与证据

将代码候选、迁移集合、模板版本、规则版本、样本清单及 hash、运行命令、JUnit/浏览器结果绑定在一次验收中。来源升级后重跑受影响门槛。新表和文件绑定关系进入既有完整恢复验证，恢复后不得自动补发、自动导出或自动采纳旧审批。

脱敏夹具可入库；原始工资、驾驶员身份、客户文件及含秘密配置不得自动入库。权限与恢复测试使用独立环境，保护 C01 既有控制与验收。

## 三、P0：核心链路与正确性（TAX01–TAX09）

### TAX01｜确认业务口径、接入契约与试点基线

**范围：** 复用政策、主档和服务计划机制，形成版本化的试点配置及待确认清单，不新增一套规则平台。

**工作：**

- 确认业务事实来源、T+ 权威边界、平台是否仅做凭证交付或另做内部核算；防止两个引擎重复确认业务。
- 获取 T+ 产品版本、空白 54 列模板、成功导入样例和结果；确认字号、编号分配、导入重复判定与附件关联。
- 收齐一个完整月份的原始工具文件和相邻月份必要数据，建立经会计确认的预期结果；展示材料仅作需求说明。
- 为 336/335 行、832.19 不平、3,550 差额、保险算法、5,990 基数及税额分位差登记负责人、依据和处理状态。
- 确认驾驶员、车辆、租赁、成本、计税方式和报表映射的规则有效期；不把所有收入套一个税率或公式。
- 从第一轮开始记录人工搬表次数、制单/复核分钟数、导入拒绝及差异定位时间。

**验收：** 未决规则不能激活；旧规则和模板可定位；配置变更使相关未完成预览失效；缺失累计、所得税等数据保持未知。客户数据不足时明确缺项，不宣布规则已定。

**依赖：** 无。资料确认可与 TAX02 的通用修复并行。

### TAX02｜修复损益结转及辅助维度正确性

**范围：** `periodic`、损益科目分类、既有正式凭证与报表接口及对应测试。

**失败测试先行：** 将本轮隔离红测纳入正式测试：收入 100、费用贷方冲减 10，应结转利润 110。增加收入借方冲减、零余额、正负混合、辅助项目和科目版本用例。

**工作：** 修复反向余额遗漏；按确定的损益分类结转；保留车辆/部门等辅助余额归属；补重复生成、源凭证变更、更正后旧草稿失效、已冻结历史不变。避免把所有成本类科目直接当损益，也不改变已记账历史。

**验收：** 总账与需结转的辅助账均对平；相关科目结转后残额符合政策；独立复核仍必需；本地与 PG16/17 成功、拒绝和并发路径通过。

**依赖：** 通用遗漏可立即修；客户分类映射依赖 TAX01。

### TAX03｜车辆、驾驶员、合同主数据与期初承接

**范围：** 复用 `ledgers` 主体/别名、辅助核算、`opening` 与 `subledger`；补业务关系与外部映射。

**工作：**

- 车辆对应项目、驾驶员对应往来主体，保存稳定外部 ID；车牌和姓名仅用于展示/候选匹配。
- 保存经营权、合同、单双班、驾驶员换车/换班的有效期；历史期间按历史关系读取。
- 将期初驾驶员欠款、预收、车辆资产和累计摊销按已确认范围承接，避免从期初导入重复生成本期收入。
- 维护 T+ 科目、辅助对象与出管 ID 的审核映射；多份项目表不自动互相覆盖。

**验收：** 重名/改名/同一脱敏车牌不会错误合并；双班及换车不改旧账；错企业映射、重叠有效期或欠缺映射阻断相关生成；期初总额与分户合计一致并有独立复核。

**依赖：** TAX01 的主来源与主键定义。

### TAX04｜行业文件接入与行级来源链

**范围：** 扩展现有 ingestion、import、附件、事实版本与来源定位；先文件后 API。

**工作：** 建立指定页签/区块的解析配置；保留原文件 hash、页签、行号、源记录 ID、源版本、核定状态、参与或排除理由。把“受理→解析→校验→可生成→失败待办”接成实际处理链。禁止执行任意公式，历史月份残留进入隔离清单。

支持“多源行合并一分录”和“一源行拆多分录”，记录各自金额贡献；贯通事实、规则版本、草稿行和导出行。首次导入和更正版导入的语义分开，重复上传不产生第二套事实。

**验收：** 每一输入行都有明确去向；明细总额与采用/排除总额勾稽；同 ID 异内容进入更正流程；来源变更不能沿用旧审批；损坏文件、外链、公式、超限和跨企业数据受控拒绝。保留银行通用解析器原有安全限制。

**依赖：** TAX01 的文件契约，TAX03 的身份解析。

### TAX05｜大凭证与批次复核

**范围：** 现有草稿、正式凭证、批量任务和复核组件；不再建立一套审核状态机。

**工作：** 先用 575、约 258、1,001 行的合成样例复现接口限制，再选择受控大凭证或业务平衡拆分方案。补来源不同但同科目同辅助项的表达方式；不简单删除重复限制，也不机械按行数切开借贷。

前端按需加载分录，以批次金额、行数、差异和复核范围为入口。每张结果凭证仍有独立身份、版本、复核依据和源批次关系。

**验收：** 不丢行、不重复、不改变金额；拆分后每张平衡且合计守恒；并发生成/重试不重复；部分失败可定位；复核期间来源变化被拒绝；桌面和手机能定位指定源行，未展开不等于已复核。

**依赖：** TAX04；具体分组规则依赖 TAX01。

### TAX06｜规费应收核定与生成

**范围：** 复用企业规则、确定性计算、批次草稿与主数据，增加出租车规费转换。

**工作：** 核定驾驶员应收借方、单车收入贷方、优惠/减免、零额排除与跨期调整；摘要由本次核定期间生成；把双班驾驶员与车辆收入映射到同一来源链。收入确认与实收分别建事实，不因银行到账再次生成收入。

**验收：** 按人、按车、批次三个层级对平；336/335 的差异必须有逐行解释；缺主档、未核定和旧月份数据不得自动生成；重复生成、规则变更、人工修改保护及独立复核均通过。

**依赖：** TAX01、03、04、05。

### TAX07｜驾驶员收款核销及多银行核验

**范围：** 复用 settlements、subledger、银行原件覆盖与核验，不旁路现有企业锁和 RLS。

**工作：** 补部分收款、多次收款、汇总代收、预收、退款、跨期与撤销核销。对“付款人不等于驾驶员”的情况，引入经核定的代收分配依据，不取消同交易对方检查后直接放行。接入实际银行模板，保留未达账和对账差异明细。

**验收：** 欠款余额与分配金额守恒；一次银行金额不能被重复消费；退款/撤销追加历史而非删账；跨企业、错账户、旧指纹和并发超额分配拒绝；银行核验通过不自动锁期。

**依赖：** TAX03、04、06；期初欠款由 TAX03 提供。

### TAX08｜T+ 原生文件与结果核对

**范围：** 既有 integrations、冻结导出清单、delivery 回执与对应页面。

**工作：** 按客户具体模板实现 54 列适配，处理字号、编号、金额格式、辅助编码和空列要求。冻结模板/规则/映射/已复核凭证版本，保留源行到输出行关系。接入部分导入成功、拒绝、重复、结果未知的逐项处理与回传对照。

**验收：** 未复核、旧版本、缺映射不可导出；导出后修改不能悄悄替换旧文件；同批重试不会创建第二个交付意图；异常结果可人工核查且不自动重发。**本地文件金标通过与客户 T+ 测试账套成功导入分开验收。** 后者需实际模板、环境和授权。

**依赖：** TAX01、04、05、06；收款凭证依赖 TAX07。

### TAX09｜最小办理界面与 P0 集成门槛

**范围：** 复用当前导航、月度服务单、待办、核验、复核和 T+ 页面。

**工作：** 接通“资料→差异→草稿→复核→T+ 交付/核查”入口。每条阻断显示对象、金额/原因、负责人和下一步；点击进入具体源行或凭证。返回保留企业、期间、筛选、分页和滚动位置。员工只补资料，不重复办理已有 OA 业务。

**验收：** 真实本地身份/API/PG 下成功走完核心链，另一个企业不能查看或办理；换范围、迟到响应、撤权、409、未知结果都不显示旧数据或假成功；桌面/手机可用；P0 同候选门禁通过。客户 T+ 验证未做则明确待验。

**依赖：** TAX03–08；原型与入口接线随各包推进，不能留到最后一次性补。

## 四、P1：完整月度业务（TAX10–TAX18）

### TAX10｜按车维修成本与包干过渡

复用 periodic 和规则服务，建立车型/合同费率、生效日期、车辆有效范围、当月计提和次月冲回关联。包干“特殊项目”转按车期间设置明确切换点，保留实际维修费入口及包干覆盖范围，防止重复计费。

**验收：** 有效车辆数×适用费率与明细/凭证合计一致；中途增减车、费率变更、包干与实际重叠、实付冲回均有金标和独立复核。依赖 TAX03–05。

### TAX11｜保险、折旧和其他摊销全生命周期

复用资产与计提引擎，补车辆/保单/合同/底稿引用、历史累计、起止日、停用/退保/增批、补提和末期尾差。保险、固定资产折旧、装修摊销分别使用审核后的策略，不强套同一月均公式。

**验收：** 首末月、非整月、漏提补提、处置、历史授权缺失、退保、更正失效、付款与摊销不重复；累计不超核定可摊基数；没有确认算法的保单保持人工核定。依赖 TAX01、03–05。

### TAX12｜OA 费用、工资社保与计息底稿接入

先接经核定文件及审批快照，复用业务交接与附件；保留 OA 业务 ID 和版本，不要求重新审批同一业务申请，但会计复核不可省略。工资、社保、资金计息分别绑定金额来源、期间、部门和采用依据；外部审批撤销使后续未冻结结果失效。

**验收：** 同一 OA 事项不重复入账；工资汇总与授权明细可勾稽；非授权人员看不到明细、下载或搜索结果；已付款与计提/冲回不重复确认费用。依赖 TAX03–05。

### TAX13｜租赁收入、预收与跨期确认

复用收入、预收子账和周期草稿，补合同、车辆、客户、服务期间及收入计划。处理预收释放、合同变更、退款、跨期调整、开票信息与确认信息分离；按已确认税务政策作确定性价税计算。

**验收：** 合同总额、累计确认、未确认和预收余额可勾稽；收款/开票不自动等于当期收入；3,550 等未解释差异保留；更正版不重算已冻结历史。依赖 TAX01、03–05、07。

### TAX14｜税费底稿与人工办理证据

优先让不同业务的收入、计税口径、税额、附加和调整依据能独立核对，复用税务档案、底稿、办理记录和附件。客户政策未确认或当前引擎不支持的路径采用有版本、有复核的人工核定底稿，不把一般纳税人改成小规模绕过限制。

**验收：** 错业务税率、缺来源、错期间、重复登记、旧底稿引用、金额差异均受控；申报、缴款、回执原件及更正分别留痕；系统只证明其已核验的内容。复杂进项分配未支持时明确范围，不能标“自动税务完成”。依赖 TAX01、06、10–13。

### TAX15｜利润表分类与四层下钻

复用 reports、正式账簿、analysis 和已有证据面板，建立版本化科目到报表项目映射，区分营业收入、成本、税金、各类费用、营业外及所得税。贯通确认方式、计算逻辑、基础资料、输出凭证四层。

**验收：** 对经核定金标逐项对平；负费用保留符号；混合凭证只取相关行；当月净额与单凭证金额分开；缺所得税/年累计不填零；来源变化、分页、导出和撤权使用同一范围。依赖 TAX02、04及相关业务数据。

### TAX16｜T+ 外部账务证据与月度双档

复用交付回执、月度包、签收和原件归档，增加外部权威账模式的证据与前置核验，保留现有内部模式。归档源文件、核定底稿、规则版本、凭证、导出文件、T+ 回传和报表；区分原始凭证与记账凭证。

**验收：** 不删除现有内部锁期/报表门槛；外部模式有明确对应的冻结、完整性、对平和独立复核证据；旧包不被新版本覆盖；签收不等于过账；恢复后文件 hash、身份和权限可验证。依赖 TAX08、14、15。

### TAX17｜六阶段岗位工作台与月结办理

把现有服务组织成“收齐资料、核对差异、准备凭证、会计复核、T+ 交付核查、月度确认归档”。不是新增六套页面或状态机；复用现有导航与办理组件。内部十类业务允许按依赖并行，最终结账前检查全部受影响事实。

**验收：** 银行核验不早于事实稳定而永久冻结整期；后续租赁/税费/调整会触发必要重检；每岗首屏只突出主任务；待办直达并能返回；领导暂估数和已核定数明确分开；实际用户能完成任务而非只看说明。依赖 TAX09–16。

### TAX18｜一户两期、恢复与综合试点验收

使用同一候选跑两家隔离企业中的目标试点企业两个连续期间；另一企业作为越权反例。覆盖期初欠款、换车换班、多银行、跨期冲回、模板升级、撤权、重复导入和处理中断；跨年另设回归场景。验证约 240 辆车、数百驾驶员及千行凭证规模。

**验收：** PG16/17 无跳过关键门槛、桌面/手机成功路径、完整恢复、T+ 测试导入回核均有证据；恢复后不自动补发、不复活旧审批。获授权后才开展真实两期试点，记录人工分钟、差异、退回和一次导入成功率，客户会计与复核人确认结果。

**依赖：** TAX01–17。本地综合验收和真实试点分别结项，不把前者写成后者。

## 五、P2：效率、经营分析与持续改进（TAX19–TAX24）

### TAX19｜单车、驾驶员与经营管理指标

复用既有报表、只读分析和驾驶员/车辆来源链，补单车收入、已归属成本、贡献、欠款账龄、收款进度。资金计划、业务预算执行单独定义实际/计划/占用/已支付口径，不与利润或 AI 调用预算混淆。

**验收：** 指标可回到源行；总分一致；未分配共用成本可见，未完整分摊不称“单车净利润”；驾驶员只看获授权范围；指标定义变更可追溯。依赖 TAX15、18及客户确认的经营指标。

### TAX20｜出管/OA 自动同步与受控提醒

在文件链稳定后，复用既有接入、队列、通知和核查机制接实际只读接口。补签名/鉴权、分页游标、断点续传、更正撤回、乱序、重放和来源版本；发送提醒只带最小必要信息。

**验收：** 自动接入与同版本文件结果一致；受理不冒充已处理；断连与重放不重复事实；外发未知不自动重发；更正回源办理。先本地替身，再授权测试环境，最后单独批准真实运行。依赖 TAX18；不以此阻塞已可用的人工文件流程。

### TAX21｜出租车助手与规则记忆的离线质量

复用现有只读调查、ContextPack、证据图、H01/AG05/RSI 和企业规则。围绕“哪位驾驶员欠款、哪辆车成本异常、本月为何不能交付、利润为何变化”补任务集；历史已审核规则只作候选，不覆盖当前事实与有效政策。

**验收：** 固定分母、独立验收集、关键退步否决；回答给金额、来源版本、未检查范围和办理入口；撤权/来源变更/预算不足明确弃答；无真实模型调用的结果只称离线契约结果，费用 unknown 不计零。不增加写账、审批、任意 SQL 或自动发送工具。依赖 TAX15、17、18。

### TAX22｜单企业大数据与持续运行容量

按试点瓶颈测量文件解析、行级来源查询、辅助账、千行复核、54 列导出、报告下钻和原件下载。补多进程、慢存储、取消、租约恢复和长时间运行；再决定索引、分页、任务拆分和准入预算。

**验收：** 记录输入规模、硬件、p50/p95、队列等待、锁等待、内存及连接占用；无丢行、越权、重复核销或重复导出；另一企业不被长期饿死。先取得基线并商定预算，再作优化前后对照，不靠扩大连接池凑通过。依赖 TAX18。

### TAX23｜真实岗位易用性与视觉精修

沿用既有视觉 token、导航和角色界面。聚焦表格密度、金额对齐、异常突出、原件与差异并排、手机固定操作不遮输入、键盘与屏幕阅读器。通过真实任务观察调整，不增加首页模块凑功能。

**验收：** 首次使用者能找到并完成分配任务；待办、补件、复核、回核的步骤和误操作可量化；状态含义不依赖颜色；跨浏览器、真机和无障碍人工走查有记录。基本可访问性与办理入口已在 P0/P1 完成，此包负责进一步打磨。依赖 TAX17、18。

### TAX24｜持续门禁、运行监控和周期性恢复

复用现有 CI、doctor、容量、执行记录与恢复工具。将行业关键测试纳入 PR 快检、定期完整回归和发布前联合门槛；业务规则/模板更新触发对应回放。监控缺来源、待复核积压、导入拒绝、未知结果、队列年龄和备份完整性，并指定处理人。

**验收：** 发布证据绑定同一候选，不拼接旧报告；关键门槛不可静默跳过；告警能定位到授权范围内的批次并进入人工办理；新增行业数据和原件可完整恢复。现有测试与恢复在 P0/P1 期间始终执行，本包负责长期化及效率改进。依赖 TAX18，并随前序增量积累。

## 六、推荐执行批次

| 批次 | 任务 | 本批应交付的可用结果 |
|---|---|---|
| A | TAX01、02 | 客户依赖清单、版本化政策边界；结转红测修复，不能再忽略反向余额。 |

| D | TAX07–09 | 收款核销、T+ 文件及结果核查连通；P0 最小链本地验收。 |
| E | TAX10–12 | 维修、保险/资产、OA 费用/薪酬接通；未定算法保留受控人工口。 |
