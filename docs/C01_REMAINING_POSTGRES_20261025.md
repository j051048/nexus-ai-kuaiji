## 受控 WSL 桥

本机 Windows Python 子进程调用 `wsl.exe` 返回 `Wsl/E_ACCESSDENIED`，而 PowerShell 工具入口直接调用正常。没有改变 OS 权限、重启 WSL 或关闭运行中的数据库；改由获授权的直接入口启动受控桥。

- 仅监听 `127.0.0.1:25510`，使用私有随机 Bearer nonce，拒绝浏览器 Origin。
- 只支持固定 `pg_dump`／`pg_restore` 和官方固定摘要 GoTrue 的启动／停止；没有任意 shell、argv、环境变量或远程 DSN 接口。
- 数据库限制为事先列出的回环 25496–25499 目标，身份试验只可派生严格前缀与 32 位随机后缀的新 Auth 库。
- 保留原备份的导出快照，以及恢复的单事务、出错退出、所有者／权限重建语义。密码只传工具子进程环境，不进入命令行或响应。
- 原件产物路径必须在显式私有测试根目录；输出不得覆盖既有文件。GoTrue 仅可占用 25511／25512，停止时只操作本桥持有的真实子进程对象。
- 真实 smoke 已完成：2.6 MB 自定义 PG 备份→独立新 smoke 库恢复→148 个迁移可读；独立 GoTrue 新库启动 `/health=200` 后停止。未把 smoke 写入完整恢复任务的目标库。
- 单独 5 项基础设施约束测试通过；这些不计入原 167 项账务门禁。
- 真实 HTTP 再验 6 个拒绝路径：无／错 nonce、浏览器 Origin、任意 shell 操作、未知远程目标、越界文件路径。
- 随后实际身份业务发现仅启动 `auth serve` 的健康检查可返回 200，但库里没有身份表。桥现先执行固定 `CREATE SCHEMA IF NOT EXISTS auth`、官方 `auth migrate`，再查询实际 `auth.identities` 和表数大于零，全部成功才启动服务。官方迁移另依赖兼容 `postgres` 角色，恢复任务仅在独立集群创建 NOLOGIN 兼容角色；不向应用登录增加权限。身份恢复结果仍以负责人真实业务报告为准。
