# 衡账全前端重构规划

2026-11-17 · 以五家企业财务共享中心为目标，以出租车公司为首个验证场景。

本规划按 Open Design 0.27.1 随包工作流编写，并使用其设计变量规范校验。当前 Windows 启动故障使应用内生成与预览仍待验证。后续的品牌、美学、动效、原型与前端实施已编排为 [DeepSeek 分阶段执行总令](design/frontend-redesign/00_EXECUTION_MASTER.md)。

## 设计目标

员工打开手机就能交资料和补件，会计从待办直接核对差异和原件，负责人扫一眼就知道哪家公司卡住、谁在处理。视觉方向采用低饱和深绿、暖灰白画布、深墨文字和对齐的数字。通过版式、留白和明确的主操作建立辨识度，状态色用于表达真实业务状态。

同一套视觉语言采用两种密度。员工与客户端看步骤、进度和下一步，会计端用紧凑表格、行定位和并排证据提高处理速度。跨企业视图强调企业名称和处理期限，进入单笔始终展示业务企业、期间和版本。账号所属单位和当前正在办理的企业分别标明。

视觉规范、时长与字体已写入 [衡账 DESIGN.md](design/open-design/hengzhang/DESIGN.md)。同目录提供 Open Design 设计系统清单与原型色值。生产样式以 `src/tokens.css` 为来源，设计原型的确认值通过现有 token 逐批落地。

## Open Design 的使用方式

1. **提取现状。** 按官方 Code Migration 流程，从当前代码、角色路径、脱敏截图和测试提取界面结构与 token。列出保留、合并、移位的内容，以及每个动作背后的业务契约。记录工作区候选、角色、视口和页面状态。[官方 Code Migration](https://github.com/nexu-io/open-design/blob/main/plugins/_official/scenarios/od-code-migration/SKILL.md)
2. **定设计规范。** 选择衡账自己的 [设计系统目录](design/open-design/hengzhang/manifest.json)。参考 Linear 的界面层级与 Stripe 的数字可读性，使用衡账自己的品牌、页面结构和财务文案。Open Design 消费 `DESIGN.md` 和语义变量来维持不同页面的视觉一致性。[官方设计系统规范](https://github.com/nexu-io/open-design/blob/open-design-v0.27.1/docs/design-systems.md)
3. **以真实任务做原型。** 只给设计工作区虚构企业、脱敏字段和流程说明。先做三条连续原型：手机交票与退回补件、桌面核验与独立复核、共享中心跨企业处理阻断。原型要能从列表进入确切对象、处理异常、返回原筛选。再补月结交付与客户签收、税务/行业工作区和助手证据。
4. **逐次评审。** 每次针对一个明确问题，比如“会计如何一眼读到差额”或“员工补件失败后还能否继续”。评审同时对照键盘、手机、慢请求和撤权情况。按 `ui-animation` 逐处说明动效用途、属性、时长及减少动态效果时的表现，后续用录屏核对。演示视频属于培训材料，产品状态反馈沿用现有 CSS 动效。[官方 Design Refine](https://github.com/nexu-io/open-design/blob/main/plugins/_official/scenarios/od-design-refine/SKILL.md) · [UI Animation](https://github.com/nexu-io/open-design/blob/main/skills/ui-animation/SKILL.md)
5. **移交实现。** 按现有 React 路由、组件和接口落地。每次交付包含可核对的组件清单、状态差异、颜色/尺寸映射、回归证据和可撤回的一组改动。逐批检查构建、浏览器与实际权限行为，再推广到下一类页面。

## 前端改造顺序

| 阶段 | 页面和组件 | 应交付的结果 |
| --- | --- | --- |
| **P0 基线与设计样板** | 五角色截图基线，登录与账号身份，按钮、字段、任务行、差异提示、状态、原生弹窗 | 先定员工手机、会计桌面和负责人桌面三条原型。每条展示正常、空、错误、无权限、版本已变等状态。验收字号、颜色、间距、范围和主操作，再用原组件实现一组样板 |
| **P0 员工移动首屏与补件** | 员工首页、我的事项、消息、拍票与反馈 | 员工首屏可开始拍照/上传和打开待补件。初次录入引导按资料→核对→提交，业务类型允许后选。多企业或账期不明确时显式处理。OCR 不可用时原件仍在，用户可手填。退回说明给具体要改的材料，返回保留操作位置 |
| **P0 财务核验与独立复核** | 核验、会计待审、原件查看、凭证明细与批量预检 | 保留单位/期间/版本和待审责任。桌面左侧任务及分录、右侧原件，手机先金额和差异，再切换原件。撤权、锁期、旧版或制单人自审都有明确阻断。按钮来自服务端允许动作，退回及确认继续可见 |
| **P1 共享中心工作台与账套** | 待协调、企业目录、单户工作台、批量和人工接手 | 五家公司同屏按卡点和截止日期阅读。从待办直接进到具体银行、合同、凭证或补件。汇总只含有权访问的企业。批量操作显示冻结范围、通过/失败/未知明细，返回保留筛选及位置 |
| **P1 月结、报表、交付** | 银行/子账阻断、锁期、利润下钻、客户简报、交付包和签收 | 页面用现有状态标明当前环节和责任，失败可直达操作。利润说明口径与来源，未知不补零。交付包显示版本、清单、历史及客户确认。通道受理、送达、查看、签收、结果待核查各有明确文字 |
| **P1 行业办理与助手** | 出租车规费/租赁/费率/资产、其他 FSC 领域、税务底稿、辅助调查 | 页面沿原业务链展开证据和历史。先支持出租车的差额和缺资料样板，再将视觉规则迁到其他行业。助手按当前对象显示结论、来源、未检查范围及下一步，数据不足、撤权或版本变化时清除不再可用的信息 |
| **P2 扩面和持续校验** | 设置、运营、个人资料、长尾报表、打印与导出入口 | 收口全部路由与状态。系统设置按权限渐进展示，审计信息在对象详情可查。报表打印处理分页、列头与期间，正式导出仍走现有发布边界。整理已迁移 CSS，登记每个路由采用情况 |

第一轮原型用出租车实操结构，例如员工交维修票据，企业财务核对金额与车辆，复核会计对照原件，负责人处理月结阻断。五家企业共用任务、证据、表格及动作样式，各行业按 FSC 的已启用流程决定字段、权限和下一步。

## 每次验收

- **实用性。** 记录浏览器中的首次主操作位置、员工完整提交时间和步骤、处理差异的往返次数、返回后的定位。和同角色同数据旧版对照。原型试用先找是否选错企业、期间或对象，再比较审美偏好。
- **状态。** 每个任务页检查慢加载、首次加载、刷新保留、空队列、加载失败、部分成功、撤权、锁期、旧版本、外部结果未知。切换企业后不显示之前的原件/金额或迟到响应。未知状态提供核查路径。
- **响应式。** 375/390 手机、平板和 1366/1920 桌面。另测真实 200% 缩放、短高度、横屏、软键盘、长单位名和大额/负数。密集账簿保留受控表格横向浏览，普通任务页无整页横向溢出。
- **可访问性。** 键盘完成登录、浏览、筛选、核验、确认和退回。焦点可见，弹层只关闭最上层且归还到原入口，中文输入组合期不会触发提交，颜色与文案共同表达状态。自动化过后再安排 iOS、微信内打开及人工读屏。
- **性能。** 沿用 `npm run typecheck`、`npm run lint`、`npm run build` 和 `npm run test:frontend-budget`。当前入口脚本将 JS 原始体积、JS gzip、CSS 原始体积分别限为 570000、176000、110000 字节，首页还有独立预算。追加按角色的加载和首个操作可用时间，测冷启动及慢网。每批复跑相关浏览器套件。
- **业务正确性。** 界面金额使用现有权威数据与整数分/精确格式化，独立复核、企业隔离、版本围栏和会计复核后导出继续通过。涉及跨企业、账期、复核或文件的接线，在本地真实身份/API/PG/原件服务核验。纯视觉修改以现有边界回归为主。

## 给原型设计的任务说明

> 使用衡账设计系统和虚构数据，设计三个可连续操作的工作流。390px 员工从拍照/上传进入核对，再处理一次退回补件。1366px 会计从当前企业的待审队列进入同屏复核，能对照凭证、金额差异和原件。共享中心负责人看五家公司，进入一项月结阻断，找到处理人并返回原筛选。每个流程提供正常、加载、无记录、错误和撤权状态。请交付桌面/手机画面、组件与变量映射、可复用的交互说明、目标与原页面的差分，以及未验证内容。

本规划以本地代码和既有验收档案为依据。新视觉与密度数值是待评审方案，真实用户完成任务的耗时、出错率和主观评价需在试用中测量。
