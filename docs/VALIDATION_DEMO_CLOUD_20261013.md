## 验证的关键边界

- API、OCR/分录、助手和迁移进程均通过同一 storage factory；remote `root=None`，导入及旧账 store 通过 clone 复用 backend。两个独立客户端只共享合成远端对象，不共享本地目录。
- 私有 bucket metadata 检查、无覆盖上传、长度 / SHA 校验、公开 bucket / 重定向拒绝、原始供应商错误隐藏。新 secret key 使用 apikey；旧 service_role JWT 使用 apikey + Bearer。
- 员工本人、部门及企业授权仍先于原件下载；跨企业、非本人及撤权被拒绝。已发出但结果未知的模型任务不自动重发，费用保持待核验。
- 真实 PostgreSQL 上传元数据，独立 worker 领取和读取远端原件，OCR / 自动建议生成草稿；未审导出被拒绝，独立会计审核后才导出。
- 上传在真实 SQLite COMMIT 后丢失确认时，清理能力已关闭，不删除可能已被引用的原件；包括事项、员工预填、补件和流水文件。
- 新 PostgreSQL 072 只为内部助手公平调度表启用并强制 RLS、撤销直接 runtime / PUBLIC ACL，未修改已应用迁移。带 BYPASSRLS 的固定 SECURITY DEFINER 所有者仍能领取任务。四个角色的只读目录 / 迁移摘要 / FORCE RLS 自检均实际通过。
- Zeabur 入口按角色拒绝管理员 DSN 与另一服务 DSN；API 监听注入 PORT，后台初始化完成后才开放内部 `/healthz`，退出关闭探针。内部探针表示进程就绪，任务及企业状态仍由工作台监控。
- 备份从数据库快照读取引用元数据，再通过私有存储获取原件；清单不含密钥或连接。恢复仍落到新本地目录，不自动上传或切换云端 bucket。

当前主机和 WSL 均没有 Docker CLI，未构建 Docker 镜像。Compose 已解析且检查 DSN 隔离，实际镜像构建须在 Zeabur 或有 Docker 的机器执行。

尚未连接真实 Supabase 项目、Zeabur 或 Vercel 生产项目；须实际确认托管数据库的角色创建权限、完整迁移、Auth 用户与私有存储策略、网络和模型输出 / 真实报价。此前 Vercel 多服务本地联调记录见 [Vercel 验证](VALIDATION_VERCEL_20261013.md)，本轮未宣称完成真实云部署。
