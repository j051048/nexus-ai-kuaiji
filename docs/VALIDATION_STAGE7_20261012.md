## 环境与边界

Windows Python 3.11、Node 26，本机独立 WSL PostgreSQL 14 测试库。数据库管理员、受限 API 登录、独立受限 worker 分开验证；只使用虚构企业、合成原件及注入模型响应。没有连接用户的生产数据库、真实 Supabase 项目、真实模型或客户财务软件。

PostgreSQL 021–027 已在专用测试库实际迁移，运行连接逐项验证迁移摘要；SQLite 010–016 在隔离临时库验证。没有修改历史迁移。

## 已验证的关键行为

- 真实客户科目 JSON 预览不写入，导入原子且检查版本；停用、模板冲突、不可变历史和关闭期间受服务与 SQL 守卫保护。
- 必填辅助值缺失进入异常汇总和分页，并阻断审核；合法值保存、冻结、按分录导出，公式型文本转义。
- 账套人员事实与授权分离；撤销员工权限后已有合法核算事实可继续审核导出，撤权员工没有新权限，其他企业人员不能伪造。
- 事实变化增加事实版本，审批不增加；审批期间的当前 OCR 结果仍可发布，事实、原件或配置变化阻断旧结果。
- 同企业原件复用不发模型请求、不新增费用；跨企业不复用。当前附件权限、撤权、企业关闭、字节哈希与受限缓存函数边界实际验证。
- 移交与自动任务原子登记，重复移交返回稳定任务标识。缺原件、依赖失败、等待超时、容量不足与核对异常进入人工处理。
- 模板优先，含核对税额拆分；无模板才调用模型。规则采用不产生模型费用，警告保留给人工；取消、过期租约、失权、关期、策略变化或人工改稿或人工采用不能发布旧结果；人工确认当前自动候选后也不能被后台覆盖，旧版本回执重放及冻结记录不写入新确认。
- OCR 与分录跨多个 worker 共享全库 2 件、企业 1 件限制和轮转；发送后未知结果不自动重发，费用保留及预算闸门有效。
- 仅分录任务的等待、失败、失联与人工积压也进入运行监控；同事项已有异常快照不重复计数；监控不向员工或未授权企业泄露原件信息。
- 账套、凭证、来源与票据批次在授权之后分页；摘要不加载全部凭证分录。已授权第 21 项之后的账套可以移交及定位复核，旧请求不覆盖切换后的范围。

## 查询与界面

`python scripts/benchmark_workbench.py --books 500 --sources 100` 使用临时 SQLite，构造 500 账套、50,000 来源、100,000 分录行。最终首页只返回默认 50 个账套摘要，5 条 SQL（含事务和授权读取），单次汇总测得约 474 ms；统计覆盖获授权全集，不把全部分录装入 Python。

该数据只代表单进程合成首页查询，不代表 PostgreSQL/RLS、模型吞吐、后台批处理、真实审核用时或完整做账容量。阶段七继续保留 2/1 并发限制。

前端将业务、核对、任务、监控和科目维护按需加载；构建首屏脚本约 431.29 KB（gzip 126.97 KB）。浏览器实测覆盖原有导入/审批/审核/CSV流程、科目模板维护、25 笔待办的 20/5 分页、辅助项阻断与补齐、关闭期间、22 个授权账套的跨页移交和窄屏。

界面截图为真实本地页面、虚构企业资料：[客户科目与模板](../artifacts/stage7-catalog-mvp.png)。已检查截图与窄屏无横向溢出。浏览器测试服务自动关闭，专用 PostgreSQL 测试服务在核验完成后停止。
