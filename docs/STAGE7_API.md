# 第七阶段：客户科目、后台草稿与待办分页

本阶段用于中国大陆、人民币、2–3 家企业的辅助记账试点。流程为员工录入、部门与企业财务审批、财务移交账套、后台识别与核对、生成未审核草稿、会计复核、导出。内置演示科目不代表完整行业科目表；试点会计应先维护客户实际科目和模板。

## 客户配置

在当前账套点击“科目与模板”。有当前账套复核权限的人员可以发布配置；编辑人员消费配置，查看人员只读。关闭期间禁止修改配置及辅助值。所有接口仍使用登录身份及 `X-Firm-Id`，数据库重新核对授权。

| 接口 | 用途 |
| --- | --- |
| GET `/api/books/{book_id}/catalog` | 当前科目、模板版本、配置权限 |
| POST `.../catalog/accounts/import/preview` | 预览整批 JSON，不写数据库 |
| POST `.../catalog/accounts/import` | 原子导入；已有科目须提供 `expected_version` |
| POST `.../catalog/accounts`、PUT `.../catalog/accounts/{code}` | 新建或更新科目，更新检查版本 |
| POST `.../catalog/templates/preview` | 用具体业务与明确金额演算模板 |
| POST `.../catalog/templates`、PUT `.../catalog/templates/{id}` | 发布不可变模板版本 |

科目包含 `code/name/category/normal_balance/active/auxiliary_requirements`；辅助项支持 `department/employee/counterparty/project`。已用于凭证的科目不能改代码或辅助要求；停用保留历史。模板条件仅业务类型、收支方向、费用类别、付款状态；金额公式仅 `gross/net/tax`，借贷两侧各等于一份总额，无可执行表达式。同优先级模板冲突要求会计处理。

科目导入例子（实际代码与科目名称须由客户会计确定）：

```json
{"rows":[{"code":"6401.01","name":"客户配置的服务成本","category":"cost","normal_balance":"debit","active":true,"auxiliary_requirements":["counterparty"]}]}
```

拆分税额模板只能消费已识别且经过金额核对的净额、税额；不推测税率、可抵扣性或未知税额。大陆银行存款明细使用 `1002` 前缀；任意字母代码不能被视为银行科目。

## 事实与识别复用

业务 `version` 继续保护编辑和审批；`fact_version` 仅业务内容实际变化、原件变化增加，提交、批准和移交不增加事实版本。业务项目是可选事实字段，不由模型推测。

OCR 复用键包含事务所、企业、原件 SHA、供应商 URL、视觉模型、输出格式、提示词与解析器版本。复用前校验当前附件授权和真实字节哈希，形成绑定当前事项及附件的新识别记录和证据引用；不共享原事项标识或人工异常确认。缓存命中不发模型请求，不增加模型费用。需要明确重识别时，原 OCR 请求增加 `force_refresh: true`。公司识别开关仍控制处理入口。

人员辅助核算通过账套内不可变人员事实字典与授权关系分开。首次记录须有当前企业归属或已移交业务申请人的历史证明；撤销员工登录权限不删除历史核算事实，也不恢复账号权限。

## 自动草稿

现有 `handoff` 在一个事务内保留来源、模板草稿、映射并登记自动任务。财务仍明确选择当前企业、期间的账套。公司识别开关、模型及费用配置不足时，任务给出人工处理原因，已有人工工作流保留。

缺少当前有效 OCR 时，自动任务建立附件识别依赖；先复用已有有效识别，再处理缺失附件。依赖失败或等待超过 30 分钟进入 `needs_attention`。附件准备、外部调用与数据库事务分开。

核对通过后优先采用会计发布的企业模板；模板不匹配才调用模型。匹配模板缺税额或辅助信息时进入人工处理，不能让模型绕过模板。模型警告保留给人工，自动采用只允许无阻断且未被人工修改或人工采用的当前版本草稿。人工明确确认当前自动候选也保护该版本，旧版本幂等重放不当作新确认。最终审核与导出仍由会计执行，申请人不能审核本人业务凭证。

任务状态：`waiting/queued/running/retry_wait/succeeded/failed/interrupted/stale/cancelled/needs_attention`。OCR 和分录共用全库最多 2 件、每企业最多 1 件的执行限制与企业轮转；部署多个 worker 不能突破。发送前过期任务可有限恢复；发送后的不确定结果不自动再次付费发送。重试重新检查权限、事实、期间、草稿及策略，不能覆盖人工改稿。

| 接口 | 用途 |
| --- | --- |
| GET `/api/intelligence/proposal-jobs?book_id=...&limit=20&offset=0` | 授权后 SQL 分页的任务摘要 |
| GET `/api/intelligence/proposal-jobs/{id}` | 单项及尝试记录，按需读取 |
| POST `.../{id}/retry` | `idempotency_key` 加 3–1000 字 `reason`；同键不同理由冲突 |
| POST `.../{id}/cancel` | 保存取消依据，旧响应不能发布 |

后台任务面板仅更新任务进度；不会轮询替换会计正在编辑的分录。完成后手动刷新凭证待办。企业运行监控同时统计 OCR 和分录；分录等待、失败、心跳失联及人工积压进入现有站内告警。

## 分页与导出

`GET /api/workbench` 支持 `limit(1–100)/offset/filter(all|pending|exception|approved)/search`。筛选、分页及计数都在授权之后执行，统计包含获授权企业全集，列表只返回当前页。工作台异常数是基础账务及必填辅助值汇总；打开凭证与审核、导出时执行完整实时票据、流水和证据校验。

`GET /api/books/{id}` 支持 `limit/offset/source_offset/filter/summaries=true`；界面每页 20 项，摘要不加载全部分录或原文，打开后通过 `GET /api/books/{id}/drafts/{draft_id}` 获取实时明细。`source_page_ids` 区分当前流水页与为复核补入的关联来源。

业务移交独立使用 `GET /api/companies/{id}/books?period=YYYY-MM&limit=100&offset=0`，不把工作台当前页当作授权全集。`focus_book_id` 和 `focus_draft_id` 分别支持定位已授权账套及凭证所在页，不能跨越权限。

CSV 保留原 8 列，追加 `辅助部门/辅助人员/辅助交易对方/辅助项目`，各行与分录严格对应并保护公式型文本。历史导出回执原样返回；导出文件仍须在客户财务软件导入并核验，尚不等于外部正式入账成功。

## 试点顺序

1. 在独立测试环境迁移数据库，配置真实身份、独立受限 worker 与共享私有附件目录。
2. 每企业由会计导入实际科目，演算并发布首批模板，确认辅助要求和 CSV 导入格式。
3. 配置供应商、价格、企业预算与识别开关。先用已知答案的小批原件核对字段、证据和草稿。
4. 先跑 2–3 家完整月份，逐笔对照原会计流程，记录修改率、异常、人工分钟与模型费用。

本阶段没有实际连接用户的 Supabase 项目、真实模型或客户财务系统；真实供应商字段质量、账单与月结结果需试点验证。凭证审核和 CSV 导出流程已经实现，完整总账、税务申报及财务软件回执继续独立建设。
