# PostgreSQL 持续门槛与 C01 实体／银行证据契约

日期：2026-10-23。基线：`cf07ef0874c76b37f55c364e42b08cce9852c46e`。

## 本轮范围

本轮实现三项：PG16/17 持续验收门槛、控制科目辅助维度实体校验、银行覆盖原件与独立复核契约。所有验证使用本机隔离数据库、虚构身份、私有临时原件和受控供应商替身。没有访问线上、调用真实模型、提交或推送。

已有总账、审批、费用、attempt、企业调度与恢复规则继续复用。没有重建这些模块，也没有把本轮结果解释为 C01 全部或真实企业试点完成。

## 持续验收门槛

- `.github/workflows/accounting.yml` 保留原 `verify/e2e`，新增 PG16/17 独立 matrix job。
- `scripts/ak05_postgres_gate.py prepare` 只接受明确配置的回环、非 5432、AK05 数据库目标，创建四个新随机数据库，复用现有迁移与受限账号配置；不覆盖已有库、账号或密码。
- `run` 固定执行 unified、process、attempt、regression 四组，按 `ak05_postgres_required_cases.json` 精确核验 167 个用例身份。
- pytest 返回 0 不足以通过；缺少、替换、重复、跳过用例，零测试，XML 损坏，非零退出码，数据库版本／角色／持久化配置错误均失败。
- 核对候选源码、测试、脚本、workflow、迁移的前后指纹。运行期间候选变化，整体结果拒绝通过。
- 四组数据库独立，避免领取夹具相互污染。API、worker、projection 使用独立受限登录，能力角色 NOLOGIN、NOBYPASSRLS，无超级用户或角色管理权限。
- CI 只上传脱敏报告，临时账号配置在单独目录，不进入 artifact。

原 135 个 AK05 用例全部保留，新增辅助实体 PG 专项 15 项、银行证据 PG 专项 17 项。门禁配置及复跑方法见 [持续门槛说明](AK05_POSTGRES_CONTINUOUS_GATE_20261023.md)。本轮只在本机实际执行门禁；GitHub Actions 的远端运行和分支保护设置没有操作。

## 辅助维度实体契约

新增 `app/subledger/auxiliary.py`，配置与新建未结事项都使用同一契约；PG153、SQLite093 在数据库中补防绕过校验。

| 维度 | 资格 |
| --- | --- |
| counterparty/project | 稳定主数据 ID，同企业和事务所，kind 正确且有效 |
| employee | 有效用户且仍为本企业成员 |
| department | 本企业真实部门 ID；现有部门表没有停用字段，不虚构停用语义 |

必要维度必须受支持、不重复，控制配置不能遗漏总账科目要求的维度。自由文本、未知维度、其他企业实体、错类型、停用项目／人员、缺失必要维度均拒绝。往来方辅助项必须与事项的往来方一致。

历史记录保留读取资格；新增写入和原生 SQL 都执行当前实体契约。PG 的授权查询只返回经范围校验的布尔结果，没有扩大员工／成员关系等表的读取权限。

本轮完成实体资格校验，不把它等同于逐辅助维度余额勾稽、全部 C01 并发门槛或跨期核算验收。

## 银行覆盖证据契约

新增 `app/subledger/bank_evidence.py`，接入现有 SubledgerService 和 API。使用现有上传及导入向导保存的 CSV/XLSX 原件，不另造原件存储。

1. 声明必须绑定真实 `source_file_id + source_preview_id + source_sha256`。批次必须已确认，原件／预览／回执的企业、事务所、账套一致，批次的稳定银行账户 ID 与目标账户一致。
2. 每行必须无导入错误、属于本期、收支方向合法、金额为精确字符串；期初加冻结流水净额须等于期末。SQL 与服务层都校验，整数分计算不走浮点。银行期初、期末支持统一范围内的有符号余额。
3. `source_ref` 只接受服务端规范引用，任意文本不能成为核验依据。声明和核验前实际读取私有原件，检查字节大小及哈希；慢存储读取在写锁外执行，最终写事务再次授权及绑定不可变原件。
4. 新声明为 `pending_review`，没有核验人；另一位当前具备账套复核资格的人才能转为 `verified/rejected`，理由必填、版本递增。本人、普通编辑或撤权人员不能绕过。
5. 同一声明重复请求返回原结果；并发复核只有一个胜出且只记一次复核审计。终态及来源金额不能改删。
6. `pending_review`、`rejected`、`legacy_unverified` 均不能作为已核验覆盖通过勾稽。停用账户仍参与本期勾稽，不能借停用账户回退旧分支。
7. 驳回和历史记录保留；更正后可提交新声明。部分唯一索引只约束当前 pending／verified，避免补件被旧拒绝记录永久堵住。
8. 原有锁期、企业写域守卫继续保留；SQL 统一推进月结依赖版本，覆盖变化使旧预检失效。

API 增加银行覆盖列表、`POST /api/subledger/bank-coverages/{id}/review`。应用启动后使用既有附件存储；未配置存储时返回受控错误，不能生成无证据的核验。

## 前向迁移与兼容影响

新增 PG153/154、SQLite093/094。原有 140 个 PG、92 个 SQLite 迁移内容与校验和保持不变。

银行覆盖迁移明确标为 **breaking**：旧文本覆盖保留原金额、原引用及历史审核人，但降为 `legacy_unverified`，不能自动取得新证据资格，也不会冒认新的提交人。SQLite 为使核验人可空而重建该表，保留旧行；新唯一约束允许保留驳回历史。没有关闭 RLS、触发器或增加宽泛 GRANT。

新版本声明要求使用已确认的导入批次；原测试中的任意文本夹具已替换为真实合成上传、预览、确认和独立复核。没有通过删除核心断言换取通过。
