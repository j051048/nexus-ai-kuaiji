# 07–12 本地验证与使用说明

此轮复用现有工作台、计时记录、独立复核记录、费用台账、受限调查与 H01/AG05 回放；不新增导航、模型调用、通知渠道或数据库迁移。

## 可用入口与口径

- 客户人工投入 → 具体账套：有明确计时才显示工时；没有样本显示未知。审核统计按当前待审版本的有效审核记录分类，单人办理不得混入独立复核。不推算准确率、节省分钟或可承载客户数。
- 税务底稿：底稿不是申报结果，申报／缴款状态以现有人工登记和回执为准。内部正式记账不代表外部财务软件过账。
- 员工录入：选择企业 → 拍照或上传 → 按需解析／识别 → 对照原件确认。上传不自动调用供应商；手工修改金额不被预填覆盖；未确认不能提交。未知、处理中和多原件各有就地提示。
- 管理设置中的运行记录：按当前事务所、月份读取。没有事务采样不显示零延迟；未知费用单列，估算不当实付。管理员可打开现有处理任务、费用记录；查看告警不授予权限、不自动补发或重试。
- 交付页的既有受限调查：仍默认关闭，只读三类域事实，零模型调用。前端校验事务所、企业、账套、月份、覆盖与执行步骤；离线回放校验候选、内部证据指纹、固定分母与独立验收集。它不证明真实模型质量。

## 三层测试

`scripts/test_layers.json` 记录层级。新增 `local-quick.yml` 提供快速契约反馈、环境自检和候选摘要；**不能代替发布验收**。

既有 `accounting.yml`、`p01-recovery.yml`、`qa-reliability.yml` 保留 push/PR 门禁，并增加错开的夜间运行。发布仍核对同一候选的 PG16/17、完整恢复和浏览器结果，不因快检成功放行。

本地依赖自检：`python scripts/env_doctor.py --json`。结果明确列出未检查项，不连接生产、模型或外发通道。失败只输出错误分类，不输出连接串或密钥。

新增固定数据库用例已加入 `dcp_reliability_gate.py --suite tasks`；浏览器入口为 `node scripts/run_e2e.mjs --mode both --suite tasks`，固定 20 个用例分别在开发与构建预览模式执行。用例缺失、跳过、重试或候选变化均拒绝验收。

## 本地环境管理

继续使用 `p01_local_recovery_env.py` 的 `status/start/stop` 与独立运行配置，不新建第二套生命周期。先核对环境 ID、端口及所属运行，再启动或停止。原配置、失败现场和报告不覆盖；不要删除他人的临时目录或停止未知进程。完整恢复仍用既有 P01 门禁单独执行，环境自检通过不代表恢复通过。

## 仍需授权后的真实验证

真实客户连续两期试点、真实 OCR/模型字段质量、邮件送达与退信、真实设备辅助技术、多节点容量及远端 CI。本轮只能提供本地工程证据，不能补造这些结果或代替生产发布批准。
