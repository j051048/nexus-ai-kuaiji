# DCP 第 5–7 批本地验收

范围：通知未知结果的人工核查、受限调查离线回放与证据展示、联合恢复及同一候选回归。仅本地虚构数据；未提交、推送、部署，未调用真实模型或真实通知。

## 第 5 批：人工核查

- 复用原通知和发送租约，新增 `notification_investigations` 只追加历史；前向迁移 PostgreSQL **202**、SQLite **126**。不修改历史 SQL/checksum。
- 管理员登记人工判断、证据编号/说明与原因，绑定原通知、企业、账套、期间、包 ID/版本/manifest、收件人和发送次数。记录核查人和时间；同键重复提交返回原记录，不同内容拒绝；同一核查版本的两个并发写入仅接受一个。
- API：`GET/POST /api/books/{book_id}/delivery/notifications/{notification_id}/investigations`。事务所复核岗可读本范围；只有当前事务所管理员可追加。数据库 RLS、写入守卫、最小 GRANT 和只追加限制同时生效。
- 现有交付页展示最新核查意见并提供登记入口；完整历史通过受控查询读取。权限变化清空旧记录，409 要刷新再确认，不自动重复写入。
- 人工意见与通道状态、客户签收分开。`accepted_by_channel` 不等于送达或签收，`not_sent` 不会自动授权重发，`unresolved` 继续人工核对。原 `unknown` 任务保留隔离，不改费用/attempt，不制造回执。

## 第 6 批：领域调查回放和界面

- 继续复用现有三个固定只读工具；不增加自主循环、模型调用或业务写工具。原开关 `ACCOUNTING_ASSISTANT_INVESTIGATION` 默认关闭；增加授权范围内的能力查询，由现有交付页面按能力显示入口。
- 结果携带企业/账套/月份、已读及未读范围和内容摘要；界面明确“查询完成不代表可交付”。错企业、错账套/期间、非法数量或不完整响应不得接纳。撤权后不保留证据。
- 修复发布前二次读取异常：不再将未重新核验的旧事实返回给用户；清空证据并转人工。读取尝试数与已接纳事实数分开。
- `tools/assistant_replay/investigation.py` 是薄适配：复用 H01 原子报告与 hash、AG05 manifest 契约和既有助手候选指纹。实际调用领域调查服务；六个合成场景，dev/holdout 各三项，固定分母，不提供选优接口。
- 覆盖正常读取、其他事务所、读取故障、事实变化、途中撤权、发送未知；篡改结果/候选、重复或缺失样本不能获得完整通过。此处 holdout 是本地固定合成验收组，不是盲测真实客户数据或真实模型质量证据。

## 第 7 批：恢复

- 新核查表进入内容绑定的恢复清单。说明/证据文本在核验清单内只留 hash，变化会使摘要失效。
- 扩展现有恢复业务夹具：备份前通过服务生成未知通知的人工记录；恢复后用重新登录的身份读取同一条历史，客户/外部账号不能读取，通知仍不自动发送，旧 lease 不能结算。
- 本轮源库须应用当前候选全部迁移（包括 202）；不能用缺少新表的旧库提供完整恢复证明。沿用原 P01 独立源/空目标、私有原件、真实本地 GoTrue、RLS/列权限、hold 和会计复核后导出门槛，不降低其断言。

## 失败测试与修复证据

1. 人工核查模块缺失：9 个失败用例；涵盖幂等、来源版本、收件人、权限和历史不可改写。
2. 领域结果缺乏证据绑定、发布前读取异常未受控：2 个失败用例。
3. 离线回放薄适配不存在；前端证据解析模块不存在；分别先失败后实现。
4. 新表未进入恢复清单、证据文本未脱敏：分别复现失败后补齐。
5. 真实浏览器抓到新表单请求体重复 JSON 编码，修正为使用项目 API 客户端的对象参数。保留网络请求内容断言。
6. 恢复 HTTP 烟测最小应用没有注册新增路由依赖的既有 followup 服务，补齐测试装配；未降低业务断言。初次失败运行保留，不作为最终验收。
