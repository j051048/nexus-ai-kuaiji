# 第十一阶段数据库与运行边界

PG055–058 / SQLite040–043 新增复核包、条件自动续跑、企业规则治理和评测记录。原 PostgreSQL 001–054、SQLite 001–039 迁移保持校验和；后续修复使用前向迁移，不修改已经应用的文件。

## 复核包

`review_package_requests` 绑定 `review_previews` 的原创建者、请求哈希、幂等号及可选父包。数据库检查子选择确为父包的冻结子集；不能通过修改请求扩大范围。API 在生成、读取、选择、确认与重放时检查当前完整授权。

复核包是现有人工审核预览的投影，不增加自动批准权限。当前展示内容与整个冻结快照比较，复制正确指纹同时伪造分录不能获得审核。临时身份解析复用限定一次事务；当前事务新生成的快照复用一次，后续请求重新做完整检查。确认仍沿用逐账套事务和原不可变回执，导出另行执行。

## 自动续跑

企业策略默认关闭，修改需要企业管理权限、配置版本和理由。`proposal_resume_watch` 记录需要巡检的任务及原因，持久信号和有界企业轮转用于检查开关、补件、额度和容量恢复。任务取消会阻止续跑，管理员开关也不能替代原执行人的当前授权。

已知阻断解除后追加 `proposal_resume_events` 回执并换代输入。只有仍为同一来源、事项和未审核草稿的任务可继续；人工编辑、失权、关闭期间、取消、来源替代、规则策略变化和外发结果未知保留人工处置。独立接受的连续业务补件版本由 `queue_verified_evidence_versions` 绑定原事项、来源、账套及草稿版本。当前业务补件只推进事实版本，草稿版本必须仍相同；不能把任意草稿变更当作补件换代。

受限 worker 领取巡检候选和写恢复收据，API 不能读取全企业候选或伪造收据。恢复仍执行原处理人当前角色及公司/账套范围检查，再进行容量、费用和外发前检查。缓存、固定模板和已发布规则没有新外部调用时，不因模型费用预检被额外阻断；实际模型发送仍走原费用预留。

## 持久运行观测

`processing_job_metrics` 按任务种类、任务、换代、尝试、阶段去重。worker 使用租约和当前任务状态记录指标，重启后数据保留；只读统计按当前企业管理授权过滤。API 的进程内事务观测继续存在，与新跨 worker 指标的口径不同。

指标覆盖依赖等待、可执行排队、领取与数据库等待、模型请求、核验/准备/落库及 OCR 复用。观测不能修改任务结果、释放预算或批准凭证。全库模型并发上限为两件，同企业一件；共享写协调锁没有在此阶段拆除。真实生产峰值、供应商限流及容量仍需要部署环境测量。

## 规则治理与评测

PG057 / SQLite042 扩展原规则匹配：可选稳定往来方 ID、同企业独立审核别名、语义去重及已发布规则范围冲突。旧规则继续精确原文匹配。API、原生评估和受限 worker 采用同样的匹配条件；主数据变化使旧评估失效。规则候选不会自行发布，核销清偿样例不能用来推广普通分类。

`quality_standards` 从真实已审样例冻结事实、分录及证据，`quality_confirmations` 要求另一位当前有复核权限的人员确认，`quality_runs` 保存有界回放。原生函数重新取实际候选和计算差异，不能直接保存伪造 passed 结果。全部新增事实表启用 FORCE RLS，worker 无评测表访问权限。只读类型投影也明确限制当前事务所和账套范围。

评测按当前规则、模板或指定存量模型版本比较，单次最多 100 个标准，不发生新模型调用。原件、事实、规则、别名或所选归档结果变更后，旧记录保留并显示失效或配置变化。抽样结果、明确计时及人工回执差异各有独立口径，不推算全企业会计正确率或未测量工时。

## 升级验收

迁移管理员与 API / worker 使用不同登录账号。升级前按 [备份恢复](BACKUP_RECOVERY.md) 保存数据库和私有原件一致恢复点。使用专用环境验证默认关闭、补件换代、发送未知、人员失权、幂等重放、人工编辑保护、别名冲突、伪造评测结果和后台重启；实际试点使用明确授权的 2–3 家企业完整月份。

具体接口与使用流程见 [第十一阶段 API](STAGE11_API.md)、[任务续跑](STAGE11_QUEUE_AUTOMATION.md)、[规则治理](STAGE11_RULE_GOVERNANCE.md)、[真实业务评测](STAGE11_QUALITY.md)。
