## 2. 长期子账

### 2.1 未结事项

`subledger_items` 保存：企业/账套/期间、应收/应付/预收/预付、往来方稳定 ID、控制科目及版本、原日期/到期日、金额、来源、创建人。

- 同一未结事项跨月保留，不按月复制。
- 期间是事项归属期，不是每月余额快照。
- 期初未结事项与后续事项通过同一事项 ID/来源链衔接；**B02 期初未结自动导入尚未实现**，当前需显式创建。

### 2.2 核销

`subledger_allocations` 关联未结事项与 **B03 已记账收付款凭证**：

- 核销只改变未结余额和分配关系，**不再次生成收付款分录**。
- 分配合计不能超过事项余额，也不能超过凭证控制科目金额。
- 同一凭证+事项唯一；幂等键按 `firm_id` 作用域。
- 撤销核销新增 `subledger_allocation_reversals`，不删除原分配。
- 已记账凭证、原金融事实不变。

限制：

- 一次核销只允许一个控制科目。
- 不支持跨凭证合并分配、手续费自动拆分、部分退款联动。
- 未实现并发超额分配的 PostgreSQL 验证（SQLite 全局写锁）。

### 2.3 账龄与控制勾稽

- 账龄必须传 `as_of`；按到期日（无到期日按原日期）分 current/1–30/31–60/61–90/over_90。
- 剩余金额 = 原金额 − 有效分配 + 撤销金额。
- 控制勾稽：应收/预付控制余额（借正）与子账剩余比较；应付/预收按贷方负数比较。
- 未结明细与控制余额不一致时，`passed=false`，月结预检阻断。
- 当前只按控制科目汇总；辅助维度控制、预收预付重分类未完整。

### 2.4 银行对账

- 银行流水行可匹配正式银行/现金分录，金额和方向必须一致。
- 调整项有类型、金额、说明、状态；不自动生成差额凭证。
- 当前 `passed` 只表示“流水全部匹配且无 open 调整”；**账面与对账单差额尚未强制等于已批准调整**。
- 未实现完整未达账项滚动、后续期间自动消除和银行余额调节表。
- 因此银行对账是基础证据，不是完整银行对账验收。

## 3. 期末计提/折旧/摊销/结转

- 所有生成结果进入 `periodic_drafts`，必须经人工复核，再调用 B03 `post_manual` 正式记账；AI 不直接写正式凭证。
- 生成键：`book_id + run_key`；相同依据重复生成返回原结果。
- `periodic_runs` 记录输入指纹、规则、草稿和正式凭证。
- 计提：固定金额 + 借/贷科目配置。
- 折旧/摊销：直线法，`(原值-残值)/月数`，最后一期按剩余可计提额；开始期间前不计提。
- 结转：只处理损益类科目余额，排除已记账的 closing 凭证，避免把结转自身再次结转；目标必须是权益类“本年利润”。
- 复核人≠编制人；记账仍走 B03 的期间、锁期、权限、编号和幂等校验。

限制：

- 折旧/摊销无资产处置、变更、减值、补提/冲回。
- 结转不支持红字/负数损益、辅助维度、年度利润分配、跨年。
- 依据变化后旧草稿/旧审核的自动失效未完整实现；当前重复生成按 run_key 复用，需人工作废/调整。
- 已记账结转只能通过 B03 冲销/调整，B04 不覆盖。

## 4. 报表

### 4.1 来源与版本

- 只使用 B03 绑定期初 + 已提交正式分录；不使用草稿、exported、回执、参考余额。
- 报表模板 `report_templates` 版本化；当前仅 `small_enterprise_basic` v1。
- `report_runs` 保存期间、模板版本、输入指纹、内容 JSON、内容哈希、状态、版本、复核/发布主体。
- `published` 内容不可改；新版本通过新 run + `supersedes_id`。
- 报表不随实时数据变化；读取已保存快照。

### 4.2 公式

- 资产负债表：按末级科目 `closing = opening + debit - credit`；资产、负债、权益按类别汇总；未结转时加入当期未结利润。
- 利润表：本期收入/费用按正式分录发生额（排除结转凭证）；利润=收入−费用。
- 现金流量表：按凭证识别现金行（1001/1002）；单现金行+非现金行按对方类别分类；现金内部划转不产生现金流；多现金行/混合类别标记未分类。
- 勾稽：资产=负债+权益（+未结利润）；现金净变动=经营+投资+筹资+未分类；未分类金额阻止核验/发布。
- 金额底层为整数分；展示舍入未实现。

限制：

- 无年初/期末比较栏、本年累计、比较期、附注、权益变动表。
- 现金流分类是启发式，不处理借款本金/利息拆分、非现金交易、退款更正、复杂多借多贷。
- 多借多贷/混合交易会进入未分类并阻断，而不是猜测。
- 报表模板只覆盖合成服务企业；未核实官方准则模板/生效期。
- 无历史权限时当前服务按 book 权限读取；尚未实现“完整快照授权”或拒绝伪完整报表的专门控制。

## 5. 月结、锁期、发布

状态：

```
draft → preflight_failed / preflight_passed → reviewed → locked → published
```

- 预检检查：未记账期末草稿、未审核草稿、子账控制、银行对账、试算平衡、报表勾稽/未分类。
- 阻断项不能由管理员“忽略”放行；当前只实现阻断，不实现可解释例外。
- 复核人≠预检人；锁期需已复核报表且输入指纹未变化。
- 锁期写 `internal_period_locks`；B03 记账检查该锁，锁期后拒绝新记账。
- 发布要求已锁期，调用 `ReportService.publish`；报表保持冻结快照。
- 重开明确返回 409；未实现重开/更正影响分析。
- 旧 `closing` 交付工作流与 B04 内部月结是两套语义；本批未改旧流程。

限制：

- 预检后新增记账会使锁期 `_current` 校验失败；已测试。
- 并发预检/锁期/发布、撤权竞争未做 PostgreSQL 验证。
- 发布文件生成/PDF/归档未实现；只有内容快照。
- 跨期重开、后续期间依赖未实现。

## 6. 权限

- 子账、期末、报表、月结复用 book 读/复核权限。
- 编制/复核/锁期/发布的主体分离在报表、期末草稿、月结中实现。
- 期初/正式凭证/锁期由 B03 既有权限层校验。
- 工资明细、原件下钻、历史月份权限未在本批新增专门控制。
- 技术管理员不自动获得会计复核权；但数据库 RLS 未在 PostgreSQL 验证。
