## 实现

### 一份能力投影

新增 `projectNavigationCapabilities`，由 App 汇集已有能力和兼容回退，向 `primaryNav` 与 `AgentNavigation` 传同一对象。侧栏不再从另一组布尔参数或回调存在性重建权限。

管理能力不再被角色菜单单独提升为会计能力；月度、复核、处理中任务、运行管理、人员授权仍沿用各自的现有能力。菜单是显示投影，不能授权 API。管理回调缺失时入口禁用，不推导额外权限。

`navigationParents` 完整声明每个 `WorkspaceView` 的导航归属：服务单归月度交付，科目、长期账套、对账等账套子页归会计工作区；事实修订仍保留现有入口。未知页面不再默认高亮会计工作台。没有增加主菜单或重建业务模块。

### 每个浏览器历史位置有独立来源

- 使用 React Router 的历史条目 key，区分同 URL 的不同访问来源。
- 到达时保存经过既有路由白名单处理的选择和来源链；最多保留 64 条历史位置，每条来源链仍有原有上限。
- POP 恢复自己的副本；未知、淘汰或路由绑定不符时不猜测来源。
- PUSH/REPLACE 使用最终 URL 的范围，保存与读取均复制数据；页内返回不会修改旧历史快照。
- 每次登录范围重建内存；不保存业务事实、原件、令牌或 API 响应，不写 localStorage。
- 带账套的修订页恢复保留原账套选择，返回后仍须经现有接口重新授权读取。

### 只写一次导航，保护未保存修改

真实浏览器诊断发现菜单点击同时写入裸 URL 和带月份 URL，导致两次 PUSH；后退只能回到多出来的月度页面。删除菜单额外的裸 URL 写入，由已有路由同步器写完整选择。页内返回和跨管理界面的显式 Router 操作保留。

同 URL、不同历史 key 的离开也必须经过未保存修改提示。取消时保留编辑；明确放弃并到达目标后，以恢复 epoch 重建页面编辑器和同屏复核弹层，重新读取服务端原值。不是只清空 dirty 标记。干净导航不因 epoch 重建。
