# FSC15：维修费率卡生命周期与批次版本绑定

优先级 P1。先读 `docs/FSC_EXECUTION_MASTER_20261116.md` 及 `docs/FSC13_17_SUPPLEMENT_MASTER_20261117.md`。前置 FSC04 契约版本机制、FSC05 证据接口；本批先于 FSC16 包干结算。

## 目标和修改范围

补齐已存在费率卡的独立确认、生效、停用、续期、替代和历史查询，让生成/复核/导出真正使用当时适用且有效的版本。复用 `RepairRateService`、`TaxCostService`（当前在 `nexus_backend/app/tax/costs.py`）、FSC04 配置/契约机制、`src/TaxCostBatchPanel.tsx`、已有源指纹及批次核验。不建另一套规则管理平台，不为本批整体改写行业配置。

现有登记、解析、重叠 409、车型/数量/费率金额校验继续保留。费率适用对象、单位、含税口径、币种和有效期由确认的合同/政策决定，缺少时明确拒绝。

## 实施

1. 明确逻辑费率卡与不可变版本、适用企业/合同/车型/业务范围、日期或期间精度、价格单位、依据原件及确认人。跨月物理账套下复用同一经批准费率的稳定身份，不复制出互不相关的版本。
2. 沿 FSC04 机制实现创建草稿→独立确认→到期生效/续期/替代/停用，保留变更理由、责任和事件。确认/激活事务中再检查资格、版本和区间冲突；不能由写权限直接获得批准权。
3. 同一真实适用键的有效区间不能产生两个未明确优先级的可选价格；不使用数组第一项、最近创建或低价优先猜选。不同合同确实可有不同费率时按契约明确区分，不能用“所有同车型”全局唯一误拒合法业务。
4. 来源和成本批次绑定 rate_id/version、适用区间、合同/车型/计量单位、数量、舍入政策及证据摘要。生成、复核、记账与导出入口重新校验适用性，不能只在来源录入时查一次。
5. 变更前给出受影响的未完成来源/草稿/批次清单及下一步。停用、撤销依据、纠正历史费率、仅未来续期要分开：撤销依据或覆盖期变化可能让相关旧批次失效；未来续期/自然到期不能自动毁掉过去有效的历史依据。停用费率不等于合同义务消失。已记账版本只走追加更正。
6. 当前仅支持按月时，不默默把月中变更按整月计算。客户确需按日时，采用已批准且版本化的分摊方法再增量实现；未获政策先阻断该场景，离线用明确合成规则验边界，不自造行业算法。
7. 页面复用费率卡折叠区：当前适用版本、有效期、依据、历史、停用/续期入口、影响预览及确定结果。待处理批次可直达重新核定；版本冲突刷新后由用户重新确认，不自动提交。

## 先红后绿矩阵

- 未确认费率进入业务；企业 A 费率用于 B；同车型不同合同被误选；币种/计量单位/含税口径不明仍计算。
- 旧批次只存 rate_card_id，修改价格后旧复核继续通过；旧客户端预览在批准新版本后直接提交。
- 两会话同时批准重叠区间或续期，API 预查都通过后数据库留两条 active；需事务内正确性约束。
- 续期首尾边界、跨年、无费率/多费率、明确停用；自然到期错误地禁止对有效历史业务进行合法复核或审计查看。
- 未授权撤销/续期、本人确认自己拟定的策略、锁期后更改历史价格、直接 SQL 绕过状态/范围/版本保护。
- 数量精度、尾差、负数/bool/非法数值；API 与 UI 的金额一致，不扩大允差来过测试。
- 影响预览遗漏某批次或误作废无关期间；旧迟到响应覆盖新卡；恢复后按最高版本而不是有效期选价。

## 验收

用两企业、同车型不同适用范围、连续两期和跨年的合成规则，完成登记→独立确认→生成→复核/导出→未来续期，以及撤销依据后旧批次被正确阻断并重新核定的真实链。

PG16/17 验证受限角色、区间竞争、状态跃迁、版本围栏与有数据升级；桌面/手机完成续期/停用/历史查看及返回办理；非空恢复保留所有版本、有效区间、事件、引用批次和原件。输出 `docs/FSC15_ACCEPTANCE.md`，列清支持的时间精度、计量单位和未获批准的客户政策。
