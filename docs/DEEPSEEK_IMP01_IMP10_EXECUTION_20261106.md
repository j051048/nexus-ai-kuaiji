## IMP03：待办列表与业务文案减负

**给执行 AI 的任务**

复用现有任务投影、短清单、分页和直接办理入口，减少统计和常规下一步长句；异常信息更明确，不能因减法丢失责任和恢复路径。

**前置与范围**

- 前置：IMP02 本地通过；保留 IMP05/06 基线。
- 优先范围：`WorkspaceHome.tsx`、`task-presentation.ts`、现有 workspace/task 展示帮助模块、相关样式与测试。负责人页有同类重复可小范围处理，不重构全页状态。
- 不新增独立任务表、状态机、导航或通用巨大文案层。

**实现要求**

1. 待处理/办理进度改为一处紧凑切换与计数，沿用分页语义和返回恢复。
2. 常规行突出摘要、客户或申请人、金额、状态/期限与动作；重复的一般规则放共享帮助。
3. 退回、缺资料、冲突、撤权、unknown 保留当前原因、负责人和可做的下一步。等待别人不能显示“待我处理”。
4. 多阻断按实际负责人和原因展示，不把第一条负责人套给全部事项。
5. 改系统生成标题兜底，不改原始业务摘要。无摘要时仅使用可信类型/日期/金额；税号、票号、前导零和合法 UUID 样式原文不能被清洗。
6. 技术 ID/hash 默认收进可复制详情；报障仍能找到请求编号。来源不明时不要凭字符串模式判断它是系统 ID。
7. 未知、加载中、失败和 0 分开；不为美观补零。
8. 业务词准确：复核不叫正式记账，核验回执不叫客户签收，未知发送不叫失败可重发。

**先写失败测试**

- 03-T1：普通复核行无重复长说明，主动作仍打开同一对象和准确版本。
- 03-T2：退回本人、等待别人、无权办理、未知结果分别呈现正确原因/责任/动作。
- 03-T3：未知计数不是 0；失效/错误响应不能留下旧计数或旧列表。
- 03-T4：标题为空的兜底可读；含 UUID 的用户摘要、票号前导零、长文件名原值仍可取回。
- 03-T5：技术信息展开可读可复制且无业务写入；错误仍可查请求编号。
- 03-T6：筛选、第二页、展开详情、返回、切换 A/B 企业，列表位置与范围正确；迟到 A 响应不能覆盖 B。
- 03-T7：多负责人阻断不合并错人；unknown 不出现自动重发请求。

**验收**

同数据桌面常规清单减少重复文字和高度；异常仍能回答“什么问题、谁处理、去哪里”。手机不追求八至十行，不以固定行高裁剪内容。禁止将 assertions 改为任意 `.first()`、仅 `exists` 或隐藏全部说明来凑通过。

- 10-T2：事务回滚不产生可见通知，重复业务事件只产生原来的通知，不新增第二次发送。
- 10-T3：原生 SQL 跨企业/伪造收件人/变更来源、权限不足、恢复 hold 均拒绝或按现有安全语义不生成事件。
- 10-T4：并发撤权、重复插入、领取/结算竞争保持围栏；unknown 调查记录不能自动发送。
- 10-T5：PG16/17 从已有版本前向升级后，新旧记录可读，当前必要约束仍有效；历史 checksum 完全不变。
- 10-T6：数据库＋原件＋身份/权限联合恢复后业务可读可办；恢复不重建伪造的审核/送达/签收。

这是重构时，先写通过的表征测试固定旧行为，再写能揭示真实缺口的失败测试；不要为了满足先红后绿去故意破坏当前正确逻辑。

**验收**

PG16/17 受限角色、原生 SQL、并发和相关恢复通过；通知产生与结算语义未变、历史记录未改。只认领这个窄域，不写“数据库已完成瘦身”或“SQLite 已与 PG 全面对等”。风险无法在范围内证明可控时保持 DB 防线、报告具体未完成项，不能先删再等补测试。
