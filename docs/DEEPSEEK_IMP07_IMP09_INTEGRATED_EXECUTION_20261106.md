6. 同任务的期望业务事实、来源和版本保持确定；FakeProvider/归档回放输出可要求确定性。未来真实模型的措辞可变化，只判断事实、覆盖、支持/弃答和安全结果，不要求所有自然语言逐字一致。少量候选先过质量门槛再比成本。
7. 增加用户负担的离线指标：办理入口可达率、页面切换/点击次数、待人事项数、重复问题/观察建议数、可操作项比例、无权动作数。先定义哪些事件算一次操作、哪些只是浏览、计数快照与角色范围，再冻结基线。合成旅程点击数不是实际用户耗时，真人节省分钟数保持 pending；不通过减少必要复核/确认步骤取得好分数。
8. 当多个阻断共同存在时，评分检查每项原因与责任人对应；有一条主要行动不意味着删除其他阻断。无收件人资格、未知负责人、缺来源版本均不能被候选自报“已解决”。

## 给 DeepSeek 的提示词二：IMP08 整合版——三类只读取证、结构化接手与观察诊断

### 目标与依赖

依赖 IMP07 整合版契约通过。完成原三类分析的现有接线，并让每一步“为什么可执行、依据哪个版本、何时失效、为何停止”能被回放验证。

重点是改进现有受限取证，不建设通用工具循环。既有交付三步读取已无需模型规划，必须保持这一优势。复用决策不等于复用授权、事实或复核结论。

### 修改范围

优先核对并复用：

- `nexus_backend/app/assistant/delivery_investigation.py`、`investigation.py`、delivery context、ContextPack、分页与 worker；
- 当前 `assistant/analysis.py`、`AnalysisEvidencePanel.tsx` 及已有 router 接线；
- 现有 `fact_validation`、执行记录/事件、只读领域查询、费用与租约边界；
- 任务回放、受限 PG16/17 用例、对应组件和桌面/手机浏览器测试。

同时盘点并复用 `nexus_backend/app/handoff/`、`execution/handoff.py`、`assistant/events.py`、`src/task-presentation.ts` 及现有接手/任务卡组件；名称变化先搜索。允许窄增量投影和组件接线，不替换 provider，不新建导航/首页模块，不重建审计表，不把诊断结果变成审批、签收或正式账务写入。正常审计、任务状态与既有计量写入不应被误判为“违反只读”；只读指业务动作边界。

观察模式默认关闭，只经本地明确测试配置运行：输入现有授权事件/快照，调用同一只读诊断和规则，产出隔离目录中的 would_handoff/would_notify 或不需要处理的诊断记录。不接生产订阅，不新建定时服务，不写外发 outbox，不调用通知发送、指派、签收或复核写接口。需要的普通读取审计继续保留。

### 实现内容

1. 复用现有固定工具和步骤。只在业务确有必要时增加服务端定义的有限分支；模型可提出意图，但不能定义可执行守卫、SQL、权限或任意参数。规则必须使用结构化状态、数量和版本，不用 `contains('READY')` 等文案包含判断。
2. 在既有 trace/event 结构上增量表达步骤：任务与步骤 ID、前序步骤/回执摘要、领域动作及版本、规范化参数摘要、企业/账套/期间、事实及政策版本、守卫结果、停止原因、输出摘要与 coverage；需要恢复时由现有持久记录承载。
3. 指纹用于绑定，不代替真实性和权限检查。客户端或模型自报 `authorized=true`、`reviewed=true`、`args_resolved=true`、自算 hash 均不能授权执行或接纳。
4. 执行前校验授权、范围、取消、预算、租约和前序完成；接纳结果前再次校验授权、版本及围栏。沿用一致性快照/依赖 revision 机制，避免“检查通过后事实变了，旧结果仍发布”的窗口。
5. 原生 SQL 查询必须继续走受限角色/RLS 与已有 domain service；不得因为前面查询过权限，就在后续事务绕过。不能用跨请求权限缓存节省查询。
6. 分页绑定完整查询范围、过滤/排序、来源版本及游标；总额的来源版本与明细对应。跨期分析验证实际两期账套、稳定核算主体、科目映射/版本、币种与金额口径，不能只按科目代码、当前页版本或默认 CNY 假定可比。
7. 覆盖范围区分：总额是否完整、明细是否仅一页、哪一期缺失、哪个步骤没执行。不查询的部分不等于无异常；只完成一页不能显示全量已核对。
8. 守卫唯一且满足可继续固定只读步骤；证据不足、冲突、预算耗尽返回受控部分结论/人工接手。撤权立即停止并撤去不应展示的内容；版本变化要求刷新；租约失效拒绝旧 worker 结果；已发 unknown 走原核查流程，不重发。
9. 同任务重复步骤按现有执行身份去重；同 ID 异参数/异输出拒绝。并行结果不能覆盖他人的新事实，迟到响应不能复活过期页面。不要添加全局或跨企业复用缓存。
10. 只有确实存在并被省掉的原模型边界，才能记录替代凭据；必须绑定前序回执、实际参数、真实工具结果与被省掉的边界，并核对物理请求没有发生。原本零模型调用的路径记“确定性读取”，不能补造 bypass ID 或节省 tokens。
11. 决策和输出保留深拷贝/不可变快照约束；调用者改嵌套对象不能改变已接纳事实。恢复后重新检查当前权限/版本，不仅验证旧快照 hash。
12. UI 复用现有分析面板：默认简短结论、具体卡点、负责人/下一步、原件或凭证入口、未检查范围；执行细节折叠。不能暴露内部推理、提示词或未经事实验证的模型流。入口仍按当前权限判断。

### IMP08-B：任务卡、人工接手与只观察诊断

1. **业务事项与执行尝试分离。** 复用现有 case/handoff/task/source ID，建立最小关联适配。一个来源问题可有多次受控执行，后台一次成功不等于业务问题完成。稳定事项身份绑定企业、账套、期间、问题类型及来源对象；每次决策另绑来源版本与 attempt。不得以自然语言相似度跨企业合并；不能为每次轮询新建事项。
2. **小卡片负责定位，原始证据负责断言。** 默认只显示单位/期间、问题、当前责任人、下一步和必要的未检查范围；完整 trace、技术状态、内部 ID 放详情。卡片预览长度有限但保留指向原始证据的受控引用。金额、方向、币种和差异原因不能被摘要重写；完整上下文仍经原 ContextPack 编译，不加第二个压缩器。
3. **人工接手有结构。** 在既有 handoff schema 上补齐实际缺项：source_ref/version/fingerprint、reason_code、owner/owner_role、问题或待补资料、action_target、状态、期限（有来源才填写）、解决依据。字段名尽量复用现有契约。未知负责人、期限或资格标待分配/未知，不能编人、编截止日。
4. **不是所有阻断都要问用户。** 现有确定性服务可回答的先直接给事实；证据不足才提出一个具体问题或一组同一次操作可解决的资料要求。多个互不相关阻断按负责人分组，不按 code 去重后取第一个负责人。严重问题不能为减少提醒数被隐藏。
5. **统一展示语义。** 区分等待我、等待他人、后台处理中、事实已变化、结果待核实、已完成。由服务端权威状态和当前角色能力投影，不靠中文正则、模型输出或“列表读成功”判可操作。任务已结束、worker 已空闲、消息已发送和客户已签收是不同状态。
6. **计数与列表使用同一范围。** 同企业/期间/角色/过滤器和快照 revision 下，待我处理数量应等于服务端完整授权结果总数；分页时不能用当前页 length 代替总数。加载中/加载失败/未知不能显示 0，隐藏正常细节不能伪装系统健康。原有单位、身份与当前办理企业继续显示，避免兼任身份误导。
7. **办理入口可用。** 当前有权者看到已有办理入口；只读者看到正确处理角色，不见可执行按钮。点开、补件、返回及重新诊断都重查授权和来源版本，保留当前企业/期间。旧消息、返回页面或迟到响应不得复活旧原件。人工指派不授予任何新权限。
8. **观察模式复用真实诊断。** 只允许明确登记的少量业务事件，如资料补齐、核验完成、月结阻断变化，先校验企业/角色范围和事件版本，再调用同一诊断。相关消息只提供上下文，不授予新操作。首轮覆盖交付阻断；费用/票据差异复用同一卡片/接手契约，不额外自动扫描全部客户。
9. **重放与防噪声。** 输入事件有稳定 ID、来源版本和顺序/cursor；同事件重复投递不重复产生观察建议，同 ID 异内容拒绝。记录当前未解决问题与候选接手原因，状态未实质变化时不重复建议通知；事实有重要变化须保留新版本历史。自身观察记录不是新的业务输入，禁止反馈环。
10. **恢复不自动行动。** 原子保存观察批次状态与结果，恢复时重新检查身份、版本、取消和预算；不通过 cursor 跳过尚未可靠保存的输入。来源撤权则停止，结果待核实只显示既有核查入口，不变成“再试一次”。只有已有业务事实能证明解决才更新观察结论，不能依赖“用户说好了”擅自完成业务事项。
11. **相互独立的任务继续。** 一户等待人工不会阻止其他授权事项只读处理。是否继续由现有调度/任务契约决定，不在 UI 或模型中直接唤醒 worker。额外协调不应增加模型调用，固定只读路径继续为 0。
12. 不迁入 DSH 的 Source/Thread/Ticket/Assignment 全套表，不加入跨渠道身份映射、不做新的 prompt 编辑页。若现有契约无法表达必要关系，先给窄变更说明和失败测试，必要前向迁移及恢复清单一并补齐。

### IMP09-A：总资源预算内的交互优先

1. 在改前测量中加入“批量占用时的人已发起的继续办理/只读查询”。先确认现有助手分槽解决了多少问题；调度优先级由服务端可信请求类型决定，不能接受客户端或模型自报 urgent，也不能让任意询问借机唤醒已取消/unknown 任务。
2. 如果确有等待缺口，在既定总执行槽、总连接、供应商限制和预算内为交互保留能力，必要时从后台配额中划出；不照搬额外 +1 槽。所有进程合计资源有明确上限，连接池申请前完成应有的准入/背压，等待不长期持有事务和企业锁。
3. 唤醒/启动先原子预留容量，再执行准备；取消、失败、超时、正常结束均释放。准备慢的一个任务不阻塞整个调度循环；等待人工的业务事项不能长期占运行槽。请求排队/延迟与真正失败/结果未知分开，不把普通排队当失败重试 attempt。
4. 保持跨企业公平并防止后台饥饿。按已有机制使用配额/轮转/有界优先，确有需要才增量加入等待老化。预先声明最大等待/进展与超载判据并记录依据；不能事后调预算让结果变绿。交互优先不代表高权限账号永远抢占所有客户资源。
5. 如果为降低噪声合并待处理动作，只合并可证明幂等的只读刷新/观察建议，并绑定完整 scope/version。不能合并或覆盖物理模型 attempt、外发通知、导出/建包业务执行记录；不可清零累计 attempt。若已有 generation/lease 围栏足够，不再加平行 generation 状态机。
6. 健康状态复用当前 heartbeat/在途统计。旧 worker 或已取消的监控回调不能把新实例标健康；心跳新鲜与业务有进展分别验证。不要因等待人类判系统卡死，也不要因为仍在写心跳就宣称任务推进。只监测和记录，不新增自动重启或自动重发。
7. 调度来源、优先级、排队/获得资源/开始/结束时间、企业及任务身份进入现有本地测量。状态展示只暴露用户需要的信息，内部队列指标放现有诊断详情，不加首页面板。
8. 使用本地慢 OCR/附件/provider 替身和确定性 barrier 验证拥塞。必须覆盖：跨企业交互不中断、同企业序列正确、持续交互下后台仍前进、撤权的排队任务不执行、取消/崩溃后不重发已发送 attempt。
9. 注意力收益与性能收益分开报告：同角色同任务的页面切换/重复问题/必要操作数和等待时间，不能用更少的日志行代替用户收益，也不能把合成任务耗时当真人效率。
