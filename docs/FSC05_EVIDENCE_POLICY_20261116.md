# FSC05：分动作的证据政策与补件闭环

前置FSC03/04；先读总工作令。本批复用cases/oa_snapshots、oa_material_requests、material_requests、business、原件服务、BusinessContextCard、execution/handoff，不另造审批系统。

## 实施顺序

1. 建立版本化“业务类型×办理动作×所需证据”契约：收件、草稿、暂估、收入确认、付款准备、独立复核、月结、导出分别判断。不要写死所有行业四件套齐全才允许记录事实。
2. 证据要求由企业批准政策决定，记录适用条件、有效期、责任人和合法例外。例外不是免检开关：限定对象/期间/金额或政策边界，注明依据、独立审批及后补期限。未核定政策保持阻断。
3. OA快照包含源系统、原对象/审批链/版本、采集方式、文件hash、采集人及核验状态。手工录入不能自称外部真实性已验证；后补或替代产生新版本，旧版本仍可审计。
4. 复核页显示“已验证/缺失/待核验/过期/冲突”，每项直达准确原件。缺件一键生成已有补件任务，分配给有权经办人；经办提交→财务验收→重查受影响事项→返回原队列。
5. 状态由权威服务判断，不能前端只见附件就打勾，也不能由模型决定关键证据充分。原件缺失/损坏、证据被撤销、合同版本变化均影响当前办理资格。

## 先失败测试

- 上传任意PDF就算“审批已通过”；手工审批人字符串伪造可信身份；源审批撤回后旧草稿仍可复核。
- 付款缺验收被允许，或合法的待票/暂估记录被通用规则错误禁止；条件/例外过期仍生效。
- 同一证据跨企业/对象误复用；原件更换但hash与状态未更新；并发补件覆盖历史。
- 任务显示待补却无入口；员工打开错误企业材料；财务验收后旧页面未刷新或重复催补。
- 直接数据库写入绕过企业核定政策/独立审核或修改已冻结证据。

## 验收

至少为出租车费用、广告外包、物业采购、贸易入库、医院汇总分别跑一个合成成功和一个缺件反例，实际规则不擅自确定。PG16/17权限/版本/并发验证；桌面手机完成补件往返；新增证据与补件历史进入有数据恢复。只验证齐备性/一致性时，不在文案中承诺交易真实性或法规合规已认证。
