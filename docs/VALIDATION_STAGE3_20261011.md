## 独立审查中修复

- **提交应答不确定时保留原件**：模拟真实 COMMIT 成功后丢失确认，上传返回 503，数据库已有附件及新版事项；文件仍保留并可下载。明确业务校验失败则清理新文件。不确定结果可能保留孤立文件，当前没有自动 GC。
- **创建重试规范金额**：前端金额 `0.3/0.30` 规范为相同字符串后签名并发送，同内容重试沿用创建幂等键。
- **旧范围晚响应**：列表刷新、错误正文及 403 处理都检查当前范围和请求版本，不能清空或覆盖新事务所资料。
- **失败后的状态恢复**：上传、审批、移交的 409/503/网络异常尝试鉴权读取最新事项，保留错误并更新版本，不自动重复 POST。
- **正确凭证定位**：从业务事项打开另一账套时，等待该账套载入后定位关联草稿；凭证也能反向打开业务与附件。
- **手机账号操作**：收紧侧栏控制布局，保留身份和退出入口；交接仅显示同企业、同期间、开放且可编辑账套。

## 数据库与原件

PostgreSQL 显式迁移 001–009 已在独立测试库执行，运行角色受限并强制 RLS。SQLite 自动升级到 004，旧来源、复核、关闭期间、导出和审计保留。

事件、版本、附件、审批及移交回执通过企业和事务所复合外键绑定。申请人/部门/财务分别可见其范围；会计只接收已移交到授权账套的资料。用户停用、客户暂停、企业成员或审批授权撤销会在下一次事务中生效。管理员管理职责不自动开放员工原件或审批权。

附件采用随机私有存储键，响应不含磁盘路径，下载重验当前授权及文件 SHA-256/大小；PDF/图片以下载附件返回。检查仅覆盖文件类型/大小与可识别性，没有恶意内容扫描、OCR 或票据真实性认证。
