# P0–P2 岗位、范围与复核边界验收

基线：`7983c0fa67cac0840e07882976af270b5e54a2aa`，开始时工作区干净。本轮仅本机虚构资料与隔离数据库；未提交、未推送、未部署、未调用真实模型或通知服务。

## 已实现

### P0：正式复核属于事务所

- 客户财务仍可按既有授权核验业务、移交和准备草稿；不能取得正式会计复核、过账、凭证导出权限。
- 企业管理员与事务所管理员均不能给纯客户身份分配 `reviewer`。事务所兼任人员必须同时具备真实事务所复核身份和账套授权。
- 开通检查、实际权限、角色首页、单笔／批量复核、手工与期末记账以及 PG 原生 SQL 使用一致的正式复核边界。
- 独立复核继续绑定制单责任和版本；单人办理政策继续明确标识为非独立复核。
- 新审核记录由数据库捕获事务所复核身份快照；应用账号不能伪造或更新快照。复核员以后离职或权限改变，不会重写已经冻结的复核事实。
- 历史记录只保留历史。`cutover_current_membership` 仅说明切换时观测到的成员身份，不当作当年复核授权。缺少 `review_time` 依据的旧稿不能被继续过账或导出，不自动补造授权。

### P1：明确的岗位范围、期限和仅签收能力

- 复用原有 firm/book 角色，增加会计助理、主办会计、独立复核、质控只读四个模板。模板不能提升事务所身份。
- 范围为指定企业或显式选择的全事务所；全所包括未来客户及月份。不选择范围会拒绝请求，原有 `viewer` 不自动扩大范围。
- 新模板授权支持带时区的生效／到期时间，按数据库当前时间计算，不依赖定时删除，也不缓存授权结论。
- 重复同一授权返回同一身份，PG 并发请求不留下隐藏副本。撤销后不可原生 SQL 复活；目标人员离职后管理员仍可撤销其遗留授权。
- 授权变更写审计，HTTP 写入口继承管理员二次验证要求。
- 签收授权限定一个企业的月度账套及其当前联系人名下的冻结资料包；每次校验包 ID、版本、manifest、当前联系人和成员资格。仅签收授权不授予账簿读取、制单、复核权限。
- 客户从首页折叠入口查看、下载、签收具体版本；打开和下载均不会自动签收。撤权、错范围及错误响应清空当前文件内容。
- 管理后台账套分工可授权／撤销仅签收；普通复核员也可从月度包的联系人阻断项就地补齐仅签收权限，无需读取企业全部成员目录。

### P2：部门费用最小只读视图

- 部门审批人只查询当前获授权部门、指定月份的正式凭证费用净额。
- 汇总按原有部门辅助 ID 过滤，不返回对方部门金额、分录、交易对方或原件；普通同部门员工不因此获得查询权。
- 包含费用红字／冲销的净额，排除其他部门和未分配费用；页面明确不等于企业全部费用。
- 月份／部门切换使用现有作用域读取保护；金额必须是安全整数“分”，不接受字符串金额、NaN、小数分或错范围响应。
- 桌面与手机均复用现有导航和工作台，不增加主导航。

## 范围说明与发布前检查

- 此版本面向代理记账。企业自记账的正式复核模式未开放。
- 权限按有效授权叠加：撤销临时模板不删除其原有永久账套权限；只读模板也不会降级既有经办权限。到期时间表示授权有效时间，不表示财务数据只覆盖该日期区间。
- 期限本轮落在新岗位范围授权和仅签收授权上；未把所有企业成员、部门审批关系改造成临时关系。
- 仅签收是一项受限能力，不改变既有员工主岗位。账号已有的本人业务提交能力不会被该授权删除。
- 上线前须盘点旧的已审未入账／未导出记录。无法证明事务所复核授权的旧记录保持阻断；应制定受控补核／修订方案，尤其是旧的已审核手工、期末待记账记录，不能直接强行迁移放行。本轮未对生产历史记录执行该方案。
- 数据库新增 PG `181–187`、SQLite `115–119`；未修改基线历史迁移。发布还需按现有受控发布及完整恢复门槛验收，本报告不替代新的联合恢复演练。
