## 04：员工录入减负

复用现有录入向导、草稿保存、XML/OCR 结果与原件证据，不另建识别服务。

1. 保留当前企业、部门默认选择；分类、用途、项目折入“更多信息”。
2. 单附件、单票且证据合法时，只预填未修改的日期、金额、交易对方。人工已经填写或识别等待期间修改的字段保留。

5. 浏览器用真实本地 XML 解析，故意延迟响应并在等待期间改金额，验证人工金额不被覆盖。未调用真实图片 OCR 或模型，不据此宣称图片识别准确率。

## 05：开账与员工入职

### 开账清单接实际办理

- 复用原开账清单，将政策、正式科目、科目映射、期初包、子账/银行配置、岗位分工及首笔业务入口接到已有服务和组件。
- 新增两个受既有权限保护的期初详情 GET；没有新增审批规则或独立核算引擎。
- 期初表单明确拆成保存草稿、校验、提交复核、独立核准、冻结、绑定。本人提交的版本禁用自审；服务端仍是最终授权边界。
- 办理期间禁止返回造成重复写，结束后返回原企业/账套/月度清单并重查。写入结果无法确认时要求先读取记录，不自动重发。
- 期初粘贴入口严格解析科目与四列十进制金额，不能使用浮点凑平；复杂辅助维度/未结明细仍须通过现有完整核验，不能靠简化表单跳过。
- 桌面、手机实际跑完政策与科目登记、期初草稿、校验、提交、另一身份核准、冻结、绑定，再返回看到对应进度完成。第二身份核准通过真实本地 API，其余办理使用实际页面。

### 批量员工入职

- 只读预检最多 50 人，同批一家企业，支持员工/企业财务岗位；复用原开户、本人激活、取消与过期机制。
- 检查邮箱重复、已有待完成邀请、部门要求、当前管理权限及企业归属。预检不开户、不发信、不授予账套权限。
- 确认后逐人调用原开户命令，保存每人的请求编号；失败、结果未知或错绑回执立即停下，不自动重试剩余人员。
- 开户回执核对邮箱、企业、岗位、部门和激活模式后才显示链接。新增浏览器红测复现“同邮箱但错企业回执仍展示链接”，修复后停止后续人员，拒绝展示错绑链接。
- 未配置身份服务时可检查名单，不能生成邀请；现有链接仍由管理员私下交给本人。未接真实邀请邮件服务。
- 激活过期单独显示，过期邀请不能被接受。批量入职不授予账簿读取、会计复核或导出权限。

## 06：提醒回到原事项

1. 新增前向 PG `217_client_task_notifications.sql`、SQLite `133_client_task_notifications.sql`。业务退回、资料请求/退回、月度包生成在原事务内产生固定站内提醒，按来源事件去重。未新增外发任务或自动发送。
2. 提醒只提供必要提示；点击时重新检查当前身份和原对象权限，提醒本身不是授权。离职、撤权、他企原件和伪造引用都不能借提醒打开。
3. 业务提醒打开原事项，资料提醒返回对应请求；交付包绑定包 ID、版本和 manifest hash，不静默换成最新包。
4. 已读、打开、审批和签收互相独立。打开原事项不自动标记已读，不提交业务，不代替客户签收。
5. 保留既有事务外发送、租约围栏、费用/attempt 与 unknown 处理；恢复 hold 下新触发器不生成提醒，未添加恢复后补发逻辑。
6. 在原本机 SMTP 适配器之外增加显式选择的 `smtp_tls` 适配器：证书/主机名校验、认证、HTTPS 应用链接，不回退明文。默认仍是禁用通道。本轮只以替身传输验证连接前失败与发送后未知，不启用真实邮箱。
7. 通知链接包含精确包版本与摘要。SMTP 接受只代表通道接收，不证明送达、查看或客户签收；稳定 Message-ID 仅用于追踪，不宣称 SMTP 恰好一次发送。

部署准备涉及 `DELIVERY_SMTP_HOST/PORT/SENDER/BASE_URL/USERNAME/PASSWORD`，但本轮未修改任何实际凭据或通道配置。未来启用真实通道仍需另行授权、验证实际送达与退信。
