# 会计产品建设路线

## 本轮决策

用户已确认第一阶段为中国大陆企业、人民币、会计审核后导出凭证。先把来源、建议、复核与导出做成一条可测试的流程，正式账本仍在客户现有财务系统。用模块化单体承载领域，不先拆微服务。

本轮 SQLite 只用于本地持久化和行为验证。它不证明线上多租户隔离、并发容量或生产恢复能力；生产 PostgreSQL 将沿用领域不变量和验收用例，而不是原封不动复制 SQLite 存储实现。

## 已确定的领域边界

| 领域 | 责任与约束 |
| --- | --- |
| 事务所与成员 | 身份和职责；事务所成员资格不自动授予所有账套访问 |
| 客户账套 | 客户隔离、期间、科目模板；每次查询/写入重新校验授权 |
| 来源 | 保留流水原始规范化内容、外部 ID 和导入信息；补证单独记录 |
| 凭证建议 | 规则/未来模型输出仅供审核，保留来源及解释；无法分类进入异常队列 |
| 人工复核 | 乐观版本锁、金额平衡、来源金额、有效科目、期间、证据引用检查 |
| 导出 | 冻结审核结果，幂等收据与审计；不把下载视为外部入账成功 |
| Agent 工具 | 允许读取与提出建议；没有自行审核或正式过账权限 |

金额贯穿接口使用十进制字符串，内部为整数分，不使用二进制浮点计算。禁止直接让模型计算余额、税款或报表合计。

## 第二阶段：真实客户资料试点前

2026-10-11 已完成数据库与身份基础：PostgreSQL 受限运行连接/强制 RLS/显式迁移、Supabase 邮箱密码登录代码、客户企业与部门、成员与账套授权管理，原有流程通过回归。默认 SQLite 演示继续可用。验证边界与剩余工作见 [第二阶段记录](VALIDATION_STAGE2_20261011.md)，多行业员工录入设计见 [业务事项规划](BUSINESS_ENTRY_ARCHITECTURE.md)。下面条目仍是完整试点准入清单，并非都已完成。

1. 新建独立 PostgreSQL / 存储 / 队列环境，不能沿用原平台生产资源。加入迁移版本、事务约束、行级隔离及并发测试。
2. 迁入并收紧原 JWT 验签边界，接真实登录；建立事务所、客户、账套、成员授权表，区分录入、复核和管理权限。检索、缓存、审计按同样范围隔离。
3. 定义首个客户群与适用会计制度，由会计专家确认科目表、辅助核算、税额处理、初始资料和审核规范。示例科目不直接转成生产模板。
4. 接入文件上传与对象存储，原件哈希、字段位置、结构化 OCR、逐字段校验；补证请求、重复票号和跨来源关联进入异常队列。
5. 抽取模型 adapter 与结构化输出契约。模型只能选择账套可用科目并给出证据，超时/格式错误/证据不足均留给会计。先上线企业规则和人工审核样例检索，再做版本化分类评测。
6. 导入任务批次、进度和失败重试；多企业待办聚合、批量复核前校验、分页与队列领取，避免多人重复处理。
7. 选一家客户现有财务系统实现适配器，核对凭证号、导出版本、同步回执与差异。已导出更正先设计撤回/替代流程，不能静默改旧记录。

## 第三阶段：对账与规模验证

用户本轮优先要求员工业务录入。2026-10-11 已先完成三个通用模板、私有原件、本人/部门/企业可见范围、显式部门审批、财务核验和会计草稿移交；操作与部署要求见 [第三阶段试点](STAGE3_PILOT.md)。本阶段的下述对账与规模项目继续作为后续里程碑。

- 银行流水、发票和凭证的 1:1 / 1:N / N:1 匹配建议，金额、日期、对方和参考号依据可追溯。
- 企业级规则修正须审核与版本化；事务所共享规则需授权，禁止自动混入其他客户的原文或训练数据。
- 以 10–20 家经过授权的试点企业验证完整月份；统计每企业每月人工分钟数、每百笔复核修改数、缺资料等待时间、重复导入率、返工率与导出核验差异。
- 使用脱敏/合成数据验证 500 家账套的工作台分页、后台任务公平调度和故障恢复。记录测试环境与数据量，不把界面显示 500 家当作容量验证。
- 只有获得真实处理时间和月结质量数据后，才能评估一名会计服务 200–500 家的可行范围。

## 第四阶段：票据与结构化建议（已实现核心流程）

2026-10-11 已按用户确认实现可配置 OpenAI 兼容接口、私有附件图片/PDF 准备、结构化票据字段及原文页码、事项交叉核对、人工异常处理、同账套银行流水人工关联、模型分录建议和采用。模型不审批、不正式过账；金额、科目、期间、版本及证据引用由确定性代码复核。配置与契约见 [供应商配置](AI_PROVIDER_SETUP.md)、[第四阶段接口](STAGE4_API.md)。

初期面向 2–3 家企业。先由会计专家确定客户科目与业务样例，部署管理员配置供应商，企业管理员逐家开启处理；使用已知答案的小批票据逐字段验收，再进入真实月度的人工复核与导出。用量与处理记录已经保存，但真实模型质量、节省的会计时间和客户月结尚未验证。

第五阶段已建立持久任务队列、领取租约、重启恢复与企业轮转调度。模型调用在数据库事务外执行，数据库保存任务、发送阶段和回执；超时或连接中断不自动再次发送，用户读取结果后明确重试。异常工作台按授权范围实时核对，2–3 家 MVP 可用，200–500 家的异常聚合、费用配额和规模压测继续建设。

随后接一种客户财务软件同步适配器，验证外部凭证号、回执和差异；再引入企业审核样例检索与版本化规则。共享规则需要明确授权，不能把不同客户的附件或核对结果混入全局训练。复杂付款拆分、抵扣判定、税务申报及总账仍独立建设。

## 第五阶段：持久批量票据处理（已实现核心流程）

2026-10-12 已实现同企业多事项、多附件批量入队、单份进度与尝试历史、人工重试/取消、有限退避、发送前恢复、发送后结果不确定的人工处理，以及持久企业轮转。生产使用独立受限 worker 登录与进程，API 不能拥有跨企业领取权限；原件仍按每项任务请求人的当前权限读取，重试重新核对资料、企业开关和处理状态。

目前全库最多并发 2 件，同事务所企业同时最多 1 件；后续提升并发前，先验证模型吞吐与错误率、原件准备内存、数据库争用和异常积压。只读批次进度按当前可见票据计算，不暴露同批次其他人员的件数。重复创建与重复重试保留幂等回执；批次重试的旧请求不能包含后来新失败的票据。

2–3 家试点先等待票据识别完成后再提交审批，以保持任务资料版本一致；模型任务中资料版本、权限、期间或供应商配置变化会停止旧任务，需要按当前状态重新处理。先验证少量已知答案票据，再覆盖一个真实月份，记录每百件人工时间、失败原因、恢复次数、费用及导出差异。部署步骤见 [第五阶段接口与运行](STAGE5_API.md)。

第六阶段已实现企业费用配额和运行监控。批次保留/归档、异常聚合查询优化和真实财务软件回执继续建设。现队列采用数据库持久化，SQL 写操作用短事务串行锁协调；没有用该实现宣称达到 200–500 家高吞吐生产容量。

## 第六阶段：企业费用与运行监控（已完成核心流程）

2026-10-12 已接入每次模型调用的费用预留、token 用量与配置费率估算、未知费用保留、跨上海月份的待核定占用，以及预算管理员凭依据核定费用。OCR 同步入口、后台每次尝试和分录建议都经过同一预算检查，原件外发许可仍独立由企业开关和当前业务权限决定。

监控页汇总各获授权企业的模型费用、队列状态、后台心跳和已登记人工异常。站内提醒覆盖额度耗尽、超预留费用、未知费用、连续任务失败、人工异常积压、等待过长和后台不可用；知晓提醒不修改账务、不释放额度。普通员工、部门和仅账套授权的复核者不能读取企业全量费用，管理监控也不开放员工原件。配置和验证见 [第六阶段说明](STAGE6_API.md)。

## 第七阶段建议：真实月度试点与后台草稿闭环

用户希望试验一名会计管理多家公司。现有程序已支持少量企业的后台并行票据处理、确定性核对、规则草稿及人工复核导出；模型分录建议仍由人员触发，尚未跑通真实供应商和真实客户完整月份，不能称为自主承担正式账务的产品。

建议下一轮按以下顺序交付：

1. 由会计专家确认首批 2–3 家企业的科目、辅助核算及导出格式，提供维护界面与模板版本。现演示科目覆盖有限，不能直接承担各种行业的完整业务。
2. 将业务审批与财务移交后的模型分录建议纳入持久队列，自动生成待复核候选；校验通过才能应用为草稿，最终审核仍留给会计。按原件和业务事实版本判断任务失效，避免只有审批状态变化也无谓重复识别。
3. 建立跨企业、期间和风险的会计复核待办：责任人、待补资料、处理期限、原件与建议同屏，支持逐项及经过校验的批量复核。当前站内提醒之外，后续由用户指定接收人和渠道，再接企业微信或邮件主动通知。
4. 选一个客户现用财务软件验证凭证导入、外部凭证号、回执和差异；至少一个完整月份与原有流程并行对照，不把导出文件当作正式入账成功。

每家记录每百张凭证的人工分钟数、草稿一次通过率、补件等待量、重复来源与导入差异、月结结果和模型费用。达到真实月结与隔离验收后再扩大到 10–20 家，依处理时间和异常比例评估会计实际可管理数量；200–500 家仍是生产力目标。

## 正式总账另立里程碑

如后续决定替换客户财务软件，增加原子过账、总账与明细账、期初余额、应收应付、冲销调整、期间锁定、月末结转、余额试算与报表勾稽。过账事务必须同时检查版本、授权、期间、借贷、科目和幂等键；通知和其他外部副作用经 outbox 分离。

在这一里程碑完成前，界面与 API 使用“审核/导出”，不能标注“正式过账成功”。

## 持续验收门槛

| 验收 | 证明方式 |
| --- | --- |
| 重复导入安全 | 相同 ID 同内容不增加行，冲突整批回滚；重试结果可复算 |
| 金额准确 | 小数边界、非法金额、合计与原始来源逐笔核验 |
| 隔离 | 跨事务所、同事务所未授权账套、伪造 ID 和混合批次均拒绝 |
| 审核不可覆盖 | 过期版本被拒，已审核/导出记录不允许原位修改 |
| 期间有效 | 关闭后导入、修改、审核及新导出都拒绝 |
| 导出可靠 | 批次原子、重复请求相同收据、不同内容同键拒绝、CSV 公式防护 |
| 异常可处理 | 未分类可改科目，缺凭据可补证，接口失败不假装成功 |
| 生产准入 | 独立环境、真实身份、PG/RLS验证、备份恢复、真实月结与专家签核 |
