# 会计产品建设路线

## 本轮决策

用户已确认第一阶段为中国大陆企业、人民币、会计审核后导出凭证。先把来源、建议、复核与导出做成一条可测试的流程，正式账本仍在客户现有财务系统。用模块化单体承载领域，不先拆微服务。

SQLite 用于本地持久化和行为验证。PostgreSQL 已有受限角色、FORCE RLS、原生事务约束和独立测试，但本机合成资料验证不能代替真实试点的多租户运营、并发容量和恢复验收。正式账本仍由客户现有财务软件承担。

## 已确定的领域边界

第十四阶段完成会计 Agent 工作空间的五项界面收敛：导航与任务入口、统一后台执行事实、当前凭证依据助手、集中分诊与常用视图、字号及手机布局。该助手暂为只读证据归纳，没有新增外部模型调用或自动审账权限。后续以真实会计的处理耗时、查找与切换次数、例外比例验证体验，见 [工作空间说明](STAGE14_AGENT_WORKSPACE.md)。

第十三阶段新增独立旧账迁移与接管领域，支持标准化文件、逐月复算、独立验收、受控历史规则和未结清偿。历史账与当前草稿分开；正式账本仍在客户原软件。操作入口见 [迁移向导](STAGE13_USER_FLOW.md)，运行边界见 [迁移接口与部署](STAGE13_API.md)，验证依据见 [第十三阶段记录](VALIDATION_STAGE13_20261013.md)。下一步以客户实际 T+ 产品版本和脱敏导出验证一种完整格式，再测量真实企业资料整理、例外处理和复核耗时。

| 领域 | 责任与约束 |
| --- | --- |
| 事务所与成员 | 身份和职责；事务所成员资格不自动授予所有账套访问 |
| 客户账套 | 长期 ID 连接独立月份和科目模板；每次查询/写入重新校验当前期间授权 |
| 来源 | 保留流水原始规范化内容、外部 ID 和导入信息；补证单独记录 |
| 凭证建议 | 规则及模型输出仅供审核，保留来源及解释；无法分类进入异常队列 |
| 人工复核 | 乐观版本锁、金额平衡、来源金额、有效科目、期间、证据引用检查 |
| 导出 | 冻结审核结果，幂等收据与审计；不把下载视为外部入账成功 |
| Agent 工具 | 允许读取与提出建议；没有自行审核或正式过账权限 |

金额贯穿接口使用十进制字符串，内部为整数分，不使用二进制浮点计算。禁止直接让模型计算余额、税款或报表合计。

## 第二阶段：真实客户资料试点前

2026-10-11 已完成数据库与身份基础：PostgreSQL 受限运行连接/强制 RLS/显式迁移、Supabase 邮箱密码登录代码、客户企业与部门、成员与账套授权管理，原有流程通过回归。默认 SQLite 演示继续可用。验证边界与剩余工作见 [第二阶段记录](VALIDATION_STAGE2_20261011.md)，多行业员工录入设计见 [业务事项规划](BUSINESS_ENTRY_ARCHITECTURE.md)。下面条目仍是完整试点准入清单，并非都已完成。

1. 新建独立 PostgreSQL / 存储 / 队列环境，不能沿用原平台生产资源。加入迁移版本、事务约束、行级隔离及并发测试。
2. 迁入并收紧原 JWT 验签边界，接真实登录；建立事务所、客户、账套、成员授权表，区分录入、复核和管理权限。检索、缓存、审计按同样范围隔离。
3. 定义首个客户群与适用会计制度，由会计专家确认科目表、辅助核算、税额处理、初始资料和审核规范。示例科目不直接转成生产模板。
4. 接入文件上传与对象存储，原件哈希、字段位置、结构化 OCR、逐字段校验；补证请求、重复票号和跨来源关联进入异常队列。
5. 抽取模型 adapter 与结构化输出契约。模型只能选择账套可用科目并给出证据，超时/格式错误/证据不足均留给会计。先上线企业规则和人工审核样例检索，再做版本化分类评测。
6. 导入任务批次、进度和失败重试；多企业待办聚合、批量复核前校验、分页与队列领取，避免多人重复处理。
7. 选一家客户现有财务系统实现适配器，核对凭证号、导出版本、同步回执与差异。已导出更正先设计撤回/替代流程，不能静默改旧记录。

## 第三阶段：对账与规模验证

用户本轮优先要求员工业务录入。2026-10-11 已先完成三个通用模板、私有原件、本人/部门/企业可见范围、显式部门审批、财务核验和会计草稿移交；操作与部署要求见 [第三阶段试点](STAGE3_PILOT.md)。本阶段的下述对账与规模项目继续作为后续里程碑。

- 银行流水、发票和凭证的 1:1 / 1:N / N:1 匹配建议，金额、日期、对方和参考号依据可追溯。
- 企业级规则修正须审核与版本化；事务所共享规则需授权，禁止自动混入其他客户的原文或训练数据。
- 以 10–20 家经过授权的试点企业验证完整月份；统计每企业每月人工分钟数、每百笔复核修改数、缺资料等待时间、重复导入率、返工率与导出核验差异。
- 使用脱敏/合成数据验证 500 家账套的工作台分页、后台任务公平调度和故障恢复。记录测试环境与数据量，不把界面显示 500 家当作容量验证。
- 只有获得真实处理时间和月结质量数据后，才能评估一名会计服务 200–500 家的可行范围。

## 第四阶段：票据与结构化建议（已实现核心流程）

2026-10-11 已按用户确认实现可配置 OpenAI 兼容接口、私有附件图片/PDF 准备、结构化票据字段及原文页码、事项交叉核对、人工异常处理、同账套银行流水人工关联、模型分录建议和采用。模型不审批、不正式过账；金额、科目、期间、版本及证据引用由确定性代码复核。配置与契约见 [供应商配置](AI_PROVIDER_SETUP.md)、[第四阶段接口](STAGE4_API.md)。

初期面向 2–3 家企业。先由会计专家确定客户科目与业务样例，部署管理员配置供应商，企业管理员逐家开启处理；使用已知答案的小批票据逐字段验收，再进入真实月度的人工复核与导出。用量与处理记录已经保存，但真实模型质量、节省的会计时间和客户月结尚未验证。

第五阶段已建立持久任务队列、领取租约、重启恢复与企业轮转调度。模型调用在数据库事务外执行，数据库保存任务、发送阶段和回执；超时或连接中断不自动再次发送，用户读取结果后明确重试。异常工作台按授权范围实时核对，2–3 家 MVP 可用，200–500 家的异常聚合、费用配额和规模压测继续建设。

企业审核样例和版本化规则已在第八阶段加入，同期部分付款和合并付款辅助核销已在第十阶段加入。真实客户财务软件版本适配、跨期收付、抵扣判定、税务申报及正式总账仍待后续建设。共享规则需要明确授权，不能把不同客户的附件或核对结果混入全局训练。

## 第五阶段：持久批量票据处理（已实现核心流程）

2026-10-12 已实现同企业多事项、多附件批量入队、单份进度与尝试历史、人工重试/取消、有限退避、发送前恢复、发送后结果不确定的人工处理，以及持久企业轮转。生产使用独立受限 worker 登录与进程，API 不能拥有跨企业领取权限；原件仍按每项任务请求人的当前权限读取，重试重新核对资料、企业开关和处理状态。

目前全库最多并发 2 件，同事务所企业同时最多 1 件；后续提升并发前，先验证模型吞吐与错误率、原件准备内存、数据库争用和异常积压。只读批次进度按当前可见票据计算，不暴露同批次其他人员的件数。重复创建与重复重试保留幂等回执；批次重试的旧请求不能包含后来新失败的票据。

2–3 家试点先等待票据识别完成后再提交审批，以保持任务资料版本一致；模型任务中资料版本、权限、期间或供应商配置变化会停止旧任务，需要按当前状态重新处理。先验证少量已知答案票据，再覆盖一个真实月份，记录每百件人工时间、失败原因、恢复次数、费用及导出差异。部署步骤见 [第五阶段接口与运行](STAGE5_API.md)。

第六阶段已实现企业费用配额和运行监控。批次保留/归档、异常聚合查询优化和真实财务软件回执继续建设。现队列采用数据库持久化，SQL 写操作用短事务串行锁协调；没有用该实现宣称达到 200–500 家高吞吐生产容量。

## 第六阶段：企业费用与运行监控（已完成核心流程）

2026-10-12 已接入每次模型调用的费用预留、token 用量与配置费率估算、未知费用保留、跨上海月份的待核定占用，以及预算管理员凭依据核定费用。OCR 同步入口、后台每次尝试和分录建议都经过同一预算检查，原件外发许可仍独立由企业开关和当前业务权限决定。

监控页汇总各获授权企业的模型费用、队列状态、后台心跳和已登记人工异常。站内提醒覆盖额度耗尽、超预留费用、未知费用、连续任务失败、人工异常积压、等待过长和后台不可用；知晓提醒不修改账务、不释放额度。普通员工、部门和仅账套授权的复核者不能读取企业全量费用，管理监控也不开放员工原件。配置和验证见 [第六阶段说明](STAGE6_API.md)。

## 第七阶段：客户配置与后台草稿闭环（已实现核心流程）

2026-10-12 已增加账套真实科目维护、固定记账模板版本与辅助核算，业务事实版本与审批版本分离；财务移交同事务登记自动分录任务，先完成缺失附件的 OCR，再按当前证据核对。企业模板优先，无匹配时生成模型候选。草稿、事实、科目及模板版本变化会停止旧任务，人工改稿不被覆盖，最终仍由独立会计审核导出。

OCR 在同事务所、企业、原件哈希和识别配置内复用，当前附件权限与字节完整性仍须核验；复用不新增模型调用费用，也不沿用别事项的人工确认。OCR/分录共同企业轮转与并发限制，失败、等待和人工积压纳入站内运行监控。账套、凭证和任务查询按授权分页，凭证完整核对按需读取。跨页业务移交与复核导航不依赖工作台首 20 项。

客户人员辅助事实与账号授权分离，撤销员工权限不删除历史核算依据，也不恢复原件权限。CSV 增加分录辅助字段，并保留既有幂等回执。操作与迁移见 [第七阶段接口](STAGE7_API.md)、[第七阶段数据库](STAGE7_DATABASE.md)。

仍面向 2–3 家企业：客户会计确认实际科目及模板，配置真实供应商，在独立环境跑完整月份并逐笔对照。当前验证使用虚构数据和合成模型响应，没有声称真实客户月结或 200–500 家生产容量已通过。

## 第八阶段：集中复核、补件与版本化企业规则（已实现核心流程）

已建立跨企业、期间、模板与基础风险分页待办，明确预览后人工确认；同账套原子复核，跨账套记录逐账套结果与幂等回执。异常负责人、期限、公开补件请求、独立核验及历史原件可追溯。接受补件更新事实版本，旧预览和模型候选重新校验；明确替代原件不再参与当前金额核对。

真实已审核来源及最终分录沉淀为企业样例，修正仅形成待发布规则，经正反例及当前科目、辅助项的确定性评估后显式发布。后台规则消费绑定同企业、账套、期间及规则版本，人工处理不被覆盖，不自动审核导出。详见 [第八阶段接口](STAGE8_API.md)、[数据库](STAGE8_DATABASE.md)。

## 第九阶段：流水与事项匹配、重复防线、交付回执（已实现核心流程）

按用户确认实现同账套分页候选与固定人工匹配流程，支持多个流水全额对应一个已付款事项，金额、方向、日期、对方、来源指纹及草稿事实版本重新核验。绑定流水不能再次独立审核导出；其未关闭异常和相似交易待核验会传递到业务凭证复核、模型草稿和导出检查。

增加固定来源、账号标识与稳定交易编号，保留旧格式指纹算法。同事务所同企业稳定身份跨账套防重，账号相似流水保留并人工辨别；物理账号别名仍需会计稳定配置，不能宣称绝对防重。通用 CSV 继续可用，导出同事务保留不可变清单。中性人工 JSON/CSV 回执逐行对照冻结分录和辅助项，部分接收、未知结果、差异和重复外部凭证号留给人工；回执不自动重发、不改冻结账务。没有声称已直连或独立认证客户财务软件过账。详见 [第九阶段接口](STAGE9_API.md)、[数据库](STAGE9_DATABASE.md)。

## 第十阶段：事实纠错、持续配置、月结与人工效率（已实现核心流程）

2026-10-12 已加入移交后事实修订及独立复核：未审事实追加替代来源和草稿，保留原审批提交快照、原件、原凭证及映射历史；已审核或导出的记录只形成调整建议。待决修订、有效银行关联、核销分配或未关闭异常须先明确处置，不静默迁移到另一月份。确认重复可保留主银行来源、隔离未审副本，已审核凭证不能借此隐藏。

长期账套 ID 连接独立物理月份，旧 ID 和所有来源/导出外键保留，同企业旧账套不自动合并。新期成员须明确选择且当前仍有效；科目与模板复制，规则只继承公式，经过新期真实审核样例的正反例评估后才能形成待发布版本。企业往来方、项目和银行账户使用稳定 ID，别名经另一名会计审核，原始名称和历史证据不改写。只有旧期间权限时，只能打开替代前固定证据，不能读取新期间事实或后续补件。

月结预检记录不可覆盖的事实指纹和结果，检查资料、有效凭证、异常补件、后台任务、流水匹配、修订/调整建议及逐行交付回执。未移交资料没有可靠发生日期时，以企业账套级阻断提醒财务修正，私有原文和 ID 不进入会计报告。真人确认本期资料与银行流水完整性并复核当前快照后，数据库再次核验事实和权限才锁期。关闭后仍可追加回执和说明，不据此复开。

同期未付款事项可以接受多笔收付，一笔银行流水可以分配多个同交易对方事项，整数分余额和尾差可复算。原应付业务与银行清偿凭证分别复核，禁止重复计入费用；逆分配由另一名复核人确认，已审核银行凭证不能撤销分配。当前员工模板先验证应付；未收款模板和跨期清偿尚未实现。

运行监控改为持久变化队列与有界公平巡检，记录连接、事务和写锁等待；人工计时只确认活跃工作间隔。本机已完成两份新 PostgreSQL 库及一份虚构原件的备份恢复演练，真实部署还须验证恢复点和业务一致性。全库写协调锁和原任务并发限制保持不变，尚未据此增加生产并行度。

T+ 当前提供中性参考文件、版本化科目/辅助项映射和冻结交付意图。客户产品版本及授权尚未确定，真实发送保持关闭；参考记录不直接创建凭证或期初余额，中性文件不宣称是 T+ 原生导入格式。操作及边界见 [第十阶段 API](STAGE10_API.md)、[数据库与权限](STAGE10_DATABASE.md)、[同期辅助核销](STAGE10_SETTLEMENTS.md)、[文件接入底座](STAGE10_FINANCIAL_BRIDGE.md)、[人工效率与监控](STAGE10_OPERATIONS_EFFICIENCY.md)。

## 第十一阶段：同类复核、条件续跑及质量测量（已实现核心流程）

2026-10-13 已增加同类业务复核包、企业显式启用的条件续跑、稳定往来规则治理、独立标准回放及跨 worker 持久阶段耗时。复核包保存完整版本和证据，真人选择当前检查通过的包再确认；未确认的往来身份逐张展示。发送前已知阻断及独立核验的连续补件可在原执行人当前权限下续跑，结果未知和人工改稿不自动覆盖。

稳定企业规则使用经过审核的身份映射，语义候选去重和发布前范围冲突检测保留人工决策；真实规则命中按生成版本和最后已审分录对照。评测标准来自已审业务及原件，由另一名复核人员确认；回放当前规则/模板或指定存量模型版本，只度量明确已测项，不调用供应商或改变账务。各回放模式最新有界运行按企业、月份、业务类型汇总，旧配置的一致比例不作为当前结果，无法归因工时保留未测量。

依赖、排队、领取、模型、核验落库和 OCR 复用记录持久保存，用于定位月末峰值瓶颈。并发与协调锁没有直接扩大；真实月度人工收益、模型字段质量、客户 T+ 交付和容量仍需试点。操作与验证见 [第十一阶段 API](STAGE11_API.md)、[验证记录](VALIDATION_STAGE11_20261013.md)。

## 后续路线：真实月度验收后再扩大规模

1. 对 2–3 家已授权企业跑完整月份，由会计确认客户科目、模板和证据，逐笔对照客户现用财务软件。采用真实供应商验证票据字段、异常率及费用；记录会计每百笔复核分钟数、每家沟通与月结固定耗时、补件等待、修正和导入差异，员工录入时间也计入效率基线。
2. 确认试点使用的 T+ 产品、版本、部署方式和厂商授权，验证其真实导入格式或接口。冻结配置映射和外部操作号，认证发送与查询分离，保存厂商回执及外部凭证号；超时先查原操作，不能因未知或部分成功自动重发。人工上传回执与提供方认证回执保留不同可信来源。
3. 按真实业务扩展跨期未结事项、未收款模板、清偿科目配置及已导出调整完成流程。明确余额承接和期间授权，独立复核外部调整凭证及交付证据，不以备注宣称完成调整。行业模板、税额处理和复杂业务先经会计专家验收，模型不单凭置信度自动过账。
4. 根据实际 PostgreSQL 查询、锁等待、任务排队、供应商限流和原件准备内存指标优化瓶颈。先验证增量监控和分页效果，再按固定顺序拆分预算、账套和任务锁，逐步提高并发并验证企业公平调度、失权和重启恢复。
5. 在独立部署环境演练数据库与私有原件一致恢复，验证缺失/损坏原件、未发任务、发送未知任务、交付回执和月结快照。用脱敏或合成数据做多用户及后台并行的 500 家端到端负载实验，记录机器配置、业务复杂度、交易量、人工异常比例和 P95/P99；现有本地汇总基准不能替代这项验收。
6. 真实月份、隔离、纠错和交付验收后扩大到 10–20 家，以每家每月人工分钟数及异常处理负担估算可管理范围。200–500 家仍是目标，须由低异常率、稳定资料归集和真实会计质量证明支撑，不能只按企业数量或模型通过率承诺容量。

## 正式总账另立里程碑

如后续决定替换客户财务软件，增加原子过账、总账与明细账、期初余额、应收应付、冲销调整、期间锁定、月末结转、余额试算与报表勾稽。过账事务必须同时检查版本、授权、期间、借贷、科目和幂等键；通知和其他外部副作用经 outbox 分离。

在这一里程碑完成前，界面与 API 使用“审核/导出”，不能标注“正式过账成功”。

## 持续验收门槛

| 验收 | 证明方式 |
| --- | --- |
| 重复导入安全 | 相同 ID 同内容不增加行，冲突整批回滚；重试结果可复算 |
| 金额准确 | 小数边界、非法金额、合计与原始来源逐笔核验 |
| 隔离 | 跨事务所、同事务所未授权账套、伪造 ID 和混合批次均拒绝 |
| 审核不可覆盖 | 过期版本被拒，已审核/导出记录不允许原位修改 |
| 期间有效 | 关闭后导入、修改、审核及新导出都拒绝 |
| 月结可靠 | 当前事实快照、完整回执和本人资料确认；事实变化、权限撤销或未完成调整均不能绕过关期 |
| 跨期隔离 | 长期账套不自动授权旧月份；替代前证据可追溯，但旧权限不能打开新事实或后续材料 |
| 核销准确 | 同期部分/合并收付余额及尾差可复算，银行仅清偿应收应付，不重复计入费用/收入 |
| 导出可靠 | 批次原子、重复请求相同收据、不同内容同键拒绝、CSV 公式防护 |
| 异常可处理 | 未分类可改科目，缺凭据可补证，接口失败不假装成功 |
| 生产准入 | 独立环境、真实身份、PG/RLS验证、备份恢复、真实月结与专家签核 |
