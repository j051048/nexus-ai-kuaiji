## 容量结果

| 环境 | 50 并发 HTTP | 混合业务调用 | 200 家开期 | 200 家已复核导出 | 200 家交付包草稿 | 持续读取 |
|---|---|---|---|---|---|---|
| PostgreSQL 16 | 250/250；p95 1101.34 ms | 2,400/2,400 | 32.134 s | 15.799 s | 33.553 s | 1800.853 s；32,592 次读取 |
| PostgreSQL 17 | 250/250；p95 1107.88 ms | 2,400/2,400 | 30.765 s | 15.691 s | 32.335 s | 1800.784 s；34,224 次读取 |

HTTP 为单 API 进程、50 家企业、200 次读取与 50 次写入，250 次均成功。混合负载覆盖分散企业／热点账套两种分布和 5／20／50 并发，六组各 400 次操作，未启用允许丢弃请求的模式；错误和准入拒绝均为 0。

批量开期、导出及交付包均使用两个真实操作系统 worker 进程。开期无重复账套；导出与交付包分别使用两组 200 家虚构企业。交付包使用已独立复核、已锁期的零业务账套，计时不包含夹具准备，不能解释为 200 家真实客户的整月做账耗时。

每版额外逐户只读核对 400 个产出：企业、账套、期间、源凭证版本／报表版本、来源指纹、包 manifest、创建人及幂等键完全对应，无重复产出。逐项结果保存在 `capacity16/company-reconciliation.json` 与 `capacity17/company-reconciliation.json`。
