# 助手第五批：有界交付取证与人工接手

本批接通现有交付诊断的三段**固定只读流程**，不是自主多轮模型工具循环。不增加模型调用、费用结算分支或数据库迁移。

## 现有能力与修改范围

- 复用 `delivery_context.project_delivery` 中的事项证据、`MonthlyPackageService._inspect/_view`、月结预检与当前快照；没有重写账务判断。
- 新增小型领域协调器 `delivery_investigation.py`，只允许按固定顺序执行 `selected_materials → month_close → package_receipt`。模型和用户不能注册、选择或调用任意 SQL/工具。
- 企业员工/财务即使有账套编辑权限，也只执行已选资料核验；服务人员还必须满足原事务所角色与账套能力，才能读取内部月结和交付状态。
- 明确一个账套与月份后才诊断；范围不明确时返回选范围提示，不猜测“本月”。

## 契约与预算

当前投影为 `assistant-delivery-v2`。新增两部分：

1. `investigation`：企业、账套、期间、覆盖范围；有序步骤；每步输出范围及摘要；`read_complete` 表示这次可见范围的读取步骤完成，**不表示会计工作完成**。`model_calls=0` 只描述取证步骤，整轮助手仍可按既有流程调用模型一次。
2. `handoff`：来源与问题摘要、按负责岗位分组的问题索引、必须会计复核的标记；`assigned=false` 表示尚未创建或分派实际任务。每个问题只出现一次，保留原因、下一步和证据引用，不取第一位负责人替代所有人。

服务端默认最多 3 步、10 秒；预算不接受模型或客户端参数。时限包含权限核查，在步骤前后检查。它是**协作式时限**，不能中断已在数据库执行的 SQL，也不是任务硬超时保证。预算不足、步骤未知/重复/乱序、范围变化或权限拒绝时，不接纳该结果、不发送新的模型请求。

快照只存稳定范围与输出摘要，不写入每次读取的时间耗时；否则同一事实重读会被误判失效。顶层摘要之外还验证步骤次序、连续输出范围、输出种类和接手分组完整性。摘要用于版本/完整性检查，不是来源签名；权威来源仍是服务端当前查询和 worker 的整份快照重检。

旧 `assistant-delivery-v1` 保留历史读取/渲染兼容。当前运行一律生成 v2；旧排队快照与当前快照不一致时仍按原机制失效，不能为兼容旧数据跳过比对或重发请求。

## 权限与接纳边界

每段读取前后都执行现有授权检查，范围绑定企业、账套和期间。PostgreSQL 的只读事务使用 `REPEATABLE READ`：在该事务内重复查询不会看到另一会话后来提交的撤权；不能把步骤检查宣称为瞬时撤权屏障。

因此原 worker 的发送前重检、接纳前重新读取、完成事务围栏保持不变。新请求必须重新授权；撤权或事实变化后的旧结果不得发布；已发送且结果未知的 attempt 不得自动重发。PG 动态用例同时验证快照语义、新事务撤权，以及实际 worker 发送前/响应中/最终提交时的版本和权限改变。

回答在现有助手中显示“取证范围”和“人工接手清单”，按岗位归类；仍是有界文字和引用，没有新导航、自动指派、会计复核、过账、导出或签收动作。必需证据不裁掉换取“完成”；内容过长继续明确显示未展示条数。

## 本地复跑

```powershell
.\.venv\Scripts\python.exe scripts/assistant_delivery_postgres_gate.py `
  --pg16 <本地隔离PG16配置> --pg17 <本地隔离PG17配置> `
  --out tmp_test/assistant-bounded-pg-新的目录
```

PG 必验清单 v4 共 43 项，必须两版本同候选、无跳过；受限 API/worker、FORCE RLS、迁移摘要与持久化配置检查保持原门槛。私有配置不写入报告。六类离线任务继续使用原冻结输入与金标，没有重新定义成功分母。

本批不接真实模型、不推送、不操作线上；真实供应商效果、生产时延/容量、SSE、自主工具回灌和实际人工任务分派均不属于本批结论。
