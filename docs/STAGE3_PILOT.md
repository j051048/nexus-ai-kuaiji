# 第三阶段 MVP 试点操作

范围：2–3 家中国大陆企业、人民币；报销、采购/费用、日常收支，员工录入与原始附件、部门审批、企业财务核验、会计复核后导出。阶段验收使用虚构资料和本机数据库，实际企业验证按以下步骤单独进行。

## 准备环境与人员

1. 在独立 Supabase 项目执行最新 PostgreSQL 迁移到 009，沿用受限运行账号，见 [数据库配置](POSTGRES_SETUP.md)。业务表和原件不通过公开 Data API 暴露。
2. 为后端配置 `ACCOUNTING_ATTACHMENT_ROOT`，指向持久私有目录。生产必须显式设置；文件不能放到 Vite public/dist 或直接提供静态目录。多实例应共享同一持久存储，当前 MVP 不提供 Supabase Storage 自动适配。
3. 每位参与人使用独立 Supabase 用户并完成邮箱确认。登录一次建立身份后，事务所负责人创建客户企业和账套，再授予各自所需角色。真实模式没有演示身份切换。
4. 在“成员与账套授权 → 部门与审批人”或业务页“部门审批配置”建立部门，将员工关联到本企业部门，并授予负责人明确的部门审批权。企业 `finance` 身份用于跨部门核验，另授予该企业目标账套 `editor` 才能移交。会计复核员取得目标账套 `reviewer`。

普通企业员工只能看本人事项；部门审批人只能看授权部门；企业财务能看所属企业事项。企业和事务所管理员可配置人员，但不因此看到未移交的员工原件，也不自动成为业务审批人。会计只收到已移交到获授权账套的资料。

## 三个模板

| 模板 | 用途 | 首轮边界 |
| --- | --- | --- |
| 员工报销 | 员工垫付费用，申请企业报销 | 记录为企业待付款；生成应付款候选，不能标成企业银行已支付 |
| 采购 / 费用 | 一般费用支出与待付款申请 | 可已付款/待付款；存货、资产和税额由会计判断，不自动判定 |
| 日常收支 | 已经实际收款或付款的事项 | 固定已收付，保存方向和对方；收入确认仍由会计复核 |

填写发生日期、摘要、交易对方、人民币金额、费用类别、用途及可选项目。普通员工部门由其成员关系固定，企业管理/财务身份可选择本企业有效部门。创建后的企业、部门、申请人、模板固定，填错这些范围应创建正确事项；尚未提供撤回/作废入口，不要把错误草稿移交。

同一次创建请求在网络重试时复用幂等键；相同键相同初次内容返回原事项，相同键不同内容冲突。金额贯穿接口为字符串和整数分。

## 业务到凭证

1. **员工保存草稿并上传原件**。支持 PDF、PNG、JPEG、WebP，每个最多 10 MiB、每事项最多 10 个、总计最多 50 MiB。至少一个已登记附件且存在非申请人的有效部门审批人和企业财务，才允许提交。
2. **提交审批**。冻结当次业务字段、模板版本及附件 SHA-256 清单。原件与元数据只追加，提交后不能原位更改；哈希用于追溯完整性，不表示已核验票据真实性。
3. **部门确认、财务核验**。按阶段处理，申请人始终不能批准本人事项。职责可兼任，但阶段各有独立记录；当前没有“部门和财务必须是两名不同审批人”的可配置策略。需要补资料时填写原因退回，申请人修订/补件后重提，保留原版本及审批记录。
4. **财务移交**。选择同企业、发生日期所属期间、开放且有编辑权的账套。一次事务生成来源、候选分录、待审核草稿、移交回执和审计。重试不重复生成来源或凭证。
5. **会计复核与导出**。从事项打开指定凭证，也可从凭证反向查看事项与附件。会计检查单据、科目、金额和业务实质后确认审核，继续沿用 CSV 导出及历史重新下载。`other` 类别保留未分类异常，须由会计补齐分录。

业务审批不是付款、税务申报或正式入账。当前没有付款执行、OCR 自动识别或大模型自动核票。科目仍为验证模板，真实企业先由会计确认适用性。

## 附件保存、恢复与部署

原件采用服务端随机存储键，接口不公开磁盘路径。上传检查大小、扩展名、文件类型/图片解码；PDF 仅检查可识别的文件头尾，不提供恶意内容扫描或票据真实性认证。下载携带登录身份并重验当前事项权限、文件大小与哈希，以附件形式返回。

明确业务校验失败会清理新上传文件。数据库提交应答丢失或其他结果不确定的故障会保留文件，避免删除已登记原件；可能留下未引用文件，当前不自动清理。任何后续清理都应在数据库可可靠查询、备份完成后确认无引用再处理。不要单独恢复数据库而遗漏原件目录；试点应验证整套备份和恢复。

## 本地演示与试点记录

本地模式提供四个虚构身份：企业员工、部门审批人、企业财务、会计复核。三个虚构公司已关联部门和审批人，方便跑通不同身份的闭环。身份切换只在本地演示可用；真实模式使用每个人自己的账号。

真实企业建议先录入少量经授权样本，核对三类模板、跨范围拒绝、退回重提和重复请求，再核对完整月份。记录每事项人工分钟、补资料次数、首次完整率、会计修改率、导出差异、恢复结果。验证部署、原件和业务规则后，再扩大范围；此次代码及合成测试不能替代真实客户验收。
