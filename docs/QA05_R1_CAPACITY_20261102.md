# QA05-R1：有界准入与容量收口

范围：本地受限 PostgreSQL 16/17、虚构数据、FakeProvider。未调用真实模型或通知，未推送、部署、修改线上配置；未改历史迁移。基线 HEAD 为 `2247af5184ee872f04c0acf15bf29d81c33a9246`，上一轮及其他任务的未提交修改保留。

## 原因与修改

上一轮 50 线程突发在默认 4 条连接、32 个等待名额下，超出名额的调用会立即失败；线程随后取下一项，形成大量快速拒绝。不是必须增加数据库连接数。

- 最大连接仍为 4；默认等待名额改为 64，覆盖 50 个并发借用者与少量后台统计流量。等待名额可显式设置，范围仍为 1–256，禁止无限队列。
- 复用 psycopg_pool 已有 FIFO 与单次获取连接的等待预算；默认仍为 5 秒，配置范围仍为 0.1–30 秒。不新增队列、业务重试或授权缓存。
- 区分 `queue_full` 与 `wait_timeout`，报告保留排队等待统计；对外不暴露跨企业请求量、SQL 或连接凭据。
- 修复繁忙响应：读取可稍后重新读取；写请求可能已有前一事务提交，返回 `result_unknown` 且不带 `Retry-After`，避免据此重放业务或模型 attempt。
- 容量门禁默认要求全部请求完成，有任何拒绝即失败；`--allow-shed` 只用于显式过载摸底，不代表成功容量验收。
- CI 接入准入、撤权、FIFO、停机、费用、跨进程 attempt 与企业公平调度回归，保留禁止 skip 的插件。

## 部署含义

此次没有修改线上环境变量。显式设置为 32 的旧 `ACCOUNTING_DB_POOL_MAX_WAITING` 仍会覆盖新默认值，后续发布时须单独核对。所有进程和副本的连接上限需要相加；本轮没有增加其预算。五秒是每次借用连接的等待预算，不是 SQL 执行或整个 HTTP 请求期限；不得将预算层层重置后自动重试。

本轮只证明指定本地混合读写、热点和 200 家批量开期的容量及业务守恒，不能外推成生产 SLA、长稳结果或全部月结业务的耗时。使用现有企业锁、RLS、复核凭据和幂等机制；未复核导出仍拒绝，复核后重复导出仍返回同一回执。

## 最终候选容量结果

候选源摘要为 `3fc6fc89f51565a59e268f8c705be43412b6aec8e494fa94b084accb5aa71d00`。两版各运行 2,400 次请求：5/20/50 并发 × 多企业/热点账套，每场景 400 次、75% 读、25% 导入；没有自动重试，所有场景零业务失败、零准入拒绝。50 并发结果如下：

| 项目 | PG16 | PG17 |
|---|---:|---:|
| 多企业读 / 写 p95 | 410 / 760 ms | 394 / 726 ms |
| 热点账套读 / 写 p95 | 1,544 / 2,722 ms | 918 / 1,612 ms |
| 多企业 / 热点准入拒绝 | 0 / 0 | 0 / 0 |
| 主池最大连接 / 等待名额 / 等待预算 | 4 / 64 / 5 s | 4 / 64 / 5 s |
| 200 家企业双进程开期 | 30.364 s | 29.545 s |
| 两 worker 实际办理数 | 100 + 100 | 100 + 100 |
| 新账套 / 重复账套 | 200 / 0 | 200 / 0 |
| 应用进程 CPU / 峰值 RSS | 16.688 s / 80,101,376 B | 16.188 s / 80,048,128 B |

这些是本地服务调用耗时，不包含互联网或浏览器。热点数据随运行增长，PG16/17 顺序执行，不能据此断言数据库版本的相对性能。PG 活动采样是整库多个受限进程与监测连接的合计，不应误读为单个连接池大小。

相较旧报告的 50 线程每场景 364–365 次拒绝，此次每场景 400 次全部完成；这不是以扩大数据库连接数或放宽复核/授权换来的。当前运行配置与历史报告均保留，新证据不会覆盖旧失败结果。
