# 总账优先：Gemini 审计合并与代码改良批次 V2

日期：2026-10-18　上游：[6 客户 6 个月双轨计划](LEDGER_FIRST_6_CLIENT_EXECUTION_PLAN.md)、[代码计划 V1](LEDGER_CODE_PLAN.md)
性质：审核 + 规划，不含代码改动。估算单位：人日（pd）。

---

## 0. 结论

**Gemini 的方向判断基本正确，时间表和三个技术选择必须修正。**

- **采纳**：缺内生总账是核心断层；标准科目树、正式凭证字号与过账、现金/银行日记账、总账/明细账、余额表、三大报表、期末结转、税务底稿、本地模型兼容、私有部署、角色化 UI、L0–L3 分级。
- **修正**：总账不是 1–2 周，而是 8 周核心 + 4 周报表税务 + 4 周迁移双轨；`drafts` 不宜原位改成凭证表；已过账凭证不得断号重排；本地模型不能放开整个 RFC1918；零停机、电子签章、5 分钟/户、80–120 户是目标，不是 6 个月承诺。
- **保留**：26 周、6 家客户、全程双轨、停外部软件前必须连续 2 个账期零未解释差异。

## 2. 裁决表：采纳、修正、拒绝

| Gemini 结论 | 裁决 | 我的修正 |
|---|---|---|
| 内生总账是 P0，优先于 UI | **采纳** | 总账核心 B1 用 8 周，不是 1–2 周 |
| 内置小企业/企业会计准则科目树 | **采纳** | 做“版本化科目模板”，不硬编码；支持小规模/一般纳税人变体 |
| `posted` 状态 + 凭证字号 + 红冲 | **采纳** | 新增 `journal_entries`，不把 `drafts` 原位改成凭证表 |
| 关账前断号重排 | **拒绝** | 已过账凭证不得重排；只允许作废/断号说明，重排仅限未过账 |
| 现金/银行日记账、三栏总账/明细账、余额表、三表 | **采纳** | 现金流量表先做“简化间接法 + 人工分类”，标注管理参考 |
| 期末自动结转（工资/折旧/税费/损益） | **采纳** | 工资不做全模块，先做计提底稿；每步生成草稿，人工确认后过账 |
| 税务计提与税负测算 | **采纳** | 做“税务底稿 + 计提凭证草稿”，不自动申报 |
| 本地模型放开 RFC1918 | **拒绝** | 用显式 `ALLOWED_HOSTS` + SSRF 防护；禁止元数据/链路本地地址 |
| `<think>`/代码块清洗、`json_object` 回退、重试 | **采纳** | 增加“先 json_schema → 失败转 json_object → 最后纯文本抽取”三级回退 |
| 云端模型调用前脱敏 | **采纳** | 做数据分级与策略，不只正则；本地模型不脱敏；脱敏前后可审计 |
| 本地/云端双模 docker-compose | **采纳** | 明确 GPU/模型权重/PaddleOCR 资源；不做“零依赖”承诺 |
| 31 路由压到 12 | **部分采纳** | 方向对，但不以 12 为 KPI；用 4–6 主入口 + 专家模式 |
| 合并 7 个监控页 | **采纳** | 合并为 FirmCockpit 的“运营/队列/质量/成本”页签 |
| 简化学习规则晋升 | **采纳** | 合并进 Catalog 第二页签；三次修正后轻提示保存规则 |
| 六步流水线 | **部分采纳** | 建议 **5 步 + 1 个“账簿与报表”横切视图**；不把查询做成流程步骤 |
| 传统凭证排版、键盘流、批量操作 | **采纳** | 批量审批必须有抽样与降级机制，不做“全部自动通过” |
| L0–L3 分级授权 | **采纳** | 补“抽样审计 + 错误率降级”：L2 连续出错自动降为 L1 |
| 总账 1–2 周、私有化第 3 周、UI 第 4 周 | **拒绝** | 26 周、6 客户、双轨；私有 AI/部署作为并行批次 B4 |
| 零停机升级 | **修正** | 改为“最小停机 + 迁移兼容 + 可回滚”，并做演练 |
| 电子签章 PDF | **修正** | 先做 PDF/Excel 导出；电子签章需 CA/证书集成，单列需求 |
| 5 分钟/户、80–120 户/人 | **修正** | 作为 12 个月目标；6 个月先测量基线，不写进验收承诺 |

## 5. 关键技术决策

### 5.1 为什么新增 `journal_entries`，而不是把 `drafts` 原位改成凭证表

Gemini 建议在 `drafts` 上增加 `voucher_no/posted_at/entry_kind`，理由是保留现有外键。这个理由成立，但方案不够。

反对原位扩展的四个硬理由：

1. **`drafts.source_id` 是 `NOT NULL UNIQUE`**（`001_accounting.sql:68`）。手工计提、折旧、损益结转、红字冲销没有银行/业务 source，原位扩展要么造合成 source，要么改约束，都会污染现有查询。
2. **一张业务可能需要多张凭证**（如计提+支付、结转+调整）。`drafts` 与 source 1:1，无法承载 1:N。
3. **`posted` 状态会打乱现有查询**。`exports`、`closing_issues`、`delivery`、`revisions` 等大量 SQL 按 `status IN ('approved','exported')` 过滤；新增 `posted` 后，所有过滤都要重审。
4. **报表快照需要稳定凭证**。`drafts` 是可变复核对象；`journal_entries` 是不可变账本记录，职责分离更清晰。

**推荐结构**：

```
drafts（复核对象，保留原外键）
  └─ journal_entries（1:1 或 1:N，draft_id 可空）
       └─ journal_lines（科目属性快照）
```

- 从草稿过账：`draft_id` 写入，`drafts.journal_entry_id` 回填。
- 手工凭证：直接建 `journal_entries`，`draft_id` 为空，来源标记 `manual/accrual/closing/reversal`。
- 红冲：新 entry，`reversal_of` 指向原 entry。
- 历史回填：已审核/已导出草稿生成 `migration` 标记的 entry，供报表使用。
- 现有外键全部不动；现有页面继续用 drafts，新页面用 journal entries。

### 5.2 凭证字号与断号

- 建议：`voucher_type`（记/收/付/转）+ `voucher_no` 整数 + 展示 `记-0001`；期间单独存 `period`。
- 唯一约束：`(book_id, voucher_type, voucher_no)`。
- **已过账凭证不得重排**。断号只能通过“作废凭证 + 断号说明”处理；重排仅允许未过账草稿。
- 关账前输出《断号/作废清单》，由首席会计师签字。

### 5.3 科目模板

- 表：`account_templates(standard_kind, version, code, name, parent_code, level, is_leaf, category, normal_balance, aux_requirements, cash_flow_default, effective_from)`。
- 两套：`small_enterprise`（小企业会计准则）、`enterprise`（企业会计准则）。
- 变体：小规模/一般纳税人（增值税明细科目不同）。
- 建账时复制到 `accounts`，记录模板版本；客户可增改，但 `is_leaf` 必须校验。
- 科目改名不回溯历史：`journal_lines` 存 `account_name/category/normal_balance` 快照。

### 5.4 余额表

`account_period_balances(book_id, period, account_code, aux_hash, aux_json, opening_debit, opening_credit, period_debit, period_credit, ytd_debit, ytd_credit, closing_debit, closing_credit, updated_at)`。

- `aux_hash` = 规范化 JSON 的 SHA-256（键排序、空值统一）。
- 过账/红冲增量更新；提供“全量重建”命令；夜间巡检对比 `journal_lines` 汇总。
- 试算平衡与报表优先读余额表，异常时回退实时汇总。

### 5.5 结账与损益结转

顺序：

```
预检（未审/未过账/银行未达/税务差异/折旧未计提）
→ 生成结转草稿（损益类 → 4103 本年利润）
→ 人工确认 → 过账
→ 校验损益类期末余额为 0
→ 锁期 → 报表快照 → 期末余额滚存下期
```

- 年末：4103 → 4104 利润分配—未分配利润；盈余公积可选。
- 反结账：owner/admin + 原因 + 审计；先红冲结转凭证，再解锁。
- 结账后禁止写入；任何调整走下期或反结账。

### 5.6 报表

- 资产负债表：资产 = 负债 + 所有者权益；备抵科目（累计折旧、坏账准备）按净额列示。
- 利润表：本月/本年累计；净利润与未分配利润变动勾稽。
- 现金流量表：先做“简化间接法 + 人工分类”，不承诺全自动；标注“管理参考”。
- 每张报表保存 `mapping_version` + `source_hash`；口径变更生成新版本，不重算历史。
- 下钻：报表行 → 科目余额 → 明细账 → 凭证 → 原件证据。

### 5.7 本地模型：不能放开整个 RFC1918

Gemini 建议 `10/8、172.16/12、192.168/16` 全放开。这会引入 SSRF：攻击者可通过配置地址访问内网元数据、数据库、管理端口。

推荐：

- `ACCOUNTING_AI_ALLOWED_HOSTS=ollama:11434,vllm.internal:8000,192.168.1.50:11434`，显式 host:port 白名单。
- 仅当 `ACCOUNTING_AI_ALLOW_HTTP=1` 时允许 http；否则必须 https。
- 禁止：重定向、userinfo、query、fragment、链路本地 `169.254.0.0/16`、云元数据 `169.254.169.254`、`100.100.100.200`。
- DNS 解析后再次校验 IP；防 DNS 重绑定。
- 代理环境变量清空；不允许 `trust_env`。
- 每次调用记录目标 host（不含密钥），异常告警。
- 本地无鉴权模型允许占位密钥，但不得写日志。

### 5.8 本地模型解析

三级回退：

1. `response_format=json_schema`（strict）；
2. 失败转 `json_object` + 提示词内嵌 Schema；
3. 失败转纯文本，剥离 `<think>...</think>`、Markdown 围栏、前后缀，抽取第一个平衡 JSON。

清洗器要处理：

- ` thinking...<｜end▁of▁thinking｜>`、`<thinking>...</thinking>`、`<reasoning>...</reasoning>`；
- ```json ... ```、``` ... ```；
- JSON 前后的解释文字；
- 多个 JSON 对象（取最后一个符合 Schema 的）；
- BOM、全角引号、尾逗号（谨慎修复，记录修复标记）。

**不放松 Pydantic 校验**；修复失败一律转人工。

### 5.9 脱敏与路由

- 数据分级：公开/内部/敏感/高敏。
- 云端调用前：银行账号保留后 4 位、身份证保留前 3 后 4、手机保留前 3 后 4、邮箱掩码；交易对方名称按策略（可保留简称）。
- 本地模型：不脱敏，但审计外发目标。
- 路由：本地优先 → 校验失败/置信度不足 → 云端兜底（需企业 `allow_external_ai` + 数据级别允许）。
- 记录：模型、版本、目标、脱敏规则版本、用量、费用、是否回退。

### 5.10 5+1 导航，而不是六步流水线

Gemini 的六步把“账簿查询”做成流程步骤。账簿查询是横切能力，会计在任何阶段都会用；做成线性步骤会增加一次点击和一次心智负担。

建议：

```
5 步：① 资料与流水 → ② 匹配与核销 → ③ 凭证与复核 → ④ 对账与月结 → ⑤ 交付与导出
+1  ：账簿与报表（常驻右侧/顶部切换：总账、明细账、日记账、余额表、三表）
```

如果报表是独立交付物，可在第⑤步内做“报表”页签，不新增流程步骤。

### 5.11 批量审批的边界

- 只对 L2（高置信度、命中历史规则、金额/税号匹配）开放批量。
- 批量前随机抽样 10%（至少 3 张）人工复核；抽样不通过则整批退回。
- 连续 2 个月批量错误率 > 1%，自动降级为逐笔。
- 红冲、跨期、无票大额、新交易对方、税务调整，永远 L1 单笔。

### 5.12 L0–L3 落地

| 级别 | 能做什么 | 不能做什么 |
|---|---|---|
| L3 确定性自动 | 解析、查重、平衡校验、余额/报表汇总、日记账序时 | 过账、结账、改科目、改权限 |
| L2 批量确认 | 高置信度草稿、折旧/税金/损益结转草稿 | 自动过账、自动关账 |
| L1 单笔精审 | 新交易对方、大额、尾差、红冲、跨期、客户简报发布 | 批量通过 |
| L0 人工 | 关账/反结账、科目结构、权限、导出申报、付款 | 模型不可调用 |
