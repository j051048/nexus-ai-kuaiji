## 企业并发与费用

真实 PostgreSQL 多连接验证了不同企业持锁重叠、同企业互斥、旧排他与新共享门互斥、原生跨范围写入拒绝、语句级先取锁及未改造领域禁止锁升级。两企业完整 OCR 结果持久化能并行，审批、分录采用、导出、关期等继续采用排他事务。

OCR、分录和对话共享持久任务额度与企业轮转；供应商请求同时受进程 hostname 门、数据库全局／供应商／企业租约约束。测试覆盖忙碌前未发送不扣费用、发送后未知结果保留预留与人工处理、撤权、旧租约、重启恢复、配置边界及限额降低。默认总任务额度仍为 2。

合成 HTTP 压测只访问本机服务：12 个固定 150 ms 请求，在并发 1／2／4 下耗时约 2.088／0.972／0.511 秒，供应商峰值符合相应限制。它证明固定延迟请求可重叠处理，不代表真实模型正确率、供应商生产限流或客户会计吞吐。

## 客户月度进度与权限

- 授权先于搜索、总数及分页；24 个账套分为 20＋4，同企业多个账套保持独立。撤权后账套行、总数及详情访问立即消失。
- 单页从 1 个增加到 20 个账套时，事实读取的 SQL 数量保持有界，不逐账套加载完整证据。余额列表和参考核对不读取上传原文，只有授权下载获取原始内容。
- 本人私有录入不做企业完成度汇总；企业财务／会计双身份使用所选企业财务入口，非财务会计统计会计接收待办，其他企业的财务权限不能影响当前企业。本人及部门事项继续在各自入口处理。
- 最新未知回执不计完整核验；未知状态、无权限和未采集耗时不显示为完成或零。开放期间的历史通过预检只作参考，必须进入月结重新检查。
- 浏览器验证真实授权分页、多账套精确下钻、刷新、手机返回、未保存保护和撤权清空。

## 月度参考余额与固定事项

- 期初使用上一月期末，当前月份使用期末资料；整数分运算，明确的零与未知分开。科目汇总包含该科目辅助运动，辅助明细按稳定 ID 独立计算，汇总和明细不相加。
- 已核验交付、已审待交付、已导出待回执和未审草稿分别展示；新增未知回执撤回之前的核验运动，不能继续沿用旧回执。
- UTF-8 JSON／CSV 原文保存和授权下载保持字节一致。重复金额字段、重复辅助 JSON 字段及重复 CSV 列拒绝导入。旧账独立验收接管及 T+ 已确认文件余额保留原映射，仍需独立确认本次用途。
- PostgreSQL 原生写入拒绝错金额报告、必填统计缺失、伪造余额维度、非独立确认、错误科目、越权、已关期及历史改写。SQLite 同样以完整事实、分录、辅助项和最新回执验证检查新鲜度。
- 月度检查和人工核对追加保存，补充事实使旧检查及关期快照失效；人工填写原因保留原差异，不能改为自动平衡。
- 固定计划使用真实科目、明确事实金额和独立审批。同计划同月只生成一次普通未审草稿，未知响应后重读仍为同一结果。未审批的新结束月份不能隐藏旧版已审批的当月义务；实际科目或辅助要求变化会阻断生成。
