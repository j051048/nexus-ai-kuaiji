## 实际问题与修复

真实 PostgreSQL 检查发现并修复带参数 SQL 中字面量 `%` 的占位符冲突，以及 Mapping 行对象被按键迭代、导致布尔检查误阻断的问题。保留金额、异常及权限规则，分别用实际运行账号和 worker 复测。

上传原件后，数据库 COMMIT 成功但确认丢失时，保留可能已入库的原件并返回可恢复错误；同请求编号重试复用原文件。损坏原件、无效解析及已变更输入不会发布接管。解析每 250 条提交后的进程中断可从原检查点续跑；校验报告已提交、完成回执未提交时，重新领取同任务并复验当前依据后复用原不可变报告。测试注入真实提交后的故障，没有伪造业务 HTTP 响应或跳过原生检查。

科目映射检查来源和目标的类别、正常余额方向及辅助维度。新目标定义提前验证，防止验收后才因配置不兼容失败；非记账父科目仅归档。企业或组织字段及明确外部账套信息无法核验时阻断，不通过省略表格映射静默归入某企业。

完整浏览器首轮 42 通过、2 失败：旧用例仅按企业从全部账套选择移交目标，误选新迁移历史月份，系统正确拒绝跨月份业务移交。测试改用与业务界面相同的企业账套查询，并按业务月份、开放状态与编辑权限精确选择；服务的期间与权限约束没有放宽。最终完整 44 项通过。

已人工检查 390 像素手机截图。历史凭证默认展示中文事实、日期、状态、科目、借贷金额和辅助项；原始字段、SHA 与定位信息保留在默认折叠区，返回操作可见，无横向溢出。截图：`artifacts/stage13-migration-mobile.png`、`artifacts/stage13-migration-archive-mobile.png`。

## 数据库与恢复边界

仅使用专用端口 15432。显式应用 PG062–065、SQLite047–050；已应用迁移不再修改。PG064 原文件末尾空行会触发 Git 的新增 EOF 空行提示；为保持数据库摘要，保留原文件。临时独立 Git index 的其余空白检查通过，没有改动用户 index。

实际新建合成数据库 `stage13_backup_fb7e6a8d33c5` 与 `stage13_restore_fb7e6a8d33c5`，调用正式 `backup_accounting.py` 的共享 repeatable read 快照、`pg_dump`、`pg_restore` 与原件检查。恢复 65 个迁移版本、8 条历史记录及两份原件；没有产生当期来源、业务事项、草稿或导出。再次恢复到已有目标数据库被拒绝。

首次恢复后，运行账号因恢复的 `--no-acl` 策略无法启动，符合关闭服务的边界。续跑演练先撤销 PUBLIC 默认对象权限，仅按源库真实对象和列 ACL 重建三个 NOLOGIN 内部角色授权；不复制登录账号、owner、PUBLIC / anon 或转授权能力。任务字段的列 SELECT 与源库逐列一致，没有升为整表 SELECT。随后用真实受限运行账号验证无历史授权不可读取、原件哈希一致、接管只读和原生 RLS。结果持续为 `serving_enabled=false`。报告与可审查授权计划保留在 `.codex/stage13-recovery-fb7e6a8d33c5/`。

这不替代生产环境的恢复、云服务配置、登录账号重新配置及 RPO/RTO 验收。部署时仍需完成新环境权限审查，不能直接把恢复库切成生产服务。

## 试点限制

当前文件入口为中性 JSON、CSV / `.xlsx`；T+、用友或金蝶仅记录来源产品及版本，`vendor_native_verified=false`。必须取得客户实际版本与脱敏导出，验证具体格式、控制总数和逐月对照后，才可宣称对应版本快捷迁移。

库存、固定资产、工资、数量和外币子模块没有迁移闭环。历史期末余额为接管参考，不生成正式期初凭证或报税数据。原软件仍承担正式账本；真实模型、正式软件回执及 2–3 家企业的业务准确性需要实际试点验证。当前结果不证明一个会计管理 200–500 家企业的容量。
