## 验证的主要行为

- 第八阶段跨企业预览、明确人工确认、当前授权、同账套原子失败/成功、逐账套回执和幂等重放。员工不能读取会计样例、内部异常或跨账套待办。
- 异常指派与公开补件、员工原件追加、会计独立接受、原审批提交快照保留、事实版本变化、旧原件替代后不重复核对。公司财务只读账套权限不等同于凭证修改或批准权限。
- 真实已审样例、原/最终分录、正反例真实性、服务器计算评估上下文、规则显式版本化发布与停用。真实 PostgreSQL worker 使用当前新金额与辅助项生成企业规则草稿，无分录模型调用，仍须会计批准才可导出。
- 固定来源、账户、稳定交易编号防重；更换显示编号或文件名仍重放，内容冲突整批回滚，同企业另账套不重复导入同身份。已审或已关联旧来源与新格式相似来源仍进入人工辨别，不删除原件。
- 多笔流水合计全额匹配一个已付款业务事项；同账套、日期、方向、对方、当前事实/草稿版本及来源指纹核验。关联流水不能另行审核导出；企业模型开关关闭时，银行异常和重复风险仍阻止业务审核与导出。
- 原始 CSV 与不可变导出清单逐行一致，PostgreSQL 私有证明绑定导出原事务及科目快照。伪导出审计、其他凭证替换、跨事务伪装当前科目、损坏 CSV 均不能制造有效清单。
- 人工回执的完整范围、金额、科目、辅助项、分录序号、重复/未知凭证及外部编号冲突核验。缺项保持待核验，差异说明不改冻结记录，关闭期间可以追加交付证据，部分/未知结果不自动重发。
- 真实 worker 成功回执也不能跳过当前未关闭异常；旧模型成功证明不能绕过新异常。失权后的失败/中断任务仍可结束并保留不可变模型及应用事实。
- UTF-8 BOM、CRLF、原回执 hash、安全 CSV 文本、引号/逗号/换行和最大长度摘要/历史科目的边界。

本轮初次回归暴露的 PostgreSQL 参数类型、审计范围、规则回执金额/辅助项和 CSV 安全前缀边界均已修复并验证。最终全量结果对应全部修复后的代码，不把失败后的旧执行结果当作最终通过。

## 查询基准

`python scripts/benchmark_workbench.py` 在临时 SQLite 中生成 500 账套、50,000 来源、100,000 分录行；首页返回默认 50 个摘要，包含授权与事务共 5 条 SQL，最终单次汇总约 **484.95 ms**。

该数据不包含完整账户身份、异常、回执与模型任务负载，没有测 P95/P99、并发模型吞吐或真实会计处理效率。它仅验证当前汇总查询没有恢复逐账套/逐来源 Python 循环，不证明一名会计可以管理 500 家企业。
