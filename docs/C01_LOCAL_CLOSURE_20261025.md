## 完整恢复与真实身份

两条新集群恢复图：PG16.15、PG17.11，149个迁移至161、239张表、848项授权（含49项列授权）、5个快照身份、2份私有原件。真实 `pg_dump` 导出共享快照、`pg_restore` 到新空数据库，目标使用独立集群、新管理员和新运行账号；身份包、业务 manifest、活跃UUID集合与原件SHA联合绑定。

恢复保留 hold，先核对身份、权限、原件、未知调用和业务，再审计释放本地核验环境。释放后完整登录、授权下载、跨企业负向、新业务录入、独立会计复核、拒绝未审导出、复核后导出、撤权及新员工密码开户登录均经过真实 API。2个序列只读核验，不用 nextval 试探。未知费用、已发送 attempt、待处理任务和外部回执不会被恢复工具自动重发或改写。

另以非空新银行／跨期数据做 PG16/17 恢复补证：7张新表均有真实业务写入；22张相关表的内容SHA及关系恢复前后一致，前期锁定、次月999970分未结余额、桥接状态和两份原件字节SHA一致。补证使用独立数据库并保留hold，未启用服务，不把空表恢复冒充业务数据恢复。

真实 GoTrue 使用官方 [v2.197.0 制品](https://github.com/supabase/auth/pkgs/container/gotrue)，amd64固定manifest `839f529492d116b4e8b7777c953a27c381d34c15a744b1bcefde5eefaa1f9f9f`，二进制SHA `f2aa147268461f74784ddc8b2240aa446ee71ceb9633bac41c30e7b852a860aa`，75个官方迁移逐文件校验。没有安装系统软件、Docker或修改系统PG14；仅在私有目录启动回环测试进程。

GoTrue四项实证覆盖两版本的 Auth schema 备份恢复、原密码与UUID、真实TOTP、旧访问令牌拒绝、封禁，以及恢复后真实身份对会计API的登录／下载／跨企拒绝／独立复核导出／撤权。实际复现“只换签名密钥仍可用旧 refresh token 刷新”，因此本地身份恢复策略明确清除恢复会话及刷新令牌并写Auth审计，保留用户密码哈希和MFA配置；重新密码及MFA登录后才能访问。该策略只操作本轮隔离Auth库，不是对线上用户的会话操作，也不是生产Supabase部署模板。
