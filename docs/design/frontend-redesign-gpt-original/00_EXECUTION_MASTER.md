# DeepSeek 执行总令｜衡账品牌与全前端重构

2026-11-17。将本文件与六个阶段文件一次性交给 DeepSeek。先读总令，按依赖连续工作。每阶段给出产物、真实验证和未完成项，再进入下一阶段。

## 目标与输入

为一家出租车公司先行试点、五家企业共享财务办理的衡账产品，形成可持续的中文品牌视觉与前端体验。员工能快速交票和补件，财务核验与会计复核能迅速对照金额和原件，负责人能跨企业协调卡点。用相同样例比较品牌识别、文字可读性、任务效率和异常反馈，最终逐页替换现有界面。

先读 [现有全前端规划](../../OPEN_DESIGN_UI_REFACTOR_PLAN_20261117.md)、[现有衡账设计规范](../open-design/hengzhang/DESIGN.md)、[旧 UI 规划](../../UI_REFACTOR_PLAN_20261110.md)、[现有前端组件约定](../../FRONTEND_COMPONENT_USAGE_20261110.md)、[FSC 状态](../../FSC_EXECUTION_STATUS.md) 及当前实际存在的 I–L、FSC02/06/12–17 验收。核对 [金额录入增补](../../fsc_opt/OPT08_FRONTEND_MONEY_ENTRY.md) 与 [工作台增补](../../fsc_opt/OPT09_FRONTEND_WORKBENCH.md) 的实现或归属。路径、现状和报告需按当前工作区确认，未找到的记录说明即可。

基线已有 React 18、角色导航、账号身份、语义 token、原生弹窗、表格分页/列宽和分录定位、原件预览、现有状态与权限。已有可工作的接口、业务流程和导航直接复用。React 19 升级仍按独立的 M 批授权。项目实际组件和路由为准。

## Open Design 使用与证明

此规划的来源是衡账代码、历史截图、Open Design 0.27.1 随包的 Code Migration、Design Refine、UI Animation 和设计变量规范。上一轮核对了 56 项设计变量，Windows 版安装完成，但启动和 Codex 注册分别尝试后仍出现退出码 `0x80000003`，因此没有应用内生成或预览记录。

- 执行时先核实工具版本及启动状态。Open Design 可用时，本地工作区只导入衡账设计包和虚构样例。按代码盘点→设计提取→语义映射→需求简报→原型→细化→工程差分和验证执行。保存真实版本、导入结果、设计项目或产物路径、预览截图与使用方式。用 [官方设计系统规范](https://github.com/nexu-io/open-design/blob/open-design-v0.27.1/docs/design-systems.md) 校验设计包。
- 若原运行方式仍失败，可采用 [同版本官方浏览器运行方式](https://github.com/nexu-io/open-design/blob/open-design-v0.27.1/QUICKSTART.md#one-shot-dev-mode)。若当前环境仍不具备条件，继续用独立 HTML/CSS 原型和本地浏览器实现同一设计任务。记录“按工作流执行，应用内验证待完成”，证据中写明实际使用工具。避免再次执行相同失败路径或关闭安全功能。
- 设计样例只用虚构企业、凭证、原件及账号。实装验收仍由衡账的真实本地身份、API、数据库和存储提供。产品运行时不依赖 Open Design。

## 开工边界

1. 核对适用的 AGENTS.md、HEAD、已跟踪和未跟踪改动、并行任务归属及本地环境。先登记文件负责人和重叠风险，每次编辑前重读共用文件。禁止用 reset、clean、stash、全仓格式化或回退覆盖其他工作。
2. 默认只用本地合成数据和现有测试环境。本任务不授权真实模型、通知、客户/原件、真实外部服务、远端 CI、推送、部署或 SQL 迁移。新功能依赖由原业务批次完成，本轮用能力现状和真实停用状态表达。
3. 保持企业/账套/期间/对象/版本边界，制单与独立复核职责，原件下载授权，会计复核后导出。界面按服务端可用动作呈现。撤权、切换范围、迟到响应、历史版本失效和结果未知都进入验证。正式金额使用原金额契约。
4. 品牌素材、字体和图标先登记来源、版权、字重/字集与体积。沿用现有图标与 CSS 方案。可选的本地字库和设计素材先在原型评审。产品首屏沿现有体积预算验收。

## 每阶段执行与完成定义

1. **查证基线。** 列页面、角色、状态、现有组件、待办来源和授权。采真实本地页面，截图记录视口、主题、系统字体、场景和候选。历史截图只作参考。写清复用和新增的必要性。
2. **先建立验收。** 任务和权限真实缺口先用组件或浏览器红测复现，再修复。纯视觉改版先拍同尺寸旧图并写下评审标准和改动目标。保留有意义的截图差分、布局断言与任务步骤，避免冻结每个像素或重复现有测试。
3. **做最小可交互样板。** 先覆盖一个角色和一个高频办理链，验收正常、加载、空、错误、撤权/失效及该页独有的部分成功或未知。再推广至同类页面。测试设备和功能应能重跑。
4. **过门槛。** 相关 Vitest 和 Playwright、`npm run typecheck`、`npm run lint`、`npm run build` 后 `npm run test:frontend-budget`。关键流程在本地身份/API/原件环境验收，涉及权限/账期/复核/文件的改动纳入现有 PG16/17 子集。保留真实后端成功链，mock 用于延迟/故障或外部边界。按实际配置选择 Chromium、Firefox、WebKit 及 dev/preview。
5. **评审可用性与可达性。** 同任务同数据量比较视觉和操作。记录从首屏到主操作、处理一条任务、检查原件、错误恢复、返回定位的动作数及时间，并核对是否选错企业/期间/状态。前景与背景按真实组合测对比度，键盘、可见焦点、缩放、减少动态效果单独验收。设备或人员不足的项标明未验。
6. **交接和继续。** 每次使用 `tmp_test/frontend-redesign/<阶段>/<run-id>/`。记录候选、命令/退出码、配置、用例、旧/新图、视频、trace、已知制约、文件归属、下一条可执行工作。最终在同一候选重跑关键链。改动仍与 FSC 共同受验时，给 FSC12 提供实际证据，不拼接不同候选。

每阶段维护 `docs/design/frontend-redesign/STATUS.md` 或独立阶段记录，包含设计决策、文件和测试归属。外部依赖缺失时完成其余可验证工作，并标明阻断所需输入。用户若给出视觉偏好，下一批沿该方向更新。没有偏好反馈时以第 01 阶段的实测取舍和默认方向推进本地实施。
