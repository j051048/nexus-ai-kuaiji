# FE 总令：衡账前端改版（DeepSeek 分模块执行）

2026-11-17 修订。性质：代码实施工作令，不是上线许可或完成证明。完成后由独立验收方逐模块复查，以代码、测试和命令输出为准，不以你的报告为准。

原稿保存在 `docs/design/frontend-redesign-gpt-original/`，仅供追溯，不作为执行依据。

## 1. 目标

用户是同一集团下五家单位的五六名财务人员、各单位交票员工和少量负责人。改版的目标按重要性排序：

1. **办得快、不办错。** 会计复核和录入的信息密度与键盘效率；任何页面都看得清当前单位、身份、期间。
2. **状态说真话。** 加载、空、错误、无权限、版本失效、结果未知各有明确表达，切换单位时旧内容立即清除。
3. **全站一致。** 颜色、字号、间距、按钮、表格、弹层来自同一套变量和公共组件。
4. **品牌收敛。** 把现有"衡账"标志和绿色体系用统一，不重画标志、不引入新字体。

排在后面的目标不得以牺牲前面的为代价。

## 2. 与 OPT 批次的分工

`docs/fsc_opt/` 的 OPT08、OPT09 负责**功能和行为**：统一金额模块、科目选择器、键盘录入、风险分档、队列表格化、月度矩阵、常驻切换条、不可逆确认。本令负责**视觉层和全站一致性**。

| 本令阶段 | 需要先完成并通过验收的 OPT 模块 |
| --- | --- |
| FE01、FE02、FE03 | 无 |
| FE04 | OPT08-A、OPT08-B、OPT08-C、OPT08-D、OPT09-A、OPT09-B、OPT09-E |
| FE05 | OPT09-C、OPT09-D |
| FE06 | FE01–FE05 |

规则：

- 开工前读 `docs/fsc_opt/OPT_STATUS.md`。前置模块未标"完成"时，该 FE 阶段不开工，改做不依赖它的阶段。
- OPT 已实现的组件（`src/money.ts`、`MoneyCell`、`AccountPicker`、确认对话框、切换条、队列表格）直接使用并只调样式。不重写，不另造同类组件。
- 发现 OPT 实现有缺陷时记入状态文件"顺带发现"，不在本令内修改其行为。

## 3. 怎么干

每个阶段文件由若干模块组成（如 FE02-A）。**一次只做一个模块**，做完写状态再做下一个。每个模块固定五步：

1. **核实现状。** 文件里的路径是 2026-11-17 的线索。先搜索确认组件、路由、测试文件的实际名称和当前状态。已满足要求的记录证据并跳过。
2. **先建验收。** 行为或权限缺口先写失败测试。纯视觉改动先拍同视口旧图并写下本次要达到的可断言目标（如"首屏可见行数不少于 12""该文件不再含十六进制颜色"）。
3. **最小修改。** 只改本模块列出的范围。
4. **跑门槛。** 见第 5 节。
5. **更新 `docs/design/frontend-redesign/FE_STATUS.md`。** 格式见第 6 节。

## 4. 不可突破的边界

1. 不提交、不推送、不部署。不执行 `git reset`、`git clean`、`git stash`、`git checkout -- <文件>`，不做全仓格式化。其他智能体在并行修改，每次编辑前重读文件。
2. 不改后端业务逻辑、接口契约和数据库迁移。界面需要而接口没有的字段，记入状态文件，不在前端推算。
3. 不引入新依赖、新字体文件、新图标库、外链资源。沿用系统中文字栈、`lucide-react`、手写 CSS。
4. 新写或改动的样式只用 `src/tokens.css` 的变量。不新增十六进制颜色，不新增小于 12px 的字号。
5. 金额显示和计算只走 `src/money.ts`（OPT08-A 产物）。该文件不存在时，涉及金额的模块不开工。
6. 权限、可用动作、状态以服务端返回为准。前端不凭"有附件""有按钮"自行判断资格。
7. 只用本地合成数据。不访问真实模型、通知、客户资料、外部服务。
8. 测试不靠作弊变绿：不删断言、不加 `skip`、不放宽超时、不整体更新截图基线来掩盖差异。截图基线更新要逐张说明原因。
9. 首屏体积不超过现有预算（`npm run test:frontend-budget`）。不靠放宽预算过关。
10. 不使用 Open Design 应用。它在本机启动失败，不要再尝试安装、启动或注册。原型用独立的静态 HTML 和 CSS 文件完成。

## 5. 每模块门槛

必须跑通并把输出尾部贴进状态文件：

```
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
npm run test:frontend-budget
```

再加模块自己点名的 Playwright 用例。本机跑不了的写"未验证"和原因，不算通过。

涉及权限、账期、复核、文件下载的改动，复跑对应的后端用例；PostgreSQL 用例本机无库时写"PG 未验证"。

## 6. 状态文件格式

`docs/design/frontend-redesign/FE_STATUS.md`，每模块一节，追加不覆盖：

```
## FE02-A  <状态：完成 / 部分完成 / 阻塞 / 已满足无需改动>

- 现状核实：<命令或文件> → <关键结论>
- 验收目标：<可断言的目标，或失败测试名称与修改前输出>
- 修改文件：<逐个列出>
- 门槛命令与输出：<原样粘贴尾部>
- 截图：<路径，注明视口与场景；没有就写"无">
- 留给人评审：<本模块需要人看的具体问题>
- 未做或未验证：<如实写>
- 顺带发现：<范围外问题>
```

"完成"只在门槛全部真实通过时使用。不写估计值。

截图和其他产物存 `tmp_test/frontend-redesign/<模块>/<运行标识>/`，不覆盖旧运行。

## 7. 你做不了的事

以下项目不要伪造、不要用替代物冒充，统一写入"留给人评审"：

- 审美取舍和品牌方向选择。
- 真人操作的耗时和动作数对比。
- 真实手机、微信内浏览器、人工读屏。
- 录屏。你可以提供可重放的 Playwright 用例和 trace 代替，并写明"无录屏"。

不以自动扫描代替人工读屏，不以缩小视口代替 200% 缩放，不以模型打分代替真人试用。
