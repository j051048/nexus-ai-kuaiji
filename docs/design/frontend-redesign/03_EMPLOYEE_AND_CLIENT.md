# FE03：员工交票与补件、客户进度与签收

先读 `00_EXECUTION_MASTER.md`。前置：FE02。不依赖 OPT 模块。

线索文件：`src/WorkspaceHome.tsx`、`src/IntakeWizard.tsx`、`src/ClientPortalShell.tsx`、补件与 OA 材料相关面板、消息与"我的事项"、客户简报与签收入口。先搜索确认实际文件名。`WorkspaceHome.tsx` 可能有其他智能体在改，编辑前确认归属。

本阶段以手机为主要视口（390×844 和 375 宽），桌面保持可用。只改呈现和交互，不改提交接口、期间预检、审批策略。

## FE03-A  员工首屏

**做法。**

1. 顶部保留单位和身份。
2. 首屏只有一个主任务：有被退回事项时是"继续补件"并直达该事项；否则是"拍照或上传票据"。
3. 业务类型在开始办理后再选。现有的类型预选入口保留为次级入口。
4. 加载中、没有待办、查询失败三种情况分别显示，不共用同一个空白。

**验收。** 门槛通过；`e2e/employee-flow.spec.ts` 通过；新增断言：有退回事项时首屏主按钮指向该事项；无待办时不显示虚构数据；查询失败时显示错误和重试。390 宽截图三张（有退回、无待办、失败）。

## FE03-B  交票核对表单

**做法。**

1. 核心确认区由附件预览、日期、金额、用途、单位与期间组成。低频字段收进"更多信息"。
2. 单位或期间不明确时必须显式选择后才能继续。
3. 必填和格式错误显示在字段旁，提交失败时焦点移到第一个出错字段，错误文字与字段有程序化关联（`aria-describedby`）。
4. 底部主操作条避开软键盘和安全区，长表单滚动时不遮挡正在输入的字段。
5. 金额输入用 `src/money.ts` 的解析函数。该文件不存在时，金额字段保持现状，在状态文件注明。

**验收。** 门槛通过；`e2e/stage12-intake.spec.ts` 通过；新增断言：提交空表单后焦点在第一个错误字段；375 宽下主操作按钮完整可见且不遮挡最后一个字段。

## FE03-C  上传与提交的反馈

**做法。**

1. 上传显示真实进度或真实阶段。快速完成时不闪骨架。
2. 上传失败保留已填表单和其他附件，可重试或替换。
3. 识别结果中需要人核对的字段明确标出；识别不可用时可手工录入，不阻断。
4. 提交结果严格按服务端返回显示。服务端 5xx 或超时属于"结果未知"：提示不要重复提交，给出核查入口（沿用 `src/api.ts` 现有文案和机制）。
5. 提交按钮在请求进行中不可再次触发。

**验收。** 门槛通过；用 Playwright 拦截制造：上传失败、提交 400、提交 409、提交 500、断网。分别断言表单内容保留、错误可见、500 时无第二次提交请求。外部识别用现有合成夹具。

## FE03-D  补件

**做法。**

1. 从消息或待办进入时，直达具体事项和版本。
2. 顶部直接显示三件事：哪里有问题、要补什么、补完后由谁继续。保留已提交记录和退回原因。
3. 补件完成后返回进入前的列表，筛选条件和滚动位置不变。
4. 切换单位或权限被撤销时，已打开的原件预览立即关闭并清除。

**验收。** 门槛通过；`e2e/tax-k-oa-employee.spec.ts` 通过；新增断言：从退回消息进入的是同一对象标识；补件后回到原筛选；甲单位的原件在切到乙单位后不可见，迟到的旧响应不覆盖新页面（照仓库已有迟到响应用例的写法）。只读身份不能提交补件。

## FE03-E  客户进度与签收入口

**做法。**

1. 客户端首页用平实的句子说明：资料进度、简报覆盖范围、正式交付包的当前版本。
2. 签收状态的各种取值有不同的文字和图形，不只靠颜色。
3. 客户联系人、企业员工、企业财务三类身份按现有能力显示各自可见的内容。
4. 本模块只验证入口、呈现和状态。交付全链路在 FE05 联验。

**验收。** 门槛通过；`e2e/n04-client-signing.spec.ts` 通过；390 宽下三类身份各截首页一张。
