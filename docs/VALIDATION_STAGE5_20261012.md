# 第五阶段验证记录（2026-10-12）

## 完成范围

在第四阶段基础上新增持久 OCR 批次、逐附件任务、尝试历史、请求回执及企业调度状态。单份、单事项全部附件和本页同企业批量识别均通过队列提交，提交请求不等待模型。页面显示当前授权范围的进度、失败原因与尝试记录，支持明确重试和保留依据的取消；离开页面后后台继续执行。

PostgreSQL 使用受限独立 worker 登录及调度函数，API 无跨企业领取权限。每项任务按执行请求人的当前授权读取私有原件，模型发送和发布前再次检查权限、版本、期间、原件摘要及配置。企业间持久轮转，全库最多 2 件并行、同事务所企业最多 1 件；已采用的异常人工处理、会计独立复核及审核后导出流程继续有效。

## 关键边界

- 批次最多 100 份附件、同一企业；每项权限/原件/版本一起校验，任意一项失败整批回滚。同一附件最多一个未完成任务，重放创建不重复入队。
- 用户只能看到目前可见的任务；同批其他人的票据、失败及件数不会计入其进度。取消和重试仍重新校验当前处理权，不继承批次创建者的权限。
- 领取、发送标记、续期、OCR 结果及任务完成都有租约保护。OCR 结果、核对异常和完成回执在同一事务发布，取消/失权/过期后旧响应不能覆盖新执行。
- 尚未登记发送的过期尝试可恢复排队；已登记发送且结果不确定进入人工确认。已保存结果仅恢复回执，不重新请求模型。
- 明确繁忙/HTTP 429 允许 30/60 秒有限退避，每轮最多 3 次、历史最多 30 次；超时、断网、发送后不确定失败不自动重发。人工重试保留新旧尝试。
- 批次重试有独立接受回执，旧键不会包含后来新失败的票据；无可重试项拒绝且不记录接受。重复单件重试不增加费用尝试。
- 在已有旧 OCR 结果时，新排队任务仍阻止审核，不能通过填写说明跳过；等待结束或取消后，票据异常仍由独立财务/会计处理，采用分录仍不等于审核或入账。
- API 与 worker 账号独立；专用后台角色没有全表直接读取权。生产要求 PostgreSQL/TLS，启动拒绝危险或混合角色，不默认读取旧环境配置。

## 复现与部署

```powershell
python -m pytest nexus_backend/tests -q
npm test
npm run build
npm run test:e2e
```

真实队列 PG 测试须设置独立测试用 `ACCOUNTING_TEST_POSTGRES_URL`、`ACCOUNTING_TEST_DATABASE_URL`、`ACCOUNTING_TEST_WORKER_DATABASE_URL`。全局调度需要独占测试数据库、串行运行，不能连接有真实待处理工作的库。CI 已创建受限 API/worker 两个登录并启用全部三个测试连接。

生产显式应用 PostgreSQL **013–015**，SQLite 本地应用 **006–007**；保持已有迁移校验和不变。配置和启动命令见 [第五阶段接口与部署](STAGE5_API.md)，权限函数见 [数据库说明](STAGE5_DATABASE.md)。本轮测试服务器结束后关闭，专用测试 PostgreSQL 验证结束后停止，测试历史保留。

## 试点验收待做

继续限 2–3 家企业。配置真实供应商及登录后，先用少量已知答案票据检验字段、限流响应、断网与进程中断，再验证真实完整月份及客户软件导入回执。识别过程中事项版本变化会停止旧任务，试点先完成识别再提交审批。

测量每百件人工分钟数、失败/改科目比例、企业等待时间和模型费用，并验证数据库与原件联合备份恢复。本轮没有正式总账、税务抵扣判断或 200–500 家容量验证；费用配额、监控、历史保留及更大队列压测列入 [建设路线](ACCOUNTING_ROADMAP.md)。
