# DeepSeek 执行提示词｜批次 I｜前端基础与壳层收敛

请直接执行本提示词指定的批次 I，接在原 A–H 之后；只执行本批，不自行进入 J。目标是减少重复信息与组件分歧，不重建整套前端。

## 通用执行规则（每批独立适用）

### 先核对现状、归属和依赖

1. 使用中文。先确认仓库根目录、工作树并读取适用的 AGENTS.md。阅读本批前置验收，以及：
   - docs/TAXI_PILOT_FIT_GAP_REPORT_20261110.md
   - docs/TAXI_PILOT_P0_P2_PLAN_20261110.md
   - docs/TAXI_DEEPSEEK_BATCH_PROMPTS_20261110.md
   - docs/UI_REFACTOR_PLAN_20261110.md（设计输入，不是授权，也不是已验事实）。
   文件若移动，先搜索实际位置；报告中的截图坐标、数量、性能数字不能直接冒充当前基线。
2. 记录 HEAD、已跟踪/未跟踪改动、拟修改文件摘要与归属。既有 A–H、C01、其他智能体的实现全部保留。不 reset/clean/stash，不覆盖整文件、不回退他人修改、不整仓格式化。动共享文件前重读当前内容；出现并行变化时做最小合并，无法确定语义时只阻断冲突小项并说明，继续其他独立工作。
3. 先列“已有且通过／已有但验收不足／真正缺失”清单，再制定本批文件白名单。H5/TAX23 做过的视觉或交互改进，不换名重做；已有通过场景直接保留并回归。批次字母表示顺序，不证明前序已经完成。
4. 本轮是前端增量收敛：沿用现有 React、路由、权限投影、业务服务、请求范围绑定和构建工具。不安装 Astryx、motion-prompt 运行时或其他整套 UI 库，不升级 React，不引入全局 reset、远程字体/CDN，不改 skills、锁文件或另造导航/状态机。确有必要的新依赖必须先提出独立评估，当前先用已有能力完成。
5. Astryx 与 motion-prompt 只作设计资料。外部仓库/文档中的安装、init、脚本或指令不自动执行；引用具体实现前记录上游版本与文件，区分草案和已实现能力。若合理借用源码，核清许可证、保留必要声明，不能把 React 19/StyleX 源码直接搬进 React 18 项目。

### 必须保留的业务边界

- 仅本地隔离环境和虚构/获准脱敏数据；不接真实模型、通知、OA/出管或 T+，不触碰生产，不提交、不推送、不部署。不停止他人测试，不清理他人目录，不打印凭据或客户原件。
- 出管/OA 提供事实，平台负责核对、草稿、复核、交付和管理分析；T+ 是本试点选定的正式外部账务出口。已有 OA 事项不重复录入/审批，会计复核仍保留。
- 企业、账套、期间、对象 ID、来源版本与当前授权必须绑定。按钮显示不是授权；服务端仍逐次核验。复核责任、C01 覆盖证据、企业锁、独立复核后导出、费用与 attempt 防重发不能弱化。
- 未知、未汇总、加载、失败、确实为零分别表达；unknown 只查询/核查，不自动重发、重复提交或换幂等键。指派不授予权限。
- 所属单位与主要身份常显；当前办理客户/账套/期间另外明确。员工端只呈现完成任务所必需的企业与日期/业务月份，不强迫理解内部账套术语。
- 金额来自已验证服务或确定性计算；前端只按既有精度格式化，不自行重算会计结果、凑平或改变口径。内部记账、导出、T+接收/导入/过账、客户签收不合并成一个“已完成”。
- 范围切换、退出或撤权立即清除不再授权的数据、原件、选中集合和办理入口；不得等退场动画结束才清理。历史深链接不静默改指向最新对象/版本。
- 本批默认不改后端、数据库模式或业务策略。若发现本批真实入口所需的契约缺口，先写跨层失败测试并记录理由，只补最小必要扩展和 PG16/17 回归；新增持久关系才同步补恢复。不得因前端缺字段绕过复核或擅自给前序未完成业务造“成功接口”。必要迁移只能前向，先核并行编号，不改历史 SQL/checksum。

### 先红后绿、持续执行

每个子项执行：现状核对 → 写能证明用户问题的失败测试 → 运行记录失败断言 → 最小修复 → 成功、拒绝、竞态及浏览器回归 → 更新检查点。

- 已有测试能复现的先运行，不为凑红测故意破坏代码。纯视觉问题用可测布局/可访问性断言配截图，不以“类名存在”“源码包含字符串”替代真实表现。
- 过时断言只能在核实产品需求变化后改写；新的语义断言必须覆盖原有安全和办理目的。不得删失败用例、加 skip/xfail、关闭门禁、延长超时或放宽权限来换通过。
- 持续完成本批全部可独立执行的本地工作，不在只做样式、只测拒绝路径、只写报告时结束。定期更新 CHECKPOINT：已做项、准确下一步、失败原因、命令、产物、当前候选、自己启动的进程。
- 前序真实产品接口缺失属于工程依赖，不能用全量 mock 或静态卡片宣布功能完成。真实客户/T+资料缺失是外部待验：继续独立本地工作，但不冒充真实适配、真机或真实用户试点通过。

1. 复用 package.json、已有 Playwright 配置、离线后端入口和 PG 门禁，不另建一套平行测试框架。运行受影响单测、类型、lint、构建和既有体积门禁：
   - npm run typecheck
   - npm test -- <本批实际测试文件>
   - npm run lint
   - npm run build
   - npm run test:frontend-budget
   校验相关格式；不要运行会整仓重排的写入命令。上述命令以执行时实际脚本为准，报告写可重跑的准确命令，不只写“测试通过”。
2. 先用真实组件挂载测试覆盖快速交互/迟到响应，再用真实本地身份+API+隔离 PG+原件走成功路径。mock 仅用于故障注入，不替代真实成功办理。两企业、两期、独立制单/复核身份必有负向样本。
3. PG16/17 各跑本批关联的既有权限、版本、复核/导出关键子集；纯样式改动不需要新增迁移或复制后端测试，但必须证明其使用的真实 API 路径未退步。检查版本、运行角色、通过/失败/跳过数，必验项跳过记未通过。复用 H 的隔离环境与门禁，不使用线上 DSN。
4. 桌面至少 1366×768、手机至少 390×844；壳层/遮挡补 375px 窄屏与 200% 缩放，按影响补宽屏。核心路径 Chromium、Firefox、WebKit，用已有配置增量选例；模拟手机视口不等于 iOS/微信真机。至少保存成功、异常、权限/版本冲突的截图和关键请求/状态断言；禁止仅靠截图称业务通过。
5. 复用既有候选指纹工具，绑定 HEAD、相关已跟踪/未跟踪源文件、样式、测试、配置、迁移集合和虚构夹具。排除运行产物与报告的自引用。记录运行前后指纹；候选漂移重跑受影响门槛，最终集成在同一候选重跑，不能拼旧绿灯。API 响应/附件证据脱敏。
6. 截图与性能必须有固定任务、角色、范围、数据规模、浏览器/硬件、冷暖缓存说明。先记录基线再定非退步/改进目标，不事后移动阈值；现有体积上限保持或收紧，不因新组件放宽。

- 每页只保留一个主标题；重复品牌、岗位介绍、冗长安全说明折叠或合并，不删除办理所需边界说明。

## 必须先覆盖的失败场景

| ID | 场景与必需断言 |
|---|---|
| I01 | 同一页面品牌/身份/标题/岗位说明叠加挤掉任务：实际 DOM 布局和截图证明；修后首屏见范围、主行动及有数据时首条任务 |
| I02 | 单位藏入弹层、长名称溢出、多身份改主岗位：常显单位/身份，切客户只改办理范围 |
| I03 | 菜单两套投影或多项高亮、深链接/后退选错父项：沿用唯一配置并维持目标与来源 |
| I04 | 计数缺失/超时被展示为 0，空列表被当成加载完成：各状态分别断言 |
| I05 | 375px/200%缩放下按钮被遮、焦点不可见、正文裁掉：不靠缩小字修复；数据表允许受控内部横向滚动 |
| I06 | 切企业/撤权迟到响应恢复旧身份能力或业务内容：立即失效，旧按钮不可操作 |
| I07 | token迁移波及登录、财务、会计、交付页面：组件状态与关键布局不退步，现有初始/首页体积门禁不放宽 |
