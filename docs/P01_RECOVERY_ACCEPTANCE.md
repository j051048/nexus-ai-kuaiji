## 修复内容与红—绿

1. **税务来源绑定遗漏。** `release_recovery_hold.py` 原来没有把 `tax_workpapers.source_snapshot_json` 纳入必填清单；来源版本/金额变化可能不改变释放摘要。新增五条测试先失败，再加入必填字段及 SHA-256 投影。缺列拒绝核验，敏感正文不进入摘要。注释同时纠正为“底稿准备/复核”，不暗示已经申报。
2. **原件上传协议夹具缺失。** 原联合恢复只上传业务事项附件；最新发票导入使用签名上传，实际 PG 测试先得到存储 503。新增四条失败测试，再补本地对象协议的服务密钥签发、固定 bucket、精确对象键、到期/单次令牌、不可覆写检查。仍调用真实存储适配器，未绕过上传/来源校验或修改生产存储权限。
3. **“有表但没业务数据”不能验收。** 新夹具通过真实领域服务生成正式期初、税务底稿、锁期报表、交付包和通知。显式拒绝新域空表，即使恢复前后空摘要相同也不能通过。
4. **没有可重复执行的联合门槛。** 新本机环境工具只创建新源/目标，保留失败副本，不 DROP/清库；新验收入口固定联合恢复两例、真实 GoTrue 四例及八项业务证明。先补失败测试，再实现缺项/跳过/错误版本/字段类型/配置漂移拒绝。

上述红测中，来源快照遗漏是实际恢复清单缺陷；对象协议和工具不存在属于验收基础设施缺口，不能混称生产业务缺陷。

## 实际恢复样本

每个 PG 版本分别使用独立源集群、独立空目标集群、独立管理员和受限 app/worker/projection 登录。
SCRAM、`fsync`、`synchronous_commit`、`full_page_writes` 开启；受限登录无 SUPERUSER/BYPASSRLS/CREATEDB/CREATEROLE，能力角色 NOLOGIN。

- PostgreSQL 16.15 → 全新 16.15；17.11 → 全新 17.11。
- 当前 PostgreSQL 全部 166 个迁移，编号至 178；历史校验和不改写。
- 每套六个快照身份、三份真实持久原件；全部原件 SHA-256 相等。
- 恢复 883 项逐对象/列授权，其中 49 项列授权；不以 GRANT ALL 代替。
- 税务：实际发票 CSV 原件、上传意图、导入批次、档案、已审历史 v1 与待审当前 v2，包含来源快照和摘要。仍为 `not_filed`。
- 交付：真实零业务期初经过独立审批/冻结/绑定，真实预检/复核/锁期/报表发布，四版包与版本化收件人授权；第一版已查看签收，后续版本尚未签收。零业务样本不编造当期银行流水，也不代替 P02 非零银行/子账链路。
- 通知：非空 pending、sending、unknown；发送中保留旧 lease/restore epoch。另有未知模型费用、已发送 OCR attempt、待处理任务及人工记录的未知外部回执。

## 八项恢复后证明

| 项 | 实际断言 |
|---|---|
| 数据库 | 官方 pg_dump/pg_restore，目标原先为空；全部迁移、结构、序列及恢复清单核验；新域表均非空 |
| 原件 | 原件逐字节/hash恢复，生产适配器私有下载；新发票原件通过恢复后的实际 API 下载并核对 |
| 身份 | 独立身份包保留 UUID/密码/MFA；签名和会话验证；真实官方 GoTrue 另做 auth schema 恢复并登录会计 API |
| 权限 | RLS、角色、列授权恢复；跨企业/错账套/无权原件拒绝；撤权后旧账号拒绝；恢复后新员工开户只能访问本人权限 |
| hold | 未核验目标正常 API 无法启动；释放必须匹配恢复标记、当前权限与清单摘要，写入独立释放审计 |
| 复核导出 | 恢复后导入/生成草稿、未审导出拒绝、独立会计复核、复核后导出成功 |
| 税务交付 | 历史底稿证据不变但旧稿不能导出；当前底稿自审拒绝、独立复核后可导出；包文件/manifest核验、错版本签收拒绝、准确签收幂等 |
| 不重发 | 旧通知租约不能结算；恢复后实际调用两次本地派发，channel 调用为零；未知状态不伪装成功；旧 OCR attempt、费用和外部回执保留 |

恢复 hold 的语义是禁止正常 API/worker 启动及通知派发；不是撤销管理员对隔离副本的全部诊断能力。受控核验曾直接调用领域服务做隔离业务检查；正式业务验证另在审计释放后通过实际 API 执行，未隐藏这一差别。
