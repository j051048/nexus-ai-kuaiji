# 大文件直传与电子税务局发票导出表导入

## 1. 大文件两段式直传（> 2 MiB）

网关保持 3 MiB/单文件、4 MiB/请求 的硬限制不变；超过阈值的前端会把附件改走两段式：

1. `POST /api/uploads`（用途绑定：intake/event/case/material/bank_import/invoice_import）返回一次性凭证
   （15 分钟有效，声明大小与 SHA-256）；
2. 浏览器直传私有存储：
   - 配置了 Supabase → 使用对象存储签名 URL（完全绕开网关）；
   - 本地/自建无 Supabase → `PUT /api/uploads/{id}/content`（同源，经网关，≤4 MiB）；
3. `POST /api/uploads/{id}/complete`：服务端校验字节大小与哈希后置为 `stored`，
   附件接口再用表单字段 `upload_id` 完成 claim→take→add→confirm。

状态机：`pending → stored → consuming → consumed / discarded`。
校验失败（哈希/大小/内容嗅探）会丢弃对象并作废凭证；失败路径先提交事务再清理，
附件写入失败会把凭证 release 回 `stored` 以便重试。

### 部署注意

- 网关对 `PUT /api/uploads/{id}/content` 单独开放**流式转发**（默认上限 50 MiB，
  环境变量 `ACCOUNTING_UPLOAD_MAX_BYTES`，范围 1–200 MiB），按块转发、不在网关内存中
  缓冲整包；其余接口继续严格保持 4 MiB 有界缓冲。自建部署不配 Supabase 时，
  浏览器会落到该同源流式端点，> 4 MiB 的文件同样可以上传。
- 后端单文件上限仍为 10 MB；每事项最多 10 个附件、合计 50 MB（既有产品约束不变）。

### 银行流水导入

`POST /api/books/{book_id}/import-wizard/files` 同时支持传统 multipart 与 `upload_id`：
前端在文件超过 2 MiB 时自动申请 `bank_import` 用途的一次性凭证并直传，后端校验
（CSV/XLSX 结构、10 MB、5,000 行）后登记为导入原件，不再复制对象；用途不匹配凭证会被释放回
`stored` 以便重试。解析上限与全局单文件限制对齐（10 MB / 5,000 行 / 64 列）。

## 2. 电子税务局发票导出表导入

入口：账套「对账」页的「发票导出表」面板（`POST /api/books/{book_id}/invoice-imports`）。

### 支持格式与列容错

- 文件：`.csv`（UTF-8/GB18030）或单工作表 `.xlsx`；≤10 MB、≤5000 行。
- 列名按别名匹配：发票号码/数电票号码、开票日期、购销方名称与税号、金额/税额/价税合计、
  发票状态、发票种类、项目名称等。
- 金额一律换算为整数“分”；日期支持 `2026-10-05`、`2026/10/05`、`20261005` 与 Excel 序列号。
- 行级容错：缺发票号码的行跳过并告警；金额无法识别留空并告警；文件内重复按
  “发票代码+号码”标记。

### 批次语义（只作证据，绝不产生会计事实）

- 批次落 `invoice_import_batches`：保存原件、SHA-256、解析行与告警；
- 批内/批间去重；按公司税号判定进销项；
- 与银行流水按「交易对手 + 价税合计 + 方向」给出**候选线索**（不写关联，只作提示）；
- 写 `invoice.import` 审计；导入不会创建凭证、来源或任何账务记录。

### 当前已知边界（可作下一批产品增量）

- 红字/负数发票不参与银行预匹配；
- 对手方为“精确或包含”匹配，尚无别名/税号优先；
- 部分付款（银行金额 < 票面价税合计）不会命中；
- 批次暂无一键导出异常台账（作废/红字/重复/未勾稽）。
