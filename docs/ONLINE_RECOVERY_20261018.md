## 线上核心用例最终结果

全部操作使用本轮两家明确标记的虚构企业和五个独立账号，金额、票据、人员均为模拟。A 执行模型与会计流程，B 用于隔离负向验证；不能将其解释为两家真实客户已并行投产。

| 用例 | 实际结果 |
| --- | --- |
| 员工录入、附件、部门及财务审批、移交 | 真实同域 API 完成；员工与会计页面按角色显示 |
| PaddleOCR + 已配置兼容模型字段提取 | 取得含原文位置的结构化证据；合成票据总额 213.00、未税额 200.00、税额 13.00、交易对方识别一致 |
| 后台自动生成分录建议 | 持久任务经 waiting/running 产生真实模型候选；票据显式标注“合成、非税务有效”，模型警告正确转为 needs_attention，未强制自动采纳 |
| 风险拦截 | 业务误录 212.00、票据 213.00，确定性差异检查阻止继续采纳，异常在人工工作台可见，凭证审核被拒绝 |
| 人工补件与事实纠错 | 会计创建补件单，员工上传并说明；独立会计接受补件、关闭补件单；另走事实修订，提交人自审 403，独立审批通过，旧事实与草稿替代关系保留 |
| 纠错后的后台重跑 | 替代草稿自动出现并重新生成建议；仅对合成资料警告作带理由的人工处理，没有忽略真实金额差异 |
| 会计复核和导出 | 两次流程均由独立复核账号批准后生成 CSV；未审导出 409，员工审核 404；重复导出请求返回同一结果，导出后记录冻结 |
| 企业隔离 | B 读取 A 的事项、附件、账套、补件、助手及导出均被拒绝；另以真实受限数据库登录验证 RLS 为零条、无 BYPASSRLS |

本轮证明的是“自动识别与生成建议 → 风险转人工 → 独立会计复核 → 导出”的闭环。因合成票据本身触发合理警告，线上无警告情况下的全自动采纳尚未由本轮样本证明；不能据此宣布已实现无人正式记账或一人服务 200–500 家企业。没有调用正式记账、账本权威切换、外部财务软件交付或发送邮件。
