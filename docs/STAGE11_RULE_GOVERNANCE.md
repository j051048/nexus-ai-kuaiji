# 第十一阶段：企业规则治理

## 匹配与事实边界

- 无 `conditions.counterparty_id` 的历史规则继续按原文精确匹配。
- 新规则可以绑定本企业有效往来方 ID。规则仍保留 `counterparty` 原文；保存、评估、发布和生成时都重新确认原文唯一对应该 ID。
- 仅当前有效主数据名称和经过另一名会计独立批准的别名参与匹配。未审核、已停用和歧义映射不参与，跨企业 ID 被拒绝。
- 名称同时是往来方甲的正式名称、往来方乙的已批准别名时，解析为歧义，不能按优先级偷偷选择一个。
- 已审核样例新增冻结的 `counterparty_identity` 投影。原始 payload、来源、金额、历史分录和原件继续保留，后续主数据变化不会改写它们。实际匹配使用当前授权与当前主数据。
- 银行清偿样例继续只用于追溯，不能成为普通分类规则正例、反例或候选。

## 候选去重与冲突

同语义定义忽略规则名称和分录顺序。稳定身份规则忽略用于追溯的交易对方原文差异；来源类型、业务类型、方向、类别、付款状态、稳定 ID 和科目/金额公式仍组成语义定义。

自动捕获始终保存每一个独立审核样例。同账套已有待发布/已发布同语义规则或待评估继承候选时，不重复创建候选，并记录 `learning.candidate.deduplicated`。系统不会把新样例自动并入旧规则的正例集，也不会合并原件、审核范围或清偿证据。

显式创建同语义候选返回 409，并指向已有规则。会计可以选择已有规则、显式修订其正例和依据，重新评估后发布。

原文规则与稳定身份规则也可能覆盖同一来源。评估会报告与已发布规则重叠的范围，发布再次检查并阻断；须先停用或修订旧规则。规则覆盖范围变化、主数据/别名变化会使旧评估失效。旧的已发布冲突仍在生成阶段阻断。

## 使用统计与历史回放

`GET /api/books/{book_id}/learning/governance` 返回本账套当前规则冲突、历史同语义候选组、有效往来方和使用统计。每次调用重新检查当前账套授权。

使用统计根据同账套生成审计记录和已审核样例关联实际规则 ID/版本。未审核草稿和影子回放不计为实际命中。每次命中的原规则版本重新渲染，与最终已审核分录对照，统计未修改、会计修改和当前科目下无法复算。无法复算单独列出，不伪装为正确；统计不是总体准确率或自动过账率。

质量模块可调用：

```python
LearningService.matches_in_transaction(conn, actor, book_id, definition, snapshot)
LearningService.shadow_replay_in_transaction(conn, actor, book_id, definition, sample_ids=None)
LearningService.resolve_counterparty_in_transaction(conn, actor, book_id, original)
```

影子回放只读核对冻结审核答案，不更新业务事实、凭证或规则。单期最多 2,000 个样例；规则治理最多 200 条当前规则，超限明确拒绝，避免静默截断。解析缓存只存活于当前授权事务，不跨企业/人员缓存。

PostgreSQL 057 提供相同的 `learning_counterparty_identity`、`learning_matches_scoped` 和原生评估/发布校验，后台租约完成函数也使用同一个 matcher。SQLite 042 保留身份归属、独立别名、语义重复和发布冲突检查，作为本地演示后端。

## MVP 限制

规则仍限定本企业、物理账套和期间。长期账套继承只复制公式候选；新期必须有新期独立审核正反例并重新评估，不会读取无权访问的旧月样例。仍由真人明确发布、复核和导出。当前回放和统计不等于真实企业月结验证，也不能证明一名会计已可服务 200–500 家企业。
