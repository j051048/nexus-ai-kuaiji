# FSC02：先完成出租车一户完整办理链

完整读总工作令与FSC01结果；本批继承全部边界。范围是现有出租车A–D真实缺口，不重复E–M已有功能。

## 复用与顺序

1. 复核既有tax/source、fees、fee_guard、ledgers/transport、真实draft auxiliaries。驾驶员映射到counterparty、车辆映射到project，绑定有效日期和映射版本；生成、普通审核、批次审核、导出、下载及回执接纳均校验。身份ID保存在旁表不算进入辅助核算。
2. 核清规费应收→收款核销的断点。普通settlements目前历史上只接受已移交business来源；不得把整批多驾驶员收入假装成单一交易对方，也不得给tax-fee前缀无条件豁免。扩展现有未结事项契约，按真实驾驶员债权/行贡献登记，不重复确认收入；新来源类型/关系有DB约束、版本和幂等。
3. 成功处理部分/多次/合并收款、多银行、跨期、独立代收分配、预收、退款、撤销。缺代收核定依据继续拒绝，不删除同交易对方约束；退款/冲销通过追加记录。
4. 规费策略绑定企业审核政策和来源，不仅接受客户端自报version。未知客户算法保留合成预览，真实启用失败关闭。
5. 来源原件可验证下载；所有文件和所有行可分页办理，坏行不绕过大小/行数上限；零额/无日期/坏金额不能点击“采用”变成合法事实。旧源、旧主档、旧策略不得冒充当前可导出版本。
6. 沿现有导航串起差异→原件→草稿→独立复核→核销→冻结导出→逐行回执。完成后保留返回来源和筛选；同一笔已完成项不重复出现可办按钮。

## 必须先红后绿

- 完备映射生成后aux为空；映射撤销/版本变更后仍可审导出；缺映射静默归集总科目。
- 规费应收无法进入核销；或接入后把多个驾驶员当同一客商、同一流水超分配；并发登记重复债权。
- 本人伪造独立复核、只读直写reviewed；不同企业/期间/来源指纹在API或受限DB角色下被接受。
- 重复回执、同回执异内容、unknown自动重试；旧文件在来源升级后仍标当前。
- 来源第13行/第6份文件无法办理；坏金额超过行数上限未拒绝；员工可下载财务原件。

## 验收

两企业、连续两期（含跨年）、多银行的真实服务成功链；PG16/17双会话核销/审核/撤权竞争；桌面手机本地身份/API/PG/原件单链，断言金额及状态。备份恢复有实际出租车主档、来源原件、辅助值、复核证据、导出和unknown回执，恢复不重发。

客户真实T+版本/原生模板/成功样例不足时，合成54列明确标记；不得把54列数量或“T+5.4”文字当兼容证明。真实适配、真实两期试点保持外部待验。所有内部必验未完成前不宣布出租车收口。
