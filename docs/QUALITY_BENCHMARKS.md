# 固定样本集与版本回放比较

固定样本集将当前有效、经另一位会计核对原件独立确认的评测标准组成不可覆盖的版本。相同名称创建新集合会增加版本号；幂等键重试返回同一集合，改用同一键提交不同内容会被拒绝。同一审核样例的两份标签标准不能在同一个集合重复计数；改变答案应选择新标准并建立新集合版本。

账套复核权限控制集合、标准与比较结果。PostgreSQL 新表启用 `FORCE RLS`，编辑员、只读人员、未分配账套人员及 worker 不能读取该集合；撤销账套授权后再次请求立即拒绝。数据库还检查集合属于同一账套、标准已经独立确认、标识为字符串、不重复计算同一样例。费用数据额外要求企业或事务所管理权限。

## 比较行为

`POST /api/books/{book_id}/quality/benchmarks` 创建版本；`GET` 支持分页、详情；`POST /benchmarks/{id}/compare` 接受基线、候选回放运行 ID 和最低样本数、差异上限。

比较的对象是已归档结果及现有规则／模板的确定性回放，**不会现场调用新模型，也不会修改供应商配置、企业规则、审批权限或正式凭证**。归档模型结果已按模型名称、提示词版本筛选；没有该版本的实际结果时显示“未覆盖”，不能填成通过。

下列情况阻断升级检查：

- 两次运行没有完整覆盖同一个固定版本的标准，存在多选、少选、重复报告项或非法状态。
- OCR 字段域与分录域混用，或评测引擎版本不一致。规则、模板、存量分录模型可以在分录域比较；OCR 只测独立标注的字段及证据页码。
- 固定集合的事实或原件证据已改变；或者候选运行的科目、规则、模板、模型证据等上下文已失效。
- 样本数量不足、候选仍未覆盖／失效、差异超过上限，或者原先通过的项目发生退步。
- 用同一次运行作为基线和候选；汇总计数与逐项状态、差异证据不一致。

旧配置基线可以保留为历史档案，返回 `baseline_archived=true`；比较时必须有当前有效候选，且冻结标准与原件仍有效。旧基线变成历史档案不等于历史正确结果被删除，也不能把失效候选当作当前成绩。

## 费用口径

费用按本次报告引用的、同企业的唯一归档请求汇总；比较本身没有新收费。`confirmed_micro_cny` 与 `estimated_micro_cny` 分开，单位是百万分之一元。未知费用及尚未核定请求显示 unknown／pending，不能当作零；无管理权限返回 `not_authorized`，不泄露企业预算。纯规则／模板回放可明确显示没有模型调用，但这不表示过去制作原始资料从未发生模型费用。

这些数字仅代表当前集合引用的请求，不能作为企业月度总费用；同一归档请求被多个标准引用只计一次。只得到供应商 token 数和单价的费用是估算，正式对账核定仍走原有费用核定流程。

## 新模型的后续接入边界

本批没有把“归档回放通过”解释为未使用的新模型通过。新模型首次测试仍需要实际候选结果。后续应增加独立的评测任务及结果表，读取固定输入，调用现有有界模型接口并使用同一企业外发开关、供应商限流、费用预留及不确定请求恢复；结果只能用于评分，禁止提供采用、审核或过账工具。评测输入与标准答案须分离，避免把审核后的分录／人工字段答案放进模型输入。

当前可由有权限的会计通过标准详情核对已冻结的原件、业务事实与标签；不增加绕过外发或费用治理的通用“上传任意模型结果即可通过”接口。正式自动评测执行应另外验收后启用。
