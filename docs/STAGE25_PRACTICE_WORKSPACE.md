# 第二十五阶段：角色工作入口与月度客户服务

本阶段继续面向 2–3 家企业验证资料提交、审批、AI 草稿、会计复核与导出。月度服务计划和资料验收用于协作，不是正式账本，也不能代替凭证审核、财务软件入账回执或完整性确认。

## 使用路径

1. 管理员进入 `/admin/organizations/{company_id}?tab=setup`，选择检查月份。清单读取当前有效人员、提交模式、审批链、会计权限及本月实际审核导出记录。配置变化后重新检查；没有浏览器“已完成”开关。停用或归档企业只显示管理状态。
2. 在“客户月度进度”选择账套与月份，打开“月度服务单”。填写主办会计、独立复核人、备岗、资料联系人、交付截止与调整原因。人选来自当前已有授权；指派不会新建企业、部门或账套权限。主办与所选独立复核人不能相同。
3. 为长期账套创建资料模板，检查各项责任人、必要性、说明与截止日，然后明确生成本月清单。同一账套、模板与项目重复生成返回原请求，不重复创建；模板在新期间复用时重新核验当前人选。可选择本月或次月的 1–28 日，12 月次月正确进入下一年。
4. 员工从“资料清单”或统一待办进入本人请求。银行对账单、工资资料等可以直接上传 PDF、PNG、JPEG、WebP、XML、CSV 或 XLSX，原件保留 SHA-256；不需要创建含业务金额的事项。也可以按需关联本企业本人当月已提交的业务事项及附件。
5. 员工明确选择原件并提交，或填写“无发生／不适用”说明。提交不表示已验收。具备该账套复核权限的另一人核对后验收或退回；事实、原件引用或授权变化时不能沿用旧依据。原件及每次提交、退回、验收历史保留。
6. 必交资料尚未验收、被退回或验收依据变化，会进入月结阻断。资料请求与动作纳入月结事实指纹，旧快照不能继续关闭期间。没有生成清单不表示资料齐全，最终仍需月结人工完整性确认。
7. “客户人工投入”按月份分页汇总当前有复核权限的客户与账套，支持下钻。只有实际确认的账套计时计入；未计时显示暂无样本，不推算节省率、正确率或全所总劳动时间。

## 角色与界面

员工及部门审批人聚焦提交、审批、补件和资料请求，不显示技术运行导航，也不请求首页 Agent 运行汇总。会计、企业财务与管理员按现有能力保留后台入口。单企业员工的录入窗口显示企业及固定部门身份摘要，保留草稿恢复、手机拍照和附件确认。

服务单、资料请求、客户效率工作区分别使用 `/workspace/service`、`/workspace/materials`、`/workspace/portfolio`。服务单保留企业、账套、月份；待办保留准确资料请求 ID。URL 只提供选择提示，每次读取仍重新核权，不借用上一企业的账套或浏览器保存的角色。

桌面服务单采用人员期限、资料模板并列及下方资料清单；手机顺序显示。未保存编辑有离开保护；409 后读取当前版本，由人重新核对，不自动重提。401／403／404、身份切换及撤权清空当前资料，迟到响应不能回填。

## 权限和原件

- 服务单与模板修改需要当前账套编辑权限；资料验收需要复核权限。既有会计审核后导出、防自审、金额精度、事实修订、企业暂停与 AI 配额规则继续生效。
- 普通员工只读取当前企业有效成员关系下指派给本人的请求；没有因资料指派获得账套读取权。统一待办在计数、搜索与分页之前过滤权限。
- 未提交独立原件只对当前被指派本人开放；会计仅能读取最近实际提交所引用的独立原件。拥有其他会计职责的人失去企业资料联系人身份后，不能继续读取未提交原件。
- 业务事项引用继续遵守原有本人、部门、财务和会计接收权限；资料请求不能提前打开未移交的员工业务附件。独立资料上传不进入自动记账管道，不生成业务金额、来源交易或凭证。
- 每项最多 10 个独立原件、合计 50 MB，单件最多 10 MB；实际前端传输还受现有网关限额约束。CSV 检查编码与结构，XLSX 检查实际工作簿容器、XML、工作表关系及展开上限，拒绝宏、加密和危险容器；本入口只保存原件，不执行表格内容。
- 提交与验收先在数据库事务外读取并校验原件字节，随后在短写事务内重新检查当前权限、期间、动作版本和原件 ID／哈希。对象存储等待不会占用全局写锁。原件在提交结果未知时保留，避免删除已提交证据。
- PostgreSQL 强制 RLS、原生写入守卫、不可变历史与原子审计，与 SQLite 业务校验共同覆盖。运行账号不能通过直接 SQL 覆盖原件、伪造验收或关闭存在资料阻断的期间。

## 助手与运行指标

助手批量加载事项、附件和最新 OCR，只在同一个只读快照内复用重复的确定性 SELECT。权限与事实不跨请求缓存；原生权限函数、未知函数、时钟、锁和写操作不复用。

新增 `GET /api/assistant/conversations/{id}/progress?action_offset=0`，每次实时核对整个会话范围，返回轻量变化游标。活跃任务每秒检查，变化后读取完整工作区；每 30 秒及前台恢复时重新读事实。旧版本没有该路由且明确返回 `404 / Not Found` 才回退原轮询，撤权或资源不存在不会回退。

同一原生 PostgreSQL 证据夹具的未复用构造为 81 条 SQL，优化后的完整 detail 为 55 条，证据及事实指纹一致；SQLite 为 83 → 46。轻量进度每次不超过 7 条 SELECT。这是本机代码层对照，不代表线上 p95 或供应商生成速度提升。未验证文本不会提前发布到前端。

运行指标读取数据库当前处理容量和供应商容量，不再将全局并发固定显示为 2。读取能力函数只向当前有效企业管理员开放，运行账号仍不能直接读取或修改全局政策表。

## MVP 边界

资料模板和生成记录保留历史，本阶段由人明确生成，不按日历自动催发外部消息。生成前需核对资料责任人；已有请求在员工离职后的受审计转派／替代流程尚未提供，撤权后保持阻断，不能用恢复旧权限或伪造“无发生”绕过。模板范围和适用性须在少量试点中确认，再扩展转派治理。

当前人工效率仅覆盖已采集的账套活跃计时；没有自动推算人员产能或承诺一人服务 200–500 家。真实企业、真实票据识别质量和外部财务软件入账，需要分别验收。

## 升级与验证

PostgreSQL 新增 **085_service_plans_materials.sql、086_company_setup_facts.sql**；SQLite 新增 **068_service_plans_materials.sql**。原有迁移不改写。上线前应使用维护账号备份数据库及原件、明确执行迁移，再将 API 和相关 worker 更新为同一代码版本；受限运行账号不承担迁移。

本轮仅修改工作区代码，未提交推送、执行生产迁移或重启线上服务。使用本机虚构资料验证：

- 七个 Stage25 后端测试文件在 SQLite 与独立受限 PostgreSQL 上 **68 项通过、2 项跳过**；跳过的是仅适用于 PostgreSQL 的原生函数／RLS 断言在 SQLite 参数下的分支，PostgreSQL 对应分支已运行。其中 10 项覆盖对象存储读取时无数据库事务，以及校验后撤权、并发版本变化不得追加操作。
- 前端 **37 个测试文件、300 项单元测试通过**；TypeScript、ESLint、Prettier、Ruff、差异检查与生产构建通过。
- 生产构建配合本机 API 的 **13 项浏览器回归通过**，覆盖员工手机入口、开通清单、按角色导航、跨企业月度矩阵、撤权、流水去重、补证、复核、冻结与真实 CSV 下载。另有月度服务与资料清单 4 项、员工录入 2 项、轻量助手进度与人工投入 4 项浏览器专项通过。
- 新库已从迁移 001 完整应用至 PostgreSQL 086，验证使用独立维护账号及受限运行账号；没有访问线上账务或发起真实模型调用。

既有后端还完成了分段回归，包含月结、账务移交与导出、效率及统一待办。初次发现的 6 个旧用例依赖“新企业没有 AI 配置”的旧前提：审计断言改为比较真实基线；人工回退场景显式由管理员暂停 AI，并断言新企业默认开启。两份相关测试文件 46 项复测通过，没有放宽产品审核或权限规则。未到达的 assistant、workspace、monthly 等 18 个相关既有模块另行补测 **157／157 通过**。历史组合没有全部跑完，不将本轮结果表述为全套后端测试通过。

浏览器最终回归使用 `vite build` 与 `vite preview`。开发服务器首轮编译曾发生超时，未将增大业务断言等待时间作为修复；最终生产构建下仍使用原有断言验证完整流程。
