# 首轮验证记录

日期：2026-10-11。环境：本机 Windows，独立临时数据库及虚构测试数据。没有连接原项目生产服务、使用客户真实账务或执行正式过账。

## 自动验证

- 后端：41 项 pytest 用例通过。涵盖精确金额、重复/冲突导入、账套和角色隔离、补证与审核版本冲突、冻结、关闭期间、幂等收据、CSV 公式防护、会话和访问限制。最后工具入口接入与会话修改的相关用例另行通过。
- 前端：23 项 Vitest 用例通过。涵盖 CSV 格式、BOM、引号和多行字段、日期、重复编号、行数/字节/字段长度限制，以及 BigInt 金额边界。
- 浏览器：3 个 Playwright 场景通过。实际跑通新建账套、导入去重、冲突导入在弹窗内显示错误、生成建议、缺证阻断、补证、修改、审核冻结、下载与刷新后重新下载；验证异常筛选以及 390px 窄屏无页面横向溢出。
- TypeScript 检查与 Vite 构建通过。构建仅证明源码可编译，不代表允许生产部署。

首次浏览器运行有一处测试定位器歧义（“企业名称”同时匹配搜索框和创建框），已改为精确标签并重跑完整业务场景通过，其他两个场景通过。此问题不是产品接口失败。

独立代码审查发现并修复了来源导入 SQL 占位符数量和 SQLite 初始化连接未关闭两个问题。额外故障探针验证导出审计写入失败时收据及凭证状态一起回滚，四线程同键导出只产生一份收据与一条审计。

## 工作台统计基准

执行 `python scripts/benchmark_workbench.py`，构造 500 个账套、50,000 条来源、50,000 张草稿及 100,000 行分录，所有数据位于运行后清理的临时数据库。

| 指标 | 本次结果 |
| --- | --- |
| 总览 SQL 数量 | 7 条（5 个 SELECT + BEGIN / COMMIT） |
| 单次总览耗时 | 479.84 ms |
| 统计准确性 | 账套、待审与异常数量断言通过 |

这只是本机 SQLite 单进程、合成数据下的一次汇总查询结果，未测试多用户负载、网络、任务队列、真实 OCR/模型或会计处理时间。单账套详情仍需分页，不能据此宣称已实现一人服务 500 家企业。
