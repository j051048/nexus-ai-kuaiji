# 任务证据第4–6包：企业规则依据、离线对拍、有界只读并行

本轮延续第1–3包，复用企业规则、RSI、H01、AG05 和既有三类调查接口。验收范围仅为本地虚构数据；最终结果与候选绑定见下方验收记录。

## 第4包：企业规则候选可追溯

- 规则详情增加折叠的“审核来源与适用范围”，不新增首页或导航模块。
- 新增只读 `GET /api/books/{book_id}/learning/rules/{rule_id}/memory`。必须提供规则版本与状态版本；每次从现有授权、规则、审核回执和业务来源读取。
- RSI 与界面共用 `learning/evidence.py` 的来源绑定，校验当前待审版本、复核责任、企业、事实版本、原始来源与原件摘要。没有复制第二套规则引擎。
- 依据绑定当前企业、账套、月份、规则版本、政策、科目和往来方。前后两次独立事务重新核对；撤权或变化不能返回旧依据。
- 候选、已发布模板、失效、已停用分别展示。历史金额不进入当前事实；沿用 RSI 的历史100、当前120验证。读取不发布规则、不生成凭证、不代替复核。
- 本轮只将现有普通业务规则接成可解释的记忆。银行核销等专门领域不冒充普通规则来源，跨企业／跨月份召回、自动发布及训练均未开放。

## 第5包：固定任务离线对拍

- `tools/assistant_replay/strategies.py` 复用既有任务清单、AG05 清单校验、H01 原子报告和候选指纹；不新建评测平台。
- 两项固定策略：原串行读取、最多两条并发读取。6个固定任务分别运行，开发3个、独立验收3个；holdout不选优，不按平均分掩盖安全退步。
- 范围外请求、读取失败、版本冲突、撤权、通知结果未知都必须保留原语义。缺失样本仍计入分母；重复、额外、错绑定或篡改响应被拒绝。
- 请求同时绑定候选、清单、身份、企业账套期间和实际执行策略；结论比较忽略时钟与线程完成顺序，保留事实、范围、版本摘要及覆盖范围。
- 输出逐样本 JSON／Markdown。费用为 `null`，模型调用与模型 token 均为0，不把无模型实验解释为真实模型免费或高准确率。

## 第6包：有界只读并行

- 继续使用凭证状态、月结阻断、交付状态三个固定领域读取器。客户端不能传工具、SQL、企业权限或并发参数。
- 默认串行不变。服务器显式设置 `ACCOUNTING_ASSISTANT_READ_PARALLELISM=2` 才启用实验策略；本地浏览器测试显式开启。已有总开关仍生效。
- 每个进程最多两条在途读取，不使用无界等待队列。每任务最多3次初读和3次最终核对；不同分支使用独立连接、独立授权事务。
- `ACCOUNTING_ASSISTANT_READ_SECONDS` 默认3秒，必须在(0,10]。预算覆盖等待连接、数据库锁等待及读取。采用请求局部时限，不扩大共享池，也不修改数据库默认配置。
- 超时后仍在执行的只读分支继续占用原名额，直到真正结束；迟到结果不接纳，不产生后续业务动作。
- 每个分支前后重检授权，最终在既有企业事务中重新核对全部事实并记审计；失败、撤权或版本变化清空事实。结果未知的通知只呈现，不重发、不签收。
- UI仅补充受控停止原因和未检查范围。没有新增模型调用、通用工具、自动写账或多路径投票。
- 这是单进程有界读取能力；跨节点全局配额与真实生产容量不属于本轮结论。
