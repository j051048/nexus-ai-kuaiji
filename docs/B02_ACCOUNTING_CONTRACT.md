# B02 核算契约与期初准备边界

日期：2026-10-18　基线：`cc39a916` + B01 第二轮未提交改动
性质：领域契约 + 实现边界；**不是正式总账、正式记账或账本启用**

---

## 0. 一句话

B02 交付“可版本化、可核验、可核准、可冻结的期初准备数据包”；该包是 B03 正式记账内核的输入，不是正式账本本身。

---

## 1. 主体关系

```
事务所 firm
  └── 企业 company
        └── 长期账套 ledger（稳定核算配置的归属）
              └── 期间 period（YYYY-MM）
                    └── 旧 book（历史物理分区，保留原 ID）
```

- 一个企业可以有多个长期账套；**不按企业名称、公司 ID 或相同科目编码自动合并**。
- 一个长期账套下，一个期间只能有一个 `book` 映射（现有 `ledger_periods` 唯一约束）。
- 旧 `book`、`draft`、`source`、附件、导出和回执 ID 保留，不移动、不重写冻结历史。
- B02 不改变企业权威账本归属；`exported`、人工回执、参考余额都不是正式记账证明。

## 2. 权限矩阵（B02 范围）

| 能力 | 事务所 owner/admin | ledger_manager | 普通会计/复核 | 客户员工 |
|---|---|---|---|---|
| 查看/维护核算政策 | 是 | 是 | 否（B02） | 否 |
| 查看/维护稳定科目 | 是 | 是 | 否（B02） | 否 |
| 建立旧 book → 科目映射 | 是 | 是 | 否 | 否 |
| 创建期初包/导入/核验 | 是 | 是 | 否（B02） | 否 |
| 提交期初包 | 是 | 是 | 否 | 否 |
| 核准/冻结期初包 | 是（且≠提交人） | 是（且≠提交人） | 否 | 否 |
| 查看旧账套/历史 | 按原 book 权限 | 按原 book 权限 | 按原 book 权限 | 按原客户范围 |

- 父账套权限不自动授予全部历史月份。
- 新期间不无条件继承全部成员。
- 技术管理员身份不自动获得会计复核权。
- 撤权、企业停用后由每次请求重新校验，不使用旧缓存。
- B02 的配置/期初接口当前为“管理层/账套管理”专属；若后续需要会计只读，另行评审。

## 3. 核算政策

字段：准则、纳税人身份、行业、会计年度起始月、记账本位币、版本、生效期间。

- `standard_kind`：`small_enterprise` / `enterprise`。
- `taxpayer_kind`：`general` / `small_scale` / `non_taxpayer`。
- **纳税人身份与会计准则分开配置**；不得由“小规模纳税人”自动推出小企业准则。
- 一个长期账套同一时间只有一个 `active` 政策；旧版本保留为 `retired`。
- 目标期间必须落在政策有效期内。
- 首批只开放经确认的模板；未确认模板标“候选”，不能标记正式可用。

## 4. 金额、方向与时间

### 4.1 金额

- 人民币金额：整数分；接口输入为十进制字符串。
- 交易金额保持非负约束；余额/净变动使用有符号金额。
- 有符号余额采用 **借正贷负**（debit-positive）：
  - 资产/费用通常为正；
  - 负债/权益/收入通常为负。
- 正常余额方向是科目属性，不用于把异常余额取绝对值。
- 红字、零金额、舍入尾差必须在样本中定义；B02 不引入 float。

### 4.2 时间

- 会计日期、期间、会计年度、启用期间分别定义。
- B02 默认支持“会计期间起点启用”。
- 年中启用必须显式提供：年初余额、截至启用前的本年借贷累计、启用期期初余额。
- 不静默接受模糊日期；旧账资料归档日期范围不被破坏。

### 4.3 三个余额

| 字段 | 含义 |
|---|---|
| `year_opening` | 会计年度起点余额（有符号） |
| `ytd_debit` / `ytd_credit` | 截至启用前的本年累计发生额（非负） |
| `opening` | 启用期期初余额（有符号） |

恒等式：

```
year_opening + ytd_debit - ytd_credit == opening
```

- 不得以 `opening` 为起点再加一次 YTD。
- 历史凭证只用于查阅，不重新生成正式发生额。
- 损益累计与结转抵销分别记录；不凭结转后余额反推经营发生额。

## 5. 稳定科目身份与版本

- `ledger_accounts.id`：稳定身份；`code` 只是版本属性。
- `ledger_account_versions`：编码、名称、父级、层级、末级、类别、正常方向、辅助要求、有效期、版本。
- 同账套有效范围内编码不得冲突；编码变更必须新版本。
- 父级必须同账套、存在、无环、层级 1–6。
- 末级科目才能录入期初；汇总科目不得与末级一起重复计入。
- 科目更名/停用/辅助要求变化必须版本化；旧版本 append-only。
- 已使用科目新增子科目时，父级自动转为汇总科目（新版本），历史版本不变。
- 旧 book `accounts.code` 通过 `ledger_account_mappings` 显式映射到稳定科目及版本；不按 code 自动猜测。
- 现有模板 `account_code` 继续走旧 book 科目；B02 不改旧草稿/已审凭证/导出事实含义。

## 6. 期初包状态机

```
draft → validated → submitted → approved → frozen
  ↑         │           │           │
  └── 修订/重新导入 ←────┘           └── superseded（新版本核准时）
```

- `draft`：导入/录入，可重新导入新版本。
- `validated`：核验全部通过；配置变化会使核验失效。
- `submitted`：绑定具体版本和配置指纹；提交后内容/配置变化不能继续核准。
- `approved`：独立核准；不能原地修改。
- `frozen`：冻结；内容不可变，只能新版本 + 历史链。
- 同一 package 只能有一个 `approved/frozen` 当前版本；新版本核准时旧版本转 `superseded`。
- 核准时重新鉴权、重新核验、检查版本；并发核准只生效一次（唯一索引 + 事务）。

**核准与启用分离**：`approved/frozen` 只表示期初准备包通过；不改变账本归属、不生成凭证号、不写正式分录、不触发月结/报表。

## 7. 核验规则（B02 已实现/未实现）

已实现：

- 启用期期初合计为 0（借正贷负）。
- 逐行 `year_opening + ytd_debit - ytd_credit == opening`。
- 汇总科目不得直接录入。
- 同科目+辅助维度不得重复。
- 科目版本/政策版本必须仍是当前版本；否则 blocked。
- 配置指纹必须与导入时一致。
- 未结事项往来方必须属于当前企业且启用。

未实现/待 B03–B04：

- 总分控制科目与辅助明细的完整勾稽。
- 未结事项与应收/应付控制余额的完整性检查。
- 缺失值 vs 明确为零 vs 不适用的字段级状态。
- 复杂多栏辅助、跨期收付、税额分摊的期初勾稽。

## 9. 与现有模块的边界

| 现有能力 | B02 用法 | 不做什么 |
|---|---|---|
| `ledgers` / `ledger_periods` | 长期账套、期间、旧 book 映射 | 不新建第二套账套系统 |
| `accounts` / `catalog` | 旧 book 科目继续可用；新稳定科目另建 | 不改旧科目表含义 |
| `monthly_baselines` | 可作为期初来源，需显式映射/核验 | 不把 reference 改正式 |
| `legacy_migration` | 历史资料归档继续保留 | 不自动回填 posted |
| `settlements` | 未来未结事项勾稽 | B02 不实现完整子账 |
| 附件/备份 | 新原件走 B01 注册表 | 不新增遗漏附件类型 |
| `drafts` / `exports` | 不变 | 不生成凭证、不改 exported |

## 10. B03 可依赖的接口

B02 提供给 B03 的稳定输入：

- `opening_packages` + `opening_package_versions`：已核准/冻结的期初包头。
- `opening_lines`：按稳定科目 + 辅助维度的有符号期初、YTD、启用期初。
- `opening_open_items`：未结应收/应付。
- `opening_checks`：核验证据。
- `accounting_policies` / `ledger_accounts` / versions：准则、科目、辅助要求、版本。
- `ledger_account_mappings`：旧 book 科目到稳定科目。

B03 必须自行实现：凭证/分录、凭证号、过账、余额、总账/明细账、结账、报表。B02 不提供“正式启用”接口。
