## 关键流程与约束

- 事实修订需要另一名有当前权限的人员接受。未审事实追加替代来源及草稿，旧原件、提交快照、分录和映射历史保留；已审核或导出的事实只能形成调整建议。
- 旧月份授权不能读取新月份事实、后续补件或新原件。历史附件下载再次核验旧快照范围、当前授权、路径、大小和 SHA-256。
- 重复银行来源只隔离未审核副本，保留主来源和原记录。未完成的异常、补件、银行匹配或收付分配必须先处置。
- 月结依赖当前资料、异常、后台任务、流水匹配、事实修订和逐行交付核验结果。资料完整性由真人明确确认；事实变化令旧快照失效，关闭时重新检查权限及状态。缺失、NULL、标量或不完整回执不能制造已核验状态。
- 长期账套保留各月份旧 ID。新月份授权明确选择，科目和模板按快照继承，规则仍需本期正反例评估。稳定企业主数据不覆盖原始名称，别名由另一名复核人员审批。
- 同期部分付款、合并付款使用整数分余额和确定性尾差。原应付业务和银行清偿分别审核；银行清偿不得重复确认费用。已审核银行分配不可撤销，清偿审核样例保留追溯但不能推广为普通银行分类规则。
- 增量监控使用同事务变化登记及有界巡检；人工效率只累计明确确认的活跃间隔，缺失记录不等于零投入。全库写协调锁和全库两件、每企业一件模型并发限制保持不变。
- T+ 只接收中性参考文件，冻结映射版本及待发送意图；参考记录不直接创建账务。真实发送被禁用，尚无经过客户实际版本验证的原生导入格式或连接器。

浏览器回归还核验从核销、业务移交及批量待办跳转指定凭证的行为：请求未完成时不能操作旧凭证；目标不在当前页不能回退到第一张；过期请求不能覆盖新会话或更新后的凭证。核销测试人为延迟真实账套响应，再核对实际审核请求中的两个凭证 ID 和各自后端状态。新增失权测试通过真实 API 撤销目标账套授权，实际凭证请求返回 404，界面保留明确错误且无审核按钮，不自动显示其它企业的凭证。

## 实际恢复演练

使用 WSL PostgreSQL 14 客户端与本产品恢复脚本，在两份新建的专用本地数据库中执行真实 `pg_dump --snapshot` 和 `pg_restore`；只包含虚构账套及一份合成原件。2026-10-12 最新演练恢复了 54 个迁移，校验数据库归档、原件哈希、迁移清单、账套和 FORCE RLS 标记；再次恢复到已有数据库被拒绝，结果保持 `serving_enabled=false`。

本地演练记录：`.codex/stage10-recovery-e8596dff97f8/drill-result.json`。只有 Windows 调用 WSL 客户端的执行方式作了适配，快照、清单和恢复检查使用交付脚本实际代码。SQLite 使用实际 backup API 和原件校验的测试也已通过。

这不是生产恢复认证：没有启用恢复库对外服务，也没有覆盖 Supabase Auth/Storage、生产规模、运行角色重新授权或真实 RPO/RTO。操作边界见 [备份恢复说明](BACKUP_RECOVERY.md)。
