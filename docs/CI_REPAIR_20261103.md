## 根因与修复

1. **OCR**：Python 3.11 解码超深 JSON 抛 `RecursionError`，未转成 `ocr_response_invalid`。补解析边界捕获；保留仅一次 OCR 请求、不调用字段模型及释放未发送费用的断言，并补可跨 Python 版本复现的失败夹具。
2. **N03**：受限 worker 直接读取 `users` 被数据库正确拒绝。删除自由收件人查询；前向迁移 **208** 在既有 `begin_delivery_notification` 的授权、当前收件人、租约、恢复 hold 检查后投影当前邮箱。保留 worker 不得读用户表、旧租约无效、unknown 不重发、撤权与恢复门禁。地址不写入队列 payload。
3. **C01**：门禁复用 AK05 已积累大量夹具的库，原 300 秒预算不足。CI 为 C01 单独准备新库与受限角色；有限预算 600 秒，保留 34 个确切用例/零跳过检查，并补超时栈和脱敏部分日志。没有清空其他套件的数据。
4. **P01**：Linux pytest 的 `...current` 目录链接使同一恢复证据被计算两次。以真实路径去重；仍拒绝两个不同证据、缺证据及目录外链接。新负向测试先失败再通过。此轮没有重新宣称整个联合恢复已验收。
5. **真实前端问题**：客户管理员有提交权限却无业务导航；税务底稿 StrictMode 重放复用已取消的 AbortController，导致无法提交；手机部门配置选择框撑破视口；发票导入详情完成前仍允许切换批次。另在完整分片中复现事实修订迟到读取把已改 80 元重置成 100 元；加入真实 API 顺序回归，合并并行的输入保护，并把自动读取标记移到成功接纳后，避免 StrictMode 取消首次读取后永久不加载。分别修复并保留权限、范围与人工复核边界。
