# 月度参考余额与固定事项（第二批）

本模块用于少数客户企业的月度核对。正式账本继续归客户的财务软件所有；本模块没有连接未知版本的 T+，没有自动过账，也不把客户提供的余额或手工回执描述为实时总账。

## 参考余额的四个范围

按长期账套、当前期间、实际科目和稳定辅助项 ID 核对。期初基线取上一月期末，期末资料取当前月份，均明确“人民币、仅已记账、净借余额”口径。负数表示净贷余额。

| 范围 | 纳入参考期末计算 | 行为 |
| --- | --- | --- |
| 客户提供、经另一复核账号核对的外部期初 | 是 | 未列出的维度保持未知，明确的零才显示零 |
| 已核验完整交付 | 是 | 最新完整回执必须与冻结导出逐项、逐行一致；新回执未知或有差异会退回待核验 |
| 已审核待交付 / 已导出待回执 | 否 | 单独展示金额和数量，不能推定外部已经记账 |
| 未审核草稿 | 否 | 单独展示，不计入已审核运动 |

参考期末 = 已独立核对的外部期初 + 本系统本月已核验完整交付的借方 − 贷方。若外部系统有其他入口录入、未上传资料、遗漏回执或存在辅助项汇总口径差异，会显示差异或未知，不能推断为完整报表。

科目汇总与往来、项目等明细各自成行。客户明确提供的科目汇总使用对应科目各辅助维度的运动合计；明细使用相同辅助 ID 的运动。页面不把汇总行与明细行相加。

## 保存原始余额资料

支持结构化表单和 UTF-8 中性 JSON / CSV 文件。文件上限 2 MB，每份最多 1,000 个不重复维度。上传文本按原样保存，包括首尾空白；记录 SHA256，下载时重新检查当前账套读权限，返回私有不可缓存响应。

JSON 示例（期初需要上一月期间）：

```json
{
  "period": "2026-09",
  "currency": "CNY",
  "scope": "posted",
  "lines": [
    {"account_code": "客户实际科目编码", "balance": "123.45", "auxiliary_values": {}}
  ]
}
```

CSV 列必须为 `account_code,balance,auxiliary_values,period,currency,scope`，辅助项为 JSON 对象；金额不得使用浮点 JSON 数字、科学计数、千位分隔或三位小数。不要在上述示例中使用不存在的科目编码。

也可复用同企业、同长期账套已经独立验收接管的旧账期末，或已确认 T+ 文件接入记录。服务器从已有快照读取金额和映射，用户不能在复用请求里替换原金额；仍需另一位复核人核对本次月度用途。此类下载明确标记为 `legacy_snapshot` / `bridge_snapshot`，不是原财务软件的原始导出文件；迁移原件继续由旧账原件入口提供。表单下载标记为 `structured_entry`，不是上传原件。

余额、确认、检查和核对记录均追加保存，不能改写历史。新余额版本、草稿变更或回执变化会令原检查过时。人工关闭检查需要填写原因，原有差异数值保留，状态为“已人工核对”，不变成“自动平衡”。

## 固定事项草稿

会计配置确定性的实际科目、辅助项、借贷金额、合同或事实证据及有效月份。每行单边非零，两侧总额相等，全部金额按整数分计算。另一位有当前账套复核权限的账号审批最新版本后，才可以为 URL 所指定月份生成普通未审草稿。

同一长期账套计划、同一月份只能生成一次。重试返回同一草稿；计划新版本不能让已经生成的月份重复生成。草稿依旧需要凭证复核后导出；已审核或已导出记录继续走已有修订、调整流程。

新月份科目名称、类别、方向或辅助要求变化会阻断旧计划；必须重新配置并独立审批。无需每月重新创建长期账套。当前支持明确人工触发，未安排按日历自动批量生成或自动审批；后台任务可以调用同一确定性服务，启用自动计划前还需要事实确认和运行策略。

月结按最新已审批版本判断到期义务。尚未审批的新版修改金额或结束月份，不能把原来已审批且到期的未完成计划从月结待办隐藏；应先完成新版的独立审批，再决定本月是否生成。

适合先试验合同租金等有明确固定金额的事项。工资、税额、折旧金额和本月是否实际发生必须来源于经核对的真实资料，不能由模型猜测。变化应形成新版本，不默认沿用旧金额。

## 月结与权限

新月度数据及计划进入月结指纹。最新余额尚未独立确认、未形成相应月度检查、月度检查待人工核对或过时，以及本月已审批却未生成的固定计划，都会成为月结阻断项。旧的月结快照不会在新资料加入后仍被允许锁期；月度检查自身不进入自身指纹，避免生成即过时。

所有 HTTP 接口位于 `/api/books/{book_id}/monthly`。当前期间读、编辑、复核权限分别决定查看、录入、独立确认；撤权后立即重新检查。跨月配置只在相同长期账套且已有某一期间授权时可见，不授予原月份业务资料访问权限。已关期拒绝创建余额、检查、审批或生成草稿。

PostgreSQL 新增 `079_monthly_references.sql`，SQLite 新增 `063_monthly_references.sql`。新表启用 FORCE RLS、追加不可变保护及原生金额、来源、独立审批、版本和月份幂等检查；保持默认全局写事务门，尚未切换成账套领域细锁。

原生检查要求报告的当前事实、维度集合和金额完全一致。缺失统计字段返回拒绝，不能通过 SQL 的空值判断绕过；伪造零差异或未知科目同样被拒绝。JSON 的重复键、CSV 的重复列及辅助项对象的重复键进入人工修正，不采用“后一个值覆盖前一个值”。列表只读取原件元数据和哈希，不批量读取原始文件内容。
