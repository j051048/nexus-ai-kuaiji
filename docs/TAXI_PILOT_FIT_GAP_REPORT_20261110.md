## 1. 判断

**可以沿用当前产品建设这家出租车公司的共享财务工作台，但目前还不能直接按三份材料完成整个业务闭环。主要缺口是行业数据接入、核算规则和 T+ 衔接，界面改造只是其中一部分。**

现有的企业隔离、原件管理、制单与复核分离、版本控制、核销、银行核验、内部正式账簿、月结、交付包和签收值得保留。它们提供了可靠的流程基础，不需要重新建设一套出租车 ERP。

然而，这次试点的核心不是“员工上传发票后做报销”，而是：

> 出管系统与 OA 提供已核定业务资料 → 按驾驶员、车辆、合同和期间核对 → 按已确认规则生成待复核凭证 → 人工复核 → 导入 T+ 并核对结果 → 让管理者从收入和成本数字追到原始依据。

**建议以“共享核算、复核与经营分析工作台”定位试点，保留 T+ 为客户选定的法定账与法定报表出口。** 平台内部记账完成、文件已导出、T+ 导入成功、T+ 已审核/过账、客户已签收，必须分别展示，不能互相代替。

本轮还复现了一项与样本直接相关的代码缺陷：**损益结转遗漏费用科目的贷方余额**。因此，即使通用回归通过，也不能直接把样本利润表接到当前结转程序上。

## 4. 优先解决的代码与架构适配问题

### 4.1 损益结转必须先修正确性

当前 `PeriodicService.generate_closing()` 仅处理“收入贷方余额”和“费用借方余额”。费用贷方余额被跳过，收入借方余额也需要补对称专项测试。样本中财务费用为 **-23,976.49 元**，销售费用中也有电费和优惠冲减，正好会碰到这一类数据。

此外，当前结转按科目汇总，未保留逐车辆/部门的辅助维度。材料的 1,001 行结转、651 行成本结转并不只是“大文件”，还承担辅助账归零与追溯语义。不能把这些行随意合并成几个科目后声称等价。

应补：正常与反向余额、收入冲减、费用退款、辅助维度、科目有效版本、重复生成与更正失效的测试。损益科目要通过经审核的报表/结转分类定义；不能把所有 `cost` 科目一律当期间费用，也不能仅凭中文名称猜测。

若首期结转仍由 T+ 执行，平台可以先导入并核验 T+ 结转证据，暂不开放有缺口的内部自动结转。但需要明确产品模式，不能让两个引擎各自生成一遍再合并。

### 4.2 T+ 是已有“桥接底座”，不是已完成“原生导入”

当前通用导出是 12 列 CSV；T+ 桥接生成 `hengzhang.tplus.delivery.v1` JSON，状态为 `awaiting_adapter`，真实发送明确关闭。材料要求原生 **54 列 A:BB**，约 13 列承载实际数据，其余列也要满足客户版本的模板要求。

应在现有冻结清单和科目/辅助映射之上加一个版本化 T+ 文件适配器，绑定模板、期间、凭证集合、源版本、金额和行数。不要另造一套审核或外发队列。

材料要求统一凭证字号“记”，当前周期性记账使用“转”。应先决定内部凭证类型与外部凭证字号如何映射、哪端分配最终编号、断号/重复导入如何核对，再实现导出；不要修改历史凭证或凭空填入客户编号。

现有回执 `verified` 只证明提供的回执与冻结清单相符，不代表 T+ 已独立确认过账。首期可以人工导入 T+ 测试账套并回传结果，**不以自动直连 T+ 为试点前提**。

### 4.3 大凭证不能靠直接提高上限解决

样例规费 575 行、保险约 258 行、结转 1,001 行，会碰到当前 100/200 行上限。手工接口还禁止同科目同辅助项重复，这也可能与一张凭证内先冲回、再计提的展示方式冲突。

应明确选择并验收一种策略：允许受控的大凭证，或按业务与借贷关系拆成多张平衡凭证。若拆分，必须保留原批次、源行归属、总额与编号关系，不能按固定行数机械切割，更不能丢掉重复行的独立来源。前端需分页展示分录，批次核对不依赖渲染千行表格。

### 4.4 行级来源链是四层下钻的前提

已有银行导入保存文件 SHA、原始行号与来源对象，已有通用附件和事实版本，可以复用。但还没有贯通出租车各类底稿到凭证行、再到利润表项目的完整关系。

需要形成：

`源系统/文件版本 + 页签/行号 → 核定业务事实 → 规则版本与计算明细 → 草稿行 → 已复核版本 → 导出行 → T+ 回传凭证行 → 报表项目`

每次汇总或拆分都保留关系和金额贡献。一个工资/维修/水电混合凭证只能取相关分录，不能把整张凭证金额归到多个费用项目中。来源纠错必须使相关待审版本、预览和未冻结报告失效，冻结历史保留。

`ingestion.receive_webhook()` 目前完成受理和幂等留痕，返回 `received`，代码明确要求消费者后续产生处理结果；不能把 202 受理当成接入完成。现有银行 Excel 解析器只接受单工作表、拒绝公式，这是合理安全边界。出租车多工作表工具应增加指定页签、指定区块的领域适配器，不能直接取消通用解析限制。

### 4.5 主数据可以复用，经营关系需要补充

已有 `project/counterparty/bank_account` 主体、别名审核、实体版本，以及 `department/employee/project/counterparty` 辅助维度。车辆可对应项目，驾驶员可对应往来主体，不必为每辆车新增一种权限角色或科目。

缺的是：车辆稳定 ID、驾驶员稳定 ID、经营权/合同、单双班、驾驶员与车辆的有效期关系，以及外部编码与 T+ 编码映射。车牌和姓名是显示属性，脱敏车牌尤其不能当唯一键。一个驾驶员换车、同车双班、历史别名变更，都不能改写旧月份归属。

首期优先沿用出管系统作为这些业务关系的主来源。平台维护映射、审核和历史版本，不再建立与出管竞争的车辆管理系统。

### 4.6 内部账与 T+ 权威账要有明确接合方式

当前月度交付包要求内部锁期、正式期初/试算/银行核验、当前独立复核的已发布报表。它适用于现有内部核算路径，**不能直接拿一个 T+ PDF 附件替代全部条件**。

对于这家客户，建议先走“已复核凭证交付 T+”路径；如果要生成包含 T+ 法定报表的完整月度包，再扩展现有交付机制，明确外部报表来源、T+ 凭证与平台导出对照、截止时间、差异核验和独立复核。现有内部模式门槛保留，外部模式也要有等价证据，不能通过删除锁期或报表条件解决。

管理看板可以提供尚未月结的估计结果，但必须标出“未复核/部分覆盖/截至时间”，与 T+ 已完成核定的数字分层。交付包签收是收到某版本资料的证据，不是认可税务处理正确或证明 T+ 已过账。

税务口径需单独签认：材料把规费收入描述为含税全额确认、税费进成本，又把“租赁收入、利息收入”放在同一 `÷1.13` 分类。不能据此把全部收入套同一公式。增值税法区分交易类型与计税方式，并明确存款利息不属于应税交易；这并不自动决定客户其他利息收入的性质。具体规费业务、一般/简易计税资格、税款会计列报、优惠和附加税适用，应由客户负责会计结合有效政策确认。材料中的 3%、13% 和 7%/3%/2% 只能作为待核实的客户口径，不能作为软件内置普适真理。[财政部公布的《中华人民共和国增值税法》](https://m.mof.gov.cn/zcfb/202412/t20241225_3950494.htm)

## 6. 流程与前端应如何收敛

### 6.1 保留后台十类业务，前台只呈现六个阶段

| 前台阶段 | 用户主要做什么 | 后台负责什么 |
|---|---|---|
| 收齐本月资料 | 查看出管/OA/银行是否到齐，补传缺失文件 | 来源鉴别、期间检查、主档映射、幂等、有效版本与范围检查 |
| 核对差异 | 处理“少一人、缺项目、金额不符、旧数据混入”等异常 | 按驾驶员/车辆/合同勾稽、保留排除理由和源行指针 |
| 准备本月凭证 | 查看规费、成本、费用、租赁、税费各批次的计算预览 | 按规则生成草稿、借贷与辅助项校验、预算与版本约束 |
| 会计复核 | 对照原件、差异和计算依据，逐项确认或退回 | 独立复核、来源版本重检；源数据变化后旧审批失效 |
| 交付 T+ 并核对 | 下载已复核文件、录入/导入 T+ 结果，处理拒绝项 | 冻结导出、编号映射、逐行对照、重复与未知结果处理 |
| 月度确认与归档 | 对平最终报表，确认本月资料包 | 对账重检、结转与报表证据、期间冻结、双档归档与签收 |

资料接入、成本计算、收款核销可以按依赖并行开展，不必强制执行一条十步长向导。材料第 7 步的“银行对账后锁期”应改成银行核验结果；租赁、税费等后续分录发生后要重新检查受影响项。内部核算模式仍按现有“报表核验/复核→月结锁定→报表发布→交付”门槛运行，不颠倒它的依赖。

材料第 5 步的领导看板可以提前看，但只有明确标注的暂估/待复核数。月末完整利润要覆盖后续租赁、税费和调整，避免第 1 步与第 8 步重复确认租赁收入。

### 6.2 按岗位减少重复劳动

- **车管/经营人员**：继续在出管系统核定；平台只处理缺件、异常确认与补充依据，不要求再次录入驾驶员和车辆台账。
- **员工**：已在 OA 审批的费用不再重复提单；平台员工入口主要用于补票、解释差异及查看处理结果。
- **会计**：首屏显示本企业、本月份和“需要我处理”的异常。批次卡片只显示记录数、金额、阻断数、负责人和一个主操作。
- **复核人**：原件/底稿、计算差异、分录同屏；大批次先看勾稽与异常，再抽查或逐项复核。不能用“全绿”替代承担责任的复核动作。
- **领导**：收入、成本、利润、欠款、资金分开。点击金额后先见构成和变动原因，再按需展开凭证与底稿，不在首页展示数百行分录。

所有待办应直达“这一个期间、这一个批次、这一个差异行”，处理后返回原筛选和位置。资料来源有问题时提供“退回源系统更正/上传更正版”，不把平台编辑按钮伪装成可以修正 OA 或出管原始事实。

### 6.3 利润表下钻保留材料的优点，但不要复制成静态说明书

沿用四层结构：**确认方式 → 计算逻辑 → 基础资料 → 形成的凭证与原件**。每层内容应由同一冻结来源版本生成。

首层给金额、占比、期间和已核对范围；第二层给公式参数、规则版本和尾差处理；第三层给车/人/合同与源文件定位；第四层给对应分录和 T+ 回传位置。无依据时直接显示“该项暂不能追溯到完整底稿”，不让模型补出一个解释。

单车“贡献”与单车“净利润”也要分开：共同费用未分摊、资产折旧未按车归集时，只能展示已归属收入和成本，不能称为完整单车利润。共用费用分配规则应单独可见。
