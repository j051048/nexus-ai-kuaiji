# 任务记忆、证据关联与人工办理：第 1–3 包验收

日期：2026-11-10。范围：当前业务事项办理链的本地离线收口，不是生产发布验收。

## 交付范围

1. 任务恢复：复用业务事项页和现有路由，只在当前浏览器按用户、事务所保存事项编号、企业、月份、筛选、分页、停留区和参考版本。保留 7 天，可清除。显式深链接优先，不自动转移企业；恢复先重新授权读取当前事项。金额、原文、凭据、审批结论不写入本地记忆。不提供跨设备同步。
2. 证据关联：复用 IntelligenceService 的当前核对结果，增加版本化关系投影。原件、识别转录、申请金额、授权范围内的已关联银行来源通过证据指针关联；同一文件哈希只计一个原件来源。派生与依赖关系独立于同源、冲突关联，不按模型置信度投票。仅在业务对象、期间、币种、金额口径一致时用 Decimal 比较；分次收付与票据总额不直接判为金额冲突。旧版本不授权当前办理。
3. 人工闭环：办理卡片显示具体差异、金额对照、负责岗位和实际入口，跳到现有核对区或办理区。已有人工核对、退回、财务核验等接口保持原样。处理后重新读取依据，分别显示已记录人工核对、已不再检出、仍待处理；均不等同会计复核、正式记账或交付完成。

## 本轮修复的边界

- 事项版本不变但异常核对记录变化时，旧卡片也必须失效。第二个只读事务重新核对权限、事项状态、原件、核对指纹和处理状态，避免拼接不同时刻的依据。
- 撤权清空事项、原件、办理区及恢复记录；迟到响应不能复活资料。恢复和重新核对只发读取请求。
- 前端整体验收关系结构，拒绝错企业/事项/版本、错误原件哈希、悬空引用、派生环、未知跳转入口和不完整差异。
- 多份原件可能产生重复的同类核对提示。本轮先复现，再将相同提示合并；存在未处理副本时始终保持待处理，不虚增独立来源。
- 不新建 agent 框架、图数据库、审批状态机；不增加模型调用，不自动重发 unknown，不改变费用或 attempt 规则。
