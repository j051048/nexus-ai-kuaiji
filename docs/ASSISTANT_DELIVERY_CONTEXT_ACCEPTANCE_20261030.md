## 本轮完成范围

围绕“为什么这家企业本月还不能交付”，复用已有业务检查，不新建月结、权限或记账规则。新增 `app/assistant/delivery_context.py`，由现有助手入队、发送前重检及围栏完成事务共同调用：

- 月度服务单：取当前版本与期限，不向模型发送联系人姓名、其他人员 ID 或私有备注。
- 交付就绪检查：直接使用 `MonthlyPackageService._inspect` 的阻断原因、负责岗位和处理入口。
- 月结预检：复用 `CloseService._snapshot` 及依赖指纹；旧预检失效时要求重新预检，不拿旧结果作当前结论。
- 已冻结交付包：绑定 ID、版本、manifest hash 和现有客户签收状态；签收与外部软件过账分开表述。
- 已选事项和凭证：提示缺原件、待复核、现有金额冲突；只在单份完整、人民币、有效金额证据下以整数分计算差额，OCR 明确标为待核验。

只在包含“交付”及“为什么/为何/不能/卡/状态/进度/还没”的问题上启用，不宣称通用意图识别。必须明确单一账套和月份；不从数组第一项或系统日期猜测“本月”。普通问题不增加月度诊断读取。

## 权限与发布边界

1. 当前企业、账套及事项仍走原授权校验。客户岗位只获得当前已授权、已选事项的局部诊断；完整月度诊断还要求事务所业务角色及该账套编辑或复核权限。
2. 投影绑定企业、账套、期间、可见证据、来源版本与内容指纹。沿用原有引用类型，不新增隐藏数据查询入口。
3. `can_deliver` 始终为 `null`，输出只是核对提示。模型自由文本不能覆盖阻断项或产生审核/导出授权；建议动作不自动执行。
4. 服务单、预检依赖、资料或授权变化时，现有 Worker 重算快照并拒绝发布旧回复。发送后已知用量仍结算；未知结果与 attempt 防重发规则保持。
5. 过长诊断按完整条目截取，明确显示未展示数量；不能因摘要省略就声称无阻断。资料不完整时不默认金额为零。
6. 本轮无 SQL 迁移，无 C01、前端、费用规则、真实模型传输配置或审核导出规则改动。

## 先失败、后修复

先复现：原回复缺月份/负责岗位/下一步；服务单在回复期间改变仍成功发布；未指定账期没有明确选择提示。加入当前业务来源投影及快照绑定后通过。

另外两组明确红测：

- 80 条诊断渲染到 46,351 字符，超过受控回复预算：补齐整条截断与遗漏提示后通过。
- 不完整 OCR 边界：`5 failed, 1 passed`。被截断的证据仍显示 0.10 差额；null/缺字段/NaN/bool 金额抛异常。改为保留冲突及人工下一步，不计算无依据的差额；多票原有保守行为保留。

专项还覆盖：只读 SQL、私有备注不外发、客户不可见内部服务单/预检、旧预检、包版本/hash、提交边界发生变更、重新计算 hash 后的错企业/账套/期间/引用/伪造交付授权。

## 实际限制

结论仅为本地 SQLite + FakeProvider/MockTransport 的工程和固定任务验收。正常数据、月结、报表及交付包由既有真实领域服务在临时数据库生成；模型分类仍是预置 mock，不代表真实模型能自行识别所有阻断。
