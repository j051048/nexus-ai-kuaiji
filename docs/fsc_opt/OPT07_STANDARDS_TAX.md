先读 `OPT00_MASTER.md`。前置：OPT01。本批对应 FSC04 的追加项。

总原则（FSC 总令第 3.9 条）：税率、核算制度、确认方法来自企业批准的、带版本和生效期的政策数据。**不从行业名称推定，不替客户决定适用哪套制度**。本批只提供能力和合成数据下的验证。

## OPT07-B  报表模板数据化

**问题。** `nexus_backend/app/reports/service.py` 只有 `TEMPLATE_ID = "small_enterprise_basic"`，模板的 `definition_json` 只是指向 Python 算法名。账套上存了 `standard_kind`（`small_enterprise` / `enterprise`），但报表不读它。

**做法。**

1. 设计模板定义的数据结构：报表、行次、行名、取数规则（科目代码前缀集合、借贷方向、期末余额或本期发生额、加减关系、小计与合计行）。只允许声明式规则，不允许表达式字符串、SQL 或可执行代码。
2. 把现有小企业模板的取数逻辑**原样**搬进数据。搬迁前后同一账套同一期间的报表输出必须逐行逐分一致。
3. 模板带版本。已发布的报表记录所用模板版本，模板升级不改变历史报表。
4. 模板选择由账套的 `standard_kind` 决定。找不到对应模板时明确报错，不回退到小企业模板。
5. 报表勾稽检查（资产 = 负债 + 所有者权益）保留，改为基于模板中标注的合计行。

**先失败测试。**

- 快照对比：用现有测试账套生成修改前的三张报表保存为基准，修改后逐行比对一致。基准文件在修改前生成并入测试夹具。
- `standard_kind` 为 `enterprise` 且无对应模板时报明确错误（修改前会静默用小企业模板）。
- 模板定义含非法字段或可执行内容时加载被拒。

**验收。** `python -m pytest nexus_backend/tests -q -k "report"`，PG 侧同样通过。

## OPT07-C  企业会计准则报表模板

**做法。**

1. 在 OPT07-B 的结构上增加一套企业会计准则一般企业报表模板：资产负债表、利润表。现金流量表若现有小企业模板的实现方式无法直接套用，先不做，在状态文件说明。
2. 配套一套企业会计准则科目表种子，作为可选初始化数据，与现有小企业科目表并存。
3. 行次和科目对应关系你按公开的准则格式编制，并在模板文件头部注明"合成模板，未经客户与会计师确认，仅供离线验收"。**你不确定的行次不要编造取数规则**：留空并列入状态文件"待专业确认"清单。
4. 不为医院选模板、不新增政府会计或医院会计制度模板。

**先失败测试。** 用企业准则科目表建合成账套，录入覆盖主要报表项目的凭证：资产负债表勾稽平衡；利润表净利润等于损益类科目结转额；每个有取数规则的行次有至少一条用例验证金额。

**验收。** 新增用例 SQLite 与 PG 通过；小企业模板的快照对比仍一致。

## OPT07-E  税费政策模型扩展

**问题。** 现在每账套一个增值税率加一个附加税率（`nexus_backend/app/tax/workpaper.py` 的 `vat_rate_bp` / `surtax_rate_bp`）。不支持多税率、文化事业建设费、农产品进项抵扣、企业所得税预缴、印花税。

**设计约束。**

1. 先读 `nexus_backend/app/tax/` 全部模块和 FSC04、FSC07–FSC09 的提示词，弄清现有"企业批准的政策"是如何建模和版本化的（搜索 `policy`、`rate_bp`）。在现有模型上扩展，不另起一套。
2. 税费项目做成政策数据中的条目：税费种类、计税基础来源（哪类业务数据或哪些科目）、税率或征收率（基点）、生效起止、适用条件、依据说明、批准人。
3. 一个账套同一期间可以有多条增值税税率条目，按业务类型或发票税率分别计算。
4. 首批支持的种类及范围：
   - 增值税多税率：销项按条目分别计税再汇总。
   - 附加税费：以应纳增值税为基础，多个附加项目分别列示。
   - 文化事业建设费：计费基础和费率来自政策条目。
   - 农产品进项抵扣：抵扣基数和扣除率来自政策条目；只做计算底稿，不判断票据合规性。
   - 企业所得税预缴、印花税：只建模型和底稿结构，计算规则留作政策条目驱动的简单"基础乘比率"，不实现纳税调整。
5. 所有计算用 OPT01-C 的统一取整函数。
6. 没有对应政策条目时，该税费项目显示"未核定"并阻断真实路径，不用默认值。合成政策必须带明确标记。
7. 保持"制单人不等于复核人"，沿用现有税务底稿的复核流程。

**先失败测试。**

- 同一期间两种税率的销项分别计税，合计正确。
- 政策条目过期或缺失时计算被阻断并提示缺哪一项。
- 文化事业建设费、农产品抵扣各一条合成成功用例和一条缺政策反例。
- 政策版本变化后，已复核底稿不受影响，新底稿使用新版本。
- 现有单税率账套的计算结果不变（回归）。

**验收。** `python -m pytest nexus_backend/tests -q -k "tax"`，PG 侧同样通过。

## OPT07-F  通用别名表

**问题。** 出租车模块有 `transport_aliases`。贸易客商、广告客户同样需要"多个写法对应同一主体"，不应复用出租车专用表。

**做法。**

1. 读 `transport_aliases` 的结构、约束、使用点。
2. 新增通用别名表：事务所、企业、主体类型、标准主体标识、别名、生效期、来源、创建人。唯一约束防止同一企业同一类型下一个别名指向两个主体。
3. 出租车现有数据迁入通用表，出租车代码改读通用表。旧表保留不删，在迁移注释标注废弃。
4. 提供统一的解析函数：输入别名返回标准主体；有歧义或找不到时返回明确结果，不猜。
5. 别名增删改有审计，沿用现有"变更使旧审批失效"的规则（见 FSC02 中运输主数据变化使旧审批失效的做法）。

**先失败测试。** 出租车现有别名相关测试不改动即通过；新增客商类型别名的增删查；同别名指向两个主体被拒；跨企业别名互不可见（PG 负向）。

**验收。** `python -m pytest nexus_backend/tests -q -k "alias or transport or taxi"`，PG 侧同样通过。
