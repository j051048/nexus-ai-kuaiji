# OPT11：对 FSC07–FSC12 的追加项

先读 `OPT00_MASTER.md`。本文件不是独立批次。执行 FSC07–FSC12 各自的提示词时，把这里对应的条目一并完成，并在 `OPT_STATUS.md` 中以 `OPT11-<编号>` 记录。

## 各行业包开工前检查（FSC07–FSC10 通用）

开工前在状态文件写明以下每项的实际情况，任一项不满足则只做合成契约和阻断测试：

1. OPT01-A 已完成（金额列 64 位）。贸易包必须满足。
2. 该业态需要的税费种类在 OPT07-E 中已有模型。广告需文化事业建设费；物业与食材需农产品抵扣。
3. `docs/fsc/five_company_profiles_20261116.json` 中该企业的档案是否已由客户确认。未确认时所有规则使用带明确标记的合成政策，不写入任何"已确认"字样。
4. 新写入点使用企业级锁（见 OPT04-C），新表有 `FORCE ROW LEVEL SECURITY` 和读写分开的策略（见 OPT04-A），新金额列为 `BIGINT`。

## OPT11-A  贸易包使用通用别名表（FSC09）

客商别名使用 OPT07-F 的通用别名表，不复用 `transport_aliases`。OPT07-F 未完成时先完成它。

## OPT11-B  物业预收的术语与政策（FSC08）

复用 `lease_contracts` 的分期引擎时：

- 界面术语按业态显示"物业服务合同""预收分摊计划"，由行业配置数据驱动，不在组件里按行业名写分支。
- 分摊方法来自企业批准的政策条目。没有政策时阻断，不默认按月平均。

## OPT11-C  医院包的准入门槛（FSC10）

接入任何非合成数据前，以下各项须在状态文件逐条给出证据；缺任一项则只做无敏感信息的离线框架和拒绝测试：

1. OPT03-A、OPT03-B、OPT03-C 完成。
2. OPT10-A、OPT10-B、OPT10-C 完成。
3. 导入时剥离个人敏感字段的守卫有正反用例：含姓名、证件号、病历号的台账行，入库后只剩科室、批次、金额；原件按现有原件服务存储并受下载审计约束。
4. 模型调用路径对医院账套默认关闭，由显式配置开启；关闭时相关功能给出明确提示而不是报错。

部署形态、核算制度、数据分级由客户确认，不在代码中假设。

## OPT11-D  集团看板的口径标注（FSC11）

1. 跨企业汇总页面在标题区域固定显示"管理汇总，非合并财务报表"。
2. 每个指标可展开看到口径：取数来源、期间、包含哪些企业、数据截至时间。
3. 应收账款和存货的账龄预警阈值来自配置，不写死。
4. 先按 FSC 总令第 7 节审查 `nexus_backend/app/observability/value.py` 的跨月份混算问题，再往看板上接新指标。

## OPT11-E  助手动作卡（FSC11）

1. 新增的跨企业动作沿用 `nexus_backend/app/assistant/actions.py` 的机制：服务端生成带指纹的计划，人确认后执行。不新增绕过确认的路径。
2. 跨企业清单只包含当前用户有权访问的企业，权限在服务端逐企业判断。
3. 模型只能从固定的动作种类中选择；新增动作种类要同步更新种类枚举、服务端校验和测试。
4. 提示词登记：把 `nexus_backend/app/assistant/` 和 `nexus_backend/app/intelligence/` 中作为 Python 常量的提示词集中到一个登记模块，每条有名称和版本号，调用记录中写入所用版本。只做搬迁和登记，不改提示词内容；搬迁前后同一输入生成的请求体逐字节一致，用测试证明。

2. OPT01-A 的金额列扫描测试通过。
3. OPT02-D 的写事务范围基线没有新增条目。
4. 前端金额守卫测试（OPT08-A）通过。
5. `OPT_STATUS.md` 中每个模块的状态都有对应的验收输出；标为"部分完成"或"阻塞"的逐条列入验收报告，不省略。
