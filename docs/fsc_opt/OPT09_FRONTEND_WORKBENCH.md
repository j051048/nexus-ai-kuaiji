# OPT09：复核风险信号、高密度列表、常驻切换条、不可逆确认

先读 `OPT00_MASTER.md` 和 `OPT08_FRONTEND_MONEY_ENTRY.md` 开头的前端约束。前置：OPT08-A、OPT08-B。本批对应 FSC06 的追加项，遵守 FSC 总令第 6 节的页面要求：突出单位、身份、期间；首屏一个主任务；关键错误和复核条件不折叠。

## OPT09-A  复核队列的风险信号

**问题。** 前端没有任何置信度或风险展示（`src` 中搜不到 `confidence`、`置信`）。复核人无法先看高风险的。

**做法。**

1. **先查后端已有什么。** 读 `nexus_backend/app/intelligence/service.py`、`intelligence/checks.py`、草稿的 `issues` 字段、`RuleMemory` 相关代码，以及复核队列接口返回的字段。列出每张草稿已有的可用信号，例如：是否有异常项、来源是规则命中还是模型建议、是否人工修改过、金额与来源是否一致、证据是否齐全、是否首次出现的对方单位。
2. **不展示模型自报的置信度数字**。用上述可核验的事实组合成三档：需重点看、常规、低风险。分档规则写在后端一个纯函数里，带版本号，规则本身可测试。任何有异常项或缺证据的草稿不得落入低风险。
3. 复核队列接口返回分档和触发该分档的原因列表。
4. 前端 `src/ReviewWorkbench.tsx` 显示分档标记和原因，支持按分档筛选和排序。`src/InlineReviewDrawer.tsx` 顶部显示原因，不折叠。
5. 分档只影响排序和显示。**不改变任何审核门槛**：低风险草稿仍须逐张确认，不新增一键批量通过。

**先失败测试。**

- 后端：分档函数的单元测试，覆盖每条规则；有异常项的草稿永不为低风险。
- 接口：返回字段存在且受权限约束。
- 前端：分档与原因的展示逻辑若有纯函数则单测。

**验收。** 后端用例通过；类型检查与前端单测通过；复核流程的 Playwright 用例本机能跑则跑。

## OPT09-B  复核队列改为高密度表格

**问题。** 复核队列每条约 130 像素高，十条占满两屏。

**做法。**

1. `src/ReviewWorkbench.tsx` 的列表改为表格：一行一张草稿，列为风险分档、企业、日期、摘要、对方单位、金额（用 `MoneyCell`）、状态、异常数。行高目标 40 像素以内。
2. 表头吸顶。当前行高亮。保留现有键盘操作（J/K 上下、回车打开抽屉）。
3. 页面顶部的标语式大标题和说明段落去掉或收进一行；统计卡片压缩为一行紧凑的数字条。工作表格必须在 1280×800 的首屏内可见至少 12 行。
4. 窄屏（宽度小于 640 像素）保留卡片式布局，不强行用表格。
5. 表格样式做成可复用的类，供 OPT09-C 使用。不新写十六进制颜色和像素字号，用 `src/tokens.css` 变量；最小字号 12 像素。

**验收。**

- 类型检查、单测、格式检查通过。
- 新增或更新一条 Playwright 用例：1280×800 视口下，复核队列首屏可见行数不少于 12。
- 无障碍：现有 axe 用例（`e2e/qa-accessibility.spec.ts` 等）本机能跑则跑。
- 截图存入 `tmp_test/fsc_opt/OPT09-B/`，桌面和手机各一张。

## OPT09-C  月度交付矩阵

**问题。** "月度交付矩阵"实际是卡片列表，一屏约两家企业。

**做法。**

1. 找到该页面组件（搜索"月度交付"）。改为真正的矩阵：行是企业，列是办理环节（按页面现有环节划分，不新增环节），单元格显示状态标记，可点击直达对应对象。
2. 每个单元格的状态必须来自现有接口的权威字段。接口没有的不要在前端推算；缺的字段列入状态文件。
3. 保留现有筛选（我负责、临期与逾期、待补件、待复核、待签收）。
4. 状态不只靠颜色表达，要有文字或图标。

**验收。** 类型检查、单测通过；`e2e/monthly-batch.spec.ts` 及相关用例本机能跑则跑，断言变化逐条列出；截图存入 `tmp_test/fsc_opt/OPT09-C/`。

## OPT09-D  常驻的单位、身份、期间切换条

**问题。** 账套切换藏在折叠项里，期间是各页面自己的月份输入框。五家单位来回切换时容易做错单位。

**做法。**

1. 先读 `src/workspace-route.ts`、`src/useWorkspaceRoute.ts`、`src/api.ts` 中切换范围时中止在途请求的逻辑。上下文已经在地址参数里，本模块只是给它一个固定可见的控件。
2. 在工作区顶部加一个固定条：当前单位、当前身份（角色）、当前期间及其状态（开放或已锁）。点击可切换单位和期间。
3. 切换时：
   - 复用现有的未保存离开拦截。
   - 复用现有的中止在途请求逻辑。
   - 更新地址参数，可后退恢复。
4. 各页面自己的月份输入框：与顶部期间含义相同的，改为读顶部期间并移除；含义不同的（如查询范围）保留并改清楚标签。逐个判断，列在状态文件。
5. 只列出当前用户有权访问的单位，数据来自现有接口。
6. 检查现有截图中侧边栏在长页面上"浮在页面中部"的现象（`formal-books-desktop.png` 等）：在真实长页面上滚动验证。是真问题就修，是整页截图造成的假象就在状态文件说明。

**先失败测试。** 路由解析与切换的纯函数若有改动，补单测。

**验收。** 类型检查、单测通过；新增 Playwright 用例：切换单位后，页面数据、地址参数、顶部条三者一致；切换期间有未保存修改时出现拦截；迟到的旧请求响应不覆盖新单位的数据（仓库已有类似用例，照其写法）。

## OPT09-E  不可逆操作的确认

**问题。** 锁定期间不支持重开，却用原生 `window.confirm`。线索：`src/FormalClosePanel.tsx`、`src/FormalBooksWorkbench.tsx`、`src/RevisionWorkbench.tsx`。

**做法。**

1. 搜索 `window.confirm` 和 `confirm(` 的全部用法，按后果分两类：不可逆（锁期、正式过账、发布、对外发送）和可恢复。
2. 用 `src/AppPrimitives.tsx` 已有的 `Modal` 做一个确认对话框组件：
   - 不可逆类：显示对象、单位、期间、后果说明，要求输入期间或对象名称才能点确认。默认焦点在取消按钮。
   - 可恢复类：普通确认，默认焦点在取消按钮。
3. 全部 `window.confirm` 替换完。
4. 复核抽屉里单键 `A` 直接审核通过：保留快捷键，但确认现有的"已确认、平衡、证据齐全、无未保存修改"门槛仍然生效；再加一条：抽屉打开后的短时间内（例如 400 毫秒）忽略 `A`，防止连按误触。

**验收。**

- `grep -rn "window.confirm\|[^a-zA-Z]confirm(" src` 无业务代码命中。
- 类型检查、单测通过。
- 依赖原生确认框的 Playwright 用例（搜索 `page.on('dialog'`）逐个更新并列出。
- 新增用例：锁期确认框未输入正确期间时确认按钮不可用。
