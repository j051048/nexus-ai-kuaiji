# OPT 总令：审计整改与工程底座（DeepSeek 分模块执行）

日期：2026-11-16。性质：代码实施工作令，不是上线许可或完成证明。完成后由独立验收方逐模块复查，复查以代码、测试和命令输出为准，不以你的报告为准。

依据：`docs/FSC_OPTIMIZATION_PLAN_20261116.md`。本目录是对 `docs/FSC_EXECUTION_MASTER_20261116.md` 的补充，不替代 FSC01–FSC12。两者冲突时以更严格的一方为准。

## 1. 怎么干

每个 OPT 文件由若干模块组成（如 OPT01-A、OPT01-B）。**一次只做一个模块**，做完写状态再做下一个。模块之间除非写明前置，否则互不依赖。

每个模块固定五步：

1. **核实现状。** 文件里给的路径和行号是 2026-11-16 的线索，代码在变。先搜索确认问题仍存在。已被别人修好就记录证据并跳过，不重做。
2. **先写失败测试。** 测试必须在修改前真的失败，保存失败输出。
3. **最小修改。** 只改本模块列出的范围。发现范围外的问题记入状态文件"顺带发现"，不动手。
4. **跑验收命令。** 把命令和实际输出尾部贴进状态文件。
5. **更新 `docs/fsc_opt/OPT_STATUS.md`。** 格式见第 4 节。

## 2. 不可突破的边界

沿用 FSC 总令第 3 节全部条款。特别强调：

1. **不修改任何已存在的迁移文件**，包括未提交的。一律新增前向迁移。编号临用前执行 `ls nexus_backend/migrations/postgres | tail -3` 和 `ls nexus_backend/migrations/sqlite | tail -3` 核对，取下一个。Postgres 和 SQLite 两边都要有对应迁移。
2. **不提交、不推送、不部署**，不执行 `git reset`、`git clean`、`git stash`、`git checkout -- <文件>`，不做全仓格式化。
3. **不让测试靠作弊变绿**：不删断言、不加 `skip`/`xfail`、不放宽超时、不用管理员直写代替服务流程。
4. **金额只用整数分**。后端不出现 `float` 参与金额；前端不出现 `parseFloat`、`Number(x) * 100` 参与金额。
5. **权限从服务端和数据库重新验证**。前端隐藏按钮不算权限控制。
6. **不访问真实模型、OA、HIS、T+、生产库**。只用本地隔离库和合成数据。
7. 其他智能体正在并行修改。每次编辑前重读文件；不覆盖别人的改动。

## 4. 状态文件格式

`docs/fsc_opt/OPT_STATUS.md`，每个模块一节，追加不覆盖：

```
## OPT01-A  <状态：完成 / 部分完成 / 阻塞 / 已被修复无需改动>

- 现状核实：<命令> → <关键输出一两行>
- 失败测试：<测试文件::用例名>，修改前输出：<失败摘要>
- 修改文件：<逐个列出，含新增迁移编号>
- 验收命令与输出：
  <命令>
  <输出最后几行，原样粘贴>
- 未做或未验证：<如实写，没有就写"无">
- 顺带发现：<范围外问题，没有就写"无">
```

规则：

- "完成"只在验收命令全部真实通过时使用。有任何一条没跑或没过，写"部分完成"并说明。
- PostgreSQL 用例因本机无库而跳过的，写明"PG 未验证"，不能算通过。
- 不写估计值、不写"应该可以"。只写实际执行过的命令和看到的输出。
