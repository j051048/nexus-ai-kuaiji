# 登录身份与授权范围展示

本轮在 V10 已验收的独立候选中增量修改；没有修改后端、认证、角色优先级、权限授予、C01、复核或导出实现。未连接真实模型或线上服务。

## 界面行为

- 客户门户、会计/事务所工作台和 `/admin` 共用一个身份条，放在常显页头区域，手机不必展开侧栏。
- 默认显示当前账号姓名与真实岗位；展开“权限与范围”可看所属事务所、范围和附加能力。支持键盘操作，不发起任何业务请求。
- 岗位包括企业员工、部门审批人、企业财务、企业管理人员、经办会计、复核会计、事务所负责人、事务所管理员和只读成员。
- 财务兼任复核仍显示企业财务，详情列出获授权账套复核能力。工作台名称与岗位身份分开显示。
- 使用现有 profile/Me 数据；不会根据邮箱、能否进入管理后台或账套可见性推导“超级管理员”、记账或导出权限，不虚构 L1/L2 等等级。
- 只有当前用户与事务所匹配且 `manage_firm=true`，才能说明管理本事务所全部企业。其他情况明确限于获授权的企业、部门和账套；聚合能力不代表选中企业或所有账套都有该权限。
- 读取失败或本登录范围收到权限拒绝时，不再展示旧能力，提示重新确认。切换身份、重新取得 profile/Me 后以新的数据展示。
- 已登录但尚未取得组织授权的页面仍使用现有的姓名及“尚未获得企业或事务所授权”说明。二次验证流程未改动。

## 验证方式

```text
npm test -- src/account-identity.test.ts src/account-identity-render.test.ts
npm exec -- playwright test e2e/account-identity.spec.ts --trace=off
npm run test:e2e:core:preview
```

首个浏览器测试先复现缺少常显岗位区域；纯投影及渲染契约先失败，再实现组件。新增手机长姓名检查还复现全局样式使权限详情缩成 10px 的问题，已显式使用可读字号。另补失败测试后统一了“事务所只读成员兼任企业管理员”在工作区与管理后台的岗位文案，未增加管理权限。

浏览器采用独立本地 SQLite 和虚构账号。部分兼任能力通过受控响应投影验证显示，不作为真实授权证据；原 V07–V09 核心回归继续验证实际本地权限及会计复核后导出。截图和具体运行结果保存于本候选忽略目录 `tmp_test/account-identity/`，不上传数据库、原件或令牌。
