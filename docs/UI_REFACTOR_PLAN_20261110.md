# 衡账前端 UI 重构规划

- 日期：2026-11-10
- 状态：**仅规划，未实施**
- 参考：`motion-prompt` skill（已安装到 `.agents/skills/motion-prompt`，未提交）
- 范围：事务所端、企业员工端、财务/复核端、会计工作台、交付与证据面板
- 不改变：权限、账务状态机、独立复核、来源版本、费用/attempt 防重发、审计边界

---

## 0. 先给结论

衡账现在的问题不是“不好看”，而是**界面语言太多、层级太散、每个页面都在解释自己**。

本轮不建议做“炫技式动效重构”，而应该做：

> **一套安静、可信、可审计的会计工作台：减少装饰，统一 token，压缩壳层，强化“当前企业 / 账套 / 期间 / 下一步”，动效只用于表达状态变化。**

视觉方向建议定为：

- **关键词**：账本、编辑台、证据、克制、清晰
- **不是**：AI 科技感、Web3、营销落地页、卡片瀑布
- **品牌色**：保留深绿，但降低饱和度；米白画布；白色工作区；琥珀色只用于风险
- **字体**：中文无衬线为主；标题可用衬线体做“账本”气质；金额用 tabular numerals
- **动效**：120–320ms，只做透明度/位移/高度，不做视差、跟随光标、循环背景

一句话：

> **让会计觉得“这是一张可以放心签字的桌子”，而不是“一个会动的 AI 产品”。**

## 1. 现状诊断

结合最近两轮前端审计与代码抽查，主要问题集中在六类：

### 1.1 壳层重复

- 顶部品牌条、身份条、页面标题、岗位说明、统计卡叠在一起。
- 1366×768 下，员工首页首个主动作被推到 468px；部门审批页标题区 94px。
- 同一页面重复出现“当前工作台”“查看岗位与操作说明”“权限与范围”。

### 1.2 设计 token 失控

审计抽样曾出现：

- 35 种 font-size；
- 31 种断点；
- 36 种 radius；
- 2,000+ 处 hex、1,500+ 种颜色值；
- 457 处小于 12px 的文本。

这不是“风格问题”，是维护问题：每加一个页面就多一套间距、字号和颜色。

### 1.3 信息密度两极分化

- 事务所端表格很密，但缺少清晰的列优先级；
- 员工端卡片很大，首屏却看不到金额、日期、附件；
- 复核面板把“事实、建议、分录、政策、操作”堆在同一列。

### 1.4 状态表达不统一

- 有的地方用颜色，有的地方用文案，有的地方用 badge；
- “未知 / 加载中 / 0 / 失败”没有统一组件；
- 空状态有时说“没有待办”，有时说“数量暂未汇总”。

### 1.5 动效没有统一语言

- 当前几乎没有统一 motion token；
- 弹窗、抽屉、折叠、toast 的时长和缓动各自为政；
- 一旦加动效，很容易变成“每个组件都在动”。

### 1.6 角色心智不连续

- 员工、部门审批、企业财务、会计、复核看到的是不同壳层；
- 但“当前企业 / 账套 / 期间 / 我下一步做什么”应该始终可见且一致。

## 2. 重构目标

### 2.1 业务目标

1. 一个会计可以在 3 秒内回答：**我现在在哪家企业、哪个账套、哪个期间、下一步做什么。**
2. 一个员工可以在手机首屏完成：**拍照/选文件 → 看预填 → 核对金额日期 → 提交。**
3. 一个复核员可以在一屏内看清：**金额、差异、来源、版本、政策、阻断原因。**
4. 所有角色共享同一套壳层和状态语言，但保留角色化入口。

### 2.2 工程目标

- 把页面级 CSS 收敛为 **tokens + primitives + 少量 layout**；
- 把 `App.tsx` 的壳层逻辑拆成 `AppShell / PageHeader / ContextBar / WorkspaceLayout`；
- 所有关键页面在 1366×768、1440×900、390×844、375×812 四个视口通过；
- 关键路径支持键盘、`prefers-reduced-motion`、200% 缩放；
- 视觉回归截图纳入 Playwright，而不是靠肉眼。

### 2.3 非目标

- 不重写业务组件；
- 不改变权限、审批、记账、导出、通知逻辑；
- 不引入重型动画库；
- 不做营销式首页；
- 不为了“好看”隐藏企业/账套/期间上下文。

## 3. 新信息架构

### 3.1 壳层

```text
┌──────────────────────────────────────────────────────────────┐
│ Topbar 56px: 品牌 / 当前事务所 / 全局搜索 / 助手 / 身份       │
├──────────────┬───────────────────────────────────────────────┤
│ Sidebar      │ Page header 72–88px                           │
│ 232px        │ 标题 24px + 一句说明 + 主操作                  │
│              ├───────────────────────────────────────────────┤
│ 事务所管理    │ Context bar 44px                              │
│ 会计工作区    │ 企业 · 账套 · 期间 · 状态 · 切换               │
│ 日常业务      ├───────────────────────────────────────────────┤
│ 设置          │ Content                                       │
│              │ 12 列网格 / 主区 8 + 侧区 4                    │
└──────────────┴───────────────────────────────────────────────┘
```

**规则：**

- 品牌只在 Topbar 出现一次；页面内不再重复“HENGZHANG · ACCOUNTING AGENT”。
- 身份收进一个 popover：单位、角色、姓名、权限范围、切换身份。
- 企业/账套/期间放在 Context bar，始终可见；移动端折叠为两行。
- 页面标题只保留一个 h1；说明最多一行；主操作最多一个。
- 统计卡只在“全所概览”出现，其他页面不再重复四张卡。

### 3.2 导航分组

| 分组 | 入口 |
|---|---|
| 事务所管理 | 全所概览、客户企业、月度交付、异常与补件、人员与权限 |
| 会计工作区 | 会计工作台、待审核凭证、审核与导出、事实修订 |
| 日常业务 | 我的待办、客户开通、资料清单、消息 |
| 设置 | 科目与规则、通知与通道、使用说明 |

- 桌面 232px；1024px 以下收为 64px 图标栏；640px 以下变抽屉。
- 当前项用 3px 左侧色条 + 浅底，不用整块深色。
- 侧栏不滚动页面，独立滚动。

### 3.3 页面模板

只保留四种页面模板：

1. **Dashboard**：全所概览 / 岗位首页
2. **List + Detail**：客户企业、异常、交付、凭证
3. **Workspace**：账套工作区（tabs + 主区 + 证据侧栏）
4. **Wizard**：员工录入、开户、月结

## 4. 设计 token

### 4.1 字体

| Token | 值 | 用途 |
|---|---|---|
| `--text-xs` | 12px / 16px | 辅助、表头、时间 |
| `--text-sm` | 13px / 18px | 表格正文、次要说明 |
| `--text-base` | 14px / 20px | 默认正文 |
| `--text-md` | 16px / 24px | 表单、重点正文 |
| `--text-lg` | 20px / 28px | 区块标题 |
| `--text-xl` | 24px / 32px | 页面标题 |
| `--text-display` | 32px / 40px | 仅登录/空状态 |

- 中文：`"Noto Sans SC", "Source Han Sans SC", system-ui`
- 标题衬线：`"Noto Serif SC", "Source Han Serif SC", serif`，仅用于 h1 和金额强调
- 金额：`font-variant-numeric: tabular-nums`
- 小于 12px 只允许装饰性英文，不允许承载信息。

### 4.2 颜色

只用语义 token，禁止页面直接写 hex。

```css
--canvas: #f6f5f0;
--surface: #ffffff;
--surface-muted: #f1f0e9;
--ink: #1d2521;
--ink-muted: #66736b;
--ink-faint: #8b968f;
--line: #e2e0d5;
--line-strong: #c9c6b8;
--brand: #1f4d3a;
--brand-strong: #16382b;
--brand-soft: #e8efe9;
--accent: #2f6b4f;
--warning: #8a5a12;
--warning-soft: #fbf1df;
--danger: #9b3d2e;
--danger-soft: #f8e8e4;
--success: #2f6b4f;
--success-soft: #e8f1eb;
```

- 品牌绿只用于：主按钮、当前导航、关键数字、链接。
- 琥珀只用于：风险、待处理、期限。
- 红色只用于：阻断、错误、不可逆操作。
- 不允许用颜色单独表达状态；必须同时有文字/图标。

### 4.3 间距 / 圆角 / 阴影

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 24px;
--space-6: 32px;
--space-7: 48px;

--radius-sm: 4px;   /* badge, input */
--radius-md: 8px;   /* button, card */
--radius-lg: 12px;  /* panel, modal */
--radius-pill: 999px;

--shadow-1: 0 1px 2px rgb(29 37 33 / 0.06);
--shadow-2: 0 8px 24px rgb(29 37 33 / 0.10);
--shadow-3: 0 18px 48px rgb(29 37 33 / 0.16);
```

### 4.4 断点

只保留四个：

```css
@media (max-width: 1280px) { /* 紧凑桌面 */ }
@media (max-width: 1024px) { /* 图标侧栏 */ }
@media (max-width: 720px)  { /* 手机/平板 */ }
@media (max-width: 390px)  { /* 小屏手机 */ }
```

不再为每个组件写自己的断点。

### 4.5 密度

用 `data-density="comfortable|compact"`：

- 客户/员工端：comfortable，行高 48px；
- 会计/复核端：compact，行高 36–40px；
- 表格列可配置，不靠缩小字号塞内容。

## 5. 组件清单

先做 15 个 primitives，页面只组合它们：

1. `AppShell`
2. `Topbar`
3. `Sidebar`
4. `PageHeader`
5. `ContextBar`
6. `Button`（primary / secondary / quiet / danger）
7. `Field`（label / help / error / required）
8. `StatusPill`（neutral / info / warning / danger / success + icon）
9. `Callout`（info / warning / danger / success）
10. `DataTable`（sticky header、列优先级、空状态、分页）
11. `TaskRow`（标题、金额、状态、负责人、下一步、主操作）
12. `Tabs` / `SegmentedControl`
13. `Drawer` / `Modal` / `BottomSheet`
14. `Toast`
15. `Skeleton` / `EmptyState`

**约束：**

- 所有交互组件必须支持 `disabled / busy / error`；
- 所有表单控件有可见 label，不靠 placeholder；
- 所有金额右对齐，使用 tabular numerals；
- 所有日期显示为 `YYYY-MM-DD`，不显示歧义格式；
- 所有“未知/未汇总”必须用 `—` + 说明，不能用 0 冒充。

## 6. 动效规划（motion-prompt 映射）

### 6.1 动效原则

1. **只为状态变化服务**：打开、切换、加载、完成、失败。
2. **不做持续动画**：无视差、无跟随光标、无循环渐变、无 marquee。
3. **不把动效加在金额上**：金额、差额、税额、余额不做 count-up、不做抖动、不做渐变。
4. **一次只动一个东西**：同一视图最多一个主运动。
5. **尊重 `prefers-reduced-motion`**：全部降为 0ms 或仅透明度。
6. **时长上限**：产品内 320ms；复杂抽屉 380ms；toast 350ms。

### 6.2 选用的 motion-prompt 元素

| 场景 | 元素 | 规格 | 本项目调整 |
|---|---|---|---|
| 新建客户/确认弹窗 | **#049 Modal dialog** | 320ms 打开，280ms 关闭；scrim 0.42；scale 0.9→1 | 保留 320/280ms；scrim 降到 0.36；宽度 480/640px |
| 证据/筛选抽屉 | **#050 Drawer** | 380ms 打开，350ms 关闭；easeOutCubic；scrim 0.36 | 右侧抽屉；宽度 420px；移动端改底部 sheet |
| 手机更多字段/选择 | **#051 Bottom sheet** | 400ms 打开；拖动关闭 600ms | 只用于手机；最大高度 80vh；把手 44px 触控 |
| 行内“处理说明/更多字段” | **#052 Accordion** | 350ms 开，320ms 关；easeInOutCubic | 高度自适应；箭头旋转 180°；错误原因保持可见 |
| 保存/导出/提交反馈 | **#056 Toast** | 350ms 入，350ms 出；右下 18/16px | 只显示 4s；成功/失败都可关闭；不遮挡底栏 |
| 工作区 tabs | **#057 Tabs** | 下划线 250ms；旧内容 200ms 淡出，新内容 200ms 淡入 + 上移 8px | 内容切换不改变页面高度；保留滚动位置 |
| 期间/视图切换 | **#060 Segmented control** | 250ms 高亮滑动 | 只滑高亮；图表/数字直接切换，不做高度动画 |
| 员工录入/月结步骤 | **#068 Step indicator** | 每步 300ms；连线 300ms | 3 步：资料 → 核对 → 提交；步骤可回看 |
| 列表/详情加载 | **#069 Skeleton** | 900ms 循环微光 | 只在首次加载；不超过 2 个循环；reduced motion 静态 |
| 空队列/空结果 | **#072 Empty state** | 350ms 淡入 + 上移 8px | 文案必须给出下一步；不用插画遮挡 |
| 可点击卡片 hover | **#081 Hover lift** | 300ms；demo 10px | 产品只用 **2px**；阴影 6→14；表格行不抬升 |

### 6.3 不采用

- #073 视差滚动
- #083 光标跟随
- #084 磁吸按钮
- #085 水波纹（财务按钮不需要）
- #092 整页扫屏转场
- #094 marquee
- #095 动态渐变背景
- #096 漂浮装饰
- 任何 confetti / 庆祝动画

### 6.4 Motion token

```css
--motion-fast: 160ms;
--motion-base: 240ms;
--motion-slow: 320ms;
--motion-drawer: 380ms;

--ease-standard: cubic-bezier(0.2, 0, 0, 1);
--ease-emphasized: cubic-bezier(0.2, 0.8, 0.2, 1);
--ease-exit: cubic-bezier(0.4, 0, 1, 1);
```

- 进入用 `ease-out`，退出用 `ease-in`，位置切换用 `ease-in-out`。
- 不做 spring/bounce；会计产品不需要“弹”。
- 只动画 `transform` 和 `opacity`；高度动画只用于 accordion，且必须测 CLS。

## 7. 页面级重构

### 7.1 全所工作台（Firm Cockpit）

**现状**：标题、四统计卡、客户列表、协调列表、人员安排、四个入口同时出现。

**重构**：

- 页头：`全所工作台` + 一句“本月 3 家客户，1 家待开通” + 主按钮“客户进度”。
- 第一行只留 3 个指标：服务客户 / 待完成月结 / 待处理异常；点击可过滤。
- 主区 8 列：客户表（企业、期间、状态、负责人、下一步、操作），默认按风险排序。
- 侧区 4 列：需要你协调（最多 3 条）+ 人员安排摘要。
- 表格分页，不整表 `map`。
- 动效：加载 #069；空状态 #072；卡片 hover #081（仅客户卡，不用于表格行）。

**验收**：1366×768 首屏至少看到 5 行客户；不需要滚动就能看到“待处理异常”。

### 7.2 客户账套工作区（Book Workspace）

**现状**：5 个 tab + 后台任务 + 凭证队列 + 复核面板，信息密度高。

**重构**：

- Context bar 固定：企业 / 账套 / 期间 / 状态 / 切换。
- Tabs：资料与流水 / 匹配与核销 / 凭证与复核 / 对账与月结 / 交付与导出。
- 主区 8 列：当前 tab 内容；侧区 4 列：证据与阻断（可折叠）。
- 复核面板改为“金额摘要 → 差异 → 来源 → 政策 → 操作”五段，不把长解释放首屏。
- 证据用右侧 Drawer #050；手机上用 Bottom sheet #051。
- Tab 切换 #057；折叠 #052。
- 金额、差额、借贷合计不做动画。

**验收**：切换 tab 不丢当前企业/期间；复核员在 1 屏内看到金额、差异、版本、政策。

### 7.3 员工首页（Employee Home）

**现状**：三个大模板卡 + 统计条 + 列表，首屏被说明占满。

**重构**：

- 页头：`我的工作台` + 一句“今天要提交什么？”。
- 一个主操作：`拍照/上传票据`（直接打开录入，不先选模板）。
- 两个次操作：`采购/费用`、`日常收支`，收进一行。
- “需要我处理”显示真实数字；没有时显示 `0`，不显示“数量暂未汇总”。
- 列表只保留：类型、企业、金额、状态、下一步。
- 动效：空状态 #072；列表加载 #069；toast #056。

**验收**：390×844 首屏看到主操作 + 至少 1 条待办；不再出现未知计数。

### 7.4 员工录入（Intake Wizard）

**现状**：首屏被步骤说明、模板、企业卡、交接准备、上传区占满，金额在 1218px。

**重构**：

- 全屏 Dialog（桌面 720px；手机全屏）。
- 顶部 3 步 Stepper #068：资料 → 核对 → 提交。
- 第 1 步只做：企业选择（多企业必须显式）、拍照/上传、OCR 状态。
- 第 2 步：金额、日期、摘要、交易对方；其余字段进“更多信息” Accordion #052。
- 第 3 步：核对清单 + 提交。
- 手机：更多字段用 Bottom sheet #051；底部只保留一个主按钮 + 一个次按钮。
- 错误：字段级错误 + 顶部 Callout；不自动勾选“我已核对”。
- 上传失败：保留字段和附件，显示“重试/删除”；提交 unknown 只查询，不自动重提。
- 动效：步骤 #068；展开 #052；保存 toast #056；上传 skeleton #069。

**验收**：390×844 首屏看到金额/日期或上传按钮；金额在 footer 上方至少 24px；多企业未选择时提交禁用且有说明。

### 7.5 财务核验 / 复核

**现状**：卡片 + 列表 + 右侧详情，信息多但缺少优先级。

**重构**：

- 列表：企业、事项、金额、状态、负责人、期限；默认按“待我处理 + 逾期”排序。
- 详情首屏：金额、申请人、事由、状态、差异；原件与审批记录在下方。
- 差异用并排对比，不用颜色单独表达。
- “下一步”只保留一个主动作；次动作进“更多”。
- 动效：抽屉 #050；折叠 #052；toast #056；不做金额动画。

**验收**：一屏内看到金额、差异、来源、政策；键盘可完成核验。

### 7.6 会计工作台 / 凭证队列

- 表格化，不做卡片流。
- 列优先级：日期 / 摘要 / 金额 / 状态 / 来源 / 操作；次要列可隐藏。
- 批量选择用 sticky action bar，不遮挡表头。
- 复核详情用右侧 Drawer，不跳页；保留列表滚动位置。
- 动效：只保留 loading #069 和 toast #056；hover 不抬升行。

### 7.7 月度交付 / 客户签收

- 上方：当前包版本、期间、状态、签收人。
- 中部：文件清单（名称、大小、hash 前 8 位、下载）。
- 下方：签收记录时间线；历史版本折叠 #052。
- 动效：只做 toast 和 skeleton；不做“发送成功”庆祝。

### 7.8 AI 助手 / 证据面板

- 不做全屏聊天；助手是右侧 360px Drawer #050。
- 回答结构固定：结论 → 事实（带 fact id）→ 覆盖 → 未检查 → 下一步 → 打开原记录。
- 事实引用可点击跳转，不自动执行写操作。
- 流式输出只做文本渐显，不做打字机光标；金额不逐字跳动。
- 失败/撤权/预算不足：明确弃答，不用“正在思考”掩盖。

## 8. 移动端策略

- 员工端保留底部四 tab：首页 / 我的事项 / 资料清单 / 消息。
- 会计/复核端不做底部 tab，使用侧栏抽屉 #050 + 顶部 Context bar。
- 表格在手机上改为“两行卡片”：
  - 第一行：标题 + 金额
  - 第二行：状态 + 企业/日期 + 下一步
- 触控目标 ≥44px；输入框 16px 防止 iOS 缩放。
- 吸底只保留一个主操作；安全区 `env(safe-area-inset-bottom)`。
- 横屏/小高度：底部按钮不遮挡字段，表单可滚动到 footer 上方 24px。

## 9. 可访问性与性能

### 9.1 必做

- 所有图标按钮有 `aria-label`；
- 所有表单有可见 label，错误用 `aria-describedby`；
- 焦点环 2px，不用 `outline: none`；
- 键盘可达：Tab、Enter、Esc、方向键（tabs/segmented）；
- 对比度：正文 ≥4.5:1，大文本 ≥3:1；
- `prefers-reduced-motion: reduce` 时禁用位移/缩放/循环；
- 200% 缩放不横向滚动；
- 页面切换后焦点回到 h1 或主区；
- toast 用 `role=status`，错误用 `role=alert`；
- 不用颜色单独表达状态。

### 9.2 性能预算

- 首屏 JS gzip ≤ 180KB；
- 首屏 CSS ≤ 110KB；
- 单页新增依赖 ≤ 20KB gzip；
- 动效只使用 `transform/opacity`；
- 列表 >50 行必须分页/虚拟化；
- 图标按需导入，不引入整套图标库；
- 字体只加载 2 个字重（400/600），中文子集化。

## 12. 风险与边界

1. **动效会降低“可信感”**：会计产品不适合弹跳、庆祝、视差。所有动效必须能解释“发生了什么”。
2. **金额不能动画**：count-up、数字滚动、渐变会让人误读，尤其差额/税额。
3. **不能为了简洁隐藏上下文**：企业、账套、期间、版本必须始终可见。
4. **不能为了移动端简化审批**：独立复核、退回、补件不能少。
5. **不能一次性重写全部页面**：先壳层和 token，再逐页替换；每页有截图基线。
6. **不能只看桌面**：员工端主要发生在手机；必须 390/375 视口验收。
7. **不能把“AI 助手”做成聊天首页**：助手是证据侧栏，不是产品入口。

---

## 13. 需要确认的三个方向

1. **品牌强度**：保留深绿 + 米白的“账本感”，还是改成更中性的黑白灰？（推荐保留深绿，但降低饱和度）
2. **壳层密度**：会计端默认 compact，还是所有角色统一 comfortable？（推荐会计 compact、客户 comfortable）
3. **员工端入口**：是否接受“拍照/上传”作为唯一主操作，模板收进次级入口？（推荐是）

---

## 14. 本轮结论

- `motion-prompt` 适合作为**动效语言库**，不适合作为完整 UI 设计系统；本轮只取 10 个左右的交互元素，且全部做“降噪”处理。
- 最优先做的不是动效，而是：**tokens、壳层、员工首屏、复核信息优先级**。
- 建议先做 Phase 0–2，拿到 1366×768 与 390×844 的对比截图，再决定是否进入 Phase 3–5。

> 目标不是“让界面动起来”，而是让会计和员工**更快看懂、更少误操作、更愿意每天用**。
