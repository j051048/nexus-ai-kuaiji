# FSC10：内部医院财务汇总与数据准入

前置FSC04–06；医院数据准入和核算制度是额外前置。先读总工作令。禁止因其位于集团名单就默认普通企业权限、普通云存储或企业会计政策适用。

## 第一阶段：无敏感数据的框架

1. 将单位性质、核算制度、财务权威系统、允许字段、部署/存储位置、留存期、访问人员和禁止外发范围作为待确认政策。未知时只使用完全虚构的财务聚合数据，不等待真实患者数据才开发。
2. 来源端提供按科室/成本中心/期间/药耗批次汇总的财务数据；原则上不接患者姓名、身份、诊断、病历或监狱人员明细。hash或替换姓名不自动等于匿名化。
3. 复用科室/项目辅助维度、原件完整性、来源版本和成本草稿；接收科室消耗汇总、库存权威快照及财政/医保结算汇总。来源数据不足时不推定支出用途或收入性质。
4. 采集适用制度下批准的直接归集/间接分摊政策，整数分尾差守恒、分母明确、不可覆盖已确认期间。不得套用出租车或企业模板充当医院全部核算。
5. 专户/资金用途按已核定账户及政策做一致性检查和异常提示；未经确认不声称自动保证专款专用。跨公司管理汇总只暴露批准的最小指标。

## 第二阶段：准入具备后可交接的实现

完成字段白名单、禁止字段/附件的受控拒绝、日志最小化、权限、缓存与备份策略。真实数据导入、专网/私有化部署和外部接口必须另获明确授权，本轮不执行。

## 失败测试

- 含禁止字段/敏感附件被持久化、输出日志或送进模型；用哈希名义绕过准入。
- 集团viewer可下钻科室原件；其他公司看到医院明细；导出/缓存/恢复绕过授权。
- 科室映射过期、分摊依据变化、无适用政策仍可生成/审核；零分母、重复批次、尾差失衡。
- 恢复后丢失数据准入/保留政策，默认放开访问或自动发送。

## 验收

仅合成的两期科室成本与资金汇总链；PG16/17权限/隔离/重复与版本竞争，恢复保留政策；桌面手机财务办理，不包含临床界面。准入未核定则报告“离线框架通过、真实医院接入未批准”，不得标医院上线完成。
