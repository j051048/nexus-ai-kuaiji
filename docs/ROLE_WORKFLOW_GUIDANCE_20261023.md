# 第三批：员工、财务与会计复核的流程引导

日期：2026-10-23。基线：`cf07ef0874c76b37f55c364e42b08cce9852c46e` 加本轮开始时既有未提交修改。

## 结果

本批已完成本地实现和限定范围验收。复用既有表单、附件上传、审批、财务核验、交接、原件预览、凭证保存/审核及导出流程，没有新增审批环节或后台自动审核。

| 岗位/入口 | 现在显示什么 | 关键边界 |
|---|---|---|
| 员工录入/修改 | 确认企业与模板 → 附票并填写 → 核对后提交；指出缺附件、缺字段或未勾选核对 | 草稿、OCR 成功、请求发送中都不代表提交成功；识别不是必经步骤 |
| 业务事项/企业财务 | 填写、部门审批、财务核验、交接、会计复核与导出；实际退回原因与可执行下一步 | 直提显示授权会计接收，不虚构已进行部门/财务审批；核验、交接不等于记账或导出 |
| 常规/同屏复核 | 核对原件事实 → 检查分录差异 → 保存并确认审核 → 审核后导出 | 引用不等于原件已核验，借贷平衡不等于处理正确；原有人工确认和服务端校验保留 |

公共 `WorkflowGuide` 仅展示有序步骤、当前状态、下一步和默认折叠的核对要点。它不创建请求、业务状态、权限或新的确认控件。文字通过 React 普通文本渲染，来源文本中的 HTML 不执行。

## 具体改动

- `IntakeWizard` 的引导读取原表单校验、当前授权企业、部门、附件数量、确认勾选、实际保存签名和最新识别状态。未保存修改不会被说成已保存；识别中断或失败仍可手工核对。继续使用原服务端草稿恢复和提交幂等键。
- `BusinessWorkspace` 统一列表/详情的状态名称，替换旧单行下一步。交接成功说明根据服务端返回判断：只有真实 `mapping.draft_id` 才说明关联到草稿；没有关联则提示重新读取，不能宣称已生成。选账套引导遵循本企业、事项月份、开放状态和实际编辑权。
- `Reviewer` 与 `InlineReviewDrawer` 使用同一展示规则，按各自现有权限和按钮提示下一步。同屏没有异常指派按钮时不再引导点击不存在的入口；制单员没有复核资格时交由获授权复核员处理。
- 修改草稿后优先提示保存，并由服务端重新校验旧问题。不会在本地自行宣布问题消失。
- 常规复核补齐关期后的输入、保存和审核禁用，与已有服务端 `_open(book)` 约束一致；保留该入口原有的“仅复核权、无编辑权也能审核”行为，没有将其意外改为必须有编辑权。
- 已审核、已导出、关期、来源隔离与读取/操作失败分开说明。已审核且关期不建议新导出；已审核后读取失败仍保留审核事实；导出历史不因错误提示而丢失，也不被解释为外部软件已经入账。
- 常规保存/审核失败的提示从原请求捕获处接入引导。错误附带本次会话、账套、凭证目标，再由纯函数匹配当前选择；其他企业、账套、凭证或一般全局通知不成为当前复核失败。没有新增重试或请求。
- 同屏引导位于原有可滚动凭证列，不增加第三列；手机步骤可换行，检查清单按需展开。

2. 独立部门审批后由财务核验、选择明确授予编辑权的本企业账套交接；结果仍为草稿，无导出。

4. 退回时显示服务端真实原因，修改同一事项，员工不能代财务审批。
5. 使用现有允许直提的企业财务身份验证授权会计接收，不放宽员工的提交渠道权限。
6. 常规审核注入 409 后，引导要求重新读取，服务端凭证仍为草稿，仅发送一次审核请求。

首次组合测试中，财务新账套未授予编辑权、直提测试误使用无该渠道资格的员工，均按原授权被拒绝/排除。修正本地测试身份与显式授权，不修改权限来迁就测试。
