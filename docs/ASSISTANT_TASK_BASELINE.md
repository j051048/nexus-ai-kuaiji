# 助手任务级离线基线

问题固定为：**为什么这家企业本月还不能交付？**

这是一套可重复运行的本地验收，不是新 Agent、模型评测结论或上线许可。第一批未修改生产运行代码；第二批已把已有交付检查接入助手只读上下文和受控回复，见 [第二批验收](ASSISTANT_DELIVERY_CONTEXT_ACCEPTANCE_20261030.md)。所有业务资料和账号为虚构数据；不读线上配置，不发送真实模型/通知请求。

## 复用边界

- H01：严格 JSON、来源/金标 SHA-256、目录约束、原子 JSON 写入。
- AG05：版本化 `CandidateConfig`、manifest 身份与版本校验；坚持固定分母、缺失/未知不剔除。
- 已有 `ai_case` / `cost_case` / `execution_case`：FakeProvider、业务权限、SQLite 临时库、真实 `AssistantService` / `AssistantWorker` / `AssistantMeter`。
- 现有 `AssistantProvider` + `httpx.MockTransport`：实际构造请求、ContextPack、schema、解析模型输出、事实校验、发布和费用结算；没有第二套助手实现。
- 原有 ContextPack loader：重验实际请求中的事实、来源、版本、预算与内容指纹。

OCR 字段评分不能代替交付任务评分，所以新增的只是任务观察/评分薄层。Mock 返回分类是预置的，**没有验证模型能自己识别缺资料或冲突**。这里只验证已有系统如何接纳、拒绝、留痕并展示这些回复。

## 六类固定场景

| 场景 | 实际准备/操作 | 安全门槛 | 回答能力目标 |
|---|---|---|---|
| 正常 | 员工事项经部门、财务审批后移交生成未审草稿；会计提问 | 合法金额引用；未审导出被拒绝；助手不改变草稿或交付包 | 说明本期仍需会计复核、处理角色和下一步 |
| 缺资料 | 企业财务创建尚无原件的事项 | `missing_facts` 转人工，不接受模型“已导出”自由文本 | 指出缺原件、企业财务负责、上传原件、来源位置 |
| 冲突 | 保存金额 0.30，FakeProvider OCR 金额 0.40；实际评估产生冲突 | 保持 OCR 待核验；`conflicting_evidence` 转人工 | 指出 0.10 差额、谁核原件、证据定位 |
| 撤权 | 入队后删除会计的账套授权 | 0 次发送；旧任务不可读取；无费用 | 不泄露旧内容；不冒充已完成 |
| 超额 | 另一企业月限额 0.01，预留 0.10 | `quota_exhausted`；0 次发送；无费用 | 明确受控阻断 |
| 未知结果 | 另一企业发送后 mock 读取超时 | 1 次发送；费用 uncertain、预留保留；重建 worker 后不重发 | 结果未知且禁止自动重试，不记为成功回答 |

附加专项覆盖：发送后撤权、跨企业账套请求、跨企业 claim、错误事实版本、同幂等键重复入队、伪造 ContextPack、prompt 漂移、bool attempt、重复/缺失样本、输入/金标变化、报告覆盖、JUnit 缺例/跳过/失败。

“正常”是合法资料和合法事实回复路径，**不代表一家企业已满足全部月结、税务或交付条件**。本轮没有伪造完整月结结论。

## 运行

仓库根目录，使用已安装本项目测试依赖的 Python：

```powershell
.\.venv\Scripts\python.exe -m tools.assistant_replay
```

默认每次生成新的 `tmp_test/assistant-task/<UTC时间>/`，也可用 `--out tmp_test/唯一目录`；已有目录拒绝覆盖。`--timeout` 可配置 30–1800 秒，默认 300 秒。无需密钥、网络或 PostgreSQL。测试阻断真实 socket 连接，供应商请求只能经过 MockTransport。

输出包含：

- `candidate.json`：运行前冻结的相关代码、迁移、测试、夹具及依赖声明的文件摘要。包含未提交内容，不以 HEAD 冒充候选。
- `observations.json`：本地虚构数据的实际请求、终态、费用与权限检查观察。没有请求头或凭据；真实数据不能直接套用此输出模式。
- `report.json` / `report.md`：逐样本安全结论和业务回答缺口。
- `pytest.log` / `junit.xml`：本次测试证据。
- `summary.json`：同候选和各产物 hash、无跳过的测试结果；**以此作为本轮工程验收入口**。

运行前后候选变化、缺任何固定场景、测试失败/跳过、来源变化都会使统一入口非零退出。单独运行 pytest 只用于开发，不代替统一入口的同候选证据。

同一场景每次创建独立临时数据库，因此运行时 UUID/时间及完整请求 hash 可以不同；它们绑定本次真实请求。跨运行比较应使用冻结 case/config/候选身份和逐项结果，不能拿 UUID 差异当 prompt 退步。

## 判定口径

1. 工程通过：六类均实际执行，权限、调用次数、费用、未知态和业务不变性全部通过；全部必验测试无跳过。
2. 回答完整：评估**服务端实际发布**的回复，检查本期、阻断原因、责任角色、下一步及引用。只回显金额或安全弃答不算答完。
3. mock 费用的真实人民币成本为 `null`。数据库中的预留/估算只是合成定价下的契约断言。
4. 当前是固定中文用例的保守回归规则，不是自然语言质量评分器。更换措辞或新增能力要显式评审并版本化金标，不得为了刷通过率删除失败要求。
5. 只有开发集，没有独立未见验收集。此离线入口本身没有真实模型准确率、真实 PaddleOCR、PG/RLS、浏览器、跨进程崩溃恢复或容量结论。后续独立完成的 PG 动态验收见文末补充。

## 基线差距与第二批结果

第一批事实发布器只允许有限金额/数量/日期字段，三个业务回答均未满足完整性要求。第二批复用既有月度服务单、月结预检、交付检查和签收状态，增加范围受控的“阻断原因→负责岗位→下一步→引用”投影；原输入和金标不变，三个回答现在满足冻结规则。正常金额回复仍不能证明该企业可交付。

第一批的验收记录及产物保持原状，不用新结果覆盖历史缺口。第二批候选编号为 `assistant-delivery-projection-v2`；截至第二批验收时，真实模型效果、未见验收集和 PG 运行尚未验证。不能用未校验自由文本、放宽审核、自动导出提高指标。

## 2026-10-30 PostgreSQL 动态验收补充

随后新增的专用门禁已在本机 PostgreSQL 16.15/17.11 各执行 33 项、零跳过，并通过 16 项门禁自身测试。涵盖企业隔离、来源失效、撤权、费用、多进程领取和发送后崩溃防重发；前两批业务代码与金标未变。详见 [PG16/17 验收记录](ASSISTANT_DELIVERY_POSTGRES_ACCEPTANCE_20261030.md)。真实模型效果、浏览器、远端 CI 和线上运行仍不在该结论内。
