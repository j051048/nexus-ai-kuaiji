# 第二批改造：多企业调度与月度工作闭环

版本 `0.17.0`，面向 2–3 家真实企业的试点。新增企业并发底座、客户月度进度矩阵、参考余额核对及固定事项草稿；正式账本仍由客户财务软件保管，凭证仍由会计复核后导出。

## 一个会计的操作路径

1. 从“客户月度进度”选择月份，查看当前获授权企业和账套的资料、待审、异常、交付与月结情况。同一企业不同账套独立列出，不把企业资料数量误当作某个账套资料已完整。
2. 点击某一格进入该企业、账套、月份的实际工作页。下钻到复核保持账套过滤；返回矩阵或刷新保留所选月份。手机使用纵向卡片和侧栏导航。
3. 从“参考余额与月度差异”上传客户外部余额资料。期初取上一月期末，期末取本月，口径为人民币、已记账、净借余额；负数表示净贷。另一位有该期间复核权限的人员确认资料。
4. 使用当前真实科目与稳定辅助项 ID 比较“独立确认的外部期初 + 本月已核验交付运动”与外部期末。已审待交付、待回执、未知回执、未审核草稿分别保留，不计入已核验运动。
5. 形成不可改写的差异快照，由另一复核账号记录人工核对。补充余额、修改草稿或更新回执后必须重新检查。记录人工原因保留差异事实，不将其改为自动平衡。
6. 对合同租金等明确固定事实，在“固定事项草稿”配置实际科目、金额、辅助项和生效月份，独立审批后为本月生成普通未审草稿。相同长期账套计划同月只生成一次，重试返回原结果；会计仍须复核后导出。
7. 在现有月结页重新预检、复核并锁期。月度资料未确认、检查过时或待核对、已审批却未生成的当月固定事项会阻断月结。

当前固定事项需要明确人工触发，没有按日历自动执行。工资、税款、折旧等金额和是否实际发生须由真实资料提供，不由模型推算。T+ 的实际产品版本仍未确定，当前使用已有文件接入和回执核验底座，未启用真实 T+ API 连接。

## 进度矩阵的统计口径

`GET /api/monthly/workbench?period=2026-10&limit=20&offset=0`。权限过滤先于搜索、计数和分页；详情统计只读取当前页的账套。企业、期间与账套均保留在工作区 URL。

| 列 | 依据与限制 |
| --- | --- |
| 资料与草稿 | 当前账套来源及凭证草稿；业务待交按下钻入口统计，企业财务身份使用所选企业范围，其他会计使用会计接收范围。员工本人及部门待办保留在各自入口，不做企业汇总 |
| 会计复核 | 当前实际未审、已审待交付、已导出草稿数 |
| 异常与补件 | 当前可见账套未结、待补件及逾期事项，不扩大部门或企业授权 |
| 交付核验 | 按导出批次统计待核验、未知、有差异、完整核验；必须采用最新完整逐行回执 |
| 月结 | 展示真实关期状态与上次预检记录。开放期间一律要求进入月结重新检查，不显示“可直接关期” |
| 人工投入 | 已记录的复核、人工操作及符合现有计时条件的时间；未采集或无权限显示未知，不显示零耗时 |

只有事务所管理者可见“当月尚未建账套”的企业。普通会计未获权限不会被显示为未建账套。矩阵是处理入口，不是财务报表或完整性保证。

## 月度余额资料

中性 UTF-8 JSON / CSV 文件最多 2 MB、1,000 个维度。保存上传原文及 SHA256，当前账套读权限决定私有原文下载。结构化人工录入、上传原件、旧账归档复用、T+ 文件快照复用分别标明来源。格式与权限详见 [月度参考余额与固定事项](MONTHLY_REFERENCES_AND_RECURRING.md)。

科目级余额比较相应科目全部辅助维度的运动；辅助明细只比较相同稳定 ID。科目汇总和辅助明细不能相加。未提供的期初或期末维度保持未知，只有明确输入的零才表示零。

## 企业并发与升级

升级前备份数据库及私有原件、停写，再用管理员维护环境显式运行迁移。PostgreSQL 新增 **077–079**，SQLite 新增 **061–063**；已有迁移保留原校验摘要。API、OCR/分录 worker、助手 worker 和旧账 worker 应使用同一版本，再运行部署自检。

OCR 创建、发送前检查和结果持久化采用企业范围锁，同企业串行、不同企业可并行，并与未改造的排他写事务互斥。审批、分录采用、导出、关期及月度写入仍使用原排他事务。SQLite 保持单写者模式。

OCR、分录建议、对话共享数据库运行额度与企业轮转，员工预填也受供应商容量限制。默认全局任务上限仍为 **2**；每个 worker 线程仍为 1–2。管理员可将数据库持久额度显式配置为 1–8，运行环境只请求容量，不绕过数据库上限。

```sh
# 独立管理员维护环境中执行；ACCOUNTING_ADMIN_DATABASE_URL 不注入运行服务
python scripts/configure_processing_capacity.py --processing 4 --provider-global 3 --provider-default 2 --supplier api.example.com=1
```

增加副本时同时核对数据库连接池总数、供应商并发和企业费用上限。没有发送的繁忙请求可延后重试；已发送但结果未知的请求继续进入人工确认并保留费用事实。具体锁范围、配置与合成传输压测见 [并发与公平调度](CONCURRENCY_STAGE17.md)。

验收范围见 [第二批验证记录](VALIDATION_STAGE17_20261014.md)。真实供应商、真实 T+ 版本、外部账本余额完整性及真实会计月结仍需要试点验收；此版本不代表已验证一位会计管理 200–500 家企业。
