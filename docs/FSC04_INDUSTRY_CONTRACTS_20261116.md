# FSC04：行业配置与可核验的导入契约

前置FSC02/03；完整遵守总工作令。FDE目录不等于运行引擎，先核实现有接线，禁止新增同类规则平台。

## 范围

integrations/fde、tax/pilot、tax/sources、现有规则服务/RuleMemory、ledgers/company_master、现有导入向导与草稿生成。允许增量领域表，禁止为避免表而把所有行业写进出租车模型。

## 实施

1. 提取真正共用的导入信封：企业/账套/期间、源系统/对象/版本、原件hash、行身份、字段映射版本、单位币种、规则版本、逐行状态和贡献。复用原件、导入与指纹组件。
2. 行业配置描述允许的源契约、主数据维度、证据政策及批准的计算处理器；配置本身不可执行任意代码。草稿→独立确认→生效/替代/停用留痕，变更使未完成输出失效。
3. 五个profile先表示可用能力和未支持范围，缺实现/缺政策的能力显示未启用，不能仅增加枚举宣称支持。
4. 客商复用company_master_entities/aliases；科室、项目、商品等用有语义的实体/维度，不把车辆ID当通用对象。跨系统编码映射须版本化、可审核、有有效期。
5. 相同内核的第二个真实领域成功后再抽公共接口，保留出租车回归；不一次性全仓重构，不强制所有业务共用金额算法。

## 失败测试

- 修改表头/单位/金额含税口径却沿用同文件版本；同名客商自动合并；跨企业复用别名或规则。
- 重复文件、同外部ID异内容、部分行失败重跑造成重复草稿；数量单位不明自动换算。
- 配置嵌入SQL/公式/指令被执行；未审核规则激活；停用规则的旧预览还能提交。
- 配置版本只进入显示层，实际运行未绑定；恢复后丢失规则/映射依赖但输出仍显示有效。

## 验收

每类profile至少有正确、坏结构、错范围、错版本的合成契约样本；至少出租车和一个第二领域通过同一导入内核真实生成/拒绝路径。PG16/17并发激活与去重、前后端共享契约样本、配置和原件恢复验证通过。未有客户确认的profile保持试验/未启用。
