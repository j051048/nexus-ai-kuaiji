# V03 员工录入与同屏复核精修

日期：2026-10-23。Git 基线：`b5bedc9c5303d937b1fd27d5de64fe3b0b81b3f9`，包含起始工作区已有的 V01、V02 和其他任务未提交成果。

## 交付范围

本批精修现有员工录入、分录和会计同屏复核，不新增业务流程、首页模块、模型调用、依赖、API 或数据库迁移。权限、企业和账套范围、幂等、事实版本、自动保存、确认审核和审核后导出的业务条件保持不变。未提交、推送、部署或访问线上。

### 员工录入

- 三个原有模板保留，增加可见的“当前模板”提示，仍使用原有 `aria-pressed` 选中语义。选中装饰文字不重复进入按钮可访问名称。
- 将企业身份、附件和核对信息分成轻卡片，复用现有三步引导；附件与字段区域编号对应原有步骤，不新增第二套流程。
- 附件文件名、保存状态、AI 字段建议、识别失败和最终提交确认分别使用清晰的文字和语义表面。草稿保存不表示已提交或已审核。
- 手机保留 16px 输入字号、44px 主要点击区域和固定底部操作，补回被旧全局样式隐藏的模板说明。不会因为选择模板、上传文件或打开引导而自动提交。

### 会计同屏复核与分录

- 原件、事实、分录和操作区统一使用根级 token。附件完整文件名独立换行显示，保留原有选择、授权下载、证据引用和 SHA-256 信息。
- 预览加载提供忙碌/状态语义；读取失败保留明确错误和“重新打开凭证读取原件”的提示。保留现有 Blob 作用域检查、Abort、撤权清理及 401/403/404 处理，没有新增预览请求或自动重试。
- 原件预览高度有界，手机继续使用上下滚动布局；900px 以下提前上下排列，避免 740px 两栏把科目栏挤至约 58px。
- 修复旧全局 `dl > div` 布局对来源事实的干扰，金额与标签分行，测试大额不再把小数部分折到另一行。
- 分录根据**所在面板宽度**使用容器查询选择表格或条目布局，宽区域保留表格，窄复核面板和手机完整提供科目及借贷输入空间。金额仍为原始十进制字符串，合计计算未改。
- 分录表头注明人民币元，冻结字段维持禁用且清晰可读；待审核、借贷平衡、已审核、已导出仍为不同含义。借贷平衡不代表问题已处理，也不会自动审核。
- 队列存在下一笔时只突出“审核并下一笔”，原“确认审核”继续保留为次操作；两个回调和 `canApprove` 均未改变。审核后仍需通过原有授权入口单独导出。
