# 第十八阶段验证记录

本轮在本机隔离 SQLite、PostgreSQL 及合成企业数据上验证组织管理功能。真实身份验证单独使用 Supabase Auth，不向真实企业写入会计资料。

## 已覆盖的边界

- 企业资料修改要求连续版本；暂停、归档及恢复保留原始账务和审计。其他事务所无法读取管理摘要。
- 企业管理员不能自提权、不能管理事务所人员，移除或降级成员清理本企业派生授权；重新加入不恢复旧授权。
- PostgreSQL 受限 API／worker 登录、RLS、原生 SQL 和 HTTP 均参与权限验证，不能只依赖前端按钮。
- 具备明确长期账套管理权的企业财务仍可创建新期间，原有跨期继承不被新管理保护误拦。
- OCR／分录直接调度和合并调度都跳过停用企业，恢复后继续领取原任务；在途请求撤权后不能发布成功结果。
- 未复核草稿不能导出。管理者身份不会绕过既有事实版本、审批、期间和导出约束。
- 账号开通覆盖幂等、失败重试、取消、过期、发起人撤权、企业停用及已有账号保护；完成请求重放不会重新授权。
- 真实模式关闭公开创建事务所，管理入口与旧授权写接口均验证 MFA；本人接受邀请保持独立身份校验。
- 浏览器覆盖桌面、390 像素手机布局、角色可见范围、企业生命周期、版本冲突、开户恢复和旧会计工作台流程。
- 企业财务可继续读取获授权费用信息；仅管理员可见的性能面板按权限渲染，不再向普通财务发起会触发失权刷新的管理员请求。

## 身份服务验证

使用一个新建、明确标记的合成 Supabase 身份验证了无邮件激活、设置本人密码、密码登录、已有账号不生成重置链接、AAL1 与 TOTP 后 AAL2 的后端验证。测试结束已删除仅本轮创建的该身份。整个验证没有发送邮件。

用户指定的初始负责人另按明确授权创建，并完成密码登录验证和现有试点事务所的 `owner` 授权，记录 `admin.bootstrap.owner` 审计。源代码、迁移、本文和审计均不包含其密码。线上 API 当时返回 502，Zeabur 列表显示 API 与全部 worker 为 `SUSPENDED`，因此没有声称完成线上业务登录验证。

## 发布边界

- 本轮没有发布前端、API 或 worker，也没有执行线上 schema 迁移。
- 线上只读检查为迁移 072；新版本要求完整迁移到 082，并同步更新 API 与所有 worker。具体顺序见 [部署说明](STAGE18_ADMIN_WORKSPACE.md)。
- 管理员首次使用新后台仍需本人绑定验证器。本人邮件恢复需要部署方配置 Supabase SMTP 与 `/account-recovery` 重定向白名单；邮件恢复测试使用模拟服务，不代表实际邮件投递已验收。
- 新功能通过试点范围验证不等于已完成生产容量、真实外部财务软件入账或 200–500 家企业效率验收。

## 自动验证结果

- 后端：本机四个独立文件分片，另以受限 API／worker PostgreSQL 连接补跑数据库用例，修复历史测试准备方式后定向回归。按测试 ID 合并最终结果，**2,229 通过、1 项按设计跳过**。跳过项是 PostgreSQL 专属断言在 SQLite 参数组合中的占位，PostgreSQL 对应组合已执行。
- PostgreSQL 专用套件 **536 通过**，未包含在文件名过滤中的参数化用例另 **35 通过、1 跳过**；这两组已计入上述合并结果，不能重复相加。
- 带合成旧数据的 **072 → 082** 完整升级通过，核验金额、原始来源、未审草稿、暂停服务状态及审计归属；重复迁移返回无新增变更。
- 后端 Ruff 检查和格式校验通过。
- 前端类型、构建、ESLint、Prettier 与 **281 项 Vitest** 通过。
- 浏览器 **67 个不同用例通过**：稳定全量 63 项通过，修正邮件回跳重挂载、企业筛选断言及费用性能面板权限后，9 项定向回归通过，补齐原失败用例；另新增生产模式 MFA 用例，验证错误验证码不读取管理 API、验证成功后才使用 AAL2 会话请求。邮件恢复与浏览器 MFA 使用模拟 Supabase 响应，没有发送真实邮件。

首次回归暴露了新状态字段造成的查询歧义、旧测试绕过负责人保护、旧 schema 测试调用新目录代码等问题。修复后重跑相应用例；最终结果不采用修复前进程中缓存的旧代码结果。
