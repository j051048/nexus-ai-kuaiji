# 助手交付诊断 PostgreSQL 16/17 动态验收

日期：2026-10-30。范围：前两批「助手任务级离线基线」与「交付检查接入助手只读上下文」。全部为本机隔离数据库、虚构企业和 Mock/FakeProvider；无真实模型、通知、线上操作、提交或推送。

## 结论

**本轮同候选的 PostgreSQL 16/17 动态门槛通过。** 未发现需要修改前两批业务实现的新缺陷。本轮新增专项测试、验收入口和必验清单，修正测试夹具与测试初始化顺序；未修改业务权限、账务状态机、数据库迁移或 C01 文件。

| 验收 | 最终结果 | 说明 |
| --- | --- | --- |
| PostgreSQL 16.15 | 33 passed，0 skipped | 实际 `server_version_num=160015` |
| PostgreSQL 17.11 | 33 passed，0 skipped | 实际 `server_version_num=170011` |
| 门禁自身单元测试 | 16 passed，0 skipped | 缺例、替换、跳过、失败、重复及非隔离目标不能通过 |

这是 **66 次真实 PG 用例执行 + 16 项门禁单测**，不是 82 个不同业务场景。两套 PG 运行完全相同的 33 项清单。

## 覆盖矩阵

新增 20 项专项，复用原有 12 项助手对话/计费 PG 测试及 1 项会计复核后导出全流程测试：

| 项目 | 实际执行及断言 |
| --- | --- |
| 六类任务 | 复用冻结 manifest/gold：正常、缺资料、金额冲突、撤权、超额、发送后未知。核对实际状态、调用次数、attempt、费用；正常回复有期间、原因、责任岗位、下一步和引用。 |
| 企业与会话隔离 | 原生 SQL 与服务入口均拒绝跨企业账套、他人私有会话；客户财务仅获取自身事项范围，不获得事务所内部服务单备注。 |
| 版本失效 | 服务单在发送前、等待回复时、最终接纳前发生变化，旧回复不能发布。已锁期来源、交付包 ID/版本/manifest 被绑定；新包或签收变化使旧回复失效。 |
| 撤权 | 同样覆盖三个时点；发送前零调用零费用，发送后不发布、原生查询不可见，但已知供应商 usage 保留结算。 |
| 数据库执行权限 | API 登录不能直接改写任务快照、伪造回复或调用 worker 完成函数。 |
| 两会话竞争 | mock 响应挂起时，另一真实 PG 会话提交服务单变更；旧结果被拒绝，已发生费用仍保留。 |
| 两进程领取 | 两个独立 Python 进程同时领取同一任务，仅一个成功；一次 attempt、一次发送、一笔费用。 |
| 崩溃与重启 | 子进程在发送标记后或 mock 收件凭据落盘后退出；租约过期后另一个进程恢复，不能重发，旧租约不能结算。 |
| 未知费用 | 不猜测零费用：保留预留，token/估算为未知；崩溃路径允许已有 `sent` 或 `uncertain` 状态，不把未完成核定说成已结算。 |
| 会计控制 | 未审核导出被拒绝；复用独立复核后导出的 PG 全流程。不因助手回答而审核、过账或导出。 |

Mock 返回固定内容，**不证明模型能够自行正确诊断交付问题**。测试验证的是服务端对模型回复、既有交付事实和权限的处理。

## 红—绿记录

1. 首次新增 PG16 任务组：`2 failed, 11 passed`。一项 OCR 冲突夹具没有同步合成定价，另一项将 PG 提前淘汰撤权任务的领取返回值误认作 SQLite 行为。
2. 修正夹具定价与观察断言后 `13 passed`；撤权必须零发送、零 attempt、零费用的断言没有放宽。扩展进程/交付包测试后 `20 passed`。
3. 先新增门禁失败测试，最初因入口未实现而无法导入；实现后缺例、跳过、重复、篡改清单等测试通过。
4. 发现普通 pytest 可能在函数级安全检查前初始化模块级 PG 夹具；将本模块设为显式隔离运行，并在迁移夹具前校验目标。新增五种非法目标负向测试，断言迁移夹具根本没有被调用。
5. 最终代码冻结后，重新执行 PG16/17 各 33 项和 16 项门禁测试，结果见上表。早期红测及中间结果保留，未用最终结果覆盖。

普通未显式启用隔离环境的 pytest 会跳过本 PG 模块，以免意外初始化数据库；**这不属于验收通过**。专用门禁必须全量执行，任何 skip 都失败。

## 环境与数据库条件

- 复用已有 AK05 隔离 runner、受限角色配置、迁移检查和候选指纹实现，没有再实现一套权限或迁移器。
- 本轮独立 WSL PG16/17 实例端口为 `25616/25617`；库名使用 `ak01_local_ak05_` 前缀；只连接 `127.0.0.1`。没有使用 C01 集群或线上 DSN。
- API 与 worker 使用不同受限登录角色；检查非超级用户、无 BYPASSRLS、无建库/建角色能力以及既有角色授权。管理员连接仅用于空库初始化、虚构夹具与按 fixture 企业清理。
- 两库均应用当前 **168 个 PostgreSQL 迁移文件**，逐文件登记 checksum 匹配；168 是文件数量，不是声称最新迁移编号为 168。
- `fsync/synchronous_commit/full_page_writes` 均为 on。
- 9 张相关表启用并强制 RLS：books、assistant_conversations、assistant_messages、assistant_turns、service_plan_versions、internal_close_runs、monthly_delivery_packages、monthly_delivery_acknowledgements、model_costs。
- 私有配置位于忽略目录 `.codex/assistant-delivery-pg-20261030/`，未输出 DSN 或密码、未纳入报告。
- 收尾已停止本轮两个实例，保留数据和证据；原有 PG14/16/17 实例状态未改变。停机记录为 `environment-stop.json`。

## 可复跑入口

先使用现有 AK05 隔离环境工具准备或启动两套本机测试库，应用当前迁移并配置 API/worker/投影的受限角色。门禁只验收，不会创建数据库、安装软件或修改服务配置。

在仓库根目录执行，`--out` 每次使用不存在的新目录：

```powershell
.\.venv\Scripts\python.exe scripts/assistant_delivery_postgres_gate.py `
  --pg16 .codex/assistant-delivery-pg-20261030/pg16.json `
  --pg17 .codex/assistant-delivery-pg-20261030/pg17.json `
  --out tmp_test/assistant-delivery-pg-new-run

.\.venv\Scripts\python.exe -m pytest `
  nexus_backend/tests/test_assistant_delivery_pg_gate.py -q
```

配置结构与 `scripts/ak05_postgres_gate.py`、`scripts/test_accounting_postgres_isolated.py` 既有契约一致。不能将生产连接改名后用于此入口。超时默认每个版本 600 秒，可用 `--timeout` 在 60–1800 秒内调整。
