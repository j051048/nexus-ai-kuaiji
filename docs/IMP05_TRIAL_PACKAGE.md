## 1. 场景与身份

本地演示数据库由 `ACCOUNTING_SEED=1` 创建，含两家及以上虚构企业。服务端按当前本地测试身份授权；页面右上角的身份切换器是**本地测试登录替身**，不是生产登录方式。每个身份在服务端有独立 user/firm membership/book grant，切换身份不会继承上一个身份的权限。

| 试用岗位 | 本地测试身份 | 服务端职责 | 不应看到/不应能做 |
|---|---|---|---|
| 企业员工 | `employee`（示例员工 小陈） | 提交本人业务、补件、查看本人进度 | 审批、复核、导出、跨企业 |
| 部门审批人 | `department`（示例部门负责人 小林） | 本部门审批/退回 | 会计复核、跨部门审批 |
| 企业财务 | `finance`（示例企业财务 小周） | 资料核验、交接到账套、退回补件 | 独立复核、正式记账决策 |
| 制单会计 | `accountant`（本地复核会计） | 制单、草稿、提交复核 | 自审本人待审版本 |
| 独立复核人 | `reviewer`（示例复核会计 小吴） | 独立复核、允许的导出 | 修改制单责任、替客户签收 |
| 事务所负责人 | `accountant` 的 owner 视角 | 全所协调、查看卡点、分派 | 绕过独立复核政策 |
| 客户签收人 | P02 真实客户身份（外部试用时） | 查看包、签收准确版本 | 会计复核、内部审批 |

> 本机 `ACCOUNTING_AUTH=local` 只用于试用；真实试用必须使用独立 Supabase 测试账号。不得把身份切换器当作生产授权能力。

## 2. 六项任务卡

### T1 员工提交 128.50 元虚构差旅费

- 角色：企业员工
- 目标企业：澄光科技（虚构示例）
- 任务：提交 128.50 元差旅费，上传一张虚构票据，填写日期、事由、交易对方。
- 正确依据：金额 128.50；企业与日期正确；附件 1 份；只提交 1 次；员工能在“我的事项”找到进度。
- 观察点：是否需看说明才能找到入口；是否被要求填写与任务无关的字段。

### T2 员工处理退回补件

- 角色：企业员工
- 前置：T1 被部门/财务退回，原因写明“缺行程说明”。
- 任务：从原事项补一张说明或补充用途，再次提交。
- 正确依据：保留原企业/日期/金额/附件；没有新建第二条事项；能看懂退回原因。
- 观察点：是否误点“新建”；是否丢失已填内容。

### T3 上传中断后恢复

- 角色：企业员工
- 前置：上传过程中断网或关闭页面。
- 任务：重新进入草稿，核对最新版本后继续。
- 正确依据：同一事项、同一企业、已填字段保留；附件不重复；不自动提交。
- 观察点：错误提示是否能说明“已保存/未保存”；是否重复上传。

### T4 企业财务核验并交接

- 角色：企业财务
- 任务：核对 T1 的金额、日期、用途和原件，选择正确账套后交接到会计；另一条事项退回并说明原因。
- 正确依据：选对企业/账套/期间；下一位处理人明确；退回原因具体；原记录可追溯。
- 观察点：是否能区分“核验”与“复核”；是否误以为交接即记账。

### T5 会计复核并返回

- 角色：制单会计 + 独立复核人
- 任务：制单会计打开待审凭证核对原件与分录；独立复核人完成复核；制单会计返回列表。
- 正确依据：复核人不是制单人；金额、版本、原件一致；返回保留筛选/位置；未复核不能导出。
- 观察点：是否出现自审；是否能找到“谁处理、下一步”。

### T6 负责人找卡点与下一位处理人

- 角色：事务所负责人
- 任务：找到某客户本月卡点，说明卡在哪一步、谁负责、下一步去哪里办理。
- 正确依据：企业与期间正确；卡点原因和负责人准确；能从原记录进入；不把汇总数字当明细。
- 观察点：是否需要打开多个页面；是否把“待我处理”和“等待他人”混淆。

## 3. 记录表

模板：`tmp_test/imp/imp-20261106-a/trial/records.csv`

字段：

- `candidate`：候选 source_sha256，一次试用只用一个候选
- `participant_id`：匿名编号，不用真名
- `role`、`company`、`device`、`network`
- `task_id`：T1–T6
- `attempt`：同一参与者同一任务的第几次
- `outcome`：`completed` / `assisted` / `abandoned` / `not_started`
- `seconds`、`assists`、`wrong_turns`
- `state_understood`、`duplicate_write`（true/false）
- `failure_step`、`notes`

空表必须保持空；不要填示例成功数据。没有记录时统计脚本返回 `incomplete/no_records`，不会输出“0 错误”。

## 4. 主持说明

1. 只给任务卡，不指按钮位置；参与者问“点哪里”记 1 次求助。
2. 不替参与者填写、不替其确认、不替其选择企业。
3. 失败/放弃保留原步骤和脱敏截图；不要重试到成功再记录。
4. 每场开始记录候选、设备、浏览器、网络；候选变化后旧场次作废。
5. 真机需记录相机权限、键盘、旋转、后台恢复、iOS/Android/微信内置浏览器。
6. 3–5 人只用于形成性发现问题，不宣称统计显著或生产效率。

## 5. 统计

```bash
.venv/Scripts/python.exe scripts/imp05_trial_summary.py \
  tmp_test/imp/imp-20261106-a/trial/records.csv \
  --out tmp_test/imp/imp-20261106-a/trial/summary.json
```

契约：

- 分母 = 已开始尝试（completed + assisted + abandoned），失败和放弃不从分母删除。
- `not_started` 单列，不混入完成率。
- 自动化/CI 记录拒绝为真人。
- 缺 candidate/device/角色等必填、重复 attempt、放弃无失败步骤 => `incomplete`。
- 空文件 => `incomplete/no_records`，不生成 0 错误。
- 本脚本不把秒数换算成“人工效率”，只做记录汇总。
