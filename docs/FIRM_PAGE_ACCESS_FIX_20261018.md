# 事务所三个页面的认证与授权修复（本地验收）

日期：2026-10-18。范围：数据接入、运行可观测性、客户开通，以及共享认证处理。未提交推送、未部署、未操作线上数据库或服务。

## 问题与修复

1. 共享 HTTP 层原先把所有 403 都当成同一种权限变化；身份重载会先清空登录和工作区，导致合法登录也短暂进入登录页，再回首页。现在分开处理：
   - 401 / 明确失效的会话：清除登录和受保护数据，要求重新登录。
   - 普通 403：保留当前页面，清除旧证据与结果，后台单次重验身份；不重新播放被拒绝的请求。
   - `admin_mfa_required`：独立的二次验证提示；原页面输入保留，成功后由用户主动重新提交。
   - 身份服务网络故障：显示可重试错误，不误登出。
2. 数据接入和客户开通读取企业目录使用已有授权过滤的 `/companies`，不再为普通读取访问要求 MFA 的 `/admin/companies`。管理写入的服务端 MFA 要求保持不变。
3. PostgreSQL 的运行账号没有读取全局 `worker_heartbeats` 的权限，这是正确的边界。新增迁移 `123_firm_worker_health.sql`，通过受控聚合函数只公开服务是否可用、最近心跳及失效阈值。函数再次检查账号有效性与当前事务所管理权限，只有 `accounting_app` 可以调用。不开放原表读取，不返回进程标识、其他事务所的任务或负载。
4. 三页按授权范围隔离组件状态，拒绝访问时清空旧结果；共享请求版本阻止撤权或切换后迟到的响应恢复旧资料。
5. 工作区 MFA 弹窗与计时组件使用不同组件 key，避免身份刷新后出现验证已成功但弹窗仍显示等待的问题。
