## 3. 本轮执行边界

- 只用本地隔离环境和合成数据；不接真实模型、通知、OA、税局、T+或其他外部财务系统；不提交、不推送、不部署、不执行线上 SQL。准备真实适配所需清单不等于获得连接授权。
- 不覆盖、回退、暂存其他智能体改动；开工和每次公共文件编辑前核对归属与漂移。新迁移临用时分配编号，不改历史 SQL 和 checksum，不放宽 RLS、复核、锁期或费用/attempt 防重发。
- 账户、企业、稳定账簿身份、物理月账套、期间、对象、来源版本分别绑定。跨月不能复制资产/合同产生第二份经济业务，集团权限不能替代逐企业授权。
- 合同确认、业务核验、独立会计复核、内部记账、导出、外部接收/记账、客户签收分别表达。人工声明不变成外部官方事实；`unknown` 不自动重发、不推定未执行。
- 政策由客户/会计确认，缺依据时阻断真实启用。合成测试可用明确标记的虚构政策，不能把金额算法、税率、折旧起止或付款规则写成行业通则。
- 已记账、已锁期和已冻结历史不可重写；用现有冲销/更正及追加事件处理。历史文件允许按当前权限审计查看，但不能冒充当前有效版本再次执行。
- 复用现有页面和导航。新增办理入口就近放在原对象，显示单位/期间、差额、依据、负责人和下一步；完成后回原队列并保留筛选，不新增一套同名工作台。

## 4. 每包工作循环与完成定义

按以下步骤连续完成，不在“模块写完、以后再接线”处停止：

1. **盘点**：记录当前已有实现、测试、真实缺口、修改文件归属、依赖与待确认政策。状态不明就写未核实，不把旧报告中的未完成自动当成当前缺陷。
2. **先红**：对真实缺口写可重复失败测试，记录命令、退出码、实际错误；已完整覆盖的能力复跑即可，不故意制造失败。
3. **最小修复**：服务、数据库约束、前端接线和真实业务成功链一起补齐；不能只修 UI 或只加 API。
4. **动态验证**：SQLite 快检、PG16/17 受限业务角色、直接 SQL 负向、双会话竞争、撤权及版本失效。必验集合零 skip/xfail，不固定预期用例数量掩盖漏测。
5. **浏览器**：桌面/手机通过本地身份、实际 API/PG/原件存储办理；mock 只用于外部边界和故障注入。断言实际金额、对象/版本、请求与状态，不以截图或按钮存在代替成功。
6. **恢复与组合**：每包新增实体和关系都有非空数据恢复回归；最后一次完整 P01 联合恢复统一纳入 FSC12，不每改一行就盲跑所有历史测试。持续保留受影响的 C01、核销、复核、费用及 attempt 回归。
7. **证据**：每次 `tmp_test/fsc/FSCxx/<run-id>/` 独立目录；记录源文件/迁移/依赖/配置/政策/夹具指纹、测试前后漂移、JUnit、截图和脱敏诊断。旧证据保留但不拼成新候选通过。

维护现有 FSC 状态/归属/检查点前确认没有并行写入；必要时先写本批独立检查点，再由单一负责人合并台账。输出 `docs/FSC13_ACCEPTANCE.md` 至 `docs/FSC17_ACCEPTANCE.md` 及对应 JSON，不伪造测试结果。

外部资料缺失时继续所有不依赖外部的工作，安全关闭真实启用，列明具体资料与责任人。遇到工具/额度/环境中断要记录已完成、正在运行的进程归属和下一条可执行步骤；恢复后先检查漂移。不得把“部分通过”改写为“整批完成”。
