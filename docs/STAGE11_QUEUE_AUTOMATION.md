# 第十一阶段：受控续跑与后台阶段耗时

本阶段面向 2–3 家企业的辅助记账试点。自动任务仍只生成未审核草稿，会计独立复核后才能导出。

## 企业自动续跑

企业管理员或事务所管理员可在「后台分录任务 → 续跑配置与耗时」启用企业策略，默认关闭。配置带乐观版本和人工依据。

- 已知发送前阻断：企业处理开关、票据/分录服务缺失、缺票据、未关闭异常、OCR 积压、费用额度或单价配置。
- 每轮最多巡检 12 家企业，每家最多 1 项；持久记录下次巡检时间。异常关闭、企业开关与费用配置变化会登记持久唤醒信号，最多唤醒 200 项，剩余项由有界巡检覆盖。服务配置和容量恢复由低频巡检发现。
- 恢复始终使用原执行人的当前登录、企业、业务与账套权限。worker 不会替换为企业管理员。
- 再次检查当前业务映射、来源、开放期间、草稿状态、人工修改、模型配置和费用；实际发送前仍通过原费用预留与租约检查。
- 连续事实版本变化必须逐版对应数据库记录的独立接受补件，且该补件已关闭，marker 绑定同一账套、来源、草稿和当时草稿版本。业务补件目前只更新事实版本；草稿版本保持严格相等。
- 企业规则、科目或模板策略指纹改变、来源替代、事实修订、取消、手工修改、已审核、已发送或结果不确定等均保持人工处理。已有无法证明未发送的 OCR 失败不会自动重新发送。

恢复追加新 generation、冻结当前输入，并在不可变收据记录 old/new fact/draft/config、原阻断原因、接受补件 ID 和企业策略版本。恢复、依赖创建和审计处于同一事务；失败回滚；重启后读取持久 watch 和收据，不靠进程内计时。

费用预检只预测新外部调用。当前已识别原件、公司范围已验证 OCR 缓存、固定模板和已发布规则能够完成的路径，不因未配置模型费率或低额度阻断。无法确定未来 OCR 结果时按可能需要的模型调用保守预检；实际是否发送仍由确定性校验决定，额度始终在真正外发前预留。

## 持久性能记录

`processing_job_metrics` 汇总所有 worker，按企业授权读取，记录：

| 阶段 | 含义 |
| --- | --- |
| dependency_wait | 分录任务等待 OCR 依赖解除的时间 |
| eligible_queue_wait | 已达到可执行时间后至领取的排队时间，排除 retry 退避 |
| claim_lock | 领取调用中的连接、查询和数据库锁等待总耗时 |
| model_call | 紧邻供应商调用前后的单调时钟耗时 |
| validation_persistence | 执行开始至结果保存前减去模型耗时，包含原件准备、确定性校验和落库，不含最终 commit |
| ocr_cache_reuse | 成功复用已验证 OCR 原件内容，作为事件计数 |

领取、等待和当前有效租约内完成的执行记录持久化；撤权、取消或租约失效导致未发布的响应不保证有完整阶段样本，费用风险仍以原费用预留、执行记录和失败告警为准。指标不含原件、模型请求内容、数据库连接或 worker 密钥。

保持既有全库写锁、全局最多 2 个处理任务、每企业最多 1 个，不宣称已经验证 200–500 家容量。企业页面提供最近 7 日均值、最大值和样本数；API 可选 1–90 日。

## API 与数据库

- `GET /api/intelligence/companies/{company_id}/automation-policy` 当前可访问企业成员读取。
- `PUT /api/intelligence/companies/{company_id}/automation-policy` 企业/事务所管理员，`expected_version/enabled/allow_verified_supplements/reason`。
- `GET /api/intelligence/books/{book_id}/resume-events` 当前账套编辑权限，`limit/offset`。
- `GET /api/intelligence/companies/{company_id}/job-metrics?days=7` 企业/事务所管理员。

迁移 PostgreSQL `056_queue_automation_metrics.sql`、SQLite `041_queue_automation_metrics.sql`。PG 所有新增表启用并强制 RLS，worker 无直接表访问。专用 worker 可调用有界候选领取、原执行人身份下的恢复能力和租约绑定的指标写入能力；API 无执行这些函数的权限。
